# IBKR 交易指令解析引擎

把中英混合的自然语言交易指令解析成结构化订单,经硬校验后直连 Interactive Brokers 执行,
并把每一笔从提交到终态自动落库。实现依据是 `ibkr_prompt_design_2.md` 设计方案。

核心原则照抄设计文档:**提示词负责理解,软件层负责最后防线;宁可拒绝,绝不猜测。**

## 快速开始(桌面端)

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev,broker]"   # 用富途通道再加 ,futu
cd desktop && npm install && npm start
```

首次启动会自动从示例生成 `config/settings.json`。然后在右栏「大模型」面板选供应商、填 API Key
(写进 macOS Keychain,不落配置文件),在「TWS 连接」面板检测 TWS——**IBKR 的 API 跑不起来
就到「富途 OpenD」面板切过去**——再在「设置」面板核对限额与执行闸门。

> 如果 `npm install` 卡在下载 Electron 二进制(几分钟没有进展),那是 `@electron/get`
> 偶发的挂起,不是网络问题。手动补上即可:
> ```bash
> V=$(node -p "require('electron/package.json').version")
> curl -L -o /tmp/e.zip "https://github.com/electron/electron/releases/download/v$V/electron-v$V-darwin-arm64.zip"
> unzip -q -o /tmp/e.zip -d node_modules/electron/dist
> printf 'Electron.app/Contents/MacOS/Electron' > node_modules/electron/path.txt
> ```

## 界面

侧栏导航,页面如下:

- **交易指令** — 输入框(⌘Enter 解析)与解析结果并排;「解析并校验(不下单)」/「发送到 IBKR」
  两个按钮,结果卡片含通过 / 排队 / 拒绝 / 警告与本次调用的模型、耗时、token 用量
- **订单看板** — 「排队等待触发」与「已提交」分列(§8.2b),下方是实时通知流;侧栏项带排队数徽标
- **交易记录** — 可筛选列表与完整详情、数据导出
- **K线 PA** — 实时 K 线 + 价格行为读盘(摆动结构、BOS/CHoCH、关键位、FVG、扫单、形态),
  判断由代码算、权重公开;见后面专门一节
- **TWS 连接 / 富途 OpenD / 大模型 / 设置 / 关于** — 见后续各节

顶栏常驻:美东时间、市场状态、模型、网关连接状态(按生效的券商显示 `TWS` 或 `OpenD`)、
当前模式,以及**「暂停全部自动执行」熔断按钮(⌘⇧H)**——§9.7 要求的那个总闸。

界面结构参照 Apple Design Resources 的 macOS UI Kit 应用模板:**统一工具栏 + 源列表侧栏 +
内容区**。侧栏分三组(工作区 / 接入 / 应用),七个页面:交易指令、订单看板(带排队徽标)、
交易记录、TWS 连接、大模型、设置、关于;选中项为强调色填充,图标是按 SF Symbols 几何手绘的
内联 SVG(描边 1.4,`currentColor`,不引外部字体,CSP 依旧只允许 'self')。

### 视觉底子:按 macOS HIG 来

- **系统字体与字号层级**(正文 13px / 说明 11px),不自造字号
- **系统语义色**(systemBlue/Red/Green/Orange),浅色 `#007AFF`、深色 `#0A84FF`
- **跟随系统深浅色**——桌面应用不该强制一种外观
- **材质**:窗口开 `vibrancy`,界面用半透明底让模糊透出来;工具栏 `hiddenInset` + 拖拽区
- **AppKit 风格控件**:胶囊分段控件、开关(不是复选框)、System Settings 那种内嵌分组列表
- 0.5px 发丝分隔线、10px 圆角、克制的阴影

半透明只是装饰,不是可读性的前提:**macOS 打开「减弱透明度」辅助功能、或在 Windows 上没有
vibrancy 底材时,自动切换成实底**(`prefers-reduced-transparency` + 非 darwin 平台的
`data-vibrancy="off"`)。这一条是实测发现的——在没有底材的环境里,半透明面板背后是空的,
文字对比度会直接塌掉。

### 两个平台各按各的规矩

原来这套界面是照 macOS HIG 一路做下来的,跑在 Windows 上就露了馅。搭了个
[界面预览台](desktop/tools/README.md)之后才看得见问题——之前根本没法给 Electron
窗口截图,UI 只能盲改。

**被量出来的一个真 bug**:`.shell` 写的是 `height: calc(100% - 52px)`,把工具栏高度
硬编码了,而工具栏下面还有一条宏观行情带。于是壳层比可用高度多出 27px,**侧栏最底下
那一项和内容区底部被裁掉**——窗口越矮越明显。现在改成 body 竖向 flex + `flex: 1`,
高度由布局自己算。

**窗口按钮在哪一侧,两个平台正好相反。** macOS 的红绿灯在左上,所以工具栏左边留了
88px;Windows 的最小化/最大化/关闭在右上,那 88px 就成了纯浪费,而右边的按钮会被系统
按钮压住。现在 macOS 继续 `hiddenInset`,Windows 改用 `titleBarStyle: 'hidden'` +
`titleBarOverlay`——把系统按钮直接画在应用自己的工具栏右侧,省掉一整条原生标题栏,
也没有"一个应用两条栏"的割裂感(VS Code、Teams、Edge 都是这个做法)。叠加层的配色
跟着深浅色重画,否则浅色主题下会画出一组看不见的白色按钮。

**字体栈原来在 Windows 上会一路 fallback 到 Arial**:`-apple-system` → `SF Pro Text`
→ `PingFang SC` 全都解析不到,中文再退到另一套字库,字重和西文对不上。补上
`Segoe UI Variable Text`(Win11)/ `Segoe UI`(Win10)和 `Microsoft YaHei UI`。

**`cursor: default` 是 macOS 的规矩**,Windows 用户看到不变的箭头会以为点不动——
非 darwin 平台给按钮、导航项、记录行换回 `pointer`。

**快捷键要显示这个平台上真实存在的键。** 界面上原来画的是 `⌘⏎`,Windows 键盘上没有
这个键;现在按平台渲染成 `Ctrl+Enter`。监听端本来就是 `metaKey || ctrlKey` 和
`CommandOrControl`,功能一直是对的,错的只是标签。

### 界面上的券商名也跟着切

和引擎侧那次"文案平替"是同一类问题,只是这次在按钮上:切到富途之后,主按钮还写着
**「发送到 IBKR」**,而单子实际会发到富途——这种不一致在下单界面上是会出事的。现在
按钮、快捷键提示、执行条件说明、二次确认弹窗里的券商名都跟着 `broker_provider` 走。

顺带修掉:交易记录里的在途状态原样显示券商的英文枚举(`Submitted` / `PreSubmitted`),
终态翻了、在途没翻,同一列中英夹杂——而这恰恰是最常扫的一列。

### 密度与层次

- **卡片和页面原来是同一个背景色**,只靠一条 0.5px 边框区分,深色下几乎看不出来。
  拆出 `--bg-elevated`,卡片真的浮起来一层。
- **页头吸顶**:列表一长,标题和旁边的「导出 / 清空」就滚没了,想点还得先滚回去。
- **顶栏状态条不再换行**:栏高写死 52px,一换行第二行直接被裁掉,显示成半个词。
  改成不换行,窄窗口下按重要性**整颗**丢弃(时间和模型可以没有,连接状态和模式不能)。
- **数字用等宽字形**:价格、数量、时间竖着排要能对上位。
- **列表时间收紧**成 `08-21 21:41`(当天只显示时分),完整时间放 tooltip——年份在
  列表里没有信息量,却挤掉了后面的账户标签。

### 键盘与读屏

侧栏原来是一排普通 `<button>`,读屏软件只会念出"八个按钮",既说不出这是导航,也说
不出当前停在哪一项。补上 `role="tablist"` / `aria-selected`,并让**方向键**在项之间
走(Home / End 跳到首尾)——这是所有成熟应用侧栏的标准行为。焦点环原来只有开关有,
现在所有可交互元素都有;另外尊重「减弱动态效果」。

### 按可用性启发式过了一遍

有了[预览台](desktop/tools/README.md)之后又做了一轮,这次不是看好不好看,而是逐条对
Nielsen 那十条可用性启发式。另外配了一份**首次启动的数据源**(`tools/mock-bridge-empty.js`)
——什么都没配、什么都没连、一条记录都没有。这是新用户唯一会看到的状态,也是开发时最少
看到的状态:手上有数据的时候一切都好看,空的时候才知道哪里缺引导。

**「还差 N 步才能开始」。** 新用户打开软件落在「交易指令」页,而这一页在没配 API Key、
没连券商之前什么也做不了——原来唯一的线索是按钮下面一行灰色小字。现在缺什么列什么,
每条直接跳到能解决它的那一页;必要条件都满足就整块消失。它是状态,不是唠叨,所以刻意
**没做成可以永久关掉的横幅**——关掉只会让人更找不到问题在哪。

同理,「发送」按钮为什么点不动,鼠标停上去说得出来了(未打开自动执行 / 未连接 / 已熔断)。
禁用而不说明原因是最招人烦的一种交互。

**记录详情原来是一坨 JSON。** `JSON.stringify(record, null, 2)` 是开发者视图。而记录是
这个软件的核心产物(§6 每一笔从提交到终态都落库),用户想知道的是:发了什么、走到哪一步、
成交在什么价、模型花了多少钱。现在是一张单据:这笔单 / 合约 / 订单 / 成交 / 模型 /
**状态时间线** / **成交明细表**。原始 JSON 没删,收进折叠区——这个项目在意可审计性,
那份原文要留得住。

**内部枚举不再漏给用户。** `OPT` / `BUY` / `LMT` / `EXPLICIT` / `DAY` / `Submitted` 这些
是协议里的取值,不是给人看的词。现在统一翻译,翻不过来的原样显示——露一个英文,好过编
一个错的中文。买卖方向另外着色,那是扫列表时最先看的字段。到期日从 `20260821` 变成
`2026-08-21`。

**回测参数原来叫「参数 fast」「参数 buy_below」。** 用户得自己猜 buy_below 是买入线还是
买入下限。参数名是策略定义的一部分,所以中文名加在引擎侧的 `STRATEGIES` 里和策略写在
一起,界面认不出就退回原名——而不是散到界面里去维护一份会和引擎失配的表。

**交易记录能按状态筛了。** 翻记录时最常问的是"哪些成了、哪些还挂着、哪些被拒了",而原来
只有一个关键词框——想看被拒的单得先记住"校验拒绝"这四个字。每一档带条数,空的档位直接
禁用,省掉一次白点。

**长操作会转圈。** 解析一条指令要 2 到 60 秒,握手诊断 8 秒。原来只是把按钮置灰、换一行
文字,用户分不清"在跑"和"卡死"。

**横幅会自己消失。** 提示类 6 秒后走,错误类留着等人看,两者都点得掉。永远挂在那里的
横幅,过几分钟就没人再看它一眼。

**键盘。** `Esc` 收起打开的记录详情——打开了一个面板却没法用键盘关掉,是最基础的一条
"用户控制权"缺失。注册在案的快捷键有四个,界面上原来只提过一个,现在「关于」页有完整
一览,按平台渲染真实键名。

**读屏与标签。** 18 个输入框看着有标签,但那个 `<label>` 没有 `for`——读屏软件只会念
"一个数字输入框",点标签也不会聚焦到输入框(所有原生表单都有的行为,少了会让人觉得
这个界面"怪怪的")。这类问题人眼一页页看很容易漏,所以写了
[`tools/audit_ui.py`](desktop/tools/audit_ui.py) 让机器扫:无名按钮、无标签输入、
引用了不存在的 DOM id、界面文案里漏出来的内部枚举。

**交易记录给了密度切换。** 之前在"卡片流"和"密集表格"之间纠结过:表格扫得快,但塞不下
`intent_summary` 和 `reason`,而那两段恰恰是这个软件区别于普通下单终端的地方(自然语言
交易)。答案不是二选一——**舒适**保留意图和理由,适合回看"我当时在想什么";**紧凑**
一行 28 像素、时间/标的/方向/意图/状态列对列,适合扫"哪笔出了问题"。选择记在本地。

(实现上有个坑值得记:紧凑模式用 grid 排版时,DOM 顺序和列顺序不一致会让 grid 的自动
排布把靠后的元素甩到第二行——行高从 28 变回 100,"紧凑"就白做了。所以行列都写死。)

**顶栏按"要不要马上处理"重排。** 工具栏的位置很贵,只该留会变、且变了要处理的东西:

* **时间和市场时段合成一格**——时间之所以要看,正是因为它决定了现在是盘前还是盘中;
  拆成两格既占位又要读两遍。只留时分,秒在这里没有决策价值却让这格每秒都在跳。
* **模型名是配置不是状态**,一个月不变一次却占着最宽一格。降级成背景色小字,完整名进
  tooltip,窄屏第一个丢的就是它。
* **券商连接和执行模式挪到最左**——前者会断,后者是安全闸门,它们才是要盯的。

**参考资料按需展开。** 三块常驻的教学内容(「读盘常识」和两处「连不上时照着做」)第一次
来的时候是救命的,连上之后就成了每次都要滚过去的一堵墙。处理原则不是"藏起来",而是
**需要它的那一刻自动展开**:没连上时指引默认打开、连上就收起;订单簿还没关注标的时常识
默认打开、加了标的就让路。手动点过一次之后就记住用户的选择,不再自动改——自动化可以
帮忙猜第一次,但不该反复推翻用户的手动操作。

**开机即可打字。** 主输入框是整个软件唯一的入口,原来每次都要先用鼠标点一下。现在启动时
和切回该页时都自动聚焦。

**列表里的时间统一成紧凑格式**(`08-21 21:41`,当天只显示时分),完整时间进 tooltip。
详情页的「提交时间」和状态时间线保留完整格式——那里正是要看准确时刻的地方。

**残缺负载不该让整页塌掉。** 设置页原来是 `settings.policies.auto_execute` 直接点进去,
少一个字段就整页空白 + 一句 JS 报错。现在缺什么空着那一格,其余照常可用。

## 期权墙与价位警告

选好标的 → 算当天期权墙 → 在墙的位置和整数关口上设警报,价格穿过时报一次。

**价位的两个来源:**

| 来源 | 具体是什么 |
|---|---|
| 期权墙 | 持仓量墙(OI 最大的行权价)、成交量墙、最大痛点、Gamma 翻转位 |
| 整数关口 | 现价上下最近的步长整数倍。IREN 41 块、步长 5 → **40 和 45** |

墙落在整数关口上是常事(它们本来就互相吸引),会**合并成一个**价位,标签两个都留着——
同一个位报两次,和报错在使用上是一回事。合并时以更可信的一方为准:墙压过整数关口,
**当天到期时成交墙压过持仓墙**。

**三个口径含义完全不同,界面上分开摆:**

- **OI 是隔夜存量** —— OCC 每天开盘前公布一次,盘中看到的不含当天的流
- **成交量墙**才是今天真正的流向。0DTE 合约绝大多数当天开当天平,**OI 墙基本没有参考价值**
- **GEX 的符号是一个假设,不是事实** —— 这里用最主流的那个(做市商多头 call、空头 put)。
  真实持仓没人看得到,换个假设结论可能反过来。它适合判断波动会被压住还是放大,不适合判断方向

最大痛点只是个统计量;「到期会被拉到那儿」这个因果**没有可靠证据**,当参考位看,别当预言。

### 不刷屏是这个模块最难的部分

价格在 40 附近来回蹭一分钟,朴素实现能报几十次——**报到第三次人就不看了,警告也就废了**。
所以每个价位有独立的状态机:

```
穿过 → 报一次 → 落防 → 价格离开 band 之外 且 过了冷却 → 重新上膛
```

外加两条:第一次取价**只登记不报警**(否则一打开页面就把现价附近的位全报一遍);
价位重算后,老价位的状态会被丢掉,不会越攒越多。状态存在 SQLite 里,重启不会重报。

### 降级

期权墙是加分项:标的没有期权、链拿不到、行情没权限都可能失败。这时候**整数关口照样能用**
(它不依赖期权链),但失败原因会明确显示出来——降级可以,不能悄悄降级。

警告轮询是全项目唯一**不看当前在哪一页**的:切走了还得报,不然就没用了。

八格常驻行情,**双来源混合**,界面上分得清哪格是哪个:

| 来源 | 走哪些 | 刷新 | 界面标记 |
|---|---|---|---|
| **TWS 流式** | 标普500·SPY、纳指100·QQQ、黄金·GLD、原油·USO、美元指数·UUP、比特币·IBIT | **2 秒** | 数值后一个绿点,小字标出实际标的 |
| 公开数据源 | VIX、美债10Y,以及上面任何一格拿不到实时数据时 | 10 秒(已连 TWS)/ 60 秒 | 无绿点 |

为什么指数要换成 ETF:SPX / NDX / VIX 指数值和 GC / CL 商品期货在 IBKR 都要**单独订阅**,
多数账户没有;而对应 ETF 属于普通美股,只要有 US Equity Streaming 就是实时的。ETF 的涨跌幅
贴近指数,但**绝对价位差一个量级**(IBIT 几十美元 vs 比特币几万美元),所以每格都标出实际
读的是哪个标的——不标的话那个数字会让人以为行情崩了。

**VIX 与美债10Y 永远走公开源,不给 ETF 替身。** 这是刻意的:VIXY 有 contango 损耗、长期偏离
VIX;TLT 是价格,和收益率**反向**——换上去会让人把「利率下行」读成「利率上行」。宁可慢一格,
不可错一格。有测试钉着这条(`test_vix_and_10y_never_get_an_etf_stand_in`)。

秒级只在连了 TWS 时才开:那时走的是**常驻订阅**,读一次几乎不花时间。没连 TWS 时八格全走
公开端点,而那个端点本身就不是逐笔更新的——刷快了只是反复拿同一个值,还会把自己的 IP 打进限流。

## 实时 K 线与价格行为分析(K线 PA)

「K线 PA」页拉一段实时 K 线,按价格行为(Price Action)读盘。**方向判断全部由代码算,
一个字都不经过模型**——模型只在你按下「AI 解读」时,拿代码算好的事实做叙述。

K 线走 TWS 的历史数据接口。**历史数据同样要行情权限**——这一点容易记反:没订阅时
`reqHistoricalData` 直接回 error 162,不会悄悄降级。所以请求前会把行情类型切到延迟(3),
让只有延迟权限的账户也能出图,用完立刻切回实时(1)——`AUTO_MID` 是按盘口定价的,
绝不能被拖成延迟。没有实时订阅时最后一根大约落后 15 分钟,所以标题右侧常驻新鲜度
(最后一根的时间 + 距今多久),超过 30 分钟明确告警。权限不足时报错会直接告诉你去哪开订阅,
而不是甩一句 IBKR 原文。支持 1m / 2m / 5m / 15m / 30m / 1h / 日线,每个周期自动配一个高周期做方向背书。

**默认读全时段(含盘前盘后)**,页面上可以切回「只看正常交易时段」。默认这样定是因为
只取盘中的话,收盘后整条 K 线就停在当日 16:00,盘前那一段完全看不见——而隔夜和盘前
恰恰是缺口与扫单最密集的地方。代价写在警告里:盘前盘后成交稀薄,ATR 会偏小、摆动点会偏碎,
跨隔夜的「缺口」多半只是没人交易。这个开关只影响取哪些 K 线,不影响任何判断逻辑。

软件读出来的东西:

| | 说明 |
|---|---|
| 摆动结构 | 分形高低点整理成严格交替的序列,打 HH / HL / LH / LL,据此判上升 / 下降 / 震荡 |
| BOS / CHoCH | **收盘**突破前高/前低:顺势记 BOS(延续),逆势记 CHoCH(性质改变) |
| 关键位 | 邻近摆动点按 ATR 容差并成一条线,再数有多少根 K 线在这个价位留过痕迹 |
| FVG | 三根 K 线之间留下、尚未被回补的缺口(回补 ≥90% 的自动摘掉) |
| 订单块 | 推动最近那次突破之前的最后一根反向 K 线,以及它有没有被回踩 |
| 流动性扫单 | 影线刺穿前高/前低但收了回来 —— 假突破/猎止损 |
| 等高 / 等低 | 两个几乎同价的摆动点,那一侧大概率堆着一池止损 |
| K 线形态 | 只看最近几根:吞没、锤子、射击之星、内包、外包、十字星、大实体推动 |
| 环境 | ATR、区间位置、EMA20/50 排列、相对量能、当日开高低 |

有两条是刻意的,少了这个模块就会开始骗人:

**突破一律用收盘价确认。** 盘中影线穿一下就当突破,是这类分析最常见的自欺来源。
影线穿透单独归到「扫单」,和真突破分开报——这两件事的含义正好相反。

**打分公开权重。** 结论是各项证据加权求和(结构 30、CHoCH 25、BOS 15、区间位置 15、
扫单 15、均线 12、形态 10、贴近关键位 8、量能 8),每一条连同权重原样显示在「判断依据」里,
分数就是这张表的和。不同意某一条,直接把它从总分里减掉再看结论。权重写死在
`priceaction.py` 顶部,不随行情浮动。

页面只给价位与条件(确认位、失效位、观察点),**不给方向性建议、不给仓位**,
也不接任何下单链路。停留本页且已连 TWS 时每 20 秒自动刷新;IBKR 对历史数据请求有节流
(同一请求 15 秒内重发即超频,10 分钟超过 60 次会掐断行情连接),引擎侧按周期做了 TTL 缓存,
`force` 也压不到 15 秒以下。

AI 解读那条链路发出去的仍然只有 S2 级数据:**算好的结构结论,连原始 K 线都不发**——
给模型一堆 OHLC 它就会开始自己「看图」,而它看图的结果没人能复核。

## 接入外部大模型

界面「大模型」面板可以直接配置解析引擎用哪个模型,不必改代码:

| | 说明 |
|---|---|
| 供应商 | **Anthropic(Claude)** 或 **OpenAI 兼容端点**(DeepSeek、通义、Kimi、智谱等都暴露这种端点) |
| 模型 | 预设下拉 + 自定义输入,填任意模型标识 |
| Base URL | 仅兼容端点需要;**强制 https**,只给 `127.0.0.1` 放行 http(§9.4) |
| API Key | 写入 macOS Keychain,**按供应商分开存**,换供应商不会用错上一把;界面只显示"已配置/未配置",永不回读密钥 |
| 调用参数 | `effort`(仅 Anthropic)、`temperature`、`max_tokens`、超时 |
| 测试连接 | 真打一次最小请求,报告延迟、token 用量、模型名,以及**结构化输出用的是哪种模式** |

换供应商不会松掉任何一条边界:

- **发出去的仍然只有 S2 级数据**——指令原文、当前时间、行情快照、别名表与限额。真实账号、余额、
  持仓、成交记录一概不出本机,和供应商是谁无关。
- **输出仍然要过 schema**。能用 `json_schema` 就用;端点只支持 `json_object` 时自动降级,
  把 schema 内嵌进系统提示词,并在界面上明确标出已降级——因为这会直接影响解析可靠性、抬高拒绝率。
- 无论模型多弱,§5 的硬校验层照样逐条复核限额、方向、账户与价差结构。模型再离谱也越不过这一层。

界面能改的只有上面那几项。`keychain_service` 之类的字段被 RPC 层显式拒绝,base_url 写错会
**回滚且不落盘**。

## TWS 连接:检测、诊断、引导

**本软件不接触你的 IBKR 账号密码。** IBKR 凭证是 §9.1 的 S0 级数据,只允许存在于 IBKR 自己的
程序里——登录在 TWS / IB Gateway 的窗口里完成,这里做的是它前后那几步:

| 面板分区 | 做什么 |
|---|---|
| 1 · 程序 | 检测 TWS / IB Gateway 是否安装、是否在运行;装了没开的可以一键启动(路径在引擎侧解析,界面传不了任意路径) |
| 2 · API 端口 | 探测 7496 / 7497 / 4001 / 4002 及配置里的自定义端口,标出每个端口对应哪条连接、是否已连接。纯 TCP 探测,不发协议帧,不打扰已有会话 |
| 3 · 握手与账户 | 真连一次(**只读连接**)读回服务器版本与账户列表,连完即断;同时核对**账户别名是否对得上真实账号** |
| 4 · 连接引擎 | 建立引擎真正用来下单的长连接 |
| 连不上时照着做 | 6 步指引,写死 TWS 的确切菜单路径,并按你的实际配置显示端口号 |

两个细节值得单独说:

**别名映射校验。** 配置里 `模拟 → DU7654321` 如果账号写错了,下单时 IBKR 不会报错,只会静默
落到错误账户。所以诊断会拿 `managedAccounts()` 的真实列表逐条比对,对不上就红字标出;
反过来,会话里能管到、但没写进别名表的账号也会列出来(那些账号 LLM 永远指不到,是设计使然)。

**错误翻译。** 连不上时给的是下一步该做什么,不是 traceback。最常见的一种——端口开着但握手
超时——会明确告诉你:要么「Enable ActiveX and Socket Clients」没勾,要么 TWS 正弹着
「接受传入连接」的确认框等你点 Yes。

## 富途 OpenD:IBKR 用不了时的备用通道

IBKR 的 API 不是每个人都能跑起来。TWS 装不上、握手一直超时、行情权限没开、账户压根不在
盈透——任何一条卡住,整个引擎就没有出路。所以下单层做成了两条腿:

```json
"broker": { "provider": "ibkr" }     // 改成 "futu" 就换一条通道
```

**换的只是出口。** 提示词、别名表、限额、硬校验层、记录格式一行都不变——`FutuRouter` 和
`BrokerRouter` 的接口完全一致,全系统只有 `_make_router()` 那一行知道自己连的是谁。
定价那几个最容易算错的纯函数(组合中间价、AUTO_MID 限价、行权价宽度、盘口流动性)是
**直接复用** IBKR 那一侧的实现,不是抄一份——同一套数学只能有一个来源。

同一时刻只连一家。界面在「富途 OpenD」页顶部切换,顶栏的连接标识也会跟着从 `TWS` 变成
`OpenD`,免得切过之后看不出单子会从哪条通道出去。

**切换不会替你写连接和账户。** §9.6 定的是"账户与连接只允许人手动改配置文件,不给界面通道",
换券商不是绕过它的后门——第一次切过去时,面板会把该抄的那段 JSON 直接贴出来,你并进
`config/settings.json` 再回来点一次就成。富途账号是一串数字,填 IBKR 的 `U/DU` 开头账号会被
当场拒绝。

### 面板做什么

和 TWS 那一页一一对应,连卡片样式都共用:

| 面板分区 | 做什么 |
|---|---|
| 0 · 券商接入 | 在 IBKR / 富途之间切换。切换会先断开现有连接,并把选择写进配置文件;没配过的那家会直接把该抄的配置片段贴出来 |
| 1 · 程序 | 检测 OpenD 是否安装、是否在运行(富途版 `FutuOpenD`、海外版 `moomooOpenD` 都认);装了没开的可以一键启动 |
| 2 · API 端口 | 探测 11111 / 22222 及配置里的自定义端口。纯 TCP 探测,不发协议帧 |
| 3 · 握手与账户 | 真连一次读回 OpenD 版本、**行情/交易是否已登录**、账户列表;同时核对账户别名是否对得上真实账号 |
| 4 · 连接引擎 | 建立引擎真正用来下单的长连接 |
| 5 · 交易解锁 | 仅实盘需要。密码只存 Keychain / DPAPI,而且**只存 md5** |
| 连不上时照着做 | 8 步指引,按你的实际配置显示端口号,并写明富途做不到的那几件事 |

**本软件同样不接触你的富途账号密码。** 登录在 OpenD 自己的窗口里完成,这条边界和 IBKR 那边
是同一条(§9.1 的 S0 级)。唯一的例外是实盘的交易解锁密码——富途的接口要求应用侧提交
md5,所以它只走 Keychain / DPAPI:界面填的明文在引擎里算完 md5 就丢,不落配置、不进日志、
不进审计流水(有一条测试专门盯这件事)。

### 五处和 IBKR 不一样,必须先知道

**1. 不支持组合单,而且不会偷偷拆。** 富途的下单接口是单腿的,没有 IBKR 那种把价差当成
一个合约整体撮合的 BAG。拆成单腿分别发会产生腿风险——一条腿成了另一条没成,建出来的是
裸头寸而不是价差,风险结构和你要的完全不是一回事。所以价差 / 蝴蝶 / 铁鹰在富途通道上
**直接拒绝**,理由写在报错里,请切回 IBKR。

**2. 没有原生条件单,全部退到软件盯盘。** IBKR 能把触发条件挂在它自己的服务器上(§8.1 方式 A),
软件掉线条件依然有效;富途的下单接口没有这个能力。所以在富途通道上,**所有**条件单都走方式 B
的软件盯盘队列——代价是本软件必须一直开着,好处是行为明确:不分流的话,"涨到 7500 再买"会被
当成普通单立刻发出去,而这个错误在成交回来之前完全看不出来。

**3. 回报是拉的,不是推的。** ib_insync 有事件流,富途没有。`FutuRouter.poll_order_updates()`
在界面本来就有的定时轮询里拉一次订单与成交,把结果包成和 ib_insync 同形的对象,喂给
`engine` 里那套现成的入库逻辑——**两家券商的 `status_timeline` / `fills` 因此长得一模一样**。
少了这一步,富途下的单会永远停在 Submitted。

**4. K 线周期少一档。** 富途最小 1 分钟,往上是 5 / 15 / 30 / 60 分钟与日线,**没有 2 分钟**。
缺的就明说并拒绝,不拿 1 分钟线合成——合成出来的 K 线在 PA 分析里和真线长得一样,但摆动点
是假的。

**5. 没有美股指数。** SPX / NDX / VIX / RUT 在富途 OpenAPI 上完全取不到行情(不是权限问题),
涉及指数的一切——报价、K 线、期权墙、条件单——都会被明确拒绝。详见下面「真机联调结论」。

### 代码换算:查,不猜

普通美股按 `US.<代码>` 拼就行。但有两处刻意去查而不是拼:

* **指数**。各家的指数代码命名都不一样,拼错了不一定报错,可能拿到另一个标的的价格,而触发价
  复核会照单全收。所以先看 `broker.futu.symbol_map` 的显式映射,没有就去富途自己的证券列表里
  实测一次并缓存。这个决定在真机上直接兑现了:富途的美股指数代码是 **`US..SPX`(双点)**,
  和想当然的 `US.SPX` 不一样——猜的话就错了。(不过解析出来也没用,见下面第 ① 条。)
* **期权合约**。用期权链按(到期日、行权价、Call/Put)反查代码。各家的期权代码规则都改过,
  拼错的后果是下到另一个合约上,而这个错误在回报回来之前看不出来。

### 真机联调结论(futu-api 10.10 + 本机 OpenD 实测)

接口签名、返回列名、枚举取值全部按真机对过。**三件事是文档上看不出来、只有连上去才知道的**,
都已经变成明确的拒绝或补偿,而不是留给用户去撞:

**① 富途 OpenAPI 不支持美股指数。** SPX / NDX / VIX / RUT 的快照、订阅、历史 K 线三条路
全部回「暂不支持美股指数」——这不是权限没开,是能力缺口。最阴的地方在于**指数代码在它的
证券列表里查得到**(`US..SPX`,注意是双点),所以代码解析会"成功",然后每次取数静默空手
而归。真正的后果是 SPX 条件单进了盯盘队列却永远不会触发:界面显示"正在盯盘",实际什么都
不会发生。

所以加了一道 `quote_capability()` 闸门:涉及指数的**行情与 K 线**一律当场拒绝,**条件单
在进队列之前就被拒**,并给出可选替代(SPX→SPY、NDX→QQQ、RUT→IWM、VIX→VIXY)——但
**软件绝不替你换**,SPX 七千多点、SPY 七百多块,静默换标的会让触发价整个失去意义。同理,
`symbol_map` 也不能当成"把指数映射成 ETF"的后门:闸门认的是配置里的 `index_symbols`,
跟映射后的代码无关。

闸门**刻意不挡期权链**:指数的期权链富途是支持的(`US..SPX` 回的是权限错误而不是
「暂不支持」),缺的只是现价那一个数,而它可以从链自身反推——见后面「期权墙在富途下
怎么活下来」。

**② 富途模拟盘不支持成交查询。** `deal_list_query` 在模拟账户上直接回「模拟交易不支持成交
查询」。照原样跑的话,纸面账户的记录会只有状态、没有 `fills[]`、没有均价——"自动记录每笔
交易"就成了半句空话。现在识别到之后不再重复请求,改从订单行的 `dealt_qty` / `dealt_avg_price`
**按增量合成**成交,并在 `exec_id` 上显式标注"(合成)":它不是逐笔明细,别拿它做滑点归因。
实盘账户仍然走真的逐笔成交。

**③ `is_paper` 必须和富途报的 `trd_env` 一致。** 富途的模拟账号和实盘账号是两个不同的
`acc_id`,而配置里的 `is_paper` 正是 `allow_live_trading` 那道闸的输入——把实盘账号标成
模拟,实盘保护就整个失效了。现在连接时读回每个账号真实的 `trd_env`,诊断面板逐行显示并
标红不一致的,下单前再核对一次,对不上直接拒。

顺带按真机修掉的小问题:订单状态词表补齐了 `UNSUBMITTED` / `CANCELLING_*` / `FILL_CANCELLED`
(漏一个就会被当成 Submitted,单子在界面上永远"在途");`security_firm` 的可选值补全到
SDK 的七家;期权权限报错不再反问"该标的是否有期权",而是直接说去哪开通;OpenD 回的 unix
时间戳转成了人能读的时间。

已验证跑通的路径:连接 / 诊断 / 账户与环境核对、股票报价、流式报价、**10 档盘口**(该账户
有 LV2)、日线与 1m/5m/1d K 线(1000 根,含盘前盘后)、2 分钟周期按设计拒绝、指数闸门、
RPC 全链路(`broker.select` → `futu.scan` → `futu.diagnose` → `broker.connect` →
`system.status` → `pending.poll`)。期权链需要单独的美股期权行情权限,当前账户没开,
未能实测。

### 期权墙在富途下怎么活下来

期权墙是这个软件的招牌功能之一,而它在富途通道上撞了两堵墙,处理方式完全不同:

**第一堵是权限,得你自己开。** 富途的**美股期权行情**是一份**独立于股票行情**的权限:
股票报价能用不代表期权能用,而且没有它**连期权链的到期日列表都取不到**(实测,不只是
报价为空)。所以引擎把这条错误单独拎出来说,而不是笼统地讲"没有行情权限"——否则你会
去核对那份已经开好的股票行情,白折腾一圈。开通后重连引擎即可。

**第二堵是指数没有现价,这个引擎自己解决。** 期权墙必须知道标的现价,才能判断墙在现价
上方还是下方;而富途拿不到美股指数的现价。但**指数的期权链本身是支持的**(实测
`US..SPX` 回的是权限错误,不是「暂不支持」)——所以缺的只是那一个数,而它就藏在链里。

用的是看跌看涨平价关系,一个恒等式:

```
C − K·D ... 严格写作   C − P = S − K·D        (D = e^(−rT),折现因子)
```

对同一到期日的**所有**行权价都成立。所以在整条行权价网格上均匀取样,把 (C−P) 对 K 做
一次最小二乘直线拟合:**截距就是现价 S,斜率的相反数就是折现因子 D**。利率和到期时间
都不用假设,它们被一起拟合出来了。

为什么不能图省事只看一个平值行权价、把 D 当成 1:SPX 在 7500 点、一个月到期、利率 4%
的情况下,`7500 × (1 − e^(−4%×1/12)) ≈ 25 点`——二十五个点的系统性偏差,墙的位置就整个
挪位了。测试里专门有一条钉住这件事。

**残差是天然的质量闸。** 平价关系是恒等式,报价干净时残差接近零(单测里精确还原到
1e-6)。残差一大就说明报价有问题——盘口太稀疏、深度虚价、或者混进了别的到期日——这时候
**宁可拒绝也不给一个看起来像模像样的错价**,因为墙的位置全靠它。折现因子拟合出来跑到
合理区间外同样直接拒绝。

反推出来的现价会一路带着 `spot_source: "parity"` 标记到界面上,显示成「现价由期权链
反推」。它和真实报价不是一回事,不标出来就是在骗自己。

> 这条路径的**数学部分有完整单测**(精确还原、拒绝脏报价、拒绝样本不足、拒绝零利率
> 近似),但**没能在真机上跑通**——联调用的账户没有美股期权行情权限,富途连期权链的
> 结构都不给。开通权限后应当先用一个普通股(现价能直接问到,`spot_source` 应为
> `quote`)对一遍,再看指数。

### 富途特有的两种额度

富途的行情按额度计,这是它和 IBKR 最不像的地方,踩上了报错信息也很含糊,所以引擎把它翻成了
人话:**订阅额度**(按资产等级,常见 100 条)——期权链、盘口这些一次性订阅用完立刻退订,
和 IBKR 那边防行情线路泄漏是同一类纪律;**历史 K 线额度**(按标的数计)——用完时的报错会
明确说是额度问题,而不是让你去怀疑代码写错了。

```

## 持仓追踪:到价自动平仓

盯住账户里的一个持仓,设好止盈止损,价格到位时**自动发出平仓单**。

这是整个软件里第二条会真实发单的路径(第一条是指令解析),而且它是在**你不在场的时候**
发。所以闸门要说清楚。

### 闸门:为什么不走 validator 那一套

平仓单**不过**开仓那套限额(单笔名义金额上限、期权张数上限、重复防抖、置信度)。
那些闸门限制的是"新增多少风险";平仓是**减少**风险。拿开仓的限额去挡平仓,后果是
持仓超过限额的人永远出不来——那比放开限额危险得多。

保留下来的是三类:

| 闸门 | 为什么留 |
|---|---|
| `auto_execute` + 每条追踪自己的开关 | 授权问题:你有没有同意软件替你发单 |
| 实盘账户还要 `allow_live_trading` | 这是整个软件最外层那道保护,自动平仓不能例外 |
| 熔断期间一律不发 | §9.7 说的是"停新单",平仓单也是新单 |
| 当前时段能不能交易 | 客观事实,不是策略 |

另外三条硬约束:

* **数量取持仓的绝对值,一股不多。** 多平一股就从平仓变成了反向开仓——那是完全没被
  授权过的事。
* **先落闩再发单。** `fired_at` 在 `place()` 之前写:发单走到一半抛异常时,单子可能已经
  到了券商,这时下一轮再发一次就是反向开仓。宁可少发一单让人手动补,不可重复发。
* **到价了但发不出去,必须当场说。** 用户可能正指望这个止损保命,静默失败是最坏的结果。
  提醒只发一次,不刷屏。

### 算错了会赔钱的三个地方

盈亏与触发判断全部是纯函数(`tracker.py`),脱机单测 28 项,盯的就是这三件:

**方向。** 多头止盈在上、止损在下,空头正好相反。写反了不报错,只会在开仓那一刻立刻
平掉——所以**设置时就拦**,而不是等触发了才发现。

**乘数只乘一次。** IBKR 的 `avgCost` 对期权是**含乘数**的整张成本(5.50 的期权 avgCost
是 550)。成本一侧不能再乘,市值一侧要乘。两边口径不一致会让盈亏差一百倍。

**跟踪止损的峰值要持久化。** 它跟的是"最有利价"不是最新价,只朝有利方向走。峰值不落库
的话,重启一次就退回当前价重新起算——已经锁住的那段利润白锁了。固定止损和跟踪止损同时
存在时取**离现价更近**的那个:保护按更严的算。

### 盈亏以券商报的为准

IBKR 优先用 `ib.portfolio()`、富途用 `position_list_query` 的 `pl_val`——那是和你在券商
客户端里、以及月结单上看到的同一个口径。拿不到才自己算;**连价格都拿不到时如实回 None**,
界面显示「—」,而不是拿成本价冒充现价算出一个"盈亏为零"的假象。

### 它不是券商服务器上的条件单

盯盘在本机进行:**软件关掉就不再盯**。IBKR 的原生条件单挂在券商服务器上,掉线仍然有效;
这个不是。界面上用醒目的话写着这一条,因为把它当成前者是会出事的。

> 真机验证到哪一步:失败路径实测过(未连接券商时给的是明确拒绝,不是空列表);
> **带真实持仓的成功路径没能实测**——联调时 OpenD 已经关了,而 TWS 没在跑。
> 第一次用请务必先在模拟账户上跑一遍,确认平仓方向和数量都对再开实盘。

## 桌面端架构与安全边界(§10.1 / §10.2)

```
┌─ Electron ─────────────────────────────────────────┐
│  Renderer  指令输入 / 订单看板 / 记录浏览            │
│    ↕ contextBridge:只暴露具名方法,无通用调用通道    │
│  Main      IPC 白名单 + 发起方校验 + 系统对话框      │
└──────────────┬─────────────────────────────────────┘
               │ stdio 上的 JSON-RPC 2.0(无监听端口)
        ┌──────┴────────┐
        │ Python 交易引擎 │ ←→ TWS / IB Gateway(127.0.0.1)
        └───────────────┘
```

选 stdio 而不是 §10.1 画的 localhost 端口:没有监听端口,本机其他进程就没有可连的入口。

安全基线是代码级的,不是约定:

| 措施 | 落点 |
|---|---|
| `contextIsolation` / `nodeIntegration:false` / `sandbox:true` | `main.js` BrowserWindow |
| renderer 里 `require`、`process` 均为 `undefined` | 已用 CDP 实测验证 |
| IPC 方法白名单,不在表里直接拒绝 | `main.js: ALLOWED_RPC` |
| 每次 IPC 校验发起方(必须是主窗口主 frame) | `main.js: isTrustedSender` |
| 下单/改限额/连券商需带界面确认标记 | `main.js: SENSITIVE_RPC` + 系统级确认对话框 |
| 严格 CSP(无远程资源、无 eval)、拦截导航与新窗口 | `index.html` meta + `session` 响应头 |
| 生产构建关闭 DevTools | `devTools: DEV` |
| 账户与连接配置**不开放**给界面修改 | `rpc.py: settings.patch` 拒绝 `accounts`/`connections` |
| 真实账号只以掩码形式过 RPC(`DU***321`) | `rpc.py` + 测试断言 |
| 界面写 DOM 一律 `textContent`,绝不拼 `innerHTML` | `renderer/app.js` |

### 升级安装(旧版存在时)

三个平台性根因都已处理:

| 场景 | 处理 |
|---|---|
| macOS · 从 DMG 双击运行 | 应用自己就是安装器:提出「移动到应用程序并打开」,已有旧版则先替换(此时旧版必然没在运行,否则会先走下一行),复制后去掉 quarantine、打开新副本、退出 DMG 里这份 |
| macOS/Win · 旧版还在运行 | 新副本启动被旧版的单实例锁挡下时,**旧版会弹窗说明**并提供「退出此版本」按钮——不再静默吞掉让人以为"装不上" |
| Windows · 安装目录被锁 | 两层:NSIS 装/卸载前 `taskkill` 结束在跑的旧版(`build/installer.nsh`);引擎子进程的 cwd 从安装目录挪到 userData——Windows 上进程 cwd 会锁目录,这正是"旧版存在时删不掉安装目录"的隐蔽根因 |
| 升级后依赖漂移 | userData 里的 venv 带依赖清单标记,升级后清单不符就自动补装一次 pip(幂等);venv 坏了(如底层 Python 被卸载)则推倒重建 |

**打包版的运行时布局**与开发版不同,都已实测:

| | 开发版 | 打包版 |
|---|---|---|
| 引擎源码 | 仓库 `src/` | `resources/engine/src`(extraResources,不进 asar) |
| 配置文件 | `config/settings.json` | `userData/settings.json`(应用包只读,首启从示例生成) |
| Python | 仓库 `.venv` | **首启引导**:找系统 Python → 在 userData 建专属 venv → pip 装依赖(约 1 分钟,需联网) |

首启引导找 Python 时探测的是**绝对路径**(Homebrew、python.org 安装器、CLT),因为从
Finder 启动的 GUI 应用只有极简 PATH;连 `/usr/bin/python3` 被 Xcode 许可协议卡住的情况都
处理了(直接用 shim 背后的真实二进制)。机器上确实没有 Python 时,界面会给出明确的安装指引。

`build/entitlements.mac.plist` 里注明了为什么暂时没开 App Sandbox——它会禁止拉起 bundle 外的
Python 子进程,要开必须先把 Python 运行时整个打进包里(体积 +100MB 量级,留作后续选项)。

若 electron-builder 下载 Electron 二进制时卡住(和 `npm install` 同一个毛病),用
`-c.electronDist=<解压好的 dist 目录>` 指向手动下载的副本即可,README 上方有下载命令。
注意 electron-builder 会把 `electronDist` 目录的内容**搬走而不是复制**——每次构建前要
从 zip 重新解压一份,别复用上次的目录(空目录不报错,直到构建后段才以 ENOENT 失败)。

## 一次死锁事故与它留下的约束

实盘联调时撞到过一次:界面整个变砖,连不碰券商的 `system.status` 都连续超时 159 次。
链条是这样的:

1. `Error 1100` —— **TWS 与 IBKR 服务器**之间断了(不是本机和 TWS 之间);
2. 本机到 TWS 的 socket 仍然活着,`ib.isConnected()` 仍然是 `True`,`sessions()` 照常放行;
3. 于是 `qualifyContracts()` 发得出去、却永远等不到回应 —— 它是 ib_insync 里**唯一没有
   `timeout` 参数**的阻塞调用(`reqHistoricalData` 自带 `timeout=60`,反而是安全的);
4. RPC 服务是**串行**的:这一次阻塞把后面所有请求堵在管道里,整个应用跟着死。

留下三条约束:

| 约束 | 落点 |
|---|---|
| 合约确认必须有硬超时(12 秒),宁可报错不能挂着 | `broker.py: _qualify_or_raise` |
| 要能分辨「socket 通但 TWS 没上游」——`isConnected()` 分辨不出来,只能靠 1100/1101/1102 事件 | `broker.py: _on_ib_connectivity`,顶栏第三态「TWS 上游中断」 |
| 界面的周期性轮询一律防叠加:引擎慢的时候不该攒出一队请求 | `app.js` 的 `statusPoll` / `macro.inFlight` / `auto.running` |

`test_qualify_times_out_instead_of_wedging_the_whole_engine` 钉着第一条。

**尚未解决**:RPC 服务本身仍是串行的,任何一个慢调用都会拖住其他请求。上面做的是
「不让它无限期挂住」,不是「让它并发」。真要根治得给 sidecar 加工作线程或按方法分流。

## 三道执行闸门

一条指令要真的变成 IBKR 上的订单,必须同时穿过:

1. `policies.auto_execute = true`(配置,默认 **false**)
2. `run` 子命令带 `--i-understand-this-places-real-orders`(CLI 显式确认)
3. 实盘账户还要 `policies.allow_live_trading = true`(默认 **false**,纸面账户不受此限)

外加一个随时可拉的总闸:熔断开关是**文件**状态,CLI、Python 引擎、将来的 Electron 主进程
看到的是同一个开关,软件崩溃重启后熔断依然有效。连续 N 次失败会自动熔断。

## 与设计文档的三处修正

写代码时对着当前 API 现状调整了三个地方,原因都写在对应模块的注释里:

1. **不发 `temperature=0`。** Claude Opus 5 / Sonnet 5 / Opus 4.8 及以后的模型已移除采样参数,
   发送会 400。确定性改由 structured outputs(API 层按 schema 约束输出)+ `effort` 提供;
   只有配置的模型确实接受采样参数时才发送(`llm.py: supports_sampling_params`)。
2. **用 structured outputs 而不是只靠提示词那句"只输出 JSON"。** 输出 schema 由 pydantic 模型
   生成并剥掉 API 不支持的关键字,数值约束仍在本地复校验——等于 schema 与语义两道防线。
3. **`ib_insync` 已停止维护**,维护分支 `ib_async` 需要 Python ≥3.10。`broker.py` 优先 import
   `ib_async`、回落 `ib_insync`,两者 API 同名,升级 Python 后无需改代码。

另外 §9.3 要求的 SQLCipher 静态加密需要专门编译的 sqlite3,标准库不带。当前退化为
数据库文件 0600 权限 + 依赖 FileVault;要满足原设计,需换 `pysqlcipher3` 并在
`TradeStore` 里加一句 `PRAGMA key`。

## 数据流向(§9.1 的硬约束)

```
指令文本 + 当前时间 + 行情快照 + 别名表/限额   ──► LLM API   (唯一出网点,只有 S2)
真实账号 / 余额 / 持仓 / 成交记录             ──► 永不出本机
券商凭证(IBKR 账密 / 富途账密)             ──► 只在券商自己的程序里(TWS / OpenD)
```

换券商不放松这条:富途通道唯一多出来的秘密是实盘的交易解锁密码,它只走 Keychain / DPAPI,
而且只存 md5。

这条约束是代码级强制的,不是靠自觉:`prompts.py` 在每次渲染后扫描输出,
一旦出现配置里的任何真实账号就抛异常中止调用。`test_prompts_store_broker.py` 里有对应测试。
