# 条款文本

| 文件 | 内容 |
|---|---|
| `risk-disclosure.md` | 风险揭示 |
| `terms.md` | 使用条款 |
| `privacy.md` | 隐私说明 |

三份文本随界面一起打包(`desktop/renderer-react/src/lib/legalText.ts` 直接引用这里的文件),首次启动时展示,用户同意后才能使用;
同意记录在 `userData/consent.json`(`desktop/consent.js`)。

## 这是草稿

**这三份文本没有经过律师审阅。** 它们写的是这个软件实际的行为与风险(数据流向逐项对过代码),但措辞是否足以在你要销售的地区
起到保护作用,需要执业律师判断。正式发售之前:

1. 请律师按目标市场审阅并修改;
2. 把文中的 `【发布前填写】` 换成真实信息(发布者与联系方式已填,还剩适用法律与争议解决);
3. 改了任何一份的实质内容,就把三份开头的「版本」与 `desktop/consent.js` 的 `TERMS_VERSION` 一起改成新日期——
   老用户下次启动会被要求重新确认。

`desktop/tools/check_release.js` 会在打发布包时检查第 2 条:还留着 `【发布前填写】` 就不让发。

## 写法约定

界面用一个很小的解析器显示这些文本(`lib/PlainDoc.tsx`(解析在 `lib/docParse.ts`)),只认:`#` / `##` 标题、段落、`-` 列表、`**加粗**`、`|` 表格。
别的 Markdown 语法会被当成普通文字显示。三份文本第 3 行必须是 `版本:YYYY-MM-DD`,且三份一致。
