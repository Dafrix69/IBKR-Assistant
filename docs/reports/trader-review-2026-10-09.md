# 交易员视角评审(2026-10-09)

读的是 `engine-ts/src` 全部交易逻辑(校验、保护、追踪、追价、蝶式定价与校准、剧本、期权墙、行情信号、回测、复盘)
与 `docs/features/` 对应的设计文档,立场是"一个做 SPX 0DTE 蝶和个股的交易员第一次拿到这套软件会要求改什么"。
不评工程质量(那部分已有 `architecture-review-2026-09-17.md` 与 `code-audit-report.md`),只评**口径、参数与规则**。

每一条写清:现状在哪、交易上为什么不对、建议改成什么。优先级按"改动小、省的钱多"排,不按模块排。
所有数字和行号以 2026-10-09 的源码为准。

## 一句话结论

钱路径的闸门与对账做得比大多数零售工具扎实,但**触发用的价、风险的口径、时间维度**三处还是"程序员的口径",不是交易员的:
止损在中间价上判、风险按单笔算不按账户累计、持仓没有时间止损。这三处是前三条建议,改动都不大。
其次是蝶式参数:`flyexit` 里写死的 EM=36 与若干倍数没有数据依据,而日内剧本每天都在实时算 EM,两边没有接通。
研究与复盘模块有两处前视偏差,会让人对信号与自己的行为做出错误判断。

## 一、钱路径:触发、风险、时间(最先改)

### 1. 止损与峰值用的是中间价,不是能成交的价

- 现状:`tracker.evaluate` 拿持仓行的 `market_price` 判止损、止盈、利润回撤,并推进峰值;期权腿的现价是买卖中间价,
  买价为 0 时按 `(0 + 卖价) / 2`(`docs/features/tracker.md`「现价」)。平仓时另算 `naturalClosePrice`(持有腿按买价、卖出腿按卖价)。
- 问题:0DTE 蝶夜盘与尾盘的买卖价差常有一块多(文档自己记的真机例子:3.10 / 4.25,中间价 3.70)。止损设在 3.50,
  中间价碰到 3.50 时实际能卖的只有 2.90 上下:**止损线的真实位置比你填的低一截**,而且差多少随盘口变。
  峰值同理:远翼买价为 0 时中间价是卖价的一半,一笔挂得高的卖价就能把峰值抬上去,随后一次正常报价就是"假回撤"。
- 建议:
  - 止损类判定(`stop_loss`、`trail`、`profit_drawdown`)与峰值推进改用 `naturalClosePrice`,也就是此刻真能卖到的价;
    止盈继续用中间价(挂单本来就在中间价口径上等人来接)。
  - 峰值推进加两条门槛:报价不倒挂、距上一笔盘口 tick 不超过几秒;一条腿没有有效买卖价这一轮不推峰值。
  - 界面上止损线旁边同时显示"按可成交价算,此刻相当于 X"。
- 代价:止损会比现在早触发一点,这正是它该有的样子。

### 2. 风险按单笔算,没有账户级的累计口径

- 现状:`limits.max_order_notional`(5,000)与 `max_option_contracts`(5)都是**每一单**的上限;`risk_budget` 也是每一单对权益的比例;
  `protections.daily_loss` 只看已实现盈亏。一天开 10 只 5 张的蝶,每一单都合规,账户上却压着 50 张。
- 问题:交易员的风控单位是"账户此刻一共冒多少险"与"今天一共能亏多少",不是"这一单多大"。现在这两样都没有。
- 建议(都是限额,不是新的确认框):
  - `limits.max_open_risk_usd`:在手持仓的最坏亏损合计(蝶 = 净权利金 × 张数 × 100,贷方 = 宽度 − 权利金)+ 这一单,超过就拒;
    数据已经有:`positions()` 加 `combos.ts` 能拼出每份持仓的结构。
  - `limits.max_same_underlying_contracts`:同标的同到期的张数合计上限。
  - 限额按账户分别设(`accounts[].limits` 覆盖全局):纸面账户与实盘账户用同一套 5,000 / 5 张说不通。
- 顺带:`risk_budget.equity_usd` 是手填的,IBKR 的 `NetLiquidation` 在账户摘要里就有(文档说那条路没在真机核对,核对一次比让用户填准)。

### 3. 日内亏损上限只数已实现、只数引擎自己发的单

- 现状:`protections.daily_loss` 从 `record_events` 的佣金回报累计 `realized_pnl`(`protections.md`「状态从哪来」),
  在 TWS 里手动下的单与未实现盈亏都不算。
- 问题:一只亏着 800 的蝶没平,日内亏损显示 0,新单照发。交易员说的"今天亏到线"是**权益**到线,含浮亏。
- 建议:改用 IBKR `reqPnL` 的账户级 `DailyPnL`(含已实现 + 未实现、含手动单),引擎订一次、每轮读。
  已实现那条路保留给富途与离线测试。回撤护栏同理改成按账户权益曲线算。

### 4. 持仓没有时间维度的出场

- 现状:`Targets` 只有价格类与标的位置类字段;回放策略里的 14:00 过渡、阶段 C、结算,实盘一个都没有(`tracker.md`「利润回撤」末尾自述)。
- 问题:0DTE 蝶最常见的两条纪律是"几点之前没到就走"与"不持到结算",现在只能人盯。个股期权的贷方价差有行权风险,到期日 15:30 后空头腿还在实值里就是周一醒来多一手正股,软件一个字不提。
- 建议:
  - `Targets.exit_at`(HH:MM 美东):到点按"手动平仓"那条路追价平掉,记作 `time_exit`,绩效体检单列。
  - `Targets.settle_policy`:当日到期的蝶默认"收盘前 N 分钟平",N 可调;SPXW 现金结算可以关掉。
  - 实物交割的期权(个股)到期日 15:30 后空头腿实值:至少弹一次提醒;开了自动平仓的直接平。
- 这是新增字段,契约、schema、表单都要动,但判定本身是一行比较。

### 5. 止损与止盈共用同一套追价节奏

- 现状:`chaseLimit` 对所有触发原因一样:头 2 轮挂自然价,之后每轮让 1 跳,上限 `chase_max_pct`(10%,至少 2 跳)。
- 问题:止盈可以慢慢磨,止损要的是"出去"。尾盘 gamma 大、自然价一秒跳两三跳,每秒让一跳追不上;0.40 的蝶 10% 是 0.04,
  退回到 2 跳也只有 0.10,一个尾盘插针就穿过去了。
- 建议:按触发原因分两档,都是 `auto_close` 里的字段:
  - 止损档(`stop_loss` / `profit_trail` / 标的止损):grace 0 轮,每轮让 2 跳,上限默认 25%;15:30 之后再放宽一档。
  - 止盈档(`take_profit` / 标的目标价):维持现状。
  - 追满上限仍未成交 10 秒:止损档改成挂到对手价再越一跳,不再按比例封顶。

### 6. 开仓的 AUTO_MID 挂上去就不动了

- 现状:`autoMidLimit` = 中间价 + `max_spread_slippage`(固定 0.10 美元)向上对齐跳动,之后不改单。
- 问题:固定 0.10 对 0.30 的蝶是 33%,对 12 块的价差是 0.8%,同一个数两头都不对;挂上去不动等于"成交随缘"。
- 建议:
  - 滑点上限改成两选一:结构宽度的百分比,或买卖价差的比例(先挂 mid,封顶在 mid + 50% 价差)。
  - 开仓也有可选的阶梯:每 N 秒让 1 跳,到上限停,与平仓追价对称,参数在 `limits` 里。没成交到上限就撤,记成"未成交"。

### 7. 重复单指纹不含价格

- 现状:`orderSignature` = 账户 + 方向 + 合约要素,不含价格与数量;10 分钟内数量差 20% 以内就拦,拒绝信息教人"改变数量"。
- 问题:同一只蝶 5 分钟前挂 1.80 没成交,现在想挂 1.60 再试,会被当成重复单;按提示改数量反而是错的激励。
- 建议:指纹加入限价(差 1 跳以上就不是同一张单);真正的重复(同价同量)照拦。`duplicate_window_minutes` 对 0DTE 改成 3 分钟更合适,10 分钟是股票的节奏。

### 8. 同标的冷却按 symbol,对只做 SPX 的人就是全局暂停

- 现状:`protections.cooldown` 键是 `close.symbol`。
- 建议:键改成标的 + 结构中心(蝶的中心行权价、价差的空头行权价),或给一个"按标的 / 按结构"的选项。

### 9. 标的止损"触线即算"没有去噪

- 现状:`trackerSpotStop.spotStop` 是 `≤` / `≥` 一次成立就触发;文档的理由是"等站稳的时长是没有依据的数"。
- 问题:SPX 指数值一秒一跳、没有盘口,贴线来回一两个点很常见;一次穿线就平掉的止损在剧本里叫"被扫"。
- 建议:加一个参数 `spot_stop_confirm`,三选一:触线、连续 N 秒、1 分钟 K 线收盘。默认"连续 3 秒"。这是参数,不是新闸门。

### 10. 一份持仓一条追踪、只触发一次,分批止盈做不了

- 现状:`close_fraction_pct` 只给一次触发用;同一持仓不能建两条追踪。
- 建议:`Targets.take_profit_tiers: [{price, fraction}]`,每档各触发一次,剩余数量继续盯;托管模式下对应多张 OCA 外的限价单(各自数量)。

## 二、蝶式参数与黄金基线(用户点名的部分)

### 11. EM 写死成 36,而剧本每天都在算真的 EM

- 现状:`flyexit.DEFAULTS.em = 36`,`tracker` 的 `clock` 档、交易分析回放的模型价、阶段 B / C 的切换都用它;
  `plan()` 的备注写着「应每日从 ATM straddle 取,EM = straddle × 0.85」。日内剧本(`playbook.ts`)每 5 分钟算一次 EM = 跨式 × √(π/2) ≈ 1.2533 × 跨式,并写进底账。
- 两个问题:
  - 36 点是某一天的数,VIX 从 12 到 20 时 SPX 的日 σ 从 30 多到 60 多,固定值会让阶段 C 的起点错一个小时以上。
  - 0.85 与 1.2533 差 47%。`sigmaRemaining(em, minute)` 把 `em` 当 1σ 用,1σ ≈ 1.2533 × 跨式才对;0.85 × 跨式是四分位半宽(约 0.67σ)。备注与剧本的口径必须统一,以 `sigmaRemaining` 的用法为准,取 1.2533。
- 建议:`clock` 档与回放的 EM 从剧本底账按日期取(当天有 09:35 盘初定价用它,没有用昨日定价);底账没有的日子才退到用户填的数。`DEFAULTS.em` 保留作最后兜底并在界面标"模型默认,不是市场价"。

### 12. 阶段 A → B 按钟点,B → C 按剩余方差,两套口径

- 现状:`phaseAt`:14:00 之前是 A;之后看 `sigmaRemaining < width / switch_k`。
- 建议:A → B 也改成按剩余方差份额(当前分布下 14:00 ≈ 剩 27.5%),半日市、重新校准之后自动对齐;`cutoff_a` 保留作覆盖。

### 13. 止盈策略的倍数没有数据依据

- 现状:`stop 0.5×D`、`trail_arm 1.3×D`、档位 40 / 30 / 20、`zone 0.45 / 0.55 / 0.8 W`、`switch_k 1.6`、`otm_band 10`,文档自述"没有经过拟合";
  按金额起算的 $100 / $200 有一次 30 天的回放依据。
- 建议:先不动数字,先做工具。`services/ivRecorder.ts` 已经在攒当日到期的腿盘口与 IV(5 分钟一笔),配上 SPX 分钟线就能重建蝶价序列;
  在 `backtestLab` 的样本内 / 样本外框架上对这几个参数做扫描,目标函数用 R 的期望值而不是总收益。攒够 60 个交易日再看。

### 14. 黄金基线现在是"自我快照",而且钉了不该钉的东西

- 现状:`golden-*.spec` 的期望值原本由 Python 参考实现生成(`gen_golden.py`),Python 引擎已不在仓库里;`golden:update` 用 TS 自己重写期望值。
  所以基线只能发现行为**漂移**,不能证明行为**正确**。它同时钉着三类东西:
  - 机制(给定参数与输入 → 输出),这类该永远不变;
  - 参数的当前值(`flyexit.DEFAULTS`、`VARIANCE_WEIGHTS`、跳动阶梯、`em: 36` 下的阶段切换表),这类校准后**预期会变**;
  - 拒绝文案逐字节一致,这是 Python 对拍时代的要求,现在改一个字也要 `golden:update`。
- 建议:
  - 把基线分成两层:`golden/mechanics/*.json` 只钉机制,参数由用例显式传入(`paramsFrom({em: …})` 那样);
    `golden/params-<日期>.json` 钉当前参数快照,校准脚本写参数时顺手重生成,commit 信息里写明"参数变了,机制没变"。
  - 文案只钉 `code`,`message` 用 `toContain` 钉关键数字即可。
  - 对定价类纯函数补"已知答案"的测试(Bachelier 的平价关系、σ → 0 退化为内在价值、蝶价 ≤ 翼宽),这类测试不依赖快照,才是"正确"的证据。
  这样"基线红了"只剩一种含义:机制变了。

### 15. 校准模型的三处实盘坑

- 提前收盘日:`ivPricing.expiryEpochMs` 一律 16:00,当日到期的蝶差 3 小时就是全部时间价值,`tracker.md` 已标为已知缺口;`flyPlan.seasonalFactor` 对提前收盘日直接回 1,方向也不对(半日的方差分布应压缩,不是不处理)。建议两处都按 13:00 重标,时段分布按"剩余份额对总份额重归一"。
- VIX1D 代理:上午偏当日、下午偏次日,尾盘的反应被低估(文档已述)。`ivRecorder` 攒够 40 天后 `own` 档要尽快切上去,这比任何参数微调都值。
- 隔日到期的蝶没有时段乘数、夜里与白天一样重:建议先按常规时段 / 隔夜方差比(可以从 ES 分钟线估)分两段,比"一样重"近得多。

## 三、剧本与期权墙

### 16. B2 几乎不会触发(文档自认),锚的选法是原因

- 现状:当前剩余区间每 5 分钟围**当时现价**重锚,所以 B2 要求 5 分钟内走出一整个剩余 EM。
- 建议:当前区间锚固定在 09:35 的价(或当日 VWAP),半宽 = 盘初 EM × √(此刻剩余方差份额);"扩展"就是走出这条随时间收窄的带。昨日区间不变。这样 B2 / B3 对称,也和交易员画的"今日预期区间"是同一张图。

### 17. 期权墙只扫现价上下 10 档,不到一个 EM

- 现状:`optionChain` 默认 `width = 10`,上限 15;SPX 5 点一档就是 ±50 / ±75 点,而日 EM 常在 40–70。剧本的加速档与 T2 都从这份链里找。
- 建议:按 EM 扫(±1.5 EM 向上取整到 5 点),并聚合当日 + 次日到期;`gamma_flip` 取离现价最近的零点而不是最低的那个。

### 18. GEX 符号与状态的三处假设

- `net_gex` 的符号假设做市商多 call 空 put,代码自己也承认;`regime` 只有正 / 负,没有中性带;缺 greeks 时 `netGex = 0` 显示为 positive。
- 建议:加中性带(|netGex| 小于当日总 |gex| 的某个比例 → neutral);缺数据显示 unknown;方向假设放到界面上一句话说明。

## 四、行情信号(priceaction / 提醒 / 异动)

### 19. 价格行为分数是加法,重复计数,而且没人给它打分

- 权重手定:trend 30、choch 25、bos 15、position 15、ema 12、sweep 15、pattern 10、level 8、volume 8,相加后夹到 ±100。
  trend / BOS / position / EMA / volume 都是"趋势与动量"的影子,合计 90 分;volume 的正负取自 close 对 EMA20 的方向,不是那根 K 线自己的方向,
  一根放量的看跌反转 K 线只要在 EMA20 之上就算多头证据。
- 更要紧的:PA 分数**没进信号成绩单**,所以没有任何办法知道它有没有用。
- 建议:先把每次 `pa.analyze` 的分与方向记成一种信号进 `signalLog`,跑一季度再调权重;结构上把"结构 / 位置 / 确认"拆成三个独立子分并列显示,不相加。

### 20. 用未收盘的那根 K 线判结构

- BOS / CHoCH 的收盘确认、扫单、形态、相对成交量都把正在形成的 K 线算进去,信号会重绘;分析里的历史 BOS 事件用的是最终过滤后的摆动点,带后见之明。
- 建议:判定只用上一根已收盘的 K 线,当前 K 线只做提示;事件回放按"当时看得到的摆动点"重算。

### 21. 价位提醒:固定 5 美元步长、穿越无确认、均线冻结一天

- `DEFAULT_STEP = 5.0` 是美元:41 块的股票是 12%,SPX 是 0.07%。穿越是任意一个 10 秒采样跨过就报,没有收盘或停留确认;均线每天算一次冻结,而「反复碰均线」用的是实时均线,两处口径不同;`last_price` 只在重算价位时清零,隔夜跳空可能被报成穿越。
- 建议:步长按价格分档(< 50 用 1,50–500 用 5,指数用 25)或按 ATR;穿越要 1 分钟 K 线收盘确认;两处均线统一;开盘第一笔只登记不比较。

### 22. 异动的 σ 口径

- σ 来自 30 天收盘波动率按 √时间缩放,含隔夜缺口、无日内 U 形(只有 15 分钟门槛)、无 beta;大盘 −3% 的日子每只股都是"3σ"。
- 建议:个股涨跌减 beta × SPX 同期涨跌再比;σ 优先用期权隐含(有链的标的);日内 U 形用已经校准好的 `SLOT_FRACTIONS` 同一份分布。

### 23. 反复碰均线的默认值是按"每年报几次"调的

文档写明按 3–10 次 / 年调的,这是频率不是有效性。同样接进成绩单再定。

## 五、研究与复盘

### 24. 信号成绩单有前视

- `baselineReturn` 对整段取回来的历史算平均 k 天收益,包括信号之后的日子;入场价用提醒时的原始价,之后用复权收盘价,中间有分红拆股就错位。
- 建议:基线只用信号前 250 个交易日;入场价也取复权序列上同一天的价;t 值对重叠窗口做 Newey-West 之类的修正,至少在文档里写明是高估的。

### 25. 绩效体检的几处口径

- `size_after_loss` 按**开仓时间**排序比上一笔,上一笔可能还没平,交易员当时并不知道它亏了;`revenge` 用的是平仓时间,对的。改成同样用平仓时间。
- R 的分母不一致:期权按全部权利金,股票按追踪止损(止损可能是持仓中途才设的),没设追踪的股票没有 R;SQN 与期望值因此只覆盖一部分交易。建议股票没有止损时用开仓当天 ATR 的 1 倍作名义风险并标明。
- 期望值、Kelly、盈亏比全按美元算,几千块名义的股票交易会盖过几百块的蝶。建议按 R 或按占权益的百分比。
- SQN 的档位(1.6 / 2.0 / 2.5 / 3.0)与 Tharp 的原表不一致,核对一次。
- 日亏上限建议"= 2 × 平均亏损日"是样本内拟合,文案里"其余亏损就不会发生"忽略了当天后来的回补,措辞要收。

### 26. 回测与参数扫描

- 信号与成交都在同一根收盘价上,偏乐观:改成次日开盘成交。
- `scoreOf` 在没有回撤时用年化 % 顶替 Calmar,排名里混了两种量纲:改成 Calmar 封顶一个常数(比如 10)而不是换量纲。
- 没有 Sharpe / Sortino / 期望值 / 盈亏比;胜率把未平仓的那一笔也算进去。
- 期权回测把实现波动率当隐含波动率(没有方差风险溢价,买权利金被算便宜了),σ 在入场时冻结、无偏斜、行权价不贴档。这一块在 CLAUDE.md「进定价的参数不写经验值」的要求之外,至少把 `realized_to_implied`(校准出来的 0.83)用上。
- 最好的 200 组参数里挑最好的那组,没有多重检验的修正;秩相关 0.3 的警戒线没有显著性。先在文档里写明"样本外的秩相关低于 0.5 都不要信"。

### 27. 强势股筛选的规则没问题,但没有成绩

Minervini 的 30% / 25% / RS 70 与 VCP 的规则都是书上的,可以。但"合格"从未被打分;把每日"新合格"记成信号进成绩单,三个月后就知道这张表值不值得看。

## 六、跟单

### 28. 默认值合理,缺两样

- 30 秒 / 3 单 / $300 是保守起点,够用。
- 建议补:日志里记 leader 的限价与此刻 mid 的差(事后能看出延迟成本);跟进来的持仓自动套一条默认追踪(蝶式预设 + 第 4 条的时间止损),否则"只跟开仓不管平仓"等于裸奔,文档虽写明了,实际用的人不会每单手动去设。

## 八、建议的顺序

1. 第 1、4、2 条:可成交价判定、时间止损、账户累计敞口。都是纯函数加几个字段,直接省钱。
