# 商用准备:方案、做了什么、还差什么(2026-09-28)

目标是"可以卖"。这份报告先给结论,再按六条线讲做了什么、由哪条测试钉着,然后是三张清单:
**要你在本机验证的**、**要你来定的**、**建议接着做的**。

## 结论

这个项目的底子——校验层、三道闸门、append-only 的库、stdio 传输、分层与黄金基线——本来就在同类项目的前列,
09-27 那一轮钱路径审计又补了三十多处。这一轮没有动那些,补的是**卖出去之后才会遇到的事**:

- 用户不是你。他的配置会写坏、库会打不开、电脑会在发单途中重启、他会把日志贴进群里;
- 用户付了钱。安装包里带着两百多个开源组件的许可义务,发单的软件得先让人看过风险揭示;
- 用户会升级。库要有版本号、升级前要留底、发出去的版本不能悄悄换掉。

四路审计(桌面壳、数据层、界面、发版)一共给出 50 多条发现。P0 与 P1 里**能靠写代码解决的都做了**,每一处都有
先红后绿的离线测试;**靠写代码解决不了的**(证书、律师、商标、定价)列在「要你来定的事」里,没有替你做决定。

## 一、钱路径:只在异常时刻才暴露的漏洞

09-27 的审计覆盖的是"正常运行时,一张单会不会变成另一张单"。这一轮看的是**进程的生与死**:重启、退出、超时、崩溃。

| 问题 | 后果 | 现在 | 测试 |
|---|---|---|---|
| 发单调用等了 120 秒超时,界面显示「调用失败」;而交易道是顺序的、不能取消,那张单可能还在排队 | 人顺手重发,第一张随后才到券商 | 报「结果未知…不要直接重发」;引擎回话后补一条通知说明最终有没有执行 | `desktop-engine-client` |
| 记录的第一条状态要等券商回话才落库;引擎在发单途中被结束 | 单已到券商,库里认不出:对账不认领,照原样重发也不提示重复 | 发单之前先留痕(`submit_intent`),对账与重复单防抖都认它。读记录时这条痕不可见,基线不用动 | `submit-intent` |
| `stop()` 一上来就 SIGTERM;退出应用不等引擎 | 正在发的那张单被拦腰打断;卡住的引擎变成孤儿,连着 TWS 继续跑 | 先关输入让它答完自己退,3 秒后才 SIGTERM;退出应用等它停稳;Windows 安装器同样先礼后兵 | `desktop-engine-client`、`desktop-release` |
| `preload` 无条件带 `__confirmed: true`,主进程只看标记(08 月审计的 C2,一直没修) | 界面里跑进别人的脚本就能直接发单,一个对话框都不出现 | 确认凭据:一次性、一分钟、绑着这一次的内容;确认框第一行由主进程写;发单的写明账户是纸面还是实盘 | `desktop-confirm-grants` |
| 放宽风控限额没有任何确认(08 月审计提过) | 名义上限从 5,000 改到 5,000,000 一点就生效 | 往松了改要确认,从多少到多少由主进程对着引擎现在的设置算 | 同上 |
| 关掉「自动执行」要滚到页面最底下点保存才算数 | 中途切走页面,人以为关了,其实还开着 | 关是当场生效的;页头有「有未保存的修改」 | `desktop-settings-form` |
| 设置页把清空的格子存成 0,而引擎对 0 的处理是跳过这条保护规则 | 「日内亏损上限」开关亮着,保护其实没有 | 开着的规则必须填了正数才让存;空着的格子绝不变成 0 | 同上 |
| `is_paper` 纯靠自觉(08 月审计提过) | 把实盘账号标成纸面,实盘闸门对它失效 | 账号不是 IBKR 模拟账号的样子却标成纸面的,按实盘处理并提醒 | `fix-validator-limits` |
| 排队的条件单只由界面驱动(`pending.poll`) | 界面崩溃、重载期间条件单没人盯 | 主进程跟着心跳再问一遍 | —(要连着券商才走得到) |
| 追踪列表读失败 → 清空;盯盘读失败 → 静默 | 页面显示"还没有在追踪任何持仓""盯盘正常",引擎里其实在盯、或者其实已经不回话 | 读不到就留着上一份并说出来;连着 3 轮读不到就不再拿旧心跳冒充 | — (界面,预览台里看过) |
| 顶栏「含实盘」与「仅纸面」同一个颜色;自动执行关着、熔断着的时候完全看不出实盘闸门开没开 | 一打开自动执行,实盘单就发得出去,而顶栏上没有任何预兆 | 常驻「实盘已放开 / 仅纸面」 | — |
| 熔断时撤单没做成(券商没回应),回执里有一句提醒,界面没摆出来 | 人以为"熔断 = 挂单都撤了" | 摆在横幅上 | — |
| 引擎崩溃后的重启退避(3 秒 → 60 秒)被界面每秒一次的轮询绕过 | 坏配置下引擎一秒崩一次 | 退避期间轮询拉不起引擎 | `desktop-engine-client` |
| 休市日历只写到 2026 年 | 2027 年起每个假日都算交易日 | 内置日历按交易所规则推算,和配置取并集 | `market-calendar` |
| 富途没有排队的条件单时不同步已提交订单的状态 | 成交了的单一直显示「进行中」 | 连着富途就问 | — |

口径见 [数据与配置的保险](../features/durability.md)、[确认凭据](../features/confirm-grants.md)、[内置休市日历](../features/market-calendar.md)。

## 二、数据:写不坏、坏了有路、丢了找得回

| 问题 | 现在 |
|---|---|
| 配置文件直接覆盖写;坏了引擎无限重启,界面上只有一段调用栈 | 原子写 + `.bak`;引擎用专门的退出码说"是配置的问题",主进程弹对话框:恢复上一份(闸门一律关上)/ 打开所在位置 / 重试 / 退出 |
| 交易库没有版本号,老软件打开新库不会察觉 | `PRAGMA user_version`;比软件新的库拒绝打开 |
| 没有备份;迁移会整表重建,之前不留底 | 每天、每次升级之前自动备份;「设置 → 数据与备份」里立即备份、恢复、打开目录 |
| 库打不开时每个操作回一句英文的 `SqliteError`,引擎每三分钟被心跳重启一次 | 启动时先开一遍;打不开就说人话、给出路(损坏的可以从备份恢复) |
| 整表重建是裸的 `BEGIN … COMMIT` | 放进事务函数,出错整段回滚 |
| Windows 上交易库落在 `C:\Users\<人>\Library\Application Support\…` | 新装时改到应用自己的数据目录;已有的不动 |
| 提示词版本钉死在首次启动拷走的那份配置里 | 可以写 `latest`;示例配置改用它 |

## 三、隐私与诊断

| 问题 | 现在 |
|---|---|
| 进日志的不只是引擎打过码的那些行:券商回的错误原文、调用栈、渲染层报错都是原样写的 | 落盘前统一脱敏:账号、API Key、家目录里的用户名 |
| Windows 上成交与订单摘要一直在进日志(和 `main.js` 开头那句话矛盾) | 通知行只留标题 |
| 真实账号只在下单解析那条路查;想法分析、AI 选股、行情解读、回测条件解析不查 | 每一次外发都查 |
| 出了问题只能"把 main.log 发过来" | 一键导出诊断信息:版本、引擎状态、脱敏后的配置、备份清单、最近的日志。引擎不在时照样导得出来 |
| 「在访达中显示日志」只有 macOS 菜单里有 | 「关于 → 支持」里都有;Windows 菜单补了「帮助」 |
| 某一页渲染抛异常,整个窗口空白,熔断按钮跟着没了 | 只有那一页换成说明卡 |
| 数据目录写不进去时启动是一个未捕获异常,窗口不开也没有提示 | 弹错误框说明原因 |

没有加崩溃上报,没有加遥测——隐私说明里写的是"我们没有服务器"。要不要做、用谁的服务,是你的决定。

收尾时补核的两处(审计里标着"未核实"的):

- **「交易记录 → 导出」的 JSON 里账号是完整的。** 实测:`exportAll()` 给的是库里的原样。这是有意的(它是你自己的数据的完整拷贝),
  但和界面上处处打码的印象相反,所以导出成功的那句提示里加了一句「文件里的账号是完整的,请自己保管」,隐私说明与使用指南也写明了。
  文件权限是 `0600`。要不要另给一个"打码导出"的选项,看有没有用户真的要把它发给别人——发给支持的应该是诊断信息。
- **凭证存储。** `keychain.ts` 走 `@napi-rs/keyring`:macOS 钥匙串、Windows 凭据管理器,别的平台直接报错、不退化成明文。
  它写到 stderr 的几行只带凭证库的条目名(`dafri-llm-api-key/…`),不带密钥本身。很早的 Windows 版本留下的
  `%LOCALAPPDATA%\dafri\credentials.dpapi.json`(DPAPI 密文)迁移之后**有意不删**,使用指南的卸载一节里写了要一并删除。
- 引擎里有十来处把券商回的原文直接写到 stderr(`futuBroker.ts`、`services/brokerLink.ts`)。没有逐处改——
  落盘与送到「关于」页之前统一过 `redact.js`,在出口挡比在每个源头挡可靠;新加的源头不用记得打码。

## 要你在本机验证的

我这边验不了的,按要紧程度排。前三条不做,不要发售。

1. **装依赖、启动一次。** `cd engine-ts && npm install`,`cd desktop && npm install && npm start`。
   Electron 从 40 换到了 41,两个 lock 文件都变了。看:窗口起得来、条款同意页正常、同意之后能用、引擎连得上 TWS。
2. **模拟账户上走一遍钱路径。** 先 `cd engine-ts && npm run probe`。然后:
   - 「解析并发送」:确认框第一行是「发送真实订单」,下面写着指令原文与「模拟(纸面)」;点确认,单发出去。
   - 确认框弹出来之后**改一个字再发**(做不到是对的——界面会重新弹框;这一条是确认绑定没有挡住正常操作)。
   - 「立即平仓」、建一条带自动平仓的追踪、托管到券商。
   - 发单之后立刻在「关于」里点「重启交易引擎」,等一分钟,看对账把那张单认领回来。
   - 设置里打开、关闭「允许自动执行」;把单笔名义金额上限调大,看确认框上的数字。
3. **打一次包、装一次。** `cd desktop && npm run dist:mac`。熔断丝、许可声明、条款文本进没进包、装好的应用起不起得来,
   只有这一步验得了。Windows 同理(`dist:win`,或推一个 PR 让 `安装包` 工作流跑)。
4. **从备份恢复。** 有追踪、有托管单的时候,「设置 → 数据与备份」恢复到昨天的那一份,看引擎重启后对账怎么认领。
5. **把配置文件故意改坏**(删一个逗号),启动,看对话框;点「恢复上一份可用的配置」。
6. **CI。** ~~推上去之后看 `engine-ts-platforms`(macOS / Windows)绿不绿。~~ 已看:macOS 一次就绿;Windows 第一次红了十条(文件锁、CRLF、信号,都是测试自己的事),
   修完之后绿了。两路都改成了必过。
7. **本地没有 git 仓库。** `~/Desktop/ibkr/IBKR-Assistant` 下没有 `.git`,这一轮的改动没有任何版本历史。
   在推到 GitHub 之前,请先把这个目录和仓库对上(`git init` + 接上远端,或者把改动拷进你的工作副本)。
8. **项目放在 iCloud 同步的桌面上,而且磁盘快满了**。系统已经把 `node_modules` 里七成的文件换出到了云端,
   在这个目录里跑一次测试要三分钟(正常 12 秒)。建议把项目挪出 `~/Desktop`。

## 要你来定的事

这些没有替你决定。每一条给了我的看法,供你参考。

| 事 | 为什么要定 | 我的看法 |
|---|---|---|
| **许可方式** | 仓库是公开的、MIT,README 写着"可以再分发(包括商用)"。已经发出去的版本永远是 MIT。卖的是什么——闭源的后续版本?二进制加支持?开源核心加付费功能? | 先确认有没有别人贡献过代码(影响能不能改许可)。许可密钥这类机制在许可方式定下来之前不值得做 |
| **产品名** | 名字以 IBKR 开头,那是 Interactive Brokers 的商标。"兼容 IBKR"是描述性使用;拿它当收费产品名字的主体,可能被认为暗示官方关系 | 第一次发售之前问商标律师。改名还牵涉 `appId`、数据目录、更新地址,**越早越便宜** |
| **IB API 的许可** | `@stoqey/ib` 是 MIT,但它是 IB 官方 Java 客户端的移植;IB 的 API 有自己的许可条款 | 同上,问律师 |
| **行情数据源** | 顶栏行情带与指数现价用的是 Yahoo Finance 与 Cboe 的非官方接口。个人用没人管,收费产品里用是另一回事 | 要么换成有商用许可的数据源,要么这两样只在连着 TWS 时用券商的行情 |
| **目标市场与监管定位** | 软件给出信号、评分、自动执行。是"工具"还是"投资建议",各地的线不一样 | 风险揭示里已经写明是工具;够不够要看卖到哪里 |
| **条款文本** | 三份都是草稿 | 请律师按目标市场审;填上占位符 |
| **代码签名证书** | macOS 的路接好了等证书;Windows 的还没接(证书形式没定) | Apple Developer Program;Windows 建议 Azure Trusted Signing(按月付费,不用硬件密钥)。**这是发售的前提**:没签名的安装包每个用户都要手动绕过系统警告 |
| **支持渠道** | 条款、隐私说明、安全报告指引里都要写 | 一个邮箱就够 |
