# 行情流被别处撤掉之后,盯盘拿着冻住的价继续判断

2026-09-28 读代码时怀疑、当天用离线测试复现并修掉。**没有在真机上出过事故的记录**——但它不报错、
心跳照常、界面上的价只是"不动",出过也不会有人知道。

## 链条

1. 会话层(`ibSession.ts`)的行情流按 `合约 + generic ticks` 缓存,**不记谁在用**。同一个键订第二次,
   拿到的是同一条流的另一个句柄。
2. `cancelTicker` 把这条流退订、从缓存里删掉。别人手里的句柄还在,读的还是那一份数据——
   撤掉那一刻的盘口,之后不会再有 tick,`error` 也是空的。
3. 盯盘的期权腿价(`ensureOptionStreams` → `fillOptionPrices` / `optionQuotes`)是常驻订阅,一条腿订一次
   留着;只有句柄读到 `error` 才会摘掉重订。
4. AUTO_MID 定价(`legQuotes`)现订现撤。它订的腿如果正好在持仓里,拿到的就是盯盘那条流;
   `finally` 里一撤,盯盘那条腿从此冻住。

踩到的条件很平常:**给同一只蝶加仓**(三条腿全共用),或者**开一只相邻的蝶**(共用一两个行权价)。
之后组合净价 = 会动的腿 − 不动的腿,止损、利润回撤、标的目标价的试算、追价平仓的"立刻成交价"都按它算。

盯盘的节拍器在引擎进程里自己跑,不走 RPC 的交易道,所以它和定价是真的会交错的,不是理论上。

## 改了什么

都在 `ibSession.ts`,`broker.ts` 一行没动:

| 约束 | 落点 |
|---|---|
| 句柄对应的流不在缓存里了(被别处撤掉、会话断开),读到的是**空盘口 + `error`**,不是最后一帧 | `subscribeTicker` 返回的句柄 |
| 被 TWS 拒掉的流照旧:`error` 是 TWS 的原文,数据原样 | 同上 |
| 期权的缓存键带交易类(写了才带);正股、期货的键不变 | `tickerKey` |

第一条靠的是已有的那套恢复:期权腿、持仓正股、期货、量能这四处常驻订阅本来就是"见到 `error` 就摘掉重订",
现在被别人撤掉也算在里面。不查 `error` 的两处(`streamPrice`、`streamQuotes`)读到的是"没有价":
前者当场重订,后者把这只股交给公开源兜底。

为什么是空盘口而不是"最后一帧 + error":`streamPrice` 只看有没有价、不看 `error`,留着最后一帧它永远
发现不了;断线时作废报价(`tws-connection.md`)也是同一条规矩——不拿旧数冒充现价。

## 掂量过、没选的两条路

**引用计数**(订一次加一、撤一次减一,减到零才真撤)。看上去最干净,而且不用动 `broker.ts`。没选,因为
`broker.ts` 里的订与撤并不成对,计数会把现在能用的东西改坏:

- `streamPrice` 取不到实时价时"撤掉、切到行情类型 3、重订"——重订的前提是上一条真的撤掉了。常驻流断了数据
  之后它会再订一次(不撤旧的),计数变成 2,撤一次剩 1,"重订"拿回来的还是那条没有数据的流,退延迟这条路就废了;
- `stockQuotes` 只订不撤,每调一次计数加一,那条流谁也撤不掉了;
- `volume-stream.spec` 钉着现在的语义(同一条订两次、撤一次就是撤掉)。

要上计数得先把 `broker.ts` 里每一处订阅改成成对的,那是拆 `BrokerRouter`「行情与订阅」那一簇时该做的事。

**让 `legQuotes` 用自己的一条流**(订的时候带一个 generic tick,键就和盯盘那条不同)。没选,因为:
要改 `broker.ts`(钱路径、已超线);generic tick 会真的发给 TWS,等于换了一种请求,得真机核对;
而且只治 `legQuotes` 这一处,盘口页和 `streamPrice` 还是老样子。

## 代价与还没做的

- **定价之后盯盘要重订一次。** 共用的腿被撤掉,下一轮盯盘发现、重订、等首笔 tick(最多 1.5 秒)。
  那一轮如果首笔 tick 没到,这条腿没有价,组合净价为空,按「拿不到现价,本轮不判断」处理,下一轮恢复。
  比起冻住是小代价,但它是代价:每次对共用腿定价,那只蝶的盯盘晚一两秒。
- **定价途中被盯盘撤掉。** 盯盘重订之前会先 `cancelTicker`(不带 generic,撤的是这个合约的所有变体)。
  上一次定价刚撤完、盯盘还没恢复时下一次定价就开始了,盯盘这一撤会撤到定价刚订的那条;定价读到 `error`
  当场重订一次(原有逻辑),测试里这条路是通的。一次定价里被撤两次(盯盘连跑两轮、而盘口一直没到)才会
  报「取不到盘口」,不会按错价发单。根治办法是常驻订阅恢复时**只订不撤**(那一撤本来就是空撤:出错的流
  会话层自己已经摘掉了),要动 `broker.ts`,留给拆类的时候。
- **`streamQuotes` 不会自己恢复。** 被撤掉之后读到"没有价":顶栏行情带退公开源,盯价位(`alerts`)那只股
  这一轮不检查——以前是拿着不动的价检查,一样查不出来。它不看 `error`、也没有重试的节流,
  直接加"出错就重订"会对没有行情权限的代码每轮重发请求。要单独做。
- ~~**平掉的持仓腿不撤订阅。**~~ **当天复现、修掉了,见下面「后续:平掉的持仓不撤订阅」。** 原话留着:
  `optionStreams` / `stockStreams` 只在出错和断开时清,平仓之后那几条线路一直占到重连。以前靠 `legQuotes`
  误撤"顺带"释放过一部分。一天开平几十只蝶会往 100 条的额度上靠。
- **持仓的键也不带交易类**(`positions.ts` 的 `makeKey` / `legOf`:账户|标的|类型|到期|行权价|C/P)。
  同时持有 SPX 与 SPXW 的同一到期日 / 行权价 / 看涨看跌时,持仓表里两行会并成一行。这个键进了追踪器和库,
  不是顺手能改的,这次没动。
- **富途**那条路没有看:它是拉取式的(`get_order_book`),退订之后读不到而不是读到旧价,但没有联调过。
- **真机没核对。** 离线测试里的假 TWS 只保证"退订了就不再推"。真机上要看的是:定价之后盯盘那条腿的重订
  在纸面会话(行情类型 3)下首笔 tick 多久到。

## 后续:平掉的持仓不撤订阅(2026-09-28 同日)

### 链条

1. 盯盘给每条持仓期权腿(`optionStreams`,键 `opt:<持仓键>`)、每只持仓正股(`stockStreams`,键 = 代码)
   各留一条常驻订阅。
2. 这两本账只有两个出口:句柄读到 `error`(摘掉**重订**,线路数不变)、断开连接(`cancelStreams`)。
   没有"这条腿已经不在持仓里了"这个出口。
3. 上面那次修复之前,`legQuotes` 按合约撤订阅时会把共用的持仓腿一起撤掉——错的,但顺带放掉过一些线路。
   修复之后被撤的腿下一轮就重订回来,这条"顺带"的出口也没了。

### 复现

假 TWS 搬到了 `tests/fakeTws.ts` 两份测试共用,并补上了持仓增量的推送:平仓推 `removed`、数量 0,和库一样)。

### 代价与还没做的

- **误撤的代价是一次重订。** 持仓表短暂不全(比如重连之后库把持仓一条一条重新推过来的那一瞬)时读到的持仓会少几条,
  少的那几条会被撤掉,下一轮订回来、等首笔 tick(最多 1.5 秒)。同一份不全的持仓表在追踪器那边的后果重得多
  (判「持仓已不存在」),那是另一件事;这里没有为它加"连续几轮都没有才撤"。**重连之后库到底怎么推,没有核对过。**
- **有连接断着的时候回到老样子。** 两条连接(纸面 + 实盘)里一条长时间断着(比如模拟盘的 TWS 关了),另一条上
  开平的腿这段时间不撤,连回来之后的第一轮一起撤。要分账户撤,得让这本账记下每条流属于哪个账户
  (正股那本是按代码记的,几个账户共用一条),这次没做。
- **没人读持仓就没人撤。** 撤只发生在 `positions()` 里。盯盘、托管对账、持仓页都在读;全都不读的时候
  (没有追踪、界面也没开着持仓页)平掉的腿会占到下一次有人读持仓为止。
- **`streams`(顶栏行情带、标的现价)还是只订不撤。** 它的条数跟着"看过几只股"走,不跟着开平仓走,
  涨得慢,但同样没有出口。平仓时因为它还订着而没撤的那只股,线路就归它了。
- **富途**没有看。
- **真机没核对。** 假 TWS 只认"退订了"。真机上要看的是:平掉一只蝶之后,TWS 那边的行情线路占用数确实降了三条;
  以及在纸面会话下平仓、又马上开回同一只蝶时,重订的首笔 tick 多久到。
