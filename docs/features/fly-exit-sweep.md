# 蝶式出场参数扫描

离线的研究工具:拿软件自己记下来的 SPX 当日到期期权盘口(`fly-iv/` 目录,见 [蝴蝶测算](fly-plan.md)「自己积攒 IV」),
问一句话——**换一组出场参数,过去这些天会比现行的好吗**——并且在数据撑不起结论的时候说"下不了结论",同时说清还差什么。

先说它的结论有多难拿到:蝶的盈亏偏得厉害(多数天差不多,少数几天差出一整个翼宽),"某组参数就是更好"要排除"那种大亏的天只是还没碰上"。
这件事没有捷径——差别不大的参数要攒几年才证得了,几个月的数据只够说"见过的这些天上谁领先"。报告把两句话分开说。

它只出报告,不改任何参数:`flyexit.ts`、`trackerDrawdown.ts` 里的数一个都不动,要不要改由人看过报告再定。
没有界面,没有 RPC,引擎运行时不加载它。命令是 `npm run sweep:fly`(`engine-ts/scripts/sweep-fly-exit.mjs`)。

要比的是两套出场规则:

| 规则 | 现在的数在哪 | 这里怎么跑 |
|---|---|---|
| 实盘的蝶式预设([持仓追踪](tracker.md)「蝶式按金额起算」):每组浮盈到过 $100 起算、$200 收紧、40 / 30 / 20 三档、15:00 后减半、最少回吐 0.20,外加人填的止损与到点平仓 | `flyexit.ts` 的 `FLY_ARM_USD` / `FLY_TIGHTEN_USD` / `drawdownTiers()` / `drawdownLate()` / `drawdownFloor()` | 每一笔样本过一遍 `tracker.evaluate`,再并上 `trackerExits.withTimeExit` |
| 交易分析的回放策略([交易分析](tradereview.md)「止盈策略回放」):止损 0.5 × D、激活线 1.3 × D、区间 0.45 / 0.55 / 0.8 W、阶段切换 | `flyexit.DEFAULTS` | 把记下来的现价与蝶价当成 K 线喂给 `flyexit.simulate` |

## 设计决策

| 决策 | 理由 |
|---|---|
| 价只从记下来的腿盘口来:蝶的中间价 = Σ 比例 × 腿中间价,立刻成交价 = 各腿买卖价合成 | 这是用户做的那种合约的真实报价;模型价里已经含着要检验的假设 |
| 不在行权价之间、时刻之间插值 | 插出来的价没有人报过 |
| 出场规则用原样的函数,不另写一份 | 另写的那一份迟早和实盘的差一个取整、一道闸;差出来的"更好"是假的 |
| 参照组的数从 `flyexit` 读,这里不抄 | 那边改了,参照组跟着改,不会拿旧的数当"现行" |
| 抽样单位是**天**:先按天平均,再在天上重抽 | 同一天里的情景是同一条走势、互相重叠的持有期,当成独立样本会把区间缩得没有道理 |
| "比现行的好"只在**不靠分布假设的下界**在 0 之上时才说;见过的这些天上的区间只用来描述 | 重抽出来的区间默认"以后的天和见过的是一类",多数天小赢、偶尔大亏、还没碰上大亏时它错得离谱(见「统计」) |
| 那个下界把"没见过的那种天"按合约能亏的上限算 | 上限是合约条款给的(一边卖在翼宽、另一边归零),不是估的;别的取法都得猜一个数 |
| 试了几组就把 α 平分给几组 | 试了 N 组、挑最好的那一组,它的领先里有一部分是挑出来的 |
| 结论还要经得起三样检查:隔一笔才判断一次、换一种了结方式、单数天与双数天分开看 | 前两样数据里没有答案;第三样防的是只有一半的天撑着。结论跟着它们变,就不是数据给的结论 |
| 没有"至少 N 天"的线 | 天数少时"没见过的那种天"占的比例大,下界自己就是负的;"少于几天无论如何下不了结论"是推出来的,报告里写着 |
| 佣金没有默认值 | 填一个猜的数,结果就带着一个没人确认过的假设;不给就在报告里写明"扣佣金之前" |
| 入场人群的每一道限定都是参数,报告里逐项写出 | 工具不知道用户做的是哪一种蝶;替他定了,结论说的就不是他的单 |
| 结果只打印或写到仓库之外(`--out`) | 里面是按天的盈亏,换一批数据就过时;原始行情与派生的数都不进仓库 |

`tracker.ts` 归在编排层,分析层不许 import 它(`.dependency-cruiser.cjs` 的 `analysis-is-pure`)。所以判定用的那几个纯函数
由调用方递进来(`flyExitSweepSpec.ts` 的 `TrackerRules`):脚本与测试递的都是 `import * as tracker` 那个模块本身,
类型检查保证它满足这个形状。

## 价

一笔样本里,这只蝶的三条腿(中心 − 翼宽、中心、中心 + 翼宽,同为看涨或看跌)各有买价与卖价:

| 价 | 算法 | 和实盘哪里对齐 |
|---|---|---|
| 中间价 | Σ 比例 × (买价 + 卖价) ÷ 2,取绝对值、4 位 | 持仓那一行的组合现价(`combos.comboRow`) |
| 立刻买得到的价 | 两翼按卖价买、中心按买价卖 | 蝴蝶测算的"现在立刻买得到的价" |
| 立刻卖得掉的价 | 两翼按买价卖、中心按卖价买回;不是正数就是"卖不掉" | `tracker.naturalClosePrice`(追价平仓挂的那个价) |

- 一条腿的盘口要成对:有买价(0 也算,远翼没人出价是真盘口)、卖价为正、买价不高于卖价。有一条不成对,三个价都不给。
- 入场那一笔缺报价:这个情景不要。之后某一笔缺报价:那一笔不判断(到点平仓除外:到点就是到点)。两样都数进报告。
- 三条腿不在那一笔样本里(别的蝶的样本),这一笔和这只蝶无关,不算缺报价。
- 带着到期日、却不是当日到期的样本不用;一次只扫一个标的(`--symbol`,默认 SPX),别的标的的样本不用。两样都数进报告。

**记下来的行权价摆得出哪些蝶。** 后台那一路每天的网格是锚 −75 / −50 / −25 / −10 / 0 / +10 / +25 / +50 / +75,锚以下只记看跌、
以上只记看涨。三条腿都在网格上、同向、等距的蝶一天只有四只,都是 25 宽:看跌的中心在锚 −50 与锚 −25,看涨的中心在锚 +25 与锚 +50。
标的离锚 20 点以上时添的那一对平值偶尔再凑出一只。测算顺带记的样本(`by: "plan"`)带着用户当时在看的那只蝶的三条腿,
`--by all` 或 `--by plan` 才用,时刻不规则。**这四只之外的蝶(50 宽、中心贴着锚的)这份数据说不了。**

## 情景

- 不给 `--entries`:每一笔样本 × 每一只摆得出的蝶 = 一个假想的入场,再按参数筛:样本来源、入场时刻的窗口、翼宽、看涨 / 看跌、
  入场价 D 的范围、中心在现价虚值一侧多少点(看涨 = 中心 − 现价,看跌 = 现价 − 中心)。当天最后一笔不作入场。
- 给了 `--entries`:只算文件里的那几笔真实入场,用入场时刻或之后的第一笔样本;给了实付净价就用它当 D。
- 同一天的情景先取平均,这一天算一个数,天与天等权:一天只有 1 个情景和一天有 37 个情景,权重一样。

## 成交口径

| 项 | 规则 | 参数与默认 |
|---|---|---|
| 入场价 D | 中间价 + 份额 ×(立刻买得到的价 − 中间价),朝多付的一侧取到组合的跳动(`tracker.closeTick`)上 | `--entry-spread-share`,默认 1(立刻买得到的价) |
| 出场 | 触发的那一笔按立刻卖得掉的价;那一笔卖不掉就等下一笔有价的 | 没有参数 |
| 一直没出场 | `natural`:当天最后一笔拿得到盘口的立刻卖得掉的价,不是正数按 0(留着作废,不倒贴)。`settle`:最后一笔离收盘够近的那些天按最后一笔现价的内在价值结算,其余的天同 `natural` | `--terminal`,默认 `natural`;`--settle-within` 默认 = 记录间隔 + 一个节拍(5.5 分钟) |
| 佣金 | 每张每边;一组蝶 4 张,入场一次,成交的出场再一次;结算与归零作废不收。给了佣金,追踪的成本里就含入场的那 4 张 | `--commission`,**没有默认值** |
| 止损类拿哪个价判 | 中间价,或立刻卖得掉的价(同追踪上的 `stop_basis`) | `--stop-basis`,默认 `mid` |
| 每个情景几组 | 只影响回放策略的分批;实盘预设是全平 | `--qty`,默认 1 |
| 合约乘数 | | `--multiplier`,默认 100 |

- `natural` 比真留到结算保守:尾盘价差宽,对拿得久的参数组不利。`settle` 用的现价不是结算价,差着最后几分钟。两种都不是真相,
  所以报告里同时给出另一种口径下的差值,结论要在两种下方向一致。
- 提前收盘日按 13:00 收盘(`marketCalendar`);尾盘收紧的 15:00 那天到不了,和实盘一样。

## 实盘预设

- 一组参数(`LiveParams`)是金额线与百分比;`liveTargets` 按这只蝶每组的开仓成本换成追踪上的 `Targets`。
  这一步和 `flyexit.drawdownUsdPreset` 是同一个换算,只是金额线能换(那个函数把 $100 / $200 写在里面)。
  测试钉着:参照组换出来的与建追踪时存进库的那一份(`rpc/params.drawdownTiersOf`)逐字段相同。
- 成本(`unitCost`)= 入场价 × 乘数 + 4 张 × 每张佣金:实盘追踪用的是组合行的 `avg_cost`,IBKR 的口径里含佣金,
  金额线换成倍数、浮盈都对着它算。没给 `--commission` 时成本里没有佣金,$100 / $200 两条线在这里到得比实盘略早,报告里写明。
- 止损 = 倍数 × D。止损价不低于入场那一刻的中间价(按立刻成交价判时:不低于那一刻的立刻卖得掉的价),实盘建追踪时会被
  `tracker.validate` 拒掉;这里照样问它,被拒的情景按不设止损算,并在报告里数出来。
- 到点平仓的时刻用 `trackerExits.nextOccurrenceMs`:入场时已经过了那个钟点的,当天不触发。
- 参照组里的止损与到点是空的:预设里没有这两项,它们是每条追踪上人填的。实盘固定这么设的,用 `--ref '{"stop_mult":0.5}'` 说出来。
- 没有的:实盘推峰值要连续两轮(两秒)都见到才算,这里每一笔样本都算数;追价的节奏、部分成交、托管单、标的止损价。

## 回放策略

- 喂给 `flyexit.simulate` 的 K 线:时刻是样本的时刻,标的收盘价是记下来的现价,蝶的收盘价是记下来的中间价。缺报价的那一笔不喂
  (喂了它会拿模型价补);回执里 `model_minutes` 不是 0 就报错。
- 它的每一次出手按那一刻立刻卖得掉的价重新计价;它说"结算"或"数据到此为止"的,按上面"一直没出场"的口径。
- 入场价是立刻买得到的价,比中间价高出半个价差;价差很宽时入场那一笔的中间价已经不高于 `stop × D`,`simulate` 会在入场那一笔就止损——
  那是入场价差造出来的,而且止损倍数越低越占便宜。和实盘预设同一个办法:这种情景那一组按不设价格止损算(区间止损照旧),并在报告里数出来。
- EM 每天从记下来的盘口取:最早一笔取得到平值跨式(现价旁边那一档同时有看涨看跌)的样本,跨式 × √(π/2) 再折回全天
  (`playbook.makeBand` + `sessionEm.sessionSigmaOf`,和回放从剧本底账取 EM 是同一个式子)。取不到的天、提前收盘日不做回放;
  入场早于取到 EM 那一笔的情景也不做(那是入场时还不知道的数)。`--em 36` 改成一律用一个数。
- 参数网格的键是 `flyexit.DEFAULTS` 上的(`stop`、`trail_arm`、`zone_hold`、`switch_k`……),`em` 除外。

## 两笔之间

判断只发生在记下来的那几笔上(5 分钟一笔)。两笔之间价走到过哪里不知道:实盘一秒一轮,看到的峰值只会比这里高、触发只会比这里早。
这个差别没法从两头的报价里补出来,所以不补,而是量它:每个情景另跑一遍"隔一笔才判断一次",
主结论里那一组在这样放粗之后不再领先,就不算结论。它量的是"结论对采样间隔敏不敏感",不是"一秒一轮时会怎样"。

## 统计

矩阵是 [参数组][天],每个数是那一天全部情景的平均。两个目标都算:平均 R(每个情景的盈亏 ÷ 付出的权利金)与平均每组盈亏(美元);
结论按 `--objective` 选的那一个出(默认 R),另一个只列均值。天与天当作互不相关、来自同一个分布。两层,回答两个不同的问题。

### 一、见过的这些天上谁领先(近似,不是结论)

1. **每组单看的区间**:在天上重抽(同一次重抽里各组用同一批天),bootstrap-t。没考虑挑选。
2. **算上挑选的区间**(max-t):每次重抽看各组的 t 里最极端的那一个,拿它的分位数当临界值;试的组越多越宽。
   临界值每一头取"两头分开取"与"取 |t|"里宽的那一个,并且不比这一组自己单看的窄。
3. **对半检验**:单数天上挑均值最高的一组,拿双数天打分,再反过来。给人看的。

重抽到的差值全是同一个数的概率(Σ (这个值占的天数 ÷ 总天数)^总天数)超过 (1 − 置信水平) ÷ 2 的组给不出区间:
每天都与参照组相同的、只在很少几天上不同的、天数太少时的所有组。某一组抽到全是同一个值的那几次只算在它自己头上,不连累别的组。

这一层默认"以后的天和见过的是一类"。**它不能拿来下结论**,`tests/fly-exit-sweep.spec.ts` 钉着原因,数是在合成的零均值差值上数出来的:

| 差值(均值都是零) | 区间整个在 0 之上的机会(置信水平 95%,"领先"一侧名义上 2.5%) |
|---|---|
| 多数天赢 1、一成的天亏 9,一组,5 / 9 / 15 / 30 天 | 57% / 39% / 21% / 3%(就是一次大亏都没碰上的机会:0.9ⁿ) |
| 八成的天赢 1、两成的天亏 4,9 天 | 14% |
| 12 天里 6 天是 ±1、其余与参照组相同,五组(对称) | 6.5%(另一侧 7.0%) |
| 温和的偏与稀(对称、指数分布的左偏、又稀又左偏),12 天 8 组与 40 天 5 组,200 个种子 | 0–6 次,都不超过 10 次 |

三种 max 统计量里选逐次重估标准误的那一种,也是对照出来的(组数含参照组):没有真差别、6 天 21 组、200 次里,"用原样本的标准误去除"的做法
55 次判成领先,它 1 次;尺度最小的那组真的好、20 天 5 组、100 次里,"直接取均值差的最大值"一次都找不到,它找到 89 次。

### 二、能不能说它就是更好(不靠分布假设)

蝶的盈亏有合约给的上下限:一个情景里一组参数最多比另一组多亏 `cap` = 最宽的翼宽 × 乘数(+ 一次出场的佣金)——一边卖在翼宽、另一边归零。
折成 R 再除以(入场价的下限 × 乘数);入场价的下限是 `--debit-min`,没给(或是真实入场)就是组合的一跳 0.05,那时 R 的上限是 500R,等于下不了结论。

逐日差的均值有一个对**任何**分布都成立的下界(`flyExitSweepStats.exactLower`):

```
下界 = (1 − π) × 见过的这部分的下界 − π × cap
```

| 项 | 算法 | 依据 |
|---|---|---|
| π | 1 − α^(1/n) | n 天里比见过的最差的一天还差的那种天一次都没出现;它出现的概率超过 π 的机会正好是 (1 − π)ⁿ = α,任何分布都成立 |
| 见过的这部分 | 不低于样本最小值的那部分分布的均值的下界:把经验分布往坏的方向挪 ε = √(ln(1/α) ÷ (2(n − 1))),即把最好的 ε 成的天换成见过的最差的那一天 | Anderson (1969) 的界,ε 来自 DKW–Massart 不等式;给定最小值,其余 n − 1 天是从"不低于它"的那部分里独立抽的 |
| α | 一头的 (1 − 置信水平) ÷ 2,按要比的组数平分,每组的再对半分给上面两样 | Bonferroni:不管各组之间怎么相关都成立 |

只要天与天独立、亏损不超过 `cap`,"下界在 0 之上"说错的机会不超过名义水平——包括"多数天小赢、偶尔大亏、还没碰上大亏的那种天"。
测试里在上表前两行那种差值上(另有亏 99 的、五个变体一起比的、又稀又整齐的)各跑三千次,判成"更好"的每格不许超过 75 次,数出来都是 0 次。

**它很保守,而且这不是方法的毛病。** n 天全是同一个正数 g 时,"均值其实为零、亏 `cap` 的那种天占 g ÷ (g + cap)"这种可能有
(1 − g ÷ (g + cap))ⁿ 的机会一次都不露面;只要这个机会大过 α,就没有任何方法能在水平 α 上排除它。由此推出两件事,报告里都写着:

- **少于 ⌊log₂(1/α)⌋ + 1 天,数据再好也下不了结论**(那时 π > 1/2)。置信水平 95%:比 1 组是 7 天,比 4 组是 9 天,比 17 组是 11 天。
- **差别不大的参数要攒很久**。25 宽的蝶 `cap` = $2,500:四组一起比、每天稳定好 $150(合成数据里的那种)要一百来天;
  每天平均好 $50、日间波动 $60 要五百到一千天;好 $20 的在一千天里证不了。

### 结论

`flyExitSweepStats.verdictOf`,五种:

| 状态 | 条件 | 报告里的话 |
|---|---|---|
| `better` | 有一组第二层的下界在 0 之上(第一层的区间当然也在),并且三样检查都站得住 | 「…」比现行参数好 |
| `fragile` | 下界在 0 之上,但三样检查里有没站住的 | 不能当作结论,不要据此改参数 |
| `unproven` | 第一层的区间在 0 之上,第二层的下界不在 | **下不了结论**;见过的这些天上谁领先、排除不了的那种天占几成、那种天里多亏到多少领先就没了、照现在的数还要约多少天 |
| `not_separated` | 第一层的区间也含 0 | 数据分不开这几组与现行参数(N 天) |
| `nothing_to_compare` | 只有参照组,或没有一天有情景 | — |

三样检查:隔一笔才判断一次、换一种了结口径之后,这一组比参照组的差仍为正;单数天、双数天分开看,两半上都为正
(对半检验进结论的是这一条;"在一半上挑、另一半打分"那几行只给人看)。
"现行的比某一组好"同理:不靠假设的上界在 0 之下才这么说。

## 怎么读报告

1. 先看开头:数据几天、人群怎么限的、成交口径、扣没扣佣金。这些不对,后面的数就不是你的单。
2. 「情景」一段:情景数、每天几个、入场价的范围、没要的与筛掉的各多少、缺报价没判断的占几成。
3. 每套规则一张表:每组的平均 R 与平均美元、比参照组的差、单看的区间、算上挑选的区间、不靠假设的下界、赢 / 输 / 平参照组的天数。
   两个区间只说见过的这些天;「不靠假设的下界」是结论看的那一列,多数时候是个很大的负数——它把没见过的那种天按合约上限算进去了。
4. 「出场方式」:每组各有多少情景是利润回撤、止损、到点、拿到最后出的;止损设不上的情景有多少。拿到最后的占比大,了结口径的影响就大。
5. 「结论」只有上表五种之一。`unproven` 时把那几个数读完:没见过的那种天里多亏到多少领先就没了——拿它和你认为可能的最坏一天比,
   这是数据替不了你的判断。接着是那一组换口径、单双数天的差值,以及对半检验。
6. 结论是 `better` 也只是"在这群假想的入场、这种成交口径下",见下一节。

## 它说不了什么

- **两笔之间**:5 分钟一笔,见上。
- **报价不是成交价**:组合单实际常常成交在比各腿买卖价合成的更好的位置;反过来,行情急的时候报出来的价未必成交得到。
- **假想的入场不是你的入场**:每一笔样本都入场一次,不挑时机;要看自己的单用 `--entries`,但那样天数更少。
- **只有四只蝶、一个标的、一段日子**:见「价」。记录开始之前的行情不在里面;天与天当作互不相关,趋势连着好几天的时期区间会偏窄。
- **见过的这些天上的区间不是结论**:去掉止损之类"多数天略好、偶尔大亏"的改动,样本里没碰上大亏的那种天时会显得更好(见「统计」的表)。
- **不靠假设的下界靠两条**:天与天独立、同一个分布;亏损不超过合约上限。行情换了一种状态(波动率的水平、日内的走法),前一条就不成立。
- **`settle` 的结算价**是最后一笔现价的近似;`natural` 把尾盘的价差算给了拿得久的组。
- **实盘里有、这里没有的**:峰值的两轮确认、追价、部分成交、托管单、睡醒不判断的那几轮。
- 一天里情景数相差很大时(人群限得窄),只有一个情景的那天和别的天等权,噪声大。
- **α 只在一次跑里试的那几组之间平分**。实盘预设与回放策略各出一个结论,一起跑时出一次误判的机会是两份;
  换着人群限定、成交口径反复跑,挑结论好看的那一次,它就不作数了——想清楚要比什么再跑,跑完不挑。

## 命令

```
cd engine-ts
npm run build
npm run sweep:fly -- --dir auto --wings 25 --entry-from 09:45 --entry-to 13:30 --debit-min 1 --debit-max 4 \
    --arm 50,75,100,150 --tighten 150,200,300 --commission 0.65
npm run sweep:fly -- --dir auto --entries D:/tmp/my-entries.json --by all --arm 50,100,150
npm run sweep:fly -- --dir auto --replay --replay-grid '{"stop":[0.4,0.5,0.6],"trail_arm":[1.2,1.3,1.5]}' --out D:/tmp/sweep.json
```

`--dir auto` 从配置里的 `storage.db_path` 找它旁边的 `fly-iv/`(`--config` 指定配置文件),和 `calibrate:fly -- --samples auto` 同一个找法;
没有别的默认路径。目录在哪,`options.iv_recorder` 的 `dir` 写着。不认识的参数、`--ref` / `--grid` / `--entries` 里写错的键名
(`--grid` 文件的顶层只认 `live` / `sets` / `replay`,真实入场只认 `time` / `center` / `wing` / `right` / `quantity` / `debit`)当场拒:
一个写错名字的限定被悄悄忽略,报告说的就不是你以为的那群蝶、那几组参数。

| 参数 | 默认 | 含义 |
|---|---|---|
| `--symbol` | 后台那一路记的标的(SPX) | 只扫这个标的的样本 |
| `--by` | `loop` | 用哪一路记的样本:`loop` / `plan` / `all` |
| `--entry-from` `--entry-to` | 不限 | 入场时刻的窗口,美东 `HH:MM` |
| `--wings` `--right` | 不限 | 翼宽(逗号分隔)、`C` / `P` |
| `--debit-min` `--debit-max` | 不限 | 入场价 D(点) |
| `--dist-min` `--dist-max` | 不限 | 中心在现价虚值一侧多少点 |
| `--entries` | 不给 | 真实入场的清单(JSON 数组:`time`、`center`、`wing`、`right`,可带 `quantity`、`debit`) |
| `--entry-spread-share` `--commission` `--terminal` `--settle-within` `--stop-basis` `--qty` `--multiplier` | 见「成交口径」 | |
| `--stride` | 1 | 隔几笔样本判断一次 |
| `--arm` `--tighten` `--tiers` `--tight-at` `--late-after` `--late-factor` `--floor` `--stop-mult` `--exit-at` | 不给 | 实盘预设各项要比的取值(逗号分隔;`--tiers 40/30/20,50/35/20`;不设写 `none`)。给了几项就做这几项的全部组合,没给的用参照组的;要把现值也放进组合就把它一起列上 |
| `--ref` | 预设现值,不设止损、不设到点 | 参照组上要覆盖的项(JSON) |
| `--grid` | 不给 | 同上,写成文件:`{"live":{…},"sets":[{…}],"replay":{…}}` |
| `--replay` `--replay-grid` `--em` | 不做;`auto` | 回放策略 |
| `--objective` | `r` | 结论按 `r` 还是 `usd` 出 |
| `--level` `--draws` `--seed` | 0.95、2000、1 | 置信水平、重抽次数、种子(同样的输入与种子,结果一位不变) |
| `--out` | 不写文件 | 把结果与统计写成 JSON;路径不能在仓库里 |

没有给任何要比的取值时,报告只有参照组自己的成绩。30 天、每天约 180 个情景、18 组参数,在开发机上约半分钟;整段是同步计算,
数据多时按天往标准错误输出报进度。
