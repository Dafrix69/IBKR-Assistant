# 富途 OpenD:IBKR 用不了时的备用通道

IBKR 的 API 不是每个人都能跑起来。TWS 装不上、握手一直超时、行情权限没开、账户压根不在
盈透——任何一条卡住,整个引擎就没有出路。所以下单层做成了两条腿:

```json
"broker": { "provider": "ibkr" }     // 改成 "futu" 就换一条通道
```

**换的只是出口。** 提示词、别名表、限额、硬校验层、记录格式一行都不变——`FutuRouter` 和
`BrokerRouter` 的接口完全一致,全系统只有 `_make_router()` 那一行知道自己连的是谁。
定价那几个最容易算错的纯函数(组合中间价、AUTO_MID 限价、行权价宽度、盘口流动性)是
**直接复用** IBKR 那一侧的实现,不是抄一份——同一套数学只能有一个来源。

同一时刻只连一家。界面在「富途 OpenD」页顶部切换,顶栏的连接标识也会跟着从 `TWS` 变成
`OpenD`,免得切过之后看不出单子会从哪条通道出去。

**切换不会替你写连接和账户。** §9.6 定的是"账户与连接只允许人手动改配置文件,不给界面通道",
换券商不是绕过它的后门——第一次切过去时,面板会把该抄的那段 JSON 直接贴出来,你并进
`config/settings.json` 再回来点一次就成。富途账号是一串数字,填 IBKR 的 `U/DU` 开头账号会被
当场拒绝。

## 面板做什么

和 TWS 那一页一一对应,连卡片样式都共用:

| 面板分区 | 做什么 |
|---|---|
| 0 · 券商接入 | 在 IBKR / 富途之间切换。切换会先断开现有连接,并把选择写进配置文件;没配过的那家会直接把该抄的配置片段贴出来 |
| 1 · 程序 | 检测 OpenD 是否安装、是否在运行(富途版 `FutuOpenD`、海外版 `moomooOpenD` 都认);装了没开的可以一键启动 |
| 2 · API 端口 | 探测 11111 / 22222 及配置里的自定义端口。纯 TCP 探测,不发协议帧 |
| 3 · 握手与账户 | 真连一次读回 OpenD 版本、**行情/交易是否已登录**、账户列表;同时核对账户别名是否对得上真实账号 |
| 4 · 连接引擎 | 建立引擎真正用来下单的长连接 |
| 5 · 交易解锁 | 仅实盘需要。密码只存 Keychain / DPAPI,而且**只存 md5** |
| 连不上时照着做 | 8 步指引,按你的实际配置显示端口号,并写明富途做不到的那几件事 |

**本软件同样不接触你的富途账号密码。** 登录在 OpenD 自己的窗口里完成,这条边界和 IBKR 那边
是同一条(§9.1 的 S0 级)。唯一的例外是实盘的交易解锁密码——富途的接口要求应用侧提交
md5,所以它只走 Keychain / DPAPI:界面填的明文在引擎里算完 md5 就丢,不落配置、不进日志、
不进审计流水(有一条测试专门盯这件事)。

## 五处和 IBKR 不一样,必须先知道

**1. 不支持组合单,而且不会偷偷拆。** 富途的下单接口是单腿的,没有 IBKR 那种把价差当成
一个合约整体撮合的 BAG。拆成单腿分别发会产生腿风险——一条腿成了另一条没成,建出来的是
裸头寸而不是价差,风险结构和你要的完全不是一回事。所以价差 / 蝴蝶 / 铁鹰在富途通道上
**直接拒绝**,理由写在报错里,请切回 IBKR。

**2. 没有原生条件单,全部退到软件盯盘。** IBKR 能把触发条件挂在它自己的服务器上(§8.1 方式 A),
软件掉线条件依然有效;富途的下单接口没有这个能力。所以在富途通道上,**所有**条件单都走方式 B
的软件盯盘队列——代价是本软件必须一直开着,好处是行为明确:不分流的话,"涨到 7500 再买"会被
当成普通单立刻发出去,而这个错误在成交回来之前完全看不出来。

**3. 回报是拉的,不是推的。** ib_insync 有事件流,富途没有。`FutuRouter.poll_order_updates()`
在界面本来就有的定时轮询里拉一次订单与成交,把结果包成和 ib_insync 同形的对象,喂给
`engine` 里那套现成的入库逻辑——**两家券商的 `status_timeline` / `fills` 因此长得一模一样**。
少了这一步,富途下的单会永远停在 Submitted。

**4. K 线周期少一档。** 富途最小 1 分钟,往上是 5 / 15 / 30 / 60 分钟与日线,**没有 2 分钟**。
缺的就明说并拒绝,不拿 1 分钟线合成——合成出来的 K 线在 PA 分析里和真线长得一样,但摆动点
是假的。

**5. 没有美股指数。** SPX / NDX / VIX / RUT 在富途 OpenAPI 上完全取不到行情(不是权限问题),
涉及指数的一切——报价、K 线、期权墙、条件单——都会被明确拒绝。详见下面「真机联调结论」。

## 代码换算:查,不猜

普通美股按 `US.<代码>` 拼就行。但有两处刻意去查而不是拼:

* **指数**。各家的指数代码命名都不一样,拼错了不一定报错,可能拿到另一个标的的价格,而触发价
  复核会照单全收。所以先看 `broker.futu.symbol_map` 的显式映射,没有就去富途自己的证券列表里
  实测一次并缓存。这个决定在真机上直接兑现了:富途的美股指数代码是 **`US..SPX`(双点)**,
  和想当然的 `US.SPX` 不一样——猜的话就错了。(不过解析出来也没用,见下面第 ① 条。)
* **期权合约**。用期权链按(到期日、行权价、Call/Put)反查代码。各家的期权代码规则都改过,
  拼错的后果是下到另一个合约上,而这个错误在回报回来之前看不出来。

## 真机联调结论(futu-api 10.10 + 本机 OpenD 实测)

接口签名、返回列名、枚举取值全部按真机对过。**三件事是文档上看不出来、只有连上去才知道的**,
都已经变成明确的拒绝或补偿,而不是留给用户去撞:

**① 富途 OpenAPI 不支持美股指数。** SPX / NDX / VIX / RUT 的快照、订阅、历史 K 线三条路
全部回「暂不支持美股指数」——这不是权限没开,是能力缺口。最阴的地方在于**指数代码在它的
证券列表里查得到**(`US..SPX`,注意是双点),所以代码解析会"成功",然后每次取数静默空手
而归。真正的后果是 SPX 条件单进了盯盘队列却永远不会触发:界面显示"正在盯盘",实际什么都
不会发生。

所以加了一道 `quote_capability()` 闸门:涉及指数的**行情与 K 线**一律当场拒绝,**条件单
在进队列之前就被拒**,并给出可选替代(SPX→SPY、NDX→QQQ、RUT→IWM、VIX→VIXY)——但
**软件绝不替你换**,SPX 七千多点、SPY 七百多块,静默换标的会让触发价整个失去意义。同理,
`symbol_map` 也不能当成"把指数映射成 ETF"的后门:闸门认的是配置里的 `index_symbols`,
跟映射后的代码无关。

闸门**刻意不挡期权链**:指数的期权链富途是支持的(`US..SPX` 回的是权限错误而不是
「暂不支持」),缺的只是现价那一个数,而它可以从链自身反推——见后面「期权墙在富途下
怎么活下来」。

**② 富途模拟盘不支持成交查询。** `deal_list_query` 在模拟账户上直接回「模拟交易不支持成交
查询」。照原样跑的话,纸面账户的记录会只有状态、没有 `fills[]`、没有均价——"自动记录每笔
交易"就成了半句空话。现在识别到之后不再重复请求,改从订单行的 `dealt_qty` / `dealt_avg_price`
**按增量合成**成交,并在 `exec_id` 上显式标注"(合成)":它不是逐笔明细,别拿它做滑点归因。
实盘账户仍然走真的逐笔成交。

**③ `is_paper` 必须和富途报的 `trd_env` 一致。** 富途的模拟账号和实盘账号是两个不同的
`acc_id`,而配置里的 `is_paper` 正是 `allow_live_trading` 那道闸的输入——把实盘账号标成
模拟,实盘保护就整个失效了。现在连接时读回每个账号真实的 `trd_env`,诊断面板逐行显示并
标红不一致的,下单前再核对一次,对不上直接拒。

顺带按真机修掉的小问题:订单状态词表补齐了 `UNSUBMITTED` / `CANCELLING_*` / `FILL_CANCELLED`
(漏一个就会被当成 Submitted,单子在界面上永远"在途");`security_firm` 的可选值补全到
SDK 的七家;期权权限报错不再反问"该标的是否有期权",而是直接说去哪开通;OpenD 回的 unix
时间戳转成了人能读的时间。

已验证跑通的路径:连接 / 诊断 / 账户与环境核对、股票报价、流式报价、**10 档盘口**(该账户
有 LV2)、日线与 1m/5m/1d K 线(1000 根,含盘前盘后)、2 分钟周期按设计拒绝、指数闸门、
RPC 全链路(`broker.select` → `futu.scan` → `futu.diagnose` → `broker.connect` →
`system.status` → `pending.poll`)。期权链需要单独的美股期权行情权限,当前账户没开,
未能实测。

## 期权墙在富途下怎么活下来

期权墙是这个软件的招牌功能之一,而它在富途通道上撞了两堵墙,处理方式完全不同:

**第一堵是权限,得你自己开。** 富途的**美股期权行情**是一份**独立于股票行情**的权限:
股票报价能用不代表期权能用,而且没有它**连期权链的到期日列表都取不到**(实测,不只是
报价为空)。所以引擎把这条错误单独拎出来说,而不是笼统地讲"没有行情权限"——否则你会
去核对那份已经开好的股票行情,白折腾一圈。开通后重连引擎即可。

**第二堵是指数没有现价,这个引擎自己解决。** 期权墙必须知道标的现价,才能判断墙在现价
上方还是下方;而富途拿不到美股指数的现价。但**指数的期权链本身是支持的**(实测
`US..SPX` 回的是权限错误,不是「暂不支持」)——所以缺的只是那一个数,而它就藏在链里。

用的是看跌看涨平价关系,一个恒等式:

```
C − K·D ... 严格写作   C − P = S − K·D        (D = e^(−rT),折现因子)
```

对同一到期日的**所有**行权价都成立。所以在整条行权价网格上均匀取样,把 (C−P) 对 K 做
一次最小二乘直线拟合:**截距就是现价 S,斜率的相反数就是折现因子 D**。利率和到期时间
都不用假设,它们被一起拟合出来了。

为什么不能图省事只看一个平值行权价、把 D 当成 1:SPX 在 7500 点、一个月到期、利率 4%
的情况下,`7500 × (1 − e^(−4%×1/12)) ≈ 25 点`——二十五个点的系统性偏差,墙的位置就整个
挪位了。测试里专门有一条钉住这件事。

**残差是天然的质量闸。** 平价关系是恒等式,报价干净时残差接近零(单测里精确还原到
1e-6)。残差一大就说明报价有问题——盘口太稀疏、深度虚价、或者混进了别的到期日——这时候
**宁可拒绝也不给一个看起来像模像样的错价**,因为墙的位置全靠它。折现因子拟合出来跑到
合理区间外同样直接拒绝。

反推出来的现价会一路带着 `spot_source: "parity"` 标记到界面上,显示成「现价由期权链
反推」。它和真实报价不是一回事,不标出来就是在骗自己。

> 这条路径的**数学部分有完整单测**(精确还原、拒绝脏报价、拒绝样本不足、拒绝零利率
> 近似),但**没能在真机上跑通**——联调用的账户没有美股期权行情权限,富途连期权链的
> 结构都不给。开通权限后应当先用一个普通股(现价能直接问到,`spot_source` 应为
> `quote`)对一遍,再看指数。

## 富途特有的两种额度

富途的行情按额度计,这是它和 IBKR 最不像的地方,踩上了报错信息也很含糊,所以引擎把它翻成了
人话:**订阅额度**(按资产等级,常见 100 条)——期权链、盘口这些一次性订阅用完立刻退订,
和 IBKR 那边防行情线路泄漏是同一类纪律;**历史 K 线额度**(按标的数计)——用完时的报错会
明确说是额度问题,而不是让你去怀疑代码写错了。

## 装它

```bash
(cd engine-ts && npm install)   # npm 包 futu-api 已在依赖里,只连本机的 OpenD,不直连券商服务器
```

没装也不会影响 IBKR 通道:SDK 是延迟导入的,缺了只在富途面板上报"怎么装"。

> **现状(2026-09-08)**:上面的真机结论是 Python 引擎时代用 Python SDK 验出来的;Python 引擎已退役,TS 侧的 `futuBridge.ts`
> 在真机核对前显式抛 FutuUnavailable。要重新启用富途,需要连着本机 OpenD 把 npm futu-api 的接口签名、返回列名、枚举取值
> 逐一对过,先只读,不碰下单路径。

> **一条顺带修掉的隐患**:futu-api 和它的后台线程会往标准输出打日志,而 §10.1 的纪律是
> **stdout 只跑协议**——一行非协议输出就能让 Electron 侧的 JSON 解析全线崩掉。Python 引擎当年的做法是
> 把真 stdout 私有化、把 `sys.stdout` 指到 stderr;TS 侧接入 npm futu-api 时要守同一条纪律:SDK 的日志只能落到 stderr。
