# TWS 连接:检测、诊断、引导

**本软件不接触你的 IBKR 账号密码。** IBKR 凭证是 §9.1 的 S0 级数据,只允许存在于 IBKR 自己的
程序里——登录在 TWS / IB Gateway 的窗口里完成,这里做的是它前后那几步:

| 面板分区 | 做什么 |
|---|---|
| 1 · 程序 | 检测 TWS / IB Gateway 是否安装、是否在运行;装了没开的可以一键启动(路径在引擎侧解析,界面传不了任意路径) |
| 2 · API 端口 | 探测 7496 / 7497 / 4001 / 4002 及配置里的自定义端口,标出每个端口对应哪条连接、是否已连接。纯 TCP 探测,不发协议帧,不打扰已有会话 |
| 3 · 握手与账户 | 真连一次(**只读连接**)读回服务器版本与账户列表,连完即断;同时核对**账户别名是否对得上真实账号** |
| 4 · 连接引擎 | 建立引擎真正用来下单的长连接 |
| 连不上时照着做 | 6 步指引,写死 TWS 的确切菜单路径,并按你的实际配置显示端口号 |

两个细节值得单独说:

**别名映射校验。** 配置里 `模拟 → DU7654321` 如果账号写错了,下单时 IBKR 不会报错,只会静默
落到错误账户。所以诊断会拿 `managedAccounts()` 的真实列表逐条比对,对不上就红字标出;
反过来,会话里能管到、但没写进别名表的账号也会列出来(那些账号 LLM 永远指不到,是设计使然)。

**错误翻译。** 连不上时给的是下一步该做什么,不是 traceback。最常见的一种——端口开着但握手
超时——会明确告诉你:要么「Enable ActiveX and Socket Clients」没勾,要么 TWS 正弹着
「接受传入连接」的确认框等你点 Yes。

## 连接的生命周期:自己连上、掉线要知道、自己连回来

追踪止盈止损要全天有效,而让它停摆的恰恰都是没人在场的时候。2026-09-26 排查出三处,一起修掉:

| 情形 | 以前 | 现在 |
|---|---|---|
| 电脑重启 / 应用重开 / 引擎崩了被拉起 | 连券商只能靠人点「连接」,没人点节拍器就一直不跑 | `broker.auto_connect`(默认 `true`)引擎一启动就连;连不上的每 30 秒再试(`services/brokerLink.ts`) |
| TWS 比应用晚开 | 点过一次失败就不再试 | 同上,TWS 起来 30 秒内连上;新会话挂到已有 router 上,**不重建引擎**(托管单缓存、追价进度都在内存里) |
| TWS 重启 / 与 IBKR 服务器闪断(1100 / 2110,每晚服务器重置必来) | IBApiNext 没设 `reconnectInterval`(= 永不重连),而它收到 1100 / 2110 会**主动关掉本机到 TWS 的 socket**;会话的 `connected` 又只在显式断开时变 false——持仓快照与报价冻在断开那一刻,盯盘拿一个不动的价判断,跟踪止损永远不触发,心跳却照常 | 会话按 `IB_RECONNECT_MS`(5 秒)自己重连,重连后库把持仓、行情这些常驻订阅原样重订;`isConnected()` 跟着 `connectionState` 说真话;断开时作废冻住的快照与报价;重连后补回会话级的行情类型基线 |

掉线与连回都当场提醒并留痕(`broker_link_down` / `broker_link_up`),界面顶栏跟着变。

**两条口径,都朝"宁可这一轮不判断"那一侧偏**(`ibLink.ts`):

* **全断了读持仓要报错,不回空列表。** 空列表会让盯盘判「持仓已不存在」停掉所有追踪、让托管对账撤掉券商侧的
  止损单。会话从不说自己断了的时候这个洞一直被盖着;让它说真话之前必须先堵上。
* **读不到的账户不判断。** 一个账户的会话断着、或者压根没连(模拟盘 7497 常常不开),它的持仓本来就不在列表里——
  不等于平仓了。`BrokerRouter.coveredAccounts()` 给出此刻读得到的账户,不在里面的追踪这一轮只报原因,
  不停追踪、不撤托管单、不发单;连回来的第一轮照常判断(价格在看不见的那段里穿过了止损,就在这一轮平)。

同一条口径还管着两处"空 = 读不到"的地方:

* **托管单认领。** 引擎重建那一刻某个账户的会话没连着,它在券商那边挂着的托管单认领不到。追踪保住了之后,
  等会话连上,对账会当成"没挂"**再挂一张**——两张平仓单各成交一次就是反向开仓(`link-engine.spec` 的变异检验
  实测:不重认就多挂两张)。所以托管对账记着上一轮读得到哪些账户,多出一个就重新认领一遍;认领按 orderRef 去重,
  重认是幂等的。
* **执行对账。** 断线时券商侧的未成交单一张都没读到,"券商侧没有"是假的。读不到的账户(`coveredAccountIds()`)
  的在途单这一轮不下「去向不明」的结论;自动重连回来立刻安排一次对账,不等满一分钟。

**已经连上过的连接断了,归会话层自己重连,服务层不去抢**——两边一起连会抢同一个 client id(326)。服务层只重试
本 router 上**从没连上过**的连接。首次连不上时会把那个客户端关干净,不留一个在后台每 5 秒重连、TWS 一起来
就占住 client id 的幽灵。用户点了「断开」或换了券商,就不再自动连。

自动连接只在真正的 stdio 入口(`rpc/server.ts` 的 `main()`)里启动:测试直接调 `serve()`,本机实盘 TWS 又开在 7496,
测试绝不能碰它。

**桌面端配套:** 引擎进程意外退出由主进程按 3 秒起、翻倍、封顶 60 秒的退避自动拉起(退出应用 / 手动重启不拉),
拉起来之后按 `auto_connect` 自己连回;应用开着时用 `powerSaveBlocker('prevent-app-suspension')` 挡住系统挂起。

**软件管不了的:** 电脑关机、TWS 需要重新登录(2FA)。这两种时候本机盯盘全停,要这段时间也有保护,
只能开「托管到券商」(券商服务器上的原生单)。

**还没做的:** IBApiNext 的连接看门狗(`connectionWatchdogInterval`)没开——TWS 假死而 socket 不关的情形检测不到。
1100 期间库会掐 socket、5 秒后重连,若 TWS 一连上又报 1100 会反复重连、每次重订持仓与行情;真机上看一晚
`main.log` 里 `[link]` 的密度再决定要不要给重连加退避。

## 只读联调:`npm run probe`

换了登录方式、换了用户名、TWS 升了级之后,先跑一遍这个,不用每次现写脚本:

```
cd engine-ts
npm run probe                                   # 配置里全部 IBKR 连接、全部步骤
npm run probe -- --connection live --symbols NVO,AAPL
npm run probe -- --steps entitlements           # 只看行情权限(会自动补上 connect / positions)
npm run probe -- --steps stockreview --seed-fills D:/backup/trades.db   # 股票交易复盘,见下
```

它走引擎自己的 RPC(和桌面应用同一条路),按固定顺序跑:端口 → 握手与别名核对 → 建连 → 持仓 →
盘口深度 → 历史 K 线 → 期权墙 → 宏观带 → 成交回报 → **行情权限** → 股票交易复盘 → 连接后的引擎状态,最后按已知的坑给结论。
完整返回落在系统临时目录的 `report.json`,两次联调可以直接 diff。

**敢对着实盘 TWS 跑,是因为:** 配置从真配置派生一份临时的(临时库、client id 71 起、自动执行 / 实盘 /
组合实盘三道闸强制关),RPC 只准调白名单里的只读方法;临时库是空的,盯盘循环没有追踪、托管单、条件单可动。
在 worktree 里跑会自动去主检出找真配置。

**「行情权限」为什么要单独直连问。** 引擎的行情流会自动退到延迟、被拒也只记在流上——2026-09-18 换用户名登录
同一账户时,前面十几步全部通过,可实际上这个用户名在 API 上一条实时行情都没有(NVO 10089 连延迟都没有,
ES / SPX / 期权只有延迟),持仓全无市价、夜盘 SPX 现价按延迟的 ES 推算。这一步用底层 API 逐个品种各订一次
实时与延迟,把 TWS 的原话摆出来。要记住的两件事:**行情订阅按用户名算,不按账户**;10089 说明 TWS 界面里
看得到报价也不算数,那一档只给界面用。

**「股票交易复盘」要灌历史成交。** TWS 只给当天的成交,空的临时库里看不到之前的股票交易。`--seed-fills` 给一份库的
**备份**(别直接指真库),探针只把 `broker_fills` 这一张表灌进临时库——追踪、托管单、条件单一条不带,临时库照旧没有东西
可以让盯盘循环去动。这一步先列候选(期初仓位靠当前持仓反推,所以排在「持仓」之后),再逐笔调 `review.analyze`(只读:
读成交、拉 K 线、算数),摘要里能直接看到每一笔认成了什么、carried / 期初未核对 的标记和各条结论的语气。
