# TWS 连接

本软件不接触 IBKR 的账号密码,登录在 TWS / IB Gateway 自己的窗口里完成。这里管登录前后的事:检测与诊断、连接的生命周期、只读联调。

## 面板(「接入 → TWS」)

| 分区 | 做什么 |
|---|---|
| 1 · 程序 | 检测 TWS / IB Gateway 是否安装、是否在运行;装了没开的可以一键启动(路径在引擎侧解析,界面传不了任意路径) |
| 2 · API 端口 | 探测 7496 / 7497 / 4001 / 4002 与配置里的自定义端口,标出每个端口对应哪条连接、是否已连接;纯 TCP,不发协议帧,不打扰已有会话 |
| 3 · 握手与账户 | 真连一次(只读、用独立的 client id)读回服务器版本与账户列表,连完即断;核对账户别名对不对得上真实账号 |
| 4 · 连接引擎 | 建立引擎下单用的长连接 |
| 连不上时照着做 | 6 步指引,写明 TWS 的菜单路径,按实际配置显示端口 |

- **别名核对**:配置里的账号写错时 IBKR 下单不报错,只会落到错误账户。诊断拿 `managedAccounts()` 的真实列表逐条比对,对不上标红;
  会话里管得到、但没写进别名表的账号也列出来(模型指不到它们)。
- **错误说人话**:给下一步该做什么。最常见的"端口开着但握手超时"会写明:要么「Enable ActiveX and Socket Clients」没勾,要么 TWS 正弹着接受连接的确认框。
- 同一个 IBKR 用户名在别处登录时,行情跟着那边走,本机拿不到 K 线;先在别处登出。

## 连接的生命周期

持仓追踪要全天有效,让它停摆的恰恰都是没人在场的时候。

| 情形 | 处理 |
|---|---|
| 电脑重启、应用重开、引擎崩溃被拉起 | `broker.auto_connect`(默认开)让引擎一启动就连;连不上的每 30 秒再试(`services/brokerLink.ts`) |
| TWS 比应用晚开 | 同上,TWS 起来 30 秒内连上;新会话挂到已有 router 上,不重建引擎(托管单缓存、追价进度在内存里) |
| TWS 重启、与 IBKR 服务器闪断(1100 / 2110,每晚服务器重置必来) | 会话每 `IB_RECONNECT_MS`(5 秒)自己重连,重连后底层库把持仓、行情等常驻订阅原样重订;`isConnected()` 跟着 `connectionState` 如实报告;断开时作废冻住的持仓快照与报价;重连后补回会话级的行情类型 |

- 掉线与连回当场提醒并留痕(`broker_link_down` / `broker_link_up`),顶栏跟着变。
- **反复断开只提醒一次**:连上后撑不过 10 秒又断算一次抖动,一分钟内抖动两次判定为反复断开,提醒一次并写明常见原因
  (TWS 自动重启后在等重新登录、TWS 弹出了 API 连接确认框、同一个 client id 被别的程序占用),之后通知与审计收声(审计留一条 `broker_link_flapping`),
  日志每分钟一行汇总;稳定连上 10 秒后再说一声"已重新连上"。
- 已经连上过的连接断了,由会话层自己重连,服务层不抢:两边同时连会撞上 326(client id 已被占用)。服务层只重试本 router 上从没连上过的连接,
  重试成功留一条 `broker_link_retry`;首次连不上时把那个客户端关干净,不留一个在后台重连、占住 client id 的客户端。连接尝试串行执行,
  启动时的自动连接与用户点击不会同时开两个会话。
- 用户点了「断开」或换了券商,就不再自动连。自动连接只在真正的 stdio 入口(`rpc/server.ts` 的 `main()`)里启动,测试碰不到本机的 TWS。
- **桌面端**:引擎意外退出由主进程按 3 秒起、翻倍、最长 60 秒的退避自动拉起,拉起来之后按 `auto_connect` 连回;应用开着时用
  `powerSaveBlocker('prevent-app-suspension')` 挡住系统睡眠。

**读不到 ≠ 没有**(`ibLink.ts`),规则偏向"这一轮不判断":

- 全部断开时读持仓报错,不回空列表:空列表会让盯盘判定持仓已不存在、停掉追踪,让托管对账撤掉券商侧的止损单。
- 读不到的账户不判断:一个账户的会话断着或没连(模拟盘 7497 常常不开),它的持仓本来就不在列表里。`BrokerRouter.coveredAccounts()` 给出此刻读得到的账户,
  不在里面的追踪这一轮只报原因,不停追踪、不撤托管单、不发单;连回来的第一轮照常判断。
- 托管单认领:托管对账记着上一轮读得到哪些账户,多出一个就按 orderRef 重新认领一遍(幂等),避免会话连上后把"没认领到"当成"没挂"再挂一张。
- 执行对账:读不到的账户(`coveredAccountIds()`)的在途单这一轮不下「去向不明」的结论;自动重连回来立刻安排一次对账。

**软件管不了的**:电脑关机、TWS 需要重新登录(双重认证)。这时本机盯盘全停,要有保护只能开「托管到券商」。
IBApiNext 的连接看门狗没开,TWS 假死而 socket 不断的情形检测不到。

## 只读联调:`npm run probe`

换了登录方式、换了用户名、TWS 升级之后先运行它(`engine-ts/scripts/tws-probe.mjs`):

```
cd engine-ts
npm run probe                                   # 配置里全部 IBKR 连接、全部步骤
npm run probe -- --connection live --symbols NVO,AAPL
npm run probe -- --steps entitlements           # 只看行情权限(自动补上前置步骤)
npm run probe -- --steps stockreview --seed-fills D:/backup/trades.db
```

步骤按固定顺序:端口 → 握手与别名核对 → 建连 → 持仓 → 盘口深度 → 历史 K 线 → 期权墙 → 宏观行情带 → 成交回报 → 行情权限 → 股票交易复盘 →
蝴蝶交易复盘(含止盈策略回放)→ IBKR 模型 IV 换算核对 → 连接后的引擎状态,最后按已知的坑给结论。完整返回写在系统临时目录的 `report.json`,
两次联调可以直接比较。另有 `--review-id`、`--iv-legs`、`--index`、`--client-id`、`--timeout`、`--config` 等选项。

- **能对着实盘 TWS 运行的原因**:配置从真配置派生一份临时的(临时库、client id 从 71 起、自动执行 / 实盘 / 组合实盘三道闸门强制关、`auto_connect` 关),
  RPC 只准调白名单里的只读方法;临时库是空的,盯盘循环没有追踪、托管单、条件单可动。在 worktree 里运行会自动去主检出找真配置。
- **行情权限单独直连问**:引擎的行情流会自动退到延迟、被拒也只记在流上。这一步用底层 API 逐个品种各订一次实时与延迟,把 TWS 的原话摆出来。
  行情订阅按用户名计算,不按账户;10089 说明 TWS 界面里看得到报价也不算数,那一档只给界面用。
- **股票交易复盘要灌历史成交**:TWS 只给当天的成交,`--seed-fills` 给一份库的**备份**(不要直接指真库),探针只把 `broker_fills` 一张表灌进临时库。
  这一步先列候选,再对前 8 笔调 `review.analyze`(只读),摘要里看得到每一笔认成了什么、期初持仓的标记与各条结论。
