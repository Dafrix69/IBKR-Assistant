# TWS 连接:检测、诊断、引导

**本软件不接触你的 IBKR 账号密码。** IBKR 凭证是 §9.1 的 S0 级数据,只允许存在于 IBKR 自己的
程序里——登录在 TWS / IB Gateway 的窗口里完成,这里做的是它前后那几步:

| 面板分区 | 做什么 |
|---|---|
| 1 · 程序 | 检测 TWS / IB Gateway 是否安装、是否在运行;装了没开的可以一键启动(路径在引擎侧解析,界面传不了任意路径) |
| 2 · API 端口 | 探测 7496 / 7497 / 4001 / 4002 及配置里的自定义端口,标出每个端口对应哪条连接、是否已连接。纯 TCP 探测,不发协议帧,不打扰已有会话 |
| 3 · 握手与账户 | 真连一次(**只读连接**)读回服务器版本与账户列表,连完即断;同时核对**账户别名是否对得上真实账号** |
| 4 · 连接引擎 | 建立引擎真正用来下单的长连接 |
| 连不上时照着做 | 6 步指引,写死 TWS 的确切菜单路径,并按你的实际配置显示端口号 |

两个细节值得单独说:

**别名映射校验。** 配置里 `模拟 → DU7654321` 如果账号写错了,下单时 IBKR 不会报错,只会静默
落到错误账户。所以诊断会拿 `managedAccounts()` 的真实列表逐条比对,对不上就红字标出;
反过来,会话里能管到、但没写进别名表的账号也会列出来(那些账号 LLM 永远指不到,是设计使然)。

**错误翻译。** 连不上时给的是下一步该做什么,不是 traceback。最常见的一种——端口开着但握手
超时——会明确告诉你:要么「Enable ActiveX and Socket Clients」没勾,要么 TWS 正弹着
「接受传入连接」的确认框等你点 Yes。

## 只读联调:`npm run probe`

换了登录方式、换了用户名、TWS 升了级之后,先跑一遍这个,不用每次现写脚本:

```
cd engine-ts
npm run probe                                   # 配置里全部 IBKR 连接、全部步骤
npm run probe -- --connection live --symbols NVO,AAPL
npm run probe -- --steps entitlements           # 只看行情权限(会自动补上 connect / positions)
npm run probe -- --steps stockreview --seed-fills D:/backup/trades.db   # 股票交易复盘,见下
```

它走引擎自己的 RPC(和桌面应用同一条路),按固定顺序跑:端口 → 握手与别名核对 → 建连 → 持仓 →
盘口深度 → 历史 K 线 → 期权墙 → 宏观带 → 成交回报 → **行情权限** → 股票交易复盘 → 连接后的引擎状态,最后按已知的坑给结论。
完整返回落在系统临时目录的 `report.json`,两次联调可以直接 diff。

**敢对着实盘 TWS 跑,是因为:** 配置从真配置派生一份临时的(临时库、client id 71 起、自动执行 / 实盘 /
组合实盘三道闸强制关),RPC 只准调白名单里的只读方法;临时库是空的,盯盘循环没有追踪、托管单、条件单可动。
在 worktree 里跑会自动去主检出找真配置。

**「行情权限」为什么要单独直连问。** 引擎的行情流会自动退到延迟、被拒也只记在流上——2026-09-18 换用户名登录
同一账户时,前面十几步全部通过,可实际上这个用户名在 API 上一条实时行情都没有(NVO 10089 连延迟都没有,
ES / SPX / 期权只有延迟),持仓全无市价、夜盘 SPX 现价按延迟的 ES 推算。这一步用底层 API 逐个品种各订一次
实时与延迟,把 TWS 的原话摆出来。要记住的两件事:**行情订阅按用户名算,不按账户**;10089 说明 TWS 界面里
看得到报价也不算数,那一档只给界面用。

**「股票交易复盘」要灌历史成交。** TWS 只给当天的成交,空的临时库里看不到之前的股票交易。`--seed-fills` 给一份库的
**备份**(别直接指真库),探针只把 `broker_fills` 这一张表灌进临时库——追踪、托管单、条件单一条不带,临时库照旧没有东西
可以让盯盘循环去动。这一步先列候选(期初仓位靠当前持仓反推,所以排在「持仓」之后),再逐笔调 `review.analyze`(只读:
读成交、拉 K 线、算数),摘要里能直接看到每一笔认成了什么、carried / 期初未核对 的标记和各条结论的语气。
