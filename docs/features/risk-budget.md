# 单笔风险预算

限额(`limits.max_order_notional`)是一个固定金额,账户大小变了它不跟着变;实盘比赛的优胜者说的都是比例,单笔风险压在账户的 0.5%–2%。
单笔风险预算把一单的敞口对账户权益算个比例,超线就在订单的警告里多一句。它是校验的第 10 步(`riskBudget.riskBudgetWarning`,见 [交易指令](instruction.md)),
**只提醒,不拦单**。配置在 `settings.json` 的 `risk_budget` 段,界面在「设置 → 单笔风险预算」,**默认关**。

## 规则

| 品种 | 拿什么比 | 默认线 |
|---|---|---|
| 期权、组合 | 校验层算好的最坏亏损:买方 = 权利金;贷方组合 = 宽度 − 收的权利金;AUTO_MID 的组合 = 结构宽度;卖 Put = 行权价 × 乘数(现金担保) | `max_risk_pct` 2% |
| 股票 | 名义金额(最坏亏多少取决于止损,下单时不知道;警告里提醒去持仓追踪设止损) | `max_position_pct` 25% |

- 敞口就是 `validator.checkLimits` 的 `notional`,和限额同一个数;市价单拿不到参考价时敞口是 0,不提醒。
- **权益是人填的**:按账户别名一个数(`equity_usd`),没填或填 0 的账户不提醒。引擎不向券商要 NetLiquidation(那条路没在真机上核对过)。
- 扇出到多个账户时各比各的权益,小账户那一单可能超、大账户那一单不超。
- 平仓单不受影响:持仓追踪发的平仓单不走校验层。
- 挡单的是限额与保护规则;这里只把比例摆到眼前,否则就成了第二套以随手填的权益为阈值的限额。

## 配置

```json
"risk_budget": { "enabled": false, "equity_usd": { "主账户": 50000 }, "max_risk_pct": 2.0, "max_position_pct": 25.0 }
```

`max_risk_pct` 取 0.1–100,`max_position_pct` 取 0.1–1000。写错时和别的段一样当场报中文原因、不写盘(「risk_budget 里有未知配置项」
「risk_budget.equity_usd.主账户 不能小于 0.0」);`equity_usd` 里写了不认识的别名不报错(账户可能刚改名,只是用不上)。`settings.patch` 认这一段。

## 测试

`risk-budget.spec.ts`:期权看最坏亏损、股票看名义金额、正好在线上不提醒;没开、没填权益、敞口为 0 不提醒;配置默认关、写错即报;
接进校验层后照常通过、只多一句警告,关着时警告一字不变。
