# 单笔风险预算:按账户权益的比例提醒

限额(`limits.max_order_notional`)是一个固定金额:账户翻倍它不跟着变,账户缩水它也不收紧。实盘比赛的优胜者说的都是**比例**——
单笔风险压在账户的 0.5%–2%([绩效体检](performance.md)的凯利那条也这么写)。以前这个比例只活在界面的仓位计算器里
(`lib/sizing.ts`,只算不下单),下单那一刻没人再看一眼。

现在校验层第 10 步(`riskBudget.riskBudgetWarning`)把这一单的敞口对账户权益算个比例,超了就在订单的警告里多一句。
配置在 `settings.json` 的 `risk_budget` 段,界面在「设置 → 单笔风险预算」,**默认关**。

## 口径

| 品种 | 拿什么比 | 默认线 |
|---|---|---|
| 期权、组合 | 校验层已经算好的**最坏亏损**:买方 = 权利金,贷方组合 = 翼宽 − 收的权利金,卖 Put = 行权价 × 乘数(现金担保口径) | `max_risk_pct` 2% |
| 股票 | **名义金额**:最坏亏多少取决于止损,下单时不知道;警告里提醒去持仓追踪设止损 | `max_position_pct` 25% |

敞口就是 `validator.checkLimits` 的 `notional`,和限额同一个数,不另算。市价单拿不到参考价时敞口是 0,不提醒。

## 三条边界

**只提醒,不拦单。** 挡单的是限额与保护规则;这里是把比例摆到眼前。它拦了单,就等于第二套限额,而那套限额的阈值是人随手填的一个权益数。

**权益是人填的。** 按账户别名一个数(`equity_usd`),没填、填 0 的账户不提醒。引擎不向券商要 NetLiquidation:那条路
(`reqAccountSummary`)没在真机上核对过,而且要进 `broker.ts`——它钉在体积预算的名单上。账户权益一周改一次数就够准。

**平仓单不受影响。** 持仓追踪发的平仓单不走校验层,本来就不会被提醒;减少风险的单不该被一句"占比太大"吓住。

扇出到多个账户时每个账户各比各的权益:同一句指令发到两个账户,小账户那一单可能超、大账户那单不超。

## 配置

```json
"risk_budget": { "enabled": false, "equity_usd": { "主账户": 50000 }, "max_risk_pct": 2.0, "max_position_pct": 25.0 }
```

写错了照别的段一样当场报中文原因、不写盘(`risk_budget 里有未知配置项`、`risk_budget.equity_usd.主账户 不能小于 0.0`)。
`equity_usd` 里写了不认识的别名不报错——账户可能刚改名,只是用不上。`settings.patch` 从这一版起认四段(多了 `risk_budget`)。

## 钉住它的测试

[`engine-ts/tests/risk-budget.spec.ts`](../../engine-ts/tests/risk-budget.spec.ts):期权看最坏亏损、股票看名义金额,正好在线上不说;
没开 / 没填权益 / 敞口为 0 不说;配置默认关、写错即报;接进校验层后照常通过、只多一句警告,关着时警告一字不变。
golden-rpc 的 `settings.get` / `settings.patch` 回执多了这一段的默认值(纯增)。
