# 交易纪律守护

把两件事从人手上拿走:**开仓前必须先写下止损**,**股票仓位必须有止损单**。它不出策略、不出信号,只管纪律。
配置在 `settings.json` 的 `guard` 段,**默认关**。打开之后它会替没有止损的股票仓位在券商挂止损单,所以第一次打开之前先在纸面账户上看它跑一遍。

分四步做,现在有前两步:交易意图、程序发单的开仓门槛、手动开仓没补录意图时的默认止损(第一步);
按意图挂止损并守住它、期权组合按意图盯出场(第二步)。心跳与断线推送(第三步)、每日报告(第四步)还没有。

guard 自己不发单:股票止损与组合出场都经持仓追踪(`tracker.add` / `tracker.update`)落成追踪,下单、改单、对账、断线后认领都是持仓追踪的事。
guard 只管"该有什么追踪、止损不许比哪条线松"。

## 交易意图

一份意图写明这笔交易的计划。股票:

| 字段 | 必填 | 含义 |
|---|---|---|
| `symbol` / `side` / `qty` | 是 | 代码、`BUY` 或 `SELL`、股数(正整数) |
| `entry_price` | 是 | 计划入场价;打算市价进就写当时的价 |
| `stop_price` / `stop_reason` | 是 | 止损价与一句话理由。买入的止损要低于入场价,卖空的要高于 |
| `thesis` / `invalidation` | 否 | 这笔对应什么判断、什么情况下判断作废;没写只提醒一句 |
| `account` | 否 | 账户别名;不写用默认账户 |

验的时候算两个数写进意图:`max_loss_usd = |入场 − 止损| × 股数`,`max_loss_pct_nav = max_loss_usd ÷ 净值`。

- 止损距离超过入场价的 `wide_stop_pct`(默认 8%):股数先减半(向下取整)再比;减半后为 0 就拒。
- 最坏亏损超过净值的 `max_loss_pct_nav`(默认 2%):拒,并给出这个止损下最多能买多少股。不替人减量,减多少由人重写。
- 净值先认 `risk_budget.equity_usd` 里人填的那个数,没填用券商报的 NetLiquidation;两样都没有就拒,不拿 0 去比。

期权组合(蝶、价差)不拦开仓,出场按意图盯:

| 字段 | 必填 | 含义 |
|---|---|---|
| `symbol` / `expiry` | 是 | 标的、到期日 YYYY-MM-DD |
| `structure` | 是 | 一句话写结构;从里面认行权价(`660/670/680`)与看涨看跌(call / put / C / P / 看涨 / 看跌)。认不出就另给 `strikes` 与 `right` |
| `cost_usd` | 是 | 借方成本(美元,整笔)。负数 = 贷方组合,**暂不支持**,拒 |
| `exit_rules.take_profit` / `stop_loss` | 是 | 倍数。写数(`take_profit_x: 2.5`)或一句话(「中间价 >= 成本 × 2.5」,取 × / x / * 后面那个数)。止损倍数 < 1,止盈倍数 > 1 |
| `exit_rules.time_stop` | 是 | 到期日几点平,美东 `HH:MM`(`time_stop_et: "15:00"` 或「到期日 15:00 ET」) |
| `exit_rules.level_stop` | 否 | 标的止损线:`level_stop_below` / `level_stop_above`,或「标的 < 647」 |

认出来的数存进意图的 `exits`,原文留在 `exit_rules`。规则认不出就拒,不猜。

**没有界面,意图写进文件。** 收件文件是交易库同目录下的 `guard/intents.jsonl`(`guard.inbox_path` 可改),一行一份 JSON。
引擎每一轮(`tick_s`,默认 2 秒)先把整个文件改名接走——改名是原子的,人这时再写会写进一个新文件——再一行行验;
每一行连同结果(收下的 id、算出来的数、拒的原因)追加到同目录的 `intents.log.jsonl`,收下的进交易库的 `guard_intents` 表。
上次处理到一半留下的 `.processing-*` 文件下一轮接着处理。空行与 `#` 开头的行跳过。

**关掉意图是放开止损的唯一出口。** 一行 `{"close": "BE", "reason": "..."}` 关掉这个账户这只标的所有在用的意图,不写理由就拒。
意图没有删除,只有 `open` 与 `closed` 两种状态,关掉的理由留在库里。
股票意图对应的仓位出现过、之后持仓里没了,自动关掉,理由「持仓已平」;读不到持仓的那一轮不算没了,那个账户的会话没连着时(`coveredAccounts` 里没有它)也不算。

`guard_intents` 表在第一次用到时才建:`guard` 关着的交易库一个字节都不变。

## 程序发单的开仓门槛

交易指令(含 Discord 跟单)真要发出去的**股票开仓单**,发之前查这个账户这只股票有没有在用的意图:
没有、方向不对、股数超过意图的,拒,代码 `GUARD_NO_INTENT`,记录终态 `rejected_by_guard`(界面显示「纪律拦下」)。

- 只在发单那一步问。「只解析」的单不问,照旧停在「仅校验未发送」——拦在那之前会让解析结果的样子跟着开关变。
- 每条腿都在减已有持仓的单不问(和保护规则同一个 `reducesPositions`)。读不到持仓就认不准,当开仓问。
- 持仓追踪、托管单发的平仓单不过这道门。期权与组合不过这道门。

实际上几乎所有股票都是在 TWS 里手动下的,这道门拦到的很少;真正起作用的是下面的盯仓位。

## 手动开仓的默认止损

后台每一轮读一次持仓,看每个 IBKR 账户里的每只股票仓位(多空都看):

1. 有在用、方向对得上的意图:按意图挂止损,见下一节。
2. 已经有一条启用的持仓追踪,打开了自动平仓,并且有止损价或跟踪止损:不管。
3. 其余的第一次看见:记一笔违规,发通知「`grace_s` 秒内补录意图,否则挂默认止损」。
4. 过了 `grace_s`(默认 60 秒)还没补录:算默认止损价,经 `tracker.add` 建一条**托管到券商**的追踪——券商那边是一张 GTC 的 STP 单,
   软件关掉也在。再记一笔违规(`default_stop`)与 `guard_default_stop`。同一份仓位只挂一次。

**默认止损价。** 多头:`入场价 × (1 − default_stop_pct)` 与前 `default_low_days` 个交易日的最低价,**取较高的那条**(离现价更近、更紧);
空头对称:`入场价 × (1 + default_stop_pct)` 与前几日最高价取较低的。入场价用持仓的平均成本。前几日不含今天,日线拿不到就只用比例。
按分取整,朝离现价远的方向取(多头向下、空头向上)。这是兜底,不是推荐。

任务书原文写的是「min(入场价 × 0.92, 前 10 日最低价) 取较高者」,min 与「取较高者」互相矛盾;这里按「取较高者」做,也就是 max。

**挂不上的时候不平仓。** 价格已经跌过默认止损价(多头止损必须低于现价,`tracker.add` 会拒),不替人平仓,
每五分钟提醒一次「这只股票现在没有止损,请立即处理」,记 `guard_default_stop_failed`。
已经有一条追踪但没管止损的,不改别人的追踪,同样每五分钟提醒一次。

## 按意图挂止损(股票)

有在用、方向对得上的意图的股票仓位,每一轮:

- **底线** = 意图的止损价;打开 `trail_r` 时按 R 往有利方向抬,R = |平均成本 − 意图止损价|:盈利过 1R 抬到成本价,过 2R 抬到成本 + 1R(空头对称)。
  抬过的底线存进意图(`stop_now`),**只升不降**:价格回落不往回放。抬一次记 `guard_trail` 并通知。
- **没有这只股票的追踪**:经 `tracker.add` 建一条托管到券商的追踪,`stop_loss` = 底线(券商侧 GTC STP)。记 `guard_stop_placed`。
  从成交到券商侧挂上:guard 一轮(2 秒)+ 持仓追踪的托管对账一轮(1 秒)+ 一次券商往返。
- **已有追踪**:启用、打开了自动平仓与托管、止损不比底线松——不动(比底线紧的也不动,人可以把止损收紧)。否则经 `tracker.update` 恢复:
  启用、自动平仓与托管打开、止损 = 底线;其余目标(止盈、标的止损线……)原样带回去,因为 `tracker.update` 给了目标就整套替换。
  只因为底线刚抬上去而恢复的,记 `guard_stop_raised`,不算违规;其余记违规 `stop_lowered` 并通知。
  也就是说,**在持仓追踪页把这只股票的止损改松、停掉、关托管,下一轮就被改回去**。要真的放开止损,只能写理由关掉意图。
- **券商侧的止损单被撤**(在 TWS 里撤的、券商撤的、置为失效的):持仓追踪的托管对账退避 60 秒后重挂(约 61 秒),
  并经 `HostedOrders::onExternalCancel` 回调给 guard,记违规 `stop_cancelled` 并通知。正股的 sl / trail / ptrail 都算;止盈单、组合的单不算。
- 挂不上(止损价已经在现价那一侧、托管与分批止盈冲突……):不平仓,每五分钟提醒一次,记 `guard_stop_failed`。
- 仓位平掉:持仓追踪的托管对账发现持仓不在了,撤掉托管单(「持仓已不存在」);账户读不到时不撤。guard 这边把意图关掉(「持仓已平」)。

## 期权组合按意图盯出场

在持仓的组合行(`domain::withCombos` 的 BAG 行)里认那一只:同账户、同标的、同到期日、行权价集合相同(给了方向也要相同)。认出来:

- 单位成本 = `cost_usd ÷ 组合数量 ÷ 乘数`(1 只 QQQ 蝶 157 美元 → 1.57)。止盈价 = 单位成本 × 止盈倍数,止损价 = 单位成本 × 止损倍数,按分四舍五入。
- 没有追踪:经 `tracker.add` 建一条**引擎盯的**追踪(不托管:IBKR 对三腿蝶不接 STP,组合在券商侧只能挂止盈单),
  止盈、止损、标的止损线(`spot_stop_below` / `spot_stop_above`),到价自动平仓、限价单。记 `guard_combo_tracked`。
- **几点平只在到期日当天写上去。** 持仓追踪的 `exit_at` 按"下一次到这个钟点"算,提前写就会在到期前任何一天的这个钟点平掉。
  到期日(美东)那一轮用 `tracker.update` 补上,目标原样带回去。记 `guard_time_stop_set`。
- 追踪被停掉、关了自动平仓、止损被改松(低于意图的止损价):恢复,记违规 `stop_lowered`。
- 出现过、后来持仓里没了:意图关掉(「持仓已平」)。账户读不到时不判。

**和任务书不一样的三处:**

- 平仓走持仓追踪的追价:限价从中间价起,最多让到立刻成交价的 `chase_max_pct`(默认 10%)。**任务书要的「30 秒没成交改市价」没有做**:
  持仓追踪对组合一律不发市价单(组合的市价单滑点没有上限)。
- 标的止损线按持仓追踪的标的止损价判:触线(可设确认秒数)就平,不是任务书写的"标的收盘价"。
- 引擎每秒盯一次,不是任务书的 15 秒;程序掉线就不盯,这一块只能靠第三步的心跳。

**认不出的组合不管。** 同一到期日的几只组合在持仓里会按行权价顺序切形状:两只交错的蝶(660/670/680 与 664/674/684)
被并成一个 6 腿自定义组合,两只都认不出。这种意图第一次看见时记违规 `combo_unmatched`、通知一次,之后不再说,也不建追踪;
没在持仓里出现过的意图不会被当成"已平"关掉。

**盘前盘后。** 托管的 STP 打了 `outsideRth`,但 IBKR 员工的答复是普通 STP 在常规时段以外不触发,盘外要用 STP LMT;
IBKR 夜盘只有限价单。所以默认止损从 9:30 开盘起才保护,盘后跳空要到开盘按开盘价附近成交。这是接受滑点换确定性的代价。

## 流水

`audit_log` 里 `actor = 'guard'` 的行就是 guard 的流水,每日报告(第四步)从这里读:

| action | 什么时候 |
|---|---|
| `guard_intent_add` / `guard_intent_close` | 意图收下 / 关掉(人写的或「持仓已平」) |
| `guard_reject` | 意图没收下,或开仓单被门槛拒(`what` 分 `intent` / `order`) |
| `guard_violation` | 违规:`no_intent`(看见没意图的仓位)、`default_stop`(挂了默认止损)、`track_without_stop`、`stop_lowered`(止损被改松 / 停掉,已恢复)、`stop_cancelled`(券商侧止损单被撤)、`combo_unmatched` |
| `guard_default_stop` / `guard_default_stop_failed` | 默认止损挂上 / 挂不上 |
| `guard_stop_placed` / `guard_stop_raised` / `guard_trail` / `guard_stop_failed` | 按意图挂上止损 / 底线抬上去后改了追踪 / 底线抬了 / 挂不上 |
| `guard_combo_tracked` / `guard_time_stop_set` | 组合出场追踪建好 / 到期日补上几点平 |

默认止损走 `tracker.add`,那一条照旧会写 `actor = 'ui'`、`action = 'tracker_add'`,绩效体检会把它当成这笔建仓时计划的止损。

## 配置

```json
"guard": { "enabled": false, "grace_s": 60, "max_loss_pct_nav": 2.0, "wide_stop_pct": 8.0,
           "default_stop_pct": 8.0, "default_low_days": 10, "tick_s": 2, "trail_r": false, "inbox_path": "" }
```

写错时和别的段一样当场报中文原因:不认识的键、超出范围、`default_low_days` 不是整数、`tick_s` 大于 `grace_s`。
只能手改 `settings.json`,`settings.patch` 不认这一段。关着时后台每一轮什么都不做(不读文件、不读持仓),门槛也不问。

`outsideRth` 不另设开关:持仓追踪挂正股托管单一律打上,而按 IBKR 员工的答复它对普通 STP 不起作用。
任务书要的"重连后最高优先级对账补挂"没有另写:已挂的止损单断线、关 TWS、每日登出都留在 IBKR 服务器上(见 `guard/README.md` 第 3 节),
持仓追踪重连后按 orderRef 重新认领;guard 每一轮都按意图对一遍追踪。用户自己在 TWS 里挂的止损单 API 撤不动,guard 不碰。

全部只有离线测试(`tst_guard`:规则、收件、盯仓位与默认止损、按意图挂止损、改松后恢复并保住其余目标、跟踪止损只升不降、
被撤记违规、组合认出来建出场追踪与到期日补上几点平、交错的蝶认不出只说一次、发单那一步的门槛;用假券商、假的 tracker.add / update 与临时交易库)。
持仓追踪那一侧的 `onExternalCancel` 回调只有 guard 一侧的测试,没有在托管对账的测试世界里打过。
没有在纸面账户或真实 TWS 上跑过。按意图挂止损与默认止损都依赖持仓追踪的正股 STP 托管,那条路径本身也没有真机核对记录;

在 TWS 里撤掉它,看约 61 秒后重新出现、流水里有 `stop_cancelled`;开一只纸面蝶、把止损倍数设得贴近,看它被平掉。
