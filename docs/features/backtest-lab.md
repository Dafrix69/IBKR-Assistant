# 回测的成交成本与参数扫描:别让回测骗自己

单次回测(`backtest.run`)回答的是"这组参数在这段行情上是什么样"。它有两个会让人高估策略的地方:
**不扣成本**(日线全仓进出,换手一多,几个基点的滑点就能把收益吃掉一截),以及**参数是看着结果挑的**——
在同一段行情上试十组参数、挑最好看的那组,那组的成绩里有多少是运气,单次回测说不出来。

这一份补两件事:每边成交成本,和 `backtest.sweep`(参数网格 × 样本内 / 样本外 × 滚动前推 × 多只标的)。
全是纯计算(`backtest.ts`、`backtestLab.ts`),不经过模型、不接下单链路。界面在「研究 → 回测」表单下面。

## 成交成本

`cost_pct` 是**每一边**(买进一次、卖出一次)的成本占成交额的百分比,佣金 + 滑点一起算,0~10。

| 品种 | 怎么扣 |
|---|---|
| 正股 | 收盘成交:这根日线的持仓和上一根不一样就乘一次 (1 − cost);第 0 根就持有也算一次买进。单笔收益 = 毛收益 × (1 − cost)²,还开着的那笔只扣进场一次 |
| 期权 | 开仓按权利金多付 cost、平仓少收 cost;持有中的净值也按"现在平掉能拿到多少"算 |

**默认 0 = 老口径,一位不差**:golden-backtest 的净值曲线容差 1e-9,refactor 前后都过;回执里没有 `cost_pct` 这个键。
给了、且大于 0,回执才多一个 `cost_pct`,结果卡写明"已扣每边成交成本"。

**填多少**:[绩效体检](performance.md)的「执行损耗」中位数——自动平仓触发时的现价对实际成交均价——就是这个数的实测值。
那是"软件替你平"那一段的口径;手动下的限价单一般更少。

## 参数扫描:`backtest.sweep`

| 入参 | 口径 |
|---|---|
| `symbols` | 1~8 只。多只时只用**大家都有的交易日**(对齐成同一套日期),每组参数的得分取各只的平均 |
| `strategy` + `grid` | 预置策略(均线交叉、RSI、N 日突破)的参数名 → 要试的取值;每个参数最多 20 个值,组合 ≤ 200,组合 × 标的 ≤ 800 |
| `split_pct` | 样本内占比,50~90,默认 70 |
| `folds` | 滚动前推的折数,2~6;0 = 不做 |
| `objective` | `return`(总收益)或 `calmar`(年化 ÷ \|最大回撤\|;没有回撤时退回年化,不拿无穷大比) |
| `instrument` / `cost_pct` | 同 `backtest.run` |

**信号在整段上算一次,再按日期切。** 指标全是因果的(只看当根及以前),所以这样切和"只在那一段上算"相比只多了指标的预热,
不多看未来;否则样本外的前 50 根会因为慢线没预热好而全是空仓。样本外那一段从样本内最后一根起结算:那一根的持仓决定样本外第一天算不算涨跌
(已持有就按那一刻买进付一次成本)。

输出里要看的三样:

- **样本内第一名在样本外排第几**(`best.oos_rank`):排在后面,说明样本内的第一靠的是那段行情。
- **样本内外排名的秩相关**(`rank_corr`,Spearman):全部组合按样本内、样本外各排一次,相关低于 0.3 时 notes 直说"挑参数基本等于挑运气"。
- **滚动前推的连乘收益**(`walk_forward.total_return_pct`):把区间按根数等分成 折数 + 1 段,第 j 折用前 j 段挑参数、跑第 j+1 段,
  各折测试段的收益连乘。**这是整张表里唯一一个每一步都只用了当时已有的数据的数**,和同期买入持有并排摆着。
  训练段或测试段不到 20 根的那一折跳过。

不合法的组合(快线 ≥ 慢线、RSI 买入线 ≥ 卖出线)跳过并写明原因,不算在排名里。

## 刻意不做的

| 不做 | 为什么 |
|---|---|
| 夏普 | 结算函数只交出抽样后的净值曲线(最多 300 点),拿它算日收益的标准差不准;Calmar 用的是年化与最大回撤,都是全量算的 |
| 自定义条件、买入持有的扫描 | 前者没有数值参数可扫(条件里的周期是搭出来的),后者没有参数 |
| 自动把最优参数填回表单 | 挑参数这件事正是要人看了样本外再决定 |
| 按历史成分股回测股票池 | 券商日线只有现在还在交易的代码。多只一起扫时 notes 写明幸存者偏差,结果偏乐观 |
