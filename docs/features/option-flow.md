# 期权主动成交记盘

把 SPX 近平值期权上每一次成交量增量连同前后两口盘口原样记下来，离线按报价规则分成买方主动、卖方主动、分不出三类，再拿次日持仓量对照。
这一版只记不画：不上 GEX 热图，不进任何提醒和下单。要先证明分类可信，才能拿它去判断仓位往哪边动。

代码：`engine/analysis/option_flow`（分类、组合单配对、加总、次日持仓量对照，纯计算）、`engine/domain/option_flow_log`（底账）、
`engine/orchestrate/services/flow_recorder`（记盘循环）、`tools/option_flow_report.cpp`（离线报告）。测试：`tests/tst_option_flow.cpp`。

## 订哪些合约

- SPX 的**下一个交易日**到期（`daily_trading_class`，即 SPXW），不订当日到期。当日到期的合约第二天就没了，拿不到次日持仓量。
  将来上热图用的是当日到期，那时再加；分类口径一样。
- 锚：当天订上时 SPX 现价取整到 5 点；锚 ± 25 点，11 档 × 看涨看跌 = 22 条行情线路。
- 现价离锚 20 点以上时（每分钟看一次），在新的平值 ± 10 点补档，离现价近的先补。总数最多 30 条。
- 每条流带 generic tick `101`（持仓量），跟盯盘流（不带 generic）、期权链（`100,101,106`）、蝴蝶测算（`106`）各是各的，撤的时候也只撤自己这一条。
  这 22–30 条线路和期权墙抢同一份行情线路额度：线路少的账户，期权墙抽档会更多。
- 只在常规时段（`marketStatus == 盘中`）记；关闭、断线、换会话、换日都撤掉全部订阅，撤之前把每条合约当时的累计成交量记一笔。
- 偏好键 `options.flow_recorder`，默认开。

## 记什么

底账在交易库旁边的 `option-flow/`，一天一个 `年-月-日.jsonl`，只追加，留最近 120 个文件。只有公开行情，没有账户和持仓。四种行：

| kind | 字段 | 什么时候写 |
|---|---|---|
| `sub` | `expiry`、`trading_class`、`anchor`、`spot`、`rule`、`contracts` | 每订上一批合约 |
| `print` | `expiry k r`、`dv`（成交量增量）、`last`、`lt`/`plt`（这次与上次的 LAST_TIMESTAMP）、`pb pa`（成交前的买卖价）、`b a`（成交后的）、`bs as`、`mdt` | 累计成交量变大的那一次推送 |
| `vol` | `expiry k r`、`volume`（当天累计） | 第一次读到时作底、之后每 5 分钟一次、撤订阅之前一次；累计量往回跳也记一笔新的底 |
| `oi` | `expiry k r`、`oi` | 每条合约每天第一次读到持仓量时；美东 09:35 之后，前一天那批合约（今天到期）再短订一次，读它们的持仓量 |

触发：会话有期权推送回调（`onOptionTick`）就挂上，每来一次推送把自己那一批流全读一遍、和上一次读数比；没有回调就每 250 毫秒轮询一次；另外每秒的节拍里也读一遍。
待写的行攒在内存里，每秒落盘一次。

分类不落盘，底账留原始读数，口径改了拿底账重算。

## 分类口径（quote-rule-v1）

一行 `print` → 一个结论：

1. 不分：`dv ≤ 0`（no_volume）、没有成交价（no_last）、延迟行情 `mdt ≥ 3`（delayed）、成交时刻没往前走（stale_last：成交量先到、成交价还是上一笔的）。
2. 盘口用成交**之前**那一口（`pb pa`）；它不可用才退到成交之后那一口（`b a`）。买价 ≥ 0、卖价 > 0、卖价 > 买价才算可用；锁盘（locked）和交叉盘、没盘口（no_quote）不分。
3. 成交价 ≥ 卖价 → 买方主动（at_ask）；≤ 买价 → 卖方主动（at_bid）；在中间，高于中间价算买方（above_mid）、低于算卖方（below_mid），正好在中间价不分（mid）。

组合单：两张不同合约在 250 毫秒以内各有一笔**同样张数**的成交，两笔都当作组合单的腿，只计入 `spread`，不进买卖两边。
250 毫秒是照 IBKR 期权行情的合并节拍定的，不是拟合出来的。同一合约的两笔、或者张数不同的，不配对。

## 已知的误差来源

- IBKR 的期权行情是合并过的推送，不是逐笔。两次推送之间的几笔成交并成一个 `dv`，只能拿最后一笔的价来分；这几笔方向不同时会整笔分错。
  "成交之前那口盘口"是上一次推送时的盘口，不是交易所撮合那一刻的全国最优报价。
- 这两条误差有多大，靠下面的逐笔对照量。
- 组合单配对只抓同张数、同一推送窗口的两条腿；比例价差、跨推送窗口的腿抓不到，会被当成单腿方向。
- 常规时段之后（SPX 期权 16:00–16:15）的成交没有记，覆盖率会略低于 1。

## 逐笔对照（量分类的准确率）

订上那一批之后，离现价最近的 3 张（一样近时看涨在前）另订逐笔：每张一条 AllLast（每一笔成交）、一条 BidAsk（每一次盘口变化），
原样记进交易库旁边的 `option-flow-tbt/`（行的格式见 `domain/option_flow_log.h`；留 10 个文件）。
盘口那一条只在价变了才推（请求时 ignoreSize = 真）：只变量的盘口抖动对照用不上，却最占地方。一天多大要等真机跑过才知道。
每张合约先订盘口再订成交；任一条被拒，另一条也撤，一张合约要么两条都在、要么都不在——只有成交没有盘口的合约会把真值全变成分不出。

- 线协议：请求 97 / 撤销 98 / 回包 99，字段次序照 IBKR 公开的 API 文档写（`execution/tws/wire_out`、`wire_in`），接口版本 < 137 不发、< 140 不带
  numberOfTicks / ignoreSize。会话上的入口是 `IbSession::tickByTick`。
- **逐笔的并发数 IBKR 卡得很紧**（IBKR 文档说和深度行情用同一个公式算，线路少的账户可能只有 3 条；是不是和深度行情共用一个额度没核对过——共用的话，盘中「盘口」页的深度可能空着而不报错）。3 张 × 2 条 = 6 条，超了的会被 TWS 拒掉：
  拒了记一行 `tbt_err`（带 TWS 的错误码与原话），不重试，状态里 `truth_errors` 计数。先跑一天看 `tbt_err` 再决定张数。
- 真值：每笔逐笔成交配上它到达之前、同一张合约最近的那口逐笔盘口，按同一条报价规则分。它也只是报价规则，不是交易所告诉你的主动方；
  它量的是"合并推送 + 上一次推送的盘口"这一层误差。
- 配对：每笔真值成交配到同一张合约、本机收到时刻不早于它、晚不过 2 秒的第一行记盘。两条流在同一条连接上按到达次序来；
  记盘那一行比逐笔先到的情况会配到下一行（或配不上），`match_share` 会把它显出来。
- 出的数（按张数加权）：混淆矩阵（真值 买/卖/分不出 × 记盘 买/卖/分不出/组合单/没配上）；`accuracy` = 两边都分出买卖的部分里方向一致的占比；
  `classified_share` = 真值分得出的张数里记盘也分得出的占比；`match_share`；`mixed_prints` = 一行记盘里同时并进了买卖两种成交的行数；
  每张合约真值净额与记盘净额；未报告（unreported）的成交不进矩阵，另计；按特殊条件（`cond`）分的张数；
  量对账 `volume_check`（配上的成交张数对配上的记盘行的成交量增量、两边全天总量）：差得多说明配错了行，或者累计成交量与逐笔不是一个口径（例如未报告的成交算不算进累计量）。

```
option-flow-report --dir <交易库目录>/option-flow --date 2026-10-28 --accuracy
```

## 次日持仓量对照能检验什么

持仓量的变化只说明当天开仓多还是平仓多：买方主动开仓和卖方主动开仓都会让持仓量变大。所以它**检验不了买卖方向**。
`option-flow-report` 用它量两件事：

- 覆盖率：记盘看到的张数 ÷ 当天最后一次累计成交量。远小于 1 说明推送漏了或订阅断过，那天的数据不能用。
- 开仓占比：|ΔOI| ÷ 当天累计成交量。

报告还按规则列出各类分到了多少张（`by_rule`），看分不出的那部分主要是哪一类。

```
option-flow-report --dir <交易库目录>/option-flow --date 2026-10-27
```
