# 系统凭证库

大模型的 API Key 与富途的交易解锁密码(md5)存在操作系统的凭证库里(macOS 钥匙串 / Windows 凭据管理器),
不进配置文件、不进日志。这一份写引擎怎么存取它们,以及为什么任何一次存取都不许卡住交易。
旧版存储的迁移见 [依赖选型](dependencies.md) 的「凭证的存放与迁移」。

## 引擎进程不直接调原生库

原生库(`@napi-rs/keyring`)是同步调用。macOS 钥匙串条目的访问控制认写入它的那个程序的签名:程序身份一变,
第一次解密就弹窗问人(输登录密码、点「允许」或「始终允许」)。同步调用在弹窗前一直等,整个事件循环跟着停:
盯盘节拍、托管单对账、所有 RPC 一起停。

所以引擎进程里只有 `secrets.ts`(异步、有时限)。同步的 `keychain.ts` 只在凭证子进程(`keychainChild.ts`)与一次性的 cli 里跑,
`engine-ts/.dependency-cruiser.cjs` 的 `keychain-off-the-loop` 规则不许别的模块直接引它。

## 三件事

| 做什么 | 谁在用 | 怎么做 | 会不会弹窗 | 最多等 |
|---|---|---|---|---|
| 有没有存过(`secretExists`) | `llm.catalog` 的「已配置」、`broker.catalog` 的「已存密码」 | macOS:`/usr/bin/security find-generic-password -s … -a …`,不带 `-w`,只读属性;Windows:凭证子进程读凭据管理器 | 不会(钥匙串被锁时除外) | 8 秒 |
| 取出明文(`readSecret`) | 大模型客户端第一次建起来时(解析指令、测试连接、想法分析、AI 选股……)、富途交易解锁 | 凭证子进程 | 可能 | 20 秒 |
| 写入(`writeSecret`) | `keychain.set`、`futu.set_password` | 凭证子进程,密钥经管道传 | 条目已存在、属于别的签名身份时可能 | 20 秒 |

- 界面一打开就问的只有第一行:启动、打开「接入」页都不解密,也就不弹窗。
- 「有没有存过」的答案记在引擎进程里:自己写过记成有,解密读到 null 记成没有;查不出来(超时、出错)按没存过显示,不记,下次再查。
- 明文只在真要用的那一刻取,引擎进程里不另存一份。下单解析用的大模型客户端取到 Key 后留着它,引擎重建(改配置、重连券商)时重新取;
  想法分析、AI 选股、回测条件解析、测试连接每次新建客户端,每次都重新取(多起一个子进程,约 0.1 秒);富途解锁每次都重新读。
- 20 秒是两头的折中:要留出输登录密码的时间;下单解析在交易道上等它,再长,排在后面的请求就等得太久。

## 凭证子进程

- 子进程就是引擎自己的可执行文件(打包版是应用本体加 `ELECTRON_RUN_AS_NODE`,开发时是 node),跑 `keychainChild.js`。
  钥匙串认的程序身份和引擎一样,「始终允许」放行的就是这个应用。不用 `/usr/bin/security -w` 读:那样放行的是系统自带的
  `security`,之后本机任何程序调它都能不经询问读出密钥。
- 请求(含要写入的密钥)经 stdin 一行 JSON 传进去,结果经 stdout 一行 JSON 传回来,不进命令行参数、环境变量和日志。
  子进程往 stderr 写的几句(迁移旧凭证)转进引擎的日志。
- 子进程在 worker 线程里调原生库,主线程只盯 stdin:管道一断(引擎退出、被结束、崩溃)就 SIGKILL 自己,系统弹窗随之消失。
  不能正常退出:worker 停在原生调用里时,正常退出要等这个线程结束。
- 调用方到了时限拿到 `KeychainTimeoutError`,子进程留着:弹窗还在屏幕上,用户后来点了「始终允许」,下一次就不再问。
  同一条凭证同时只有一个在途的读,后来的调用接着等它。子进程最多留 3 分钟,到点杀掉。
  写入超时也一样:用户后来点了允许,这次保存会自己完成。

## 报错与调度

- 凭证库的错(`KeychainError`,超时是它的子类)在 `rpc/server.ts` 统一报 −32008,原话给界面。超时那句说明多半是系统弹窗在等人、
  怎么处理、盯盘不受影响。它不算大模型调用失败,不记进连续失败熔断。
- `keychain.set` 与 `futu.set_password` 在本地道:一个没人点的弹窗不挡后面的下单与立即平仓。
- `instruction.submit`、调用大模型的其它方法、`futu.unlock` 仍在交易道。第一次要用 Key 时弹窗没人点,这条请求最多多等 20 秒,
  排在它后面的交易道请求跟着等,和一次慢的模型调用一样。盯盘节拍与托管单对账不走任何一条道,不受影响。

## 没有正式签名时,每装一次新包都会问

钥匙串放行的是某一个签名身份。ad-hoc 签名的包(还没有 Developer ID 证书)每重新打一次就是一个新身份,所以:

- 每装一个新包,第一次用 API Key、第一次富途交易解锁时,macOS 各问一次。点「始终允许」之后,这个包不再问;点「允许」只放行这一次。
- 启动与打开页面不会问。
- 有了 Developer ID 签名之后,升级前后是同一个签名身份,不再问(见 [发版](release.md))。
- 开发时引擎用系统 node 跑,放行的是那个 node,换了 node 版本也会问一次。
