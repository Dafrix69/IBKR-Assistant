# 日志脱敏与诊断信息

2026-09-28 加的。用户遇到问题会把日志发给别人——发给你,也可能贴进群里。

## 脱敏(`desktop/redact.js`)

引擎自己打的日志在调用处已经打了码(`store.ts` 的 `redactAccount`)。但进日志的不只是它:券商回的错误原文、
未捕获异常的调用栈、渲染层的控制台报错、引擎 stdout 上的非 JSON 行,都是原样写进去的。所以在**落盘的地方**
再过一遍(`electron-log` 的 hook),宁可多抹,不可漏。

| 抹什么 | 怎么认 |
|---|---|
| 配置里的真实账号 | 逐个精确替换(长的先换);引擎每次起来按现在的配置重建 |
| 长得像 IBKR 账号的 | `U` / `DU` / `F` / `DF` / `I` 开头加 5 到 9 位数字。订单号、行权价、日期、小写十六进制不误伤 |
| API Key 与令牌 | `sk-…`、`Bearer …`、`api_key=…` / `"apiKey": "…"` / `password=…` 这类键值 |
| 家目录里的用户名 | `/Users/张三` → `~` |
| 通知行的内容 | 非 macOS 上引擎把通知打到 stderr(`[通知] 成交回报 \| 账户 … \| BUY AAPL 100 @ 230`),里面是成交与订单摘要。只留标题 |

最后一条修的是一处自相矛盾:`main.js` 开头写着"交易数据不进日志",Windows 上却一直在进。

打码的样子和引擎一致:`DU1234567` → `DU***567`。交给界面的引擎日志(「关于」页那一块)同样先脱敏——它会被截图。

## 诊断信息(`desktop/diagnostics.js`)

「关于 → 支持 → 导出诊断信息…」,菜单「帮助」里也有。一份文本文件,存到哪由主进程的保存对话框定。

| 有 | 没有 |
|---|---|
| 版本、系统、架构、语言、内存 | 交易记录、成交、持仓 |
| 引擎在不在跑、本次启动后自动重启过几次 | 想法原文 |
| `system.status`、`system.selftest`(别名表只报条数) | API Key |
| `data.backups`(库在哪、有哪些备份) | 真实账号(已打码) |
| 配置(已脱敏) | |
| 条款同意的状态、上次检查更新的结果 | |
| `main.log` 最后 1,500 行、上一份日志最后 300 行,单行超过 2,000 字截断 | |

**引擎不在、不回话时照样导得出来**——那正是最需要它的时候。问引擎要的三样各等 5 秒,要不到就在「引擎报错」里记一笔。
配置读不出来、日志文件不在,同样只是那一节里写一句原因。

整份拼好之后再整体过一遍脱敏。

「拷贝概要」是不带日志的几行字(版本、系统、引擎与券商连接状态、闸门),贴进聊天窗口不刷屏。

**没有自动上传。** 没有崩溃上报服务,没有遥测。发不发、发给谁由用户决定——隐私说明里是这么写的,代码也是这么做的。

## 打开所在位置

`reveal` 通道只认四个固定的地方:日志、配置文件、备份目录、第三方许可声明。界面递不进路径。
