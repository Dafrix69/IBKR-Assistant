# 日志脱敏与诊断信息

用户遇到问题会把日志发给别人,也可能贴进群里。所以日志落盘之前抹掉敏感内容,另给一份可以直接发出去的诊断文件。

## 脱敏(`desktop/redact.js`)

引擎自己打的日志在调用处已经打码(`store.ts` 的 `redactAccount`);但券商回的错误原文、未捕获异常的报错与调用位置、渲染层的控制台报错、
引擎 stdout 上的非 JSON 行都会原样进日志。所以在落盘的地方(`electron-log` 的 hook)再过一遍,宁可多抹。

| 抹什么 | 怎么识别 |
|---|---|
| 配置里的真实账号 | 逐个精确替换(长的先换);引擎每次启动按当前配置重建 |
| 长得像 IBKR 账号的 | `U` / `DU` / `F` / `DF` / `I` 开头加 5 到 9 位数字;订单号、行权价、日期、小写十六进制不误伤 |
| API Key 与令牌 | `sk-…`、`Bearer …`、`api_key=…` / `"apiKey": "…"` / `password=…` 这类键值 |
| 家目录里的用户名 | `/Users/张三` → `~` |
| 通知行的内容 | 非 macOS 上引擎把通知打到 stderr(`[通知] 成交回报 \| 账户 … \| BUY AAPL 100 @ 230`),只留标题,交易数据不进日志 |

打码保留开头的字母与最后三位:`DU1234567` → `DU***567`、`U1234567` → `U***567`。引擎自己的 `redactAccount` 保留前两个字符
(`U1234567` → `U1***567`),两处只在两个字母开头的账号上一致。交给界面的引擎日志(「关于」页那一块)同样先脱敏,它会被截图。

## 诊断信息(`desktop/diagnostics.js`)

「关于 → 支持 → 导出诊断信息…」,菜单「帮助」与单页出错的说明卡上也有。一份文本文件,存到哪由主进程的保存对话框决定。
导出、打开所在位置、条款、备份恢复这几条通道在 `desktop/support-ipc.js`。

| 有 | 没有 |
|---|---|
| 版本、系统、架构、语言、内存 | 交易记录、成交、持仓 |
| 引擎在不在运行、本次启动后自动重启过几次 | 想法原文 |
| `system.status`、`system.selftest`(别名表只报条数) | API Key |
| `data.backups`(库在哪、有哪些备份) | 真实账号(已打码) |
| 配置(已脱敏) | |
| 条款同意的状态、上次检查更新的结果 | |
| `main.log` 最后 1,500 行、上一份日志最后 300 行,单行超过 2,000 字截断 | |

- 引擎不在、不回话时照样导得出来,那正是最需要它的时候。引擎在运行时,问它要的三样各等 5 秒,要不到就在「引擎报错」里记一笔;
  引擎没在运行时只写 `running: false`。配置读不出来、日志文件不在,同样只在那一节写一句原因。
- 整份拼好之后再整体过一遍脱敏。
- 「拷贝概要」是不带日志的几行字(版本、系统、Electron 与 Node 版本、引擎与券商连接状态、闸门、熔断、模型与提示词版本、引擎报错),贴进聊天窗口不刷屏。
- 没有自动上传,没有崩溃上报,没有遥测。发不发、发给谁由用户决定。

## 打开所在位置

`reveal` 通道只认四个固定的地方:日志、配置文件、备份目录、第三方许可声明。界面递不进路径。

## 测试

`tests/desktop-redact.spec.ts`:每一类都有正例与不误伤的反例;诊断信息该有的都有、不该有的没有;配置坏了、日志不在时照样出得来;主进程真的挂了 hook。
`tests/desktop-main.spec.ts` 覆盖这几条通道的接线。
