# 条款同意:首次启动先看风险揭示

2026-09-28 加的。这个软件会替人发真实订单;卖出去之前,用户得明确看过并同意三样东西。

## 三份文本

`docs/legal/` 下:`risk-disclosure.md`(风险揭示)、`terms.md`(使用条款)、`privacy.md`(隐私说明)。
界面上摆的和文档里写的是同一份:`lib/legalText.ts` 用 Vite 的 `?raw` 原样引进来,不手抄第二份;
打包时也一并拷进 `resources/legal/`。

**它们是草稿,没有经过律师审阅**,发布者、联系方式、适用法律还是 `【发布前填写】`。
`npm run release:check` 会拦住带着占位符的正式发布(见 [发版](release.md))。

隐私说明里的"发给谁、发什么"逐项对过代码;`tests/desktop-consent.spec.ts` 钉着引擎源码里出现的外部域名清单——
多了一个,隐私说明就得跟着改。

## 同意的是"某一版"

三份文本第 3 行都是 `版本:YYYY-MM-DD`,三份一致,且等于 `desktop/consent.js` 的 `TERMS_VERSION`。
用户同意时界面把**它摆出来的那一版**的版本号交给主进程,对不上就不作数——界面上要是旧文本(没重载),这次同意无效。

改了任何一份的实质内容:三份的版本与 `TERMS_VERSION` 一起改成新日期。老用户下次启动会被要求重新确认。

记录在 `userData/consent.json`,只增不改:每同意一次追加一条(条款版本、时刻、当时的应用版本)。
文件坏了按没同意过处理。

## 挡在哪

两层。

**界面**(`shell/ConsentGate.tsx`):没同意现行条款之前,整个界面挡在同意页后面。三份文本都点开看过才能勾选,
勾了才能点「同意并继续」;「不同意,退出」退出应用。

为什么挡整个界面而不是只挡发单:风险揭示要在人开始依赖这个软件**之前**看到,不是在他第一次点「发送」、正急着成交的那一刻。

**主进程**(`consent.blockedWithoutConsent`):没同意之前,`instruction.submit`(`execute: true`)、`tracker.add` /
`update` / `close_now` 不放行;`settings.patch` 里把三个闸门任何一个设成 `true` 也不放行。界面被绕过也过不去。

不挡的:只解析不发单、只读的、连券商、熔断(尤其不能挡)、关闸门。

**引擎不知道条款这回事。** 已经打开了自动执行的老用户升级之后,引擎里的追踪照常跑,只是界面要先同意才进得去。
命令行(`cli.js run`)有它自己的 `--i-understand-this-places-real-orders`。

## 显示

不引 Markdown 库。`lib/docParse.ts` 是一个只认五样东西的小解析器(标题、段落、`-` 列表、`|` 表格、`**加粗**`),
输出结构化的块,`lib/PlainDoc.tsx` 逐块画成 React 节点——整条路上没有 `innerHTML`。写条款时别用别的语法,
测试会拦(链接、图片、代码块、编号列表、引用)。

预览台里地址后面加 `?consent=0` 看首次启动的样子;平时 mock 当作已经同意过,不挡着截图。
