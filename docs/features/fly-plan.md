# 蝴蝶测算:开仓之前,按 IV 估「标的几点走到哪儿」时这只蝶赚多少

2026-09-28。用户的原话:「用户通过当时的 spx 指数开蝴蝶,根据用户选定的预计位置和到达这个位置的时间,通过 iv 计算预定盈利」;
做到一半时补了一句:「注意一个问题,如果急跌急涨,iv 会实时变化」;看到第一版之后又一句:「不要用经验公式,用历史数据校准」;
校准用的是 IV 指数而不是期权自己的 IV,于是再一句:「让软件自己攒当日到期期权的 IV」。

持仓追踪里已经有「标的目标价」([持仓追踪](tracker.md)):有了持仓之后,问"标的**现在**走到 X,这份持仓值多少"。
这里问的是**开仓之前**的那一句,而且多一维——**时间**:7718 开的 7750/25 点蝶,"14:30 走到 7745"和"10:45 走到 7745"不是一个数。

只算不下单。方法是 `options.fly_plan`,排在读道上。

## 它凭什么算得出来

和追踪的 `ibkr` 档**同一套定价**,一行没另写:

* 点数制 Bachelier,每条腿各用各的 IV,按 +1 / −2 / +1 加权(`flyexit.legValue`)。
* IV 是年化的对数正态波动率,换成点数:σ_点 = 现价 × IV × √剩余年数(`ivPricing.ibkrLegSigmas`)。
  剩余时间按日历时间 / 365。

所以**目标时刻就是此刻时,测算和追踪的试算给出同一个数**(`fly-plan.spec` 拿 `tracker.spotTarget` 对拍)。
开仓前测算出来一个数,开仓后追踪给的是另一个数——那样的话两个都没法信。

### IV 从哪来:三档,整只蝶用同一档

| 来源 | 什么时候用 | 锚不锚盘口 |
|---|---|---|
| `input` | 用户手动填了 IV(三条腿共用一个数) | 不锚:填 IV 就是想看"IV 是这个数时值多少" |
| `ibkr` | 三条腿都有 IBKR 推的模型 IV | 锚 |
| `quote` | 缺模型 IV,但三条腿都有盘口:各腿按自己的中间价反解 | 不用锚:此刻的模型价就是中间价 |

缺一条腿就整档不用,不拿别的腿的 IV 去填(偏斜就是编的)。三档都不成:报错,指到手动填 IV。

### 锚定随时间收敛

IBKR 的模型价和盘口中间价常差一截。追踪的做法是只让模型管"变多少",水平锚在盘口上;这里照做,
但多了时间之后有一处不能照搬:**那截差不能原样带到到期**——到期那一刻蝶只值内在价值。
它是时间价值上的差,所以按 √(剩余时间 / 现在的剩余时间) 收敛,到期归零。

差得太多(超过 0.3 点、也超过中间价的 25%)时照样锚,但要说一声:那时模型对"变多少"的估计也要打折扣。

### 成本

填了就用填的。没填用盘口中间价,并把"现在立刻买得到的价"(两翼按卖价、中心按买价)说出来——
中间价多半成交不了。盘口也没有:用模型价,明说它不是市场价。

盈亏按**取整之后**的净价算:界面上摆着"值 11.88、成本 2",旁边就得是 +$988。

## IV 会变

到目标时刻各腿的 IV 乘多少,「自动」档(默认)拆成两份:**时段**与**走势**。两份的参数都是拿历史数据估出来的
(`flyCalibration.ts` 估,结果存在 `flyIvModel.ts`,跑的是 `npm run calibrate:fly`)。合计夹在 [1/3, 3]。

### 为什么不用公式

第一版用的是两个经验公式:时段借止盈策略那份日内方差分布,走势用 √[1 + w(z² − 1)](超出一个标准差才上调,跌 0.30、涨 0.15)。
用户要求拿历史数据校准。一验,两个都站不住:

| | 第一版 | 数据 |
|---|---|---|
| 上涨时的 IV | 走得急就**升** | **降**(涨一个全天标准差,约 −8%) |
| 一个标准差以内 | 不动 | 照样动,大致是线性的 |
| 管用的是什么 | 走得多急(这一段的几个标准差) | 走了多远(全天标准差的几倍)。同样的距离一小时走完和四小时走完,IV 的变化差不多 |
| 尾盘(15:00 以后)占全天方差 | 28% | 15% |
| 拿没参与拟合的数据检验(R²) | 约 −0.06,**比"IV 不变"还差** | 0.32 |

### 数据

| | 用来估什么 | 样本 |
|---|---|---|
| SPY 小时线 | 标的的走势、日内方差的小时份额 | 2023-12-11 → 2026-09-25,692 个交易日 |
| SPY 5 分钟线 | 每个小时之内前后半小时怎么分 | 最近 60 个交易日(公开的分钟线只给这么多) |
| VIX1D 小时线 | 短期 IV(1 天期)怎么变;每天开盘时的隐含水平 | 同上 692 天 |
| VIX9D 小时线 | 期限长一档时反应弱多少 | 同上 |

来源是公开行情接口(和顶栏行情带用的是同一个)。**原始数据不进仓库**,进仓库的只有估出来的参数。

两处取舍:

* **标的用 SPY,不用 SPX 指数。** 指数 09:30 那一笔还是拿昨收拼的,隔夜的缺口会在头几分钟里"走"出来,第一个小时的方差被夸大。
* **小时线只用收盘价。** IV 指数的小时线除第一根以外,开盘价有七成对不上 5 分钟线;收盘价都对得上。

### 时段:日内方差分布

每天的平方收益先除以当天开盘时的隐含方差(VIX1D²),再求和取比——不归一的话几个暴跌日说了算。

| 半小时 | 份额 | 这一桶开始时还剩 |
|---|---|---|
| 09:30 | 15.1% | 100% |
| 10:00 | 11.8% | 84.9% |
| 10:30 | 9.5% | 73.2% |
| 11:00 | 8.1% | 63.7% |
| 11:30 | 6.0% | 55.6% |
| 12:00 | 5.2% | 49.7% |
| 12:30 | 6.0% | 44.5% |
| 13:00 | 5.1% | 38.5% |
| 13:30 | 6.0% | 33.4% |
| 14:00 | 6.2% | 27.5% |
| 14:30 | 6.1% | 21.3% |
| 15:00 | 5.2% | 15.2% |
| 15:30 | 10.0% | 10.0% |

按日历时间年化的 IV 要保持不变,剩余波动就得跟着钟点匀速掉;实际的掉法是上表。两者之比就是时段乘数:

```
时段乘数 = √[(那时还剩几成 / 此刻还剩几成) ÷ (那时的剩余时间 / 此刻的剩余时间)]
```

10:00 起算:11:00 约 0.95,13:00 约 0.95,14:30 约 1.00,15:00 约 1.04,15:30 之后约 1.19。比第一版小得多(那边 14:30 是 1.28)。

只管**当日到期、正常 16:00 收盘**的那种。隔日到期的蝶夜里怎么分方差不知道;提前收盘日那份分布对不上。这两种乘数是 1。

**这份分布不稳。** 分三段各自估,小时份额是:

| | 09:30 | 10:30 | 11:30 | 12:30 | 13:30 | 14:30 | 15:30 |
|---|---|---|---|---|---|---|---|
| 2023-12 → 2024-11 | 22% | 14% | 9% | 10% | 17% | 14% | 14% |
| 2024-11 → 2025-10 | 27% | 17% | 10% | 14% | 11% | 11% | 10% |
| 2025-10 → 2026-09 | 31% | 22% | 14% | 10% | 8% | 9% | 6% |

两年里波动一直在往上午挪。用的是全部样本(不追最近一段,免得把一时的样子当成规律),所以要**定期重新校准**。

### 走势:IV 对走了多远的反应

```
ln(IV 乘数) = a + b·u + c·u²          u = (目标点位 − 现价) ÷ 全天标准差,跌为负,夹在 ±4
a = −0.0105    b = −0.0969    c = 0.0253
```

| u | −3 | −2 | −1.5 | −1 | −0.5 | 0 | 0.5 | 1 | 1.5 | 2 | 3 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| IV 乘数 | 1.66 | 1.33 | 1.21 | 1.12 | 1.05 | 0.99 | 0.95 | 0.92 | 0.91 | 0.90 | 0.93 |

怎么估的:小时网格上(09:30、10:30 … 15:30、16:00)每天取所有 i < j 的窗口,共 28 个。

* y = ln(VIX1D_j / VIX1D_i),减掉 VIX1D 自己的日内平均走法(它从开盘到收盘平均涨两成多,那不是对走势的反应)。
* u = ln(S_j / S_i) ÷ 全天标准差。全天标准差 = √(0.83 / 252) × VIX1D_i(同样去掉日内走法)。
  0.83 是量出来的:实际的常规时段方差 ÷ (开盘时 VIX1D² / 252)。
* 最小二乘。试过的别的形式:按"这一段的几个标准差"z(样本外 R² 0.315)、u 与 z 都放(0.325)、上下分开的斜率(0.317)。
  u 的二次式最省、也不输,用它。

**u = 0 时不是正好 1。** 截距略小于 0:没怎么动的那些时段,IV 平均是微降的。

**测算里的"全天标准差"**:当日到期的,用期权自己的 IV 折回全天——剩余波动 ÷ √(此刻还剩几成);
别的期限,年化 IV × √(0.83 / 252)。这里假定期权隐含的剩余波动就是市场对实际波动的预期(不另算风险溢价)。

**期限。** VIX9D 的系数是 a = −0.0053、b = −0.0641、c = 0.0129,比 1 天期的弱三分之一。非当日到期的蝶在两者之间按 ln(期限) 插值;
1 天以内一律用 1 天期的,**不往更短外推**;9 天以上用 9 天期的。

系数稳不稳(分三段各自估):

| | b | c |
|---|---|---|
| 2023-12 → 2024-11 | −0.076 | 0.029 |
| 2024-11 → 2025-10 | −0.114 | 0.020 |
| 2025-10 → 2026-09 | −0.101 | 0.029 |

方向与量级都稳,斜率有三成的出入。

### 检验

前 484 个交易日(2023-12-11 → 2025-11-19)拟合,后 208 个(2025-11-20 → 2026-09-25)检验,两段不重叠。

| 拿什么预测 IV 的变化 | 检验段上的 R² |
|---|---|
| IV 不变 | −0.007 |
| 第一版的经验公式 | 约 −0.06 |
| 校准的模型 | **0.322** |

模型解释得了 IV 变化的三成。**剩下七成是估不出来的**——所以结果里不只一个数。

旁证:不借 VIX1D 的期限,直接看 SPY 自己——走了一段之后,**当天剩下的时间里**实际波动比事前预期多多少。
跌 1.5–2 个标准差之后,剩余波动是预期的 1.18 倍(VIX1D 同一格是 1.14);跌 2–3 个是 1.32 倍(1.23);涨 0.5–1 个是 0.83 倍(0.95)。
方向一致,量级相近,实际波动那一边噪声大得多。

### 半数情况下的区间

残差的标准差:

```
sd = 0.158 × √(这一段占全天方差的份额) × (0.823 + 0.265·|u|)
```

走得越久越宽,走得越远也越宽。到时的 IV 取主结果的乘数 × exp(∓0.6745 sd),两头各算一遍蝶价,和主结果一起取最小最大
(蝶价对 IV 不单调:翼内翼外方向相反)。

这个区间在样本里实际盖住了 52.5%,名副其实。它只算了 IV 估不准的那一份;**标的会不会真的在那个时刻走到那个点位,不在里面**——那是用户自己的判断。

### 界面上怎么说

* 主结果旁边:「半数情况下」的盈亏区间、「要是 IV 不变」的那个数。
* 「IV 变了会怎样」一张表:−25% / 不变 / +25% / +50% / +100%,加上主结果用的那一档(标出来)。
  那一档按它自己的乘数算,不是拿取整后的百分比再算一遍——表里那一行和主结果必须是同一个数。
* 提醒里把合计拆开说:"到时的 IV 按 −5.5% 算(时段 +1.3%,走势 −6.7%);历史上同样的走势之后,半数情况落在 −13% ~ +3% 之间"。
* 结果最下面写明校准用的是什么数据、哪一段、样本外 R²,以及"VIX1D 是恒定 1 天期的指数,不是这三条腿自己的 IV"。
* 用户可以选「不变」或「自己填」。选了之后,要是和历史上的通常情况差了十个百分点以上,提醒一句。

盈亏曲线上每一个点位用的是**它自己的**乘数(走到更远的点位,u 更大);时间线上每一行用的是它自己那一刻的时段乘数。
「现在就到」没有时间可言,自动档也按 IV 不变算——和追踪的试算一致。

### 重新校准

```
cd engine-ts
npm run build && npm run calibrate:fly -- --fetch            # 取数据、校准、出报告,不改文件
npm run calibrate:fly -- --fetch --write                     # 同上,并写进 src/flyIvModel.ts
npm run build && npx vitest run fly-
```

报告里有分段的系数与份额。`fly-calibration.spec` 对写进去的那一份有几条底线:样本至少一年、样本外 R² 明显是正的且比"IV 不变"强、
区间的覆盖率在一半上下、方向(b < 0、c > 0)。不满足就不该进定价。

`fly-plan.spec` 钉"参数怎么用"时用的是一份固定的模型,重新校准不会把它弄红。

建议每季度一次,或者在行情的样子明显变了之后。

### 局限

* **IV 用的是 VIX1D,不是当日到期期权自己的 IV。** VIX1D 是恒定 1 天期的:上午主要看当天到期的那一批,越到下午越偏向次日到期的。
  当日到期期权本身对走势的反应多半更强,尤其在尾盘。过期期权的历史行情 IBKR 不给,公开数据里也没有,这一步只能靠自己攒——
  见下一节。攒够之前用的都是指数那一份。
* **隐含的日内分布当成和实际的一样。** 估的是实际波动怎么分;期权定价用的那份分布可能不同(比如给尾盘留更多)。
* **日内分布在变**(见上)。
* **5 分钟线只有 60 天。** 小时之内前后半小时怎么分,样本短。
* **隔日到期的蝶**:没有时段那一份;"这一段占全天方差的份额"按钟点算,夜里和白天一样重。
* IV 的偏斜不跟着现价动(粘着行权价)。
* 公开行情接口的商用条款是个没定的问题(见商用化报告);校准只在开发时跑,但运行时顶栏行情带也在用它。
* 和追踪的 `ibkr` 档一样,IBKR 推的当日到期 IV 用的是什么剩余时间约定**还没在真机上核对**
  (`npm run probe -- --steps ivcheck`)。锚定挡住了水平上的偏差,挡不住"变多少"上的。

### 自己攒 IV

`services/ivRecorder.ts` 在引擎里按节拍跑(和异动监控一样,不靠界面驱动):

| | |
|---|---|
| 什么时候记 | 连着 IBKR、在常规交易时段里(休市日、提前收盘日照日历)。每 5 分钟一笔 |
| 记什么 | SPX 当日到期(SPXW):开盘后第一笔的现价取整作**锚**,围着它取 −75 / −50 / −25 / −10 / 0 / +10 / +25 / +50 / +75;锚以下记看跌、以上记看涨、锚上两样都记(都是虚值那一侧,报价最实)。每条腿:买价、卖价、IBKR 的模型 IV。外加当时的现价 |
| 行权价换不换 | **一整天不换**,引擎重启也接着用当天已经记下的那个锚。同一个行权价从早连到晚,才量得出"这条腿的 IV 在标的走了一段之后变了多少"。标的离锚 20 点以上时,再添一对跟着现价的平值 |
| 测算顺带记 | 测算读到行情时也记一笔(那三条腿)。同一只蝶一分钟最多一笔;现价是手动给的、不是当日到期的不记 |
| 存在哪 | 交易库旁边的 `fly-iv/年-月-日.jsonl`,一行一笔,只追加,只有自己读得到。留最近 400 天 |
| 里面有什么 | **只有行情**。没有账号、别名、持仓、订单(`iv-recorder.spec` 钉着键的清单) |
| 开关 | 默认开。在测算面板「更多」的最下面;存在库的偏好表里。关掉之后不订任何行情,已经攒下的不删 |

行情用的是测算那批自己的流(`optionMarks.ts`),盯盘的流碰不到。一轮十条腿上下,用完一分钟内撤掉。

不进交易库:这是行情,不是交易记录。单独放着,坏了、删了都碰不到订单与追踪,库的结构版本也不用动。

**什么时候不记都说得出原因**(`options.iv_recorder` 的 `idle_reason`):没连券商、不在常规交易时段、已关闭、拿不到现价、
行情订阅被拒(带 TWS 的原话)。出了错吞掉、记下来,循环不停。

#### 攒够了怎么用

```
cd engine-ts
npm run build && npm run calibrate:fly -- --fetch --samples auto            # 只出报告
npm run calibrate:fly -- --fetch --samples auto --write                     # 过得了下面两道关才写进去
```

`fitFromSamples` 估的是和指数那一路同样的两样,量法贴着测算自己:

* **y** = 同一条腿(同一个行权价)的 IV 对数变化——测算里乘数就是乘在固定行权价的 IV 上的。只看起点时离现价一个全天标准差以内的腿。
* **u** 的分母 = 期权自己的剩余波动折回全天(平值 IV × √剩余年数 ÷ √还剩几成),和测算里量 u 的办法一字不差。
* **IV 自己的日内走法**:10:00 起每半小时一个点、到 15:30,半小时一步的平均变化累加起来。测算的「时段」直接用它,
  不再借实际波动的分布去推——「隐含的日内分布当成和实际的一样」那一条局限也就没了。
* 半小时网格,每个点取前后四分钟之内最近的那一笔;前七成的交易日拟合,后三成留出。

两道关(`ownIsBetter`):

1. 一天有六个半小时点以上的至少 **40 天**,凑得出至少 1,000 个窗口。不够直接拒。
2. 留出的那一段上,自己这一份的 R² 大于 0.1,而且**不输指数那一份在同一批窗口上的 R²**。输了就不换。

过了,模型里多一个 `own`,当日到期的蝶的时段、走势、区间宽度都改用它;结果最下面那句话会写明
"用的是软件自己攒下来的当日到期期权 IV"。隔日到期的蝶照旧用指数那一份。

**这条路还没见过一笔真数据。** 估计方法拿已知答案的合成样本验过(日内走法与反应都估得回来;样本不够拒、估得不好不换),
但真的期权 IV 是什么样子——缺口、陈旧的报价、远翼的跳动——要等攒出来才知道。第一次带 `--samples` 校准时只出报告、不加 `--write`,
先看那几行数说不说得通。

### 止盈策略那份日内分布:一起换了

`flyexit.VARIANCE_WEIGHTS`(止盈策略的阶段切换、`clock` 档的 σ、复盘回放里没有真实蝶价时的模型价都靠它)原来是
`[0.15, 0.09, 0.07, 0.06, 0.05, 0.04, 0.04, 0.04, 0.05, 0.06, 0.07, 0.11, 0.17]`:最后一小时 28%、最后半小时 17%。
这两年的数据里是 15% 与 10%。用户看过之后定的:**改**。2026-09-28 起它就是上面校准出来的那一份,和测算用同一份。

换了之后(EM 36):

| 时刻 | 还剩几成 | 剩余 σ(点) | 翼宽 25 的阶段 |
|---|---|---|---|
| 10:30 | 76% → 73% | 31.4 → 30.8 | A |
| 12:07 | 57% → 49% | 27.2 → 25.1 | A |
| 13:30 | 46% → 33% | 24.4 → 20.8 | A |
| 15:00 | 28% → 15% | 19.0 → 14.0 | B → **C** |
| 15:30 | 17% → 10% | 14.8 → 11.4 | C |

| B → C 的切换时刻 | 原来 | 现在 |
|---|---|---|
| 翼宽 25,EM 36 | 15:25 | 14:43 |
| 翼宽 25,EM 50 | 15:43 | 15:31 |
| 翼宽 40,EM 36 | 13:14 | 12:09 |
| 翼宽 20,EM 36 | 15:39 | 15:19 |
| 翼宽 10,EM 36 | 15:55 | 15:51 |

也就是说:**下午的剩余波动比原来认为的小,策略更早进入 C 阶段**(按区间持有 / 清半 / 止损的那一段)。
`clock` 档算出来的蝶价下午更高(7725/7750/7775 的蝶、标的 7740、15:00:10.34 → 12.12)——
它只在拿不到任何市场波动率时才用,而且有过市场价之后行情一断就停在最后一次,不会拿它去推已经挂着的单。

黄金基线(`baseline/golden/flyexit.json`)用 `golden:update` 重生成了。变的只有和剩余波动有关的字段:
`sigma_rem`、`phases.c_from` / `sigma_at_switch`、没有真实蝶价时的模型价与由它推出来的回撤线;
两个用例里"数据到此为止、按最后蝶价估值"的那一笔跟着模型价变了。**没有一个用例的出场规则换了**,输入与 K 线一字未动。

**重新校准会连它一起改。** 写进 `flyIvModel.ts` 之后 `golden-flyexit` 会红,核对过再 `npm run golden:update -- golden-flyexit`。
"variance schedule / phases" 那一条为此改成了整行比对(原来是逐个标量比,`golden:update` 改不了它)。

**还没在真机上核对。** 阶段切换提早四十分钟是看得见的行为变化:下一次用止盈策略之前,先拿一笔做过的蝶在「交易分析」里回放一遍,
看新的切换时刻合不合你的手感。不合就把 EM 或 `switch_k` 调一调——分布是数据说的,这两个是你定的。

## 日程

| 没给 | 默认 |
|---|---|
| 目标日期 | 今天;今天不是交易日、或者已经收盘,就是下一个交易日(并说明) |
| 到期日 | 目标那一天(当日到期)。可以晚于目标那一天 |
| 交易类 | 指数用配置里的日到期类(SPX → SPXW,收盘结算),和本地速记开的是同一张合约 |

**提前收盘日 13:00 到期。** 追踪那边的到期时刻一律按 16:00(`ivPricing.expiryEpochMs`),这里按真的来——
差三个小时,对当日到期的蝶是全部的时间价值。追踪那一处是已知的缺口,没有在这一轮动它(钱路径)。

目标时刻不在常规时段里能算,但要提醒:那时指数不报价。目标时刻已经过去、在到期之后:拒。

## 取行情:不许碰盯盘的流

测算的腿很可能正好是持仓的腿(加仓、相邻的蝶共用行权价)。行情流按「合约 + generic ticks」缓存、
**没有引用计数**(`ibSession.tickerKey`):和盯盘订同一条再撤掉,盯盘手里的句柄就不再更新了。

所以 `optionMarks.ts`:

* 带着自己的 generic ticks(`106`)订——那是另一条流;撤也只点名撤这一条,**从不裸撤**。
* 订上之后**留一分钟**:IV 会变,界面开着「跟着行情刷新」十秒读一次,现订现撤的话大半时间都在等首笔 tick。
  一分钟没人读才撤;最多留 24 条(行情线路有配额)。
* 只管着纸面账户的会话按行情类型 3 订(有实时给实时,没有给延迟);管着实盘账户的绝不切。
* 盘口齐了之后再等模型 IV 最多 1.5 秒:它比盘口晚一拍,但休市时根本不来。
* 拿不到的给 null,不编。要不要退到手动 IV 是上一层的事。

写这一层时发现 `BrokerRouter.legQuotes`(AUTO_MID 定价)正是那样裸撤的:定价一张和持仓共用腿的新单,
会把盯盘那条腿的流撤掉。那是另一件事,同一天另行修了(被撤掉的流读到的是"没有价",盯盘自己重订,见更新记录);
这里照旧用自己的流——不碰别人的,比"碰了之后对方能恢复"稳。

现价:指数走 `router.indexPrice`(夜盘按期货推算,来源标出来)。推算失败拿到的是昨收时**不算**,请用户手动给——
和盯盘同一条规矩。

## 能离线算

现价与 IV 都手动给了,一条行情都不取:没连券商、休市、想按"假如现价是 X"推演时用。只给了其中一样,另一样照旧去券商取。
富途连接下不取期权行情(富途没有美股指数),IV 要手动给。

## 界面

在「交易指令」页的右栏,和「解析结果」是同一栏的两面(分段控件切)。放在这里是因为它就是开仓之前那一步:
左边的输入框一直看得见。点了「解析并校验」或「发送」,右栏自动切回解析结果。

* **「写进指令」只是填字。** 把测算过的这只蝶写成一句话放进左边的输入框(输入框里有字就另起一行,不覆盖),
  发不发、什么时候发还是那两个按钮和那个确认框的事。当日与下一个交易日到期的写成本地速记认得的样子
  (`SPX 7750蝴蝶 25cm 看涨 2张 1.85`);别的到期日写明日期,交给大模型。
  权利金用测算时的成本:那是"按这个价买才有这个盈利"的价。
  `desktop-fly-plan-form.spec` 把写出来的那句话真的喂给本地速记,解析出来的必须是测算的那一只。
* **「跟着行情刷新」**:十秒一次。只在面板看得见的时候跑(循环在 `store/flyPlan`,看不看得见由面板告诉它);
  一次失败就自己关掉,屏幕上留着上一次的结果并说明。
* 表单改过之后结果还摆着,但压暗、标出"这是改之前的";「写进指令」那时是灰的。
* 时刻一律是美东时间;结果里另给一个本地时间。

## 契约

`options.iv_recorder`(状态)与 `options.iv_recorder_set`(开关)在本地道上,同样不敏感。

`options.fly_plan`,入参与返回在 `contract/options.ts`。入参的 schema 是 **strict** 的、数值只认数字:
键名写错(`iv_shift` 少了 `_pct`)当场拒,不然就是"IV 变化没设上,结果看着还挺正常"。

不会发单、不改配置,不进 `SENSITIVE_METHODS`,不需要确认凭据。

错误码:入参与口径上的错 −32602;取不到现价 / 行情 −32017。

## 还没在真机上核对

全部是离线测试。要在连着 TWS 的时候看的:

1. 盘中对着一只蝶点「测算」:三条腿的盘口与 IV 出得来;「现在就到」那一行和持仓追踪的试算是同一个数。
2. 手里有这只蝶的持仓时点「测算」、开着「跟着行情刷新」放几分钟:持仓追踪的价照常在跳。
3. 开仓时记下测算的数,到了目标时刻拿实际的蝶价比——校准用的是 IV 指数,这是核对它在真的期权上准不准唯一的办法。
4. 盘中连着 TWS 放半小时:`fly-iv/` 里当天的文件在长,每五分钟一行,十条腿的 IV 都有数;这期间持仓追踪的价照常在跳。
