# 行情:K 线与价格行为

「行情」页一页看一个标的:上面是实时 K 线与价格行为读盘,图下是这个标的的盘口(一档或多档、价差、深度、失衡),
页面下半可以同时关注最多 12 个盘口,点代码就换成上面正在看的标的。
方向判断全部由代码计算;模型只在按下「AI 解读」时,拿算好的结论做叙述。RPC 是 `pa.analyze`(读道)、`pa.timeframes`、`book.snapshot`,
形状在 `contract/priceaction.ts`。

## K 线

- 走 TWS 的历史数据接口,同样需要行情权限。请求前切到延迟行情类型(3),让只有延迟权限的账户也能出图,用完切回实时(1):
  AUTO_MID 按盘口定价,不能被拖成延迟。
- 没有实时订阅时拿到的是延迟档,数据晚 15–20 分钟(IBKR 文档对延迟档的说法),所以标题右侧常驻新鲜度(最后一根的时间与距今多久)。
  「行情停了」的告警从最新一根**走完**那一刻起算:走完之后 30 分钟还没有新的 K 线才报;它还在走的时候不报,日线不报
  (日线走完之后隔一夜才有下一根)。权限不足时报错说明去哪开订阅。
- 第一档时长取回来不超过 30 根就改取长的那一档:分析要 30 根已收盘的,最后一根常常没走完。
- 周期 1m / 2m / 5m / 15m / 30m / 1h / 日线。日线以外的周期各配一个高周期做背景;高周期拿不到时 `htf` 为 null,`agreement` 照给。
- 默认读全时段(含盘前盘后),可以切到只看常规时段。这个开关只影响取哪些 K 线。盘前盘后成交稀薄,ATR 偏小、摆动点偏碎,
  跨隔夜的缺口多半只是没人交易,警告里写明。
- 缓存按周期定时长:max(15, min(K 线秒数 / 10, 60)) 秒。IBKR 把 15 秒内相同的历史请求算作超频、10 分钟超过 60 次会掐断行情连接,
  所以 `force` 也压不到 15 秒以下(`pa.timeframes` 的 `min_interval` 是 15)。停留本页且已连券商时每 20 秒自动刷新。

## 判定只用已收盘的 K 线

券商给的最后一根通常还在走。它的收盘价每一跳都在变:拿它确认突破,信号会出现了又消失。所以:

- 最后一根没走完时,把它从判定里摘出来,单独放进 `forming`(时间、几点收盘、此刻的开高低收量)。
  摆动点、BOS / CHoCH、扫单、形态、关键位、ATR、区间位置、量能、打分,全部只算到 `closed_bar` 那一根;
  同一根 K 线走完之前,`score` 与 `bias` 不变。图照旧画到最新一根(`bars` / `ma`),`last` 仍是现价。
- `forming.hints` 是"这一根若此刻收盘会成立的突破 / 扫单":把它当成已收盘再走一遍同一套规则得到的,只作提示,界面标「未确认」。
- 收没收盘由纯函数 `barCloseEpochMs` 对着调用方给的时刻算,模块自己不读钟:
  - 日内:时间戳是这一根的起点(IBKR 的口径),起点 + 周期 = 收盘。
  - 日线:只看常规时段的 16:00(美东)收盘,含盘前盘后的 20:00 收盘。提前收盘日实际更早,按这两个点算只会偏晚。
    指数没有盘前盘后,默认的全时段口径下它的日线也按 16:00(handler 看 `index_symbols` 给)。
  - 给了时刻却算不出(周期不认识、时间戳读不懂):拿不准就不让它进判定。不给时刻 = 一段历史切片,全部按已收盘。
- 对着的是**这份 K 线取数的那一刻**,不是现在:缓存里的那一份取的时候没走完,钟点过了它也还是半根(`paBars` 把取数时刻一起带出来)。
  新鲜度(`age_seconds`)照现在算。
- 高周期背景同样只算到它自己已收盘的那一根,`htf.closed_bar` 写明算到哪。

### 延迟行情:钟点到了,数据未必到齐

延迟档的最后一根停在十几分钟前,而且是半根,它的钟点却早就过了。只看钟点会把这半根当成收盘的。所以:

- 券商适配层在取回的那组 K 线上记一笔它出自哪一档(`marketdata.tagFeed`),随 `paBars` 带到分析:
  `live` 实时、`delayed` 延迟、`unknown` 说不准。历史数据的回包里没有这一项,IBKR 这一侧看的是**同一张合约的行情流**:
  会话记着每张正股 / 指数的成交价最近一次出自延迟档还是实时档(`quoteDelayed`),流撤了也记得。
  只读,不为了问这一句去订流或撤流:同一张合约的流是各处共用的,撤一次会把盯盘手里那条也撤掉。
- `delayed`:数据本身的时刻比取数时刻最多晚 20 分钟(延迟档 15–20 分钟的上限,`DELAYED_FEED_MAX_MS`;按上限算是宁可晚认一根)。
  最新一根的钟点要过去满 20 分钟才认它收盘;在那之前它照样进 `forming`,`forming.waiting` 写明原因,界面标「数据未到齐」,
  警告里说明行情是延迟的。
- `unknown`(会话还没见过这张合约的成交价,多半是刚换到一个新标的的第一次读取):按延迟对待,但不说它是延迟的。
  盘中没有差别(最新那一根本来就在走);差别只在钟点刚过的那一根,要等会话见到它的成交价、下一次取数才进判定。
- 富途不带这个记号,只看钟点:它没有延迟这一档,拿不到行情就拒。

这条规则管不到的情况:

- 行情流是实时的、历史 K 线却是延迟的(或者反过来)。两边认的是同一份订阅,按理一致,没有在真机上核对过。
- 时间戳是这一根终点的数据源(富途的日内 K 线口径没有在真机上核对):按"起点 + 周期"算,盘中没有差别(最新那一根照样被摘出来),
  只是收盘后最后一根要多等一个周期才进判定。偏晚,不会偏早。
- 本机时钟比交易所快:快多少,就会提前多少把最后一根当成已收盘。

## 读出来的东西(`priceaction.ts`)

| 项 | 说明 |
|---|---|
| 摆动结构 | 分形高低点整理成严格交替的序列,标 HH / HL / LH / LL,据此判定上升 / 下降 / 震荡 |
| BOS / CHoCH | **收盘**突破前高 / 前低:顺势记 BOS(延续),逆势记 CHoCH(性质改变) |
| 关键位 | 邻近的摆动点按 ATR 容差并成一条线(一簇里最高与最低相差不超过容差),再数有多少根 K 线在这个价位留过痕迹 |
| FVG | 三根 K 线之间留下、尚未回补的缺口;回补 90% 以上的去掉 |
| 订单块 | 推动最近那次突破之前的最后一根反向 K 线,以及突破之后它有没有被回踩 |
| 流动性扫单 | 影线刺穿前高 / 前低(超过那一根当时的容差)但收了回来 |
| 等高 / 等低 | 两个几乎同价的摆动点 |
| K 线形态 | 只看最近几根已收盘的:吞没、锤子、射击之星、内包、外包、十字星、大实体推动 |
| 环境 | ATR、区间位置、EMA20 / 50 排列、相对量能、当日开高低 |

- **突破一律用收盘价确认。** 影线穿一下单独归到「扫单」,和真突破分开报告,两者含义相反。
- **历史上的事件按当时看得到的东西算**(`structureHistory`)。第 i 根上的突破 / 扫单只用到第 i 根为止已经确认的摆动点
  (分形要等右边两根走完才算确认;同向相邻只留更极端的那个,也是确认一个折一个)与那一根自己的 ATR 容差。
  后来的摆动点、后来的波动率不回头改它:同一段 K 线截短了再算,截断处之前的事件一条不变,测试钉着这一条。
  摆动序列与趋势判定描述的是"截至最后一根已收盘 K 线"的样子,那里没有更后面的数据可偷看。
- 订单块的回踩从那次突破之后数起:突破之前的几根是把价格推出去的那一段,不算回来。
- 容差是 ATR 的 0.35 倍(没有 ATR 时退到价格的万分之五);ATR 是最近 14 个真实波幅的简单平均。
- 页面只给价位与条件(确认位、失效位、观察点),不给方向建议、不给仓位,不接下单链路。关键位的远近对着最后一根收盘价算。
- 「AI 解读」发给模型的只有算好的结构结论,不发原始 K 线:模型对着 OHLC 自己看图的结果没人能复核。
  有正在形成的那一根时,事实块里写明哪一根没收盘、哪几句还没确认。
- `pa.analyze` 另给 `ma`(MA5 / 10 / 20,与 `bars` 逐根对应),只用来画图、不进打分。图上每条线都对应引擎算出的一个字段,界面不自己计算。
- 读出方向(不是中性)时 `pa.analyze` 往信号日志记一条,同一标的、周期、方向在两个收盘之间只记一次,之后由[信号成绩单](signal-scorecard.md)按周期打分。
  高周期那份背景不记。

## 打分与三个子分

- **打分公开权重。** 总分 `score` 是各项证据的加权和,限制在 −100 到 +100:结构 30、CHoCH 25、BOS 15、区间位置 15、扫单 15、均线 12、形态 10、
  贴近关键位 8、量能 8。每一条连同权重列在「判断依据」里。权重写死在 `priceaction.ts` 顶部,`bias` 由总分分档(±18 偏多 / 偏空,±45 看涨 / 看跌)。
- **三个子分并排看,互不抵消**(`sub_scores`)。同一张权重表分开加,没有新的权重:

  | 子分 | 管哪几条 | 上限 |
  |---|---|---|
  | 结构 | 摆动结构、最近一次结构事件、均线排列 | 67 |
  | 位置 | 区间位置、贴近关键位 | 23 |
  | 确认 | 扫单、近端形态、量能 | 33 |

  子分不夹:三个加起来可以超过 ±100,总分是它们的和再夹在 ±100 之内。

  合成一个数时,位置好能抵掉结构坏,而这两件事不该互相抵;并排之后一眼看得出"结构向下、只是位置高"。
  一组里同时有看涨与看跌的依据时标 `mixed`(例:高位贴着阻力,区间位置记正、贴近关键位记负)。
- 高周期合不合(`agreement`)不进总分,在界面上和三个子分并排显示。两个周期里有一个方向不明时谈不上顺逆,那句话写明不明的是哪一个。
- 量能这一条的方向看放量那一根自己:收阳记正、收阴记负、开收同价不记方向。它在均线哪一边是「均线动能」的事,不重复算。
- **权重没有校过。** 这些数是手定的。以下几处是已知的口径问题,等这套分数有了历史成绩(见 [信号成绩单](signal-scorecard.md))再按数据定,不凭感觉改:
  摆动结构、结构事件、区间位置、均线、量能五条都是趋势与动量的影子(合计 90 分,而总共只有 123 分);
  区间位置与贴近关键位对同一个位置给出相反的读法;最近一次结构事件与扫单不随时间衰减;均线排列只有多 / 空两档;
  K 线形态不看它出现在高位还是低位(高位的长下影也记看涨)。

## 图(`desktop/renderer-react/src/lib/chart/`)

行情、交易分析、回测、扫描的图共用一个画图引擎:调用方把引擎结果翻译成一份描述(`ChartSpec`:`times / bars / lines / hlines / bands /
vlines / markers / last / legend / header / readout`,所有元素按时间定位),`lib/Chart.tsx` 挂一次、之后描述变了走更新。
框架是 TradingView 的 `lightweight-charts`,业务叠加层用它的 series primitive 自己画(`overlays.ts`):

| 库画 | 自己画 |
|---|---|
| 价格轴与刻度、时间轴、网格、蜡烛、量能子图、十字光标、缩放平移、高分屏与尺寸 | 折线、FVG / 订单块色块、竖带、关键位虚线与左端名字、开平仓竖线、带文字的标记、现价点线、轴上价格标签的避让与引线 |

画法规则:

- 按真实像素画:坐标轴字号 11px、图内标签 9–10px;线宽按每条线设定(默认 1px,净值与偏离这类图用 1.5px);150% 缩放下同样清晰。
- 主图滚轮缩放、拖动平移,拖轴缩放、双击轴复位;自动刷新原地更新,不打乱缩放位置。嵌在长页面里的小图只开拖动,不接滚轮。
- 关键位与现价的价格标签在轴上,按 y 排序、重叠的向两边推开并画引线;现价标签固定。线的名字("上翼""第一档")写在线的左端,同样避让。
- FVG 7%、订单块 6% 填充加 1px 边线,从产生那根 K 线画到最后一根。量能按 95 分位归一化,满格值写在子图右上角。
- 最后一根没进判定时(`forming`),在它上面画一条虚线竖线:还在走的标「形成中」,延迟行情下数据没到齐的标「未到齐」。这一根照常画。
- 蜡烛与量能用 `--chart-up` / `--chart-down`(青绿 / 珊瑚红),文字与圆点用系统色,颜色都从 CSS 变量读,跟随深浅色与「涨跌配色」。
  实体取奇数像素宽,根与根之间留 1–2px,影线落在正中那一列像素。
- 净值曲线画策略与买入持有两条线、1.0 基线,并标出进出场。

用 `lightweight-charts` 时要守的几条:

- 折线自己画:库的折线遇到空白点不断开,会在模型价只在部分分钟有值的蝶价图上画出不存在的线;库的线宽与虚线也表达不了 1.5px 与 `[3,2]`。
- 叠加层挂在一条看不见、每个时间槽都有值的「载体」序列上:库只在可见区间有数据的序列上换算价格坐标,稀疏的蜡烛滚到空白段时叠加层会整层消失。
  载体是第一个加进图的序列,下层(区域、关键位)画在蜡烛之下。
- 价格区间自己算,挂在载体的 `autoscaleInfoProvider` 上,其余序列不参与;下沿边距设 0,顶部按像素给读数行留位,可见范围的上沿是读数行下沿。
- 轴上标签全部用 `fixedCoordinate`,位置由一维避让算好再交给库;引线画在图区最右边几个像素里。
- 量能挂在子图自己的刻度上,不参与主图价格轴的宽度测量。
- 载体序列的 `priceFormat` 跟着小数位走,否则净值在 0.998–1.004 之间的回测图轴上只剩一个 1.000。
- 视口自己管:双击时间轴回到打开时铺满的样子;换色时原样放回视口;换了标的、周期或回测参数时重新铺满并打开价格轴自动缩放。
- 横轴把美东墙钟当作 UTC 喂进去,轴上看到的就是美东时分。
- 关掉 TradingView 角标(它注入的样式不带 nonce,会被 CSP 拦下);Apache-2.0 要求的署名放在「关于」页。
- 容器不加 `overflow:hidden`,否则画布被切成单独的合成层、截图工具抓不到;圆角底色铺在容器上,画布透明。

`desktop/tools/chart_interaction_check.js` 在预览台里真发鼠标事件核对上面这些交互;预览台的数据由 `tools/gen_pa_mock.js`
用引擎纯函数对黄金基线 K 线算出,"现在"取在最后一根走到一半的时候,所以预览台里看得到「正在形成」那一块
(`--stress` 生成首根巨量、关键位挤在一起、FVG 与订单块重叠这类极端样例)。
