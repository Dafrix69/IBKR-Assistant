# 实时 K 线与价格行为分析(K线 PA)

「行情」页(2026-09-18 前是其中的「K线 PA」子页,现在与盘口合成一页)拉一段实时 K 线,按价格行为(Price Action)读盘。**方向判断全部由代码算,
一个字都不经过模型**——模型只在你按下「AI 解读」时,拿代码算好的事实做叙述。

K 线走 TWS 的历史数据接口。**历史数据同样要行情权限**——这一点容易记反:没订阅时
`reqHistoricalData` 直接回 error 162,不会悄悄降级。所以请求前会把行情类型切到延迟(3),
让只有延迟权限的账户也能出图,用完立刻切回实时(1)——`AUTO_MID` 是按盘口定价的,
绝不能被拖成延迟。没有实时订阅时最后一根大约落后 15 分钟,所以标题右侧常驻新鲜度
(最后一根的时间 + 距今多久),超过 30 分钟明确告警。权限不足时报错会直接告诉你去哪开订阅,
而不是甩一句 IBKR 原文。支持 1m / 2m / 5m / 15m / 30m / 1h / 日线,每个周期自动配一个高周期做方向背书。

**默认读全时段(含盘前盘后)**,页面上可以切回「只看正常交易时段」。默认这样定是因为
只取盘中的话,收盘后整条 K 线就停在当日 16:00,盘前那一段完全看不见——而隔夜和盘前
恰恰是缺口与扫单最密集的地方。代价写在警告里:盘前盘后成交稀薄,ATR 会偏小、摆动点会偏碎,
跨隔夜的「缺口」多半只是没人交易。这个开关只影响取哪些 K 线,不影响任何判断逻辑。

软件读出来的东西:

| | 说明 |
|---|---|
| 摆动结构 | 分形高低点整理成严格交替的序列,打 HH / HL / LH / LL,据此判上升 / 下降 / 震荡 |
| BOS / CHoCH | **收盘**突破前高/前低:顺势记 BOS(延续),逆势记 CHoCH(性质改变) |
| 关键位 | 邻近摆动点按 ATR 容差并成一条线,再数有多少根 K 线在这个价位留过痕迹 |
| FVG | 三根 K 线之间留下、尚未被回补的缺口(回补 ≥90% 的自动摘掉) |
| 订单块 | 推动最近那次突破之前的最后一根反向 K 线,以及它有没有被回踩 |
| 流动性扫单 | 影线刺穿前高/前低但收了回来 —— 假突破/猎止损 |
| 等高 / 等低 | 两个几乎同价的摆动点,那一侧大概率堆着一池止损 |
| K 线形态 | 只看最近几根:吞没、锤子、射击之星、内包、外包、十字星、大实体推动 |
| 环境 | ATR、区间位置、EMA20/50 排列、相对量能、当日开高低 |

有两条是刻意的,少了这个模块就会开始骗人:

**突破一律用收盘价确认。** 盘中影线穿一下就当突破,是这类分析最常见的自欺来源。
影线穿透单独归到「扫单」,和真突破分开报——这两件事的含义正好相反。

**打分公开权重。** 结论是各项证据加权求和(结构 30、CHoCH 25、BOS 15、区间位置 15、
扫单 15、均线 12、形态 10、贴近关键位 8、量能 8),每一条连同权重原样显示在「判断依据」里,
分数就是这张表的和。不同意某一条,直接把它从总分里减掉再看结论。权重写死在
`priceaction.ts` 顶部,不随行情浮动。

页面只给价位与条件(确认位、失效位、观察点),**不给方向性建议、不给仓位**,
也不接任何下单链路。停留本页且已连 TWS 时每 20 秒自动刷新;IBKR 对历史数据请求有节流
(同一请求 15 秒内重发即超频,10 分钟超过 60 次会掐断行情连接),引擎侧按周期做了 TTL 缓存,
`force` 也压不到 15 秒以下。

AI 解读那条链路发出去的仍然只有 S2 级数据:**算好的结构结论,连原始 K 线都不发**——
给模型一堆 OHLC 它就会开始自己「看图」,而它看图的结果没人能复核。

## 图怎么画:按像素,不按比例

第一版 K 线是一张按 660×300 画好的 SVG 再被拉伸到整页宽:字号、线宽都跟着容器变(1900px 宽时 9px 的字
变成 26px),没有坐标轴,关键位标签直接按 y 放,价位挤在一起时叠成一团——用户截图里最刺眼的一处。
现在是 `renderer-react/src/lib/chart/`:框架交给 TradingView 的 `lightweight-charts`,业务叠加层自己画
(2026-09-13 从自写的 659 行 canvas 引擎迁过来,见下文「框架换成 lightweight-charts」),照着富途/moomoo 那类图表的工程底线来:

- **按真实像素画**:库量容器、按 devicePixelRatio 出位图,字号 11px、线宽 1px 固定;150% 显示缩放下和 100% 一样清晰。
- **有轴**:右侧价格轴取"好看的"刻度,淡网格;底部时间轴按像素间距抽样,跨日处带日期。
- **能缩放平移**:K线 PA 主图滚轮缩放、拖动平移,拖轴缩放、双击轴复位;每 20 秒的自动刷新原地更新,不把缩放到的位置刷掉。
  嵌在长页面里的小图(交易分析、回测、扫描)只开拖动,不接滚轮——不然鼠标经过图表时页面滚不动。
- **标签放轴上并做碰撞避让**:关键位与现价的价格标签按 y 排序,重叠的向两边推开、画引线回真实价位;现价标签固定不动。
- **区域退到背景**:FVG / 订单块 7% 填充 + 1px 边线,从产生那根 K 线画到最后一根,不铺到轴上。
- **量能按 95 分位归一化**:开盘第一根巨量(公开源常见)不再把其余柱子压成一条线,满格值写在子图右上角。
- **均线来自引擎**:`pa.analyze` 新增 `ma` 字段(MA5/10/20,与 `bars` 逐根对齐,只作图不进打分)。
  "图上每条线都对应引擎算出的一个字段"这条规矩没有破——界面不许自己算,所以加在引擎侧。
- **十字光标**:悬停显示那一根的开高低收量与涨跌幅,只是把 `bars` 里的字段念出来。

颜色全部从 CSS token 读(`--up/--down/--blue/--orange/--purple`),跟随深浅色与「设置 → 涨跌配色」。
预览台的 PA 数据由 `tools/gen_pa_mock.js` 用引擎纯函数对黄金基线 K 线算出(`--stress` 生成极端样例:首根巨量、
关键位挤在 0.6% 区间、FVG 与订单块重叠),改图之前这张图从来没在预览台里被看过。

**一套坐标系画全部的图。** K 线图改好之后,交易分析的两张图(标的走势、蝶价走势)和回测的净值曲线还是
第一版的做法——`viewBox` 等比拉伸、没有轴、蝶价图右侧三个档位标签叠成一团。与其再写三遍,`pa-chart.js`
改成了一个通用引擎:调用方把引擎结果翻译成一份描述(`times / bars / lines / hlines / bands / vlines / markers`,
所有元素按时间定位),轴、网格、轴上标签避让、图内文字避让、十字光标全部复用;K线 PA 只是其中一个适配器。
几条顺带定下来的规矩:

- **蜡烛不用系统绿红。** systemGreen / systemRed 是给圆点和开关用的饱和色,几百根挤在一起会发光;蜡烛与量能柱改用
  图表业界通用的一对(`--chart-up` 青绿 #26a69a / `--chart-down` 珊瑚红 #ef5350),文字与圆点仍用系统色,
  「涨跌配色」一起翻转。实体取奇数像素宽、根根之间留 1–2px 空,影线 1px 落在正中那一列像素。
- **价格标签在轴上,名字在线的左端。** 行权价、止盈档位这类线,价格进轴上的标签(避让),"上翼 / 第一档"这种名字
  写在线的左端(9px,自己也避让);同一时刻的两个事件标签("策略 1 张 @ 3.3" 与 "实际平仓 3.45")按矩形碰撞逐行错开。
- **净值曲线有轴、有起点线、有进出点**:策略与买入持有两条线,1.0 基线,交易明细里的进出场标在策略线上。
- **回测 mock 补上**:预览台的 `runBacktest` 原来返回空对象,结果卡整块 `undefined`——这张图从来没被看过。
  现在返回黄金基线 `backtest.json` 里 `sma_cross` 那一例(引擎真算出来的 curve / trade_list)。

### 框架换成 lightweight-charts(2026-09-13)

spec 的契约(`times / bars / lines / hlines / bands / vlines / markers / last / legend / header / readout`)一字未动,
五张图的调用方只是给 spec 补上了类型(`ChartSpec`)。分工:

| 库画 | 自己画(`overlays.ts`,库的 series primitive) |
|---|---|
| 价格轴与刻度、时间轴、网格、蜡烛、量能子图、十字光标、缩放平移、高分屏与尺寸 | 折线、FVG / 订单块色块、竖带、关键位虚线与左端名字、开平仓竖线、带文字的标记、现价点线、轴上价格标签的避让与引线 |

几处不看源码会踩的坑,都按原来的画法绕开了:

- **折线自己画,不用库的 LineSeries。** 库的折线遇到空白点**不断开**(空白点不进绘制序列,前后两点直接连上)。
  蝶价图的「模型价」只在部分分钟有值,交给库就是在真实价格段上画了一条不存在的线;库的线宽也只有 1–4 整数、
  虚线只有 5 种按线宽成比例的预设,表达不了 1.5px 与 `[3,2]`。
- **叠加层挂在一条看不见的「载体」序列上,不挂在蜡烛上。** 库只在「可见区间里有数据」的序列上换算价格坐标、
  跑 primitives、算价格区间;蝶价图的蜡烛是稀疏的,滚到没有 K 线的一段,挂在蜡烛上的叠加层会整层消失。
  载体每个时间槽都有值,是第一个加进图的序列,所以它的下层(区域、关键位)画在蜡烛之下。
- **价格区间自己算**,挂在载体的 `autoscaleInfoProvider` 上,其余序列一律不参与:可见区间内的蜡烛 + 折线 +
  `fit` 的水平线 / 标记 / 区域 + 现价,各留 5%,`yMin` 夹底。库的 `scaleMargins` 会在夹住的下限之下再留空,
  蝶价图就会出现负数刻度,所以下沿边距设 0、顶部按像素给读数行留位。
- **轴上标签全部用 `fixedCoordinate`。** 库自带的 `alignLabels` 也会推开重叠的标签,但不画引线、也不钉住现价;
  位置由原来的一维避让算好再交给库。避让间距取库画出来的标签高度(约 19.25px,取 20),可用范围是整根价格轴——
  顶部读数行只盖图区不盖轴;引线画在图区最右边几个像素里(库的标签底色从刻度那一段就开始铺,画在轴上会被盖住)。
- **可见范围的上沿是读数行下沿,不是 0。** 主图顶部按像素给读数行留的那一段,对应的是比价格区间上限还高的价;
  原来的引擎在那里什么都不画。不守这条,区间外的阻力位虚线会穿过均线读数行。
- **量能挂在子图自己的叠加刻度上。** 挂右侧价格轴的话,"1500000.00" 这种成交量刻度虽然不显示,仍参与轴宽测量,
  把主图的价格轴也撑宽。
- **载体序列的 `priceFormat` 跟着小数位走。** 价格轴的刻度步长以主图第一个序列为准,默认 `minMove` 0.01 会把步长卡在 0.01:
  净值在 0.998–1.004 之间晃的回测图,轴上只剩一个 1.000。
- **视口三件事自己管。** 双击时间轴回到**打开时铺满**的样子(库自带的复位是回到默认 6px 一根);
  换色(深浅色、涨跌配色)时把视口原样放回去(重新 `applyOptions` 里不能带 `rightOffset`,否则平移到中间的视图被拽回最右边);
  换了标的 / 周期 / 回测参数(`viewKey` 变了)时重新铺满并**打开价格轴自动缩放**——拖过价格轴库就把它关了,不重开的话
  换一个价位差很远的标的,新图整个落在画面外。
- 这几条都由 `tools/chart_interaction_check.js` 在预览台里真发鼠标事件核对(见 [tools/README.md](../../desktop/tools/README.md))。
- **横轴喂墙钟当 UTC。** 时间串是美东墙钟,库按 UTC 显示,原样解析成 UTC 秒数,轴上看到的就是原来的时分;
  不做时区换算。
- **TradingView 角标关掉。** 它往页面注入一段不带 nonce 的 `<style>`,被本应用的 CSP 拦下、控制台报错(截图 smoke 会失败)。
  Apache-2.0 + NOTICE 要求的署名与链接放在「关于」页。
- **不能给容器加 `overflow:hidden`**:画布会被切成单独的合成层,截图工具抓不到。圆角底色铺在容器上,画布透明。

打包体积:渲染层产物 +193 KB(gzip +64 KB)。

期权墙页的价位从一列文字改成**一把梯子**:一根竖轴,墙、关口、现价按价格定位,支撑绿、阻力红、现价蓝点,
右侧写距现价的百分比。离得远近一眼可见——一列数字要一个个读,位置不用读;挤在一起的行按和轴上标签同一套逻辑推开。
