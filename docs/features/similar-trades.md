# 下单页的历史相似交易

交易指令页解析出一张订单(提交的、排队的、只过了校验的都算),订单卡片下面列出**历史里相似的交易**:几笔、赚几亏几、
按出场方式(提前平仓 / 持有到期 / 拆腿)分开的胜负、最像的几笔,再带上提到这个标的的复盘想法。
RPC 是 `ideas.similar_trades`(读道),算法是 `tradeSimilar.ts`(analysis 层,纯函数),`tests/trade-similar.spec.ts` 钉着。

## 边界

- **只读、只展示。** 不拦单、不改单、不进校验,也不回流到任何下单决策。看完怎么下还是人定。
  它和 `protections` 是两回事:那边是规则挡单,这边是把历史摆到眼前。
- **不用嵌入、不调模型。** 规则打分,本地出结果。成交是精确数据,近似检索给的错答案不带「我不确定」
  (见 [idea-retrieval.md](idea-retrieval.md)「边界」)。
- **历史就是知识总结附带的那一批**(`services/tradeHistory.ts`,见 [ideas.md](ideas.md)「交易结果」):券商成交合成的蝴蝶与股票持仓段、
  导入的期权出场事件。成败的口径、「结果不明」的处理都一样,这里不另算。

## 怎么算相似

| 订单 | 先要满足 | 每多一项相近 +1 |
|---|---|---|
| 蝴蝶(`BUTTERFLY`,或 1:2:1 三腿) | 同标的、同为蝴蝶;底分 2 | 同看涨 / 看跌;翼宽差 ≤ 20%;同一到期桶(当日 / 一周内 / 更远);同一美东时段开仓;权利金 / 翼宽差 ≤ 0.05;中心离现价(以翼宽计)差 ≤ 0.5 |
| 垂直价差 / 单腿期权 | 同标的同结构 | —(历史里这两类只有导入的,见下) |
| 股票 | 同标的,底分 2;同自定义板块的别的股票,底分 1 | 同方向(做多 / 做空);同在近 20 日区间的同一档(低位 / 中间 / 高位)进场 |

- **美东时段**:开盘半小时(09:30–10:00)、上午(–12:00)、午后(–15:00)、尾盘一小时(–16:00)、盘外。
  订单按「现在」算,历史按开仓时刻算。
- **导入的期权没有行权价**,只能按「同标的同结构」粗配,底分 1,每条写明「只能粗配」。导出里的「多个仓位同时结算」
  按导出的说法大概率是蝴蝶,只在蝴蝶单下带上,并写明。
- **同板块的股票只列出来,不算进胜负**(`primary: false`)——别的股票赚了不说明这只会赚。
- 分数只用来排序,不是概率。列表按「算胜负的在前 → 分高在前 → 新的在前」,引擎给 8 笔,卡片放 5 笔,悬停看为什么相似。

## 要行情的两项(`services/similarContext.ts`,尽力而为)

取不到就不给,那一项不比、也不扣分,**绝不让整个请求失败**;没连券商时这两项都没有,其余照比。

- **蝴蝶中心离现价**:(中心 − 标的价)/ 翼宽,正 = 中心在上方。这一单用现价(`MarketDataService.spotOf`,指数夜盘是期货推算);
  历史每一只用**开仓那一分钟**的标的价——按开仓的美东日取那天的 1 分钟线(`BrokerRouter.intradayBars` 带 `endDay`,常规时段),
  取「该分钟或之前最后一根」的收盘。**取一次就存进 `trade_entry_context`**(历史不会变),一次请求最多补 3 个交易日、新的优先,
  剩下的下次再补——IBKR 的历史数据有请求频率限制,不能在一张订单卡片上烧光。只有 IBKR 能按日子取历史分钟线(富途的桥没核对过),
  别的券商只用库里已有的。
- **股票进场位置**:进场价在进场**之前** 20 根日线高低区间里的位置(0 = 区间最低,1 = 最高,突破可以出界),分低位 / 中间 / 高位三档;
  这一单用现价对今天之前的 20 根。日线走 `dailyHistory`(10 分钟缓存,一只股一次请求),**只算同标的的**,同板块的不算。
  日线是复权价(ADJUSTED_LAST),和当时的成交价在分红、拆股前后会差一点;拆股那种大跳会把位置算歪——现在的标的里还没有。

## 已知的不够

- 期权只有导入的、没有行权价的历史时,蝴蝶只能粗配。Flex Query 带行权价的成交进了 `broker_fills` 之后,同一天以完整的为准,
  这里自动变成逐项比(连中心离现价一起)。
