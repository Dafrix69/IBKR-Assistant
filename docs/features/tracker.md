# 持仓追踪:到价自动平仓

盯住账户里的一个持仓,设好止盈止损,价格到位时**自动发出平仓单**。

这是整个软件里第二条会真实发单的路径(第一条是指令解析),而且它是在**你不在场的时候**
发。所以闸门要说清楚。

## 闸门:为什么不走 validator 那一套

平仓单**不过**开仓那套限额(单笔名义金额上限、期权张数上限、重复防抖、置信度)。
那些闸门限制的是"新增多少风险";平仓是**减少**风险。拿开仓的限额去挡平仓,后果是
持仓超过限额的人永远出不来——那比放开限额危险得多。

保留下来的是三类:

| 闸门 | 为什么留 |
|---|---|
| `auto_execute` + 每条追踪自己的开关 | 授权问题:你有没有同意软件替你发单 |
| 实盘账户还要 `allow_live_trading` | 这是整个软件最外层那道保护,自动平仓不能例外 |
| 组合(BAG)在实盘还要 `allow_combo_live` | 平组合要反转每条腿再发 BAG 单,这条路**还没在真机上核对过**。"允许碰实盘"和"信任这条新路径"是两件事,分开授权;纸面账户不受这道闸约束 |
| 熔断期间一律不发 | §9.7 说的是"停新单",平仓单也是新单 |
| 当前时段能不能交易 | 客观事实,不是策略。**盘前、盘后都算能交易**:追踪全时段有效,只有休市才拦 |

**期权按合约自己的时段判,不用正股日历。** `Settings.market_status` 是照美股正股写的
(4:00 盘前 / 9:30 盘中 / 16:00 盘后 / 20:00 休市),拿它判 SPX 期权是错的——IBKR 报的 SPXW
是 `19:15–次日 08:25` 加 `08:30–15:00`(US/Central,即美东 **20:15–09:25 隔夜** 与
**09:30–16:00 常规**)。差异是双向的:

| 美东时刻 | 合约真实时段 | 正股日历 | 后果 |
|---|---|---|---|
| 01:10 | 盘外(能交易) | 休市 | 0DTE 蝶整个隔夜段不设防 |
| 09:26 | 休市 | 盘前 | 以为能平,实际发不出去 |
| 16:30 | 休市 | 盘后 | 同上 |

所以期权/组合的持仓走 `broker.contract_hours()`(reqContractDetails,按日缓存)+
`config.hours_status()`,拿不到时段才退回正股日历。IBKR 的时段表已经把周末与节假日算进去
(`20260905:CLOSED`),比自己维护一份假期列表可靠。第三种状态「盘外」和盘前/盘后同等对待:
能交易、只收限价单、要打 `outsideRth`。(2026-09-04 纸面账户实测确认)

**盘前/盘后/盘外照样平。** 交易所盘外只收限价单,所以在这些时段触发的市价平仓会**自动转成
限价单**(按 `slippage_pct` 朝成交方向让价)并打上 `outsideRth`;限价平仓照旧,只加盘外标志。
盘外拿不到现价算不出限价时拒绝并当场提醒,不拿一张盘外根本不会成交的市价单冒充"已平仓"。
托管到券商的止盈/止损单对股票同样打 `outsideRth`,盘前盘后也能在券商侧触发。
持仓行的现价来自 TWS 的 portfolio 推送,盘外经常是空的——拿不到时引擎会退到行情接口再要一次
(仅股票);连行情也没有(账户没有该标的的数据权限)就如实报「拿不到现价,本轮不判断」。

另外三条硬约束:

* **数量取持仓的绝对值,一股不多。** 多平一股就从平仓变成了反向开仓——那是完全没被
  授权过的事。
* **先落闩再发单。** `fired_at` 在 `place()` 之前写:发单走到一半抛异常时,单子可能已经
  到了券商,这时下一轮再发一次就是反向开仓。宁可少发一单让人手动补,不可重复发。
* **到价了但发不出去,必须当场说。** 用户可能正指望这个止损保命,静默失败是最坏的结果。
  提醒只发一次,不刷屏。

## 休市时的现价:昨收只给界面看

个股期权没有夜盘。收盘后行情流里没有买卖价,当天没成交过的合约连最新价也没有,TWS 只报**昨收**
(2026-09-17 美东 03:24 真机,主账户:USO 1016 115P / 120P 只有 close 0.40 / 0.56,订阅没有报错)。
期权腿的现价只认"买卖中间价 → 最新成交",所以那一整晚组合现价和未实现盈亏都是「—」。SPX 期权有夜盘,
不受影响。

昨收单独放在 `close_price`(腿行由 `fillOptionPrices` 填,组合行由 `comboRow` 按腿比例合成,缺一条腿就不给),
持仓列表按它另算一份 `close_pnl` / `close_pct`。界面在没有现价时显示它,并写明「组合昨收」「按昨收估算(休市无报价)」。

**它绝不填进 `market_price`。** 标的盘前 4:00 就开始动了,拿昨晚的期权价去判止损、反解波动率、推托管单的价,
都是拿一个过期的数当现在用——挂着的 GTC 托管单开盘那一下可能就成交在一个错的价上。追踪这边照旧:
没有现价就是「拿不到现价,本轮不判断」,开盘有报价后自动恢复。

## 组合(蝴蝶/价差/铁鹰)怎么平

同一账户、同一标的、同一到期日的期权腿会折成一条 **BAG 虚拟行**(`combo_row`)——用户盯的是
"这只蝴蝶值多少",不是三条腿各值多少。触发按整组净价算,口径与单腿完全同一套。

平它的时候有三条硬规矩:

* **每条腿的方向全部反转。** 持仓是 +1/−2/+1,平仓单就是 SELL 1 / BUY 2 / SELL 1。
  腿的 `action` 才是真实方向——BAG 本身**一律以 BUY 提交**,因为 IBKR 对 BAG 的 SELL 会把
  每条腿再反转一次,那就把保护翼卖了、收权腿买了,建出完全相反的结构。带符号净价由
  `bag_signed_limit` 换算:平掉借方蝶是**收**权利金,提交给 IBKR 的净价必须是负数。
* **组合一律不发市价单。** BAG 的 MKT 会让每条腿各吃一次价差,0DTE 蝶三条腿加起来能吃掉
  大半个净价。`order_type` 选了 MKT 也会自动转限价;拿不到组合现价算不出限价就拒绝发单。
* **腿比例只认 1 和 2。** 认不出的比例宁可报错也不猜——猜错的那张单会在券商侧变成一个
  谁也没打算持有的结构。
* **分批规则至少留 1 张。** "平 1/3"对 1–2 张的组合会算出 0 张,等于把分批做成清仓。

**托管到券商对组合只开了一道窄口子**:按标的目标价挂的那张 GTC 限价止盈单(见下一节)。
STP / TRAIL 与 OCA 组在 IBKR 侧对 BAG 支持不明、没核对过,仍然不挂;其余目标只能走引擎盯盘
这条路(每秒一轮)。

**端到端集成测试。** 纯函数层之外,`combo-close.spec.ts` 9 条把
`poll_trackers` 整条链路跑一遍(触发 → 构造单 → schema → 闸门 → 发单 → 落闩),两侧同构。
串起来才会暴露只有真机才碰得到的那类问题——`unrealizedPNL` 那个拼写错就是这么找到的:
纯函数全绿,账户一有持仓就整个炸。

> **真机核对到哪一步(2026-09-04,纸面账户 TWS 7497)。** `preview_combo_close.py`(随 Python 引擎退役,TS 侧尚无对应脚本;下面的记录保留作核对依据)
> 是这条路的只读预演:连上 TWS、把将要发的那张单打出来,然后停住——它不调用 `place()`。
>

## 标的目标价:预计价位、预估收益,与一张会自己调价的挂单

止盈价问的是「这份持仓值多少」,可人心里想的从来是「**标的**走到哪儿我就走」。
7720 开的 7750/25 点蝶,想的是"涨到 7740 就落袋",不是"蝶价到 8.35 就落袋"——那个 8.35
还得自己算,而且**上午和尾盘不是同一个数**。

所以追踪多了一个 `spot_target`:填标的的目标价,止盈价由引擎每轮现算。

### 它凭什么算得出来

一份持仓 = 若干条腿按**带符号比例**加权。正股 0 条腿,单腿期权 1 条,蝶是 +1/−2/+1,
价差是 +1/−1。给定标的价 S 和 σ,每条腿按 Bachelier 定价再加权求和,就是这份持仓的模型价
(`flyexit.structureValue`;蝶另走 `modelPrice`,值相同,那个写法是为了黄金基线逐字段对得上)。

| 持仓 | 预计价位 | 要不要 σ |
|---|---|---|
| 正股 | 就是目标价本身 | 不要 |
| 单腿期权 | Bachelier 单腿价 | 要 |
| 蝶 / 价差 / 铁鹰 | Σ 比例 × 腿价 | 要 |

正股这一路没有模型,也就没有误差——它的价值全在**预估收益**那一栏:到 250 是赚多少钱、
百分之多少,按和 `unrealized()` 同一套口径算(成本含乘数,市值一侧乘乘数)。

### σ 从哪来:四档,依次退让,并如实报出来

σ 是这里唯一会算错钱的地方,所以每一档都标出来源,界面照着说人话。

| 来源 | 什么时候用 | 为什么 |
|---|---|---|
| `smile` | 组合,每条腿都有报价且解得出 | 每条腿用**自己的**报价反解 σ,再各自在目标价处重估(粘着行权价)。各腿报价加起来就是组合现价,所以在当前标的处正好还原现价;单腿 vega 恒正、根唯一,**翼内翼外一样能解**;标的穿过翼时来源不换,挂单价不跳 |
| `net` | 单腿任何位置;蝶在两翼之间、但腿报价不全 | 拿这份持仓**自己的报价**反解一个 σ。同样自洽,只是所有腿共用一个 σ,没有偏斜 |
| `leg` | 上面都解不动 | 从最贴近平值的那条腿反解(那条没报价就依次往外挪),给所有腿用 |
| `clock` | 都拿不到 | EM×√剩余方差。这是**模型默认值**,不是市场价 |

**为什么组合先走 `smile`。** 用户的原话是"推算应该基于当时实际的波动率"。当时实际的波动率就写在
每条腿的报价里,而且每条腿各不相同(偏斜)——拿一个数代表整只蝶,离平值越远偏得越多。更要紧的是
翼外:蝶开在翼外、赌标的冲到翼边上,正是最常见的用法,而那时蝶价本身反解不出唯一的 σ(下一段),
以前只能退到 `leg` 或 `clock`,算出来的数和市场对不上。

**蝶价在翼外反解不得,因为它有两个根。** 蝶价对 σ 先升后降(峰值在 σ≈28、蝶价 5.04):
7725/7750/7775 的蝶、标的 7720、蝶价 4.50,σ≈19.5 和 σ≈42.6 都对得上——拿它们算
"到 7740 值多少"分别是 **10.20 和 5.54**,差出近一倍。
所以 `impliedSigmaFly` 在 `|S − K| ≥ W` 时**返回 null**,不从两个根里猜一个。`smile` 不走这条路:
它解的是每条腿各自的价,单腿的根永远唯一。

**缺一条腿的报价,`smile` 整档不用**,不拿别的腿的 σ 去填——缺腿的"微笑"还原不了组合现价。
这时退到 `net`(蝶在翼内)或 `leg`。`leg` 那一档有个系统性偏差要知道:所有腿共用最贴近平值那条腿的
σ,远离平值的腿受偏斜影响最大,算出来的会偏(偏哪边取决于当天的偏斜)。界面把来源标出来,
就是不想让人把它当成一个和市场对得上的数。

### 为什么必须每一轮重算

同一个标的目标价,对应的期权价随时间单调上行——时间价值掉光的过程。7725/7750/7775 的蝶,
标的到 7740(EM=36 的时钟 σ):

| 时刻 | 10:00 | 12:00 | 14:00 | 15:00 | 15:45 | 16:00 |
|---|---|---|---|---|---|---|
| 蝶价 | 6.89 | 8.03 | 9.13 | 10.34 | 13.45 | 15.00(内在价值) |

设一次定死,早盘那个 6.89 会在标的还没到 7740 的时候就被打掉——那不是用户要的。
盯盘和托管对账都是**一秒一轮**,这个价就跟着一秒一变。

**行情断了不许接着动价。** `clock` 是模型默认值,拿它每秒去推一张已经挂在券商侧的真单,
等于按一个写死的 EM 把用户的止盈位往上抬。规矩是:`clock` 只用来**起个头**(还没拿到过
市场价时给个初始估计),一旦有过市场价,行情一断就**停在最后一次**,绝不撤单、也绝不乱动。

### 挂单:组合的托管口子只开这一道

`host_at_broker` 打开后,这个价会变成一张 **GTC 限价单挂在 IBKR 服务器上**,并由引擎每秒
`modifyHosted` 改价(同 orderId 重发 = IBKR 的改单语义;撤了重挂会留出一段没有保护的窗口)。
挂着等成交,就是为了插针那一下能扫到——限价按最小跳动 **0.05 对齐,且朝成交方向取整**
(平多头向下),取整只该让它更容易成交,不该更难。

组合此前完全不能托管(§组合怎么平)。现在**只开这一道口子**,而且开得很窄:

* **组合只托管一张 `tp` 限价单。** STP / TRAIL 对 BAG 在 IBKR 侧支持不明、没核对过,一律不挂。
* **BAG 一律以 BUY 提交,净价带符号。** 与 `place()` 同一个 `bagSignedLimit`:平掉借方蝶是
  **收**权利金,发给 IBKR 的净价必须是负数。挂单时签了、改单时忘了签,第一次调价就会把一张
  "收 12.35"改成"付 12.35"——所以 `placeHosted` 和 `modifyHosted` 两头都签。
* **合约走 `closeBagContract`,腿方向全部反转。** 和到价自动平仓拼出同一张单;两条路拼得不一样,
  "核对过的"就只是其中一条。
* **组合托管要先填标的目标价**:券商那边挂的就是按它算出来的那张单,没有目标价就没有这张单。
* **止损 / 跟踪止损 / 利润回撤照样能设**,由引擎盯;触发时把**那张托管单**改到立刻成交的价
  (下一节)。以前这里是"开了托管就不许设"——引擎见到托管就整条让给券商,止损会没人盯,只好禁掉;
  2026-09-10 用户一开托管利润回撤就灰了,这条限制本身就是错的。
* 实盘仍受 `allow_combo_live` 约束,和自动平仓同一道闸;纸面账户不受限。

### 标的到了、或止损类目标触发:追价平仓

托管的止盈单挂在**模型价**上——"标的到了目标价时这份持仓值多少",中间价口径。可平仓是卖在买价:
夜盘 SPX 蝶的买卖价差能有一块多(2026-09-10 真机:组合 3.10 / 4.25,中间价 3.70),标的真冲到了
目标价,那张单也可能就那么挂着。用户要的是"**SPX 到了就走**"。

所以引擎每一轮还要判断**标的到了没有**(`SpotTarget.reached`):同一组 σ 下,持仓在现价处的价值
已经不低于目标价处的价值。单腿、价差就是"越过了目标价";蝶是"进了目标价与它关于中心的镜像之间"——
那一段里蝶只会更值钱。它和"持仓价 ≥ 目标价对应的价"在同一组 σ 下是一回事,两者只在行情口径不一致
(退到最近腿 / 时钟 σ)时差一点,那时以标的本身为准。

触发后怎么平,看有没有托管:

| 情形 | 做什么 |
|---|---|
| 托管的组合:止损 / 跟踪止损 / 利润回撤触发,或标的到了目标价 | 把**那张托管单**改到立刻成交的价;没成交就每一轮按最新买卖价再追,直到持仓没了 |
| 托管的单腿期权:标的到了目标价 | 同上(止损类目标本来就有券商侧的停损单站岗) |
| 托管的正股 | 不追:止盈价就是目标价本身,止损类都有券商侧的单子 |
| 没开托管、开了到价自动平仓(期权 / 组合) | 平仓单的限价按立刻成交的价算(拿不到报价才退回"现价让 0.3%");发出去之后**同样每轮追那张单**,直到成交 |
| 手动「立即平仓」落在已经有单的追踪上 | 不另发:把那张托管单 / 正在追的平仓单改成追价平仓(`sweepExisting`)。两张各平一次就是反向开仓 |

**立刻成交的价**(`naturalClosePrice`)= 把每条腿反着做一遍:持有的买入腿按买价卖出、卖出腿按卖价买回,
再按跳动朝成交方向取整。任何一条腿没有有效买卖价就不算——这一轮不动那张单,更不改回模型价。
唯一的例外是**要卖掉的腿买价为 0**:0DTE 蝶的远翼临近收盘常常没人出价,那条腿按 0 卖、在净价里贡献 0
(IBKR 自己显示组合买价也是这么算的)。以前把它当"没报价"整轮不动,远翼归零的蝶就永远追不了价。
要买回的腿没有卖价仍然不算,算出来不是正数(平掉反而要付钱)也不算。
报价来自持仓腿的**常驻**行情订阅(`optionQuotes`,和持仓腿价同一批流),每秒读得起;以前的
`legQuotes` 每次现订现撤、一等四秒,追不了价。

**越等越让**(`chaseLimit`)。挂在自然价上未必立刻成交:组合单在 COB 上要等做市商整包接,腿的报价可能只有
一张的量,夜盘的报价又常是挂着不动的。光跟着自然价改还不够,要"到了就走"就得越等越让:

| 轮(= 秒) | 挂的价 |
|---|---|
| 第 0–2 轮 | 自然价(多数时候这就成交了,没必要一上来就多让) |
| 第 3 轮起 | 每轮再让一跳(`CHASE_STEP_TICKS`) |
| 让满上限后 | 停在「自然价 − 上限」上跟着自然价走,不再多让 |

上限是 `auto_close.chase_max_pct`(默认 10%,至少两跳:很便宜的组合按百分比不到一跳,等于不追),
再往下就不是"及时成交"而是"贱卖"。试算时把"最多让到多少"和"现在立刻平掉约多少"一起摆出来。
追了 30 轮还没成交提醒一次(不刷屏),人得知道该不该自己出手。

**只朝成交方向动。** 买价抬上去了,挂在下面的卖单本来就会按买价成交,改回去只是多一次改单、多一段在
交易所排队的空档;买价掉下去了,新的自然价减去同样的让价一定更低,顺着追。所以挂的价单调:平多头只降不升。

几条硬约束:

* **改的始终是同一张单。** 追价就是改那张托管单 / 平仓单的限价,不另发——另发一张就是两张各平一次,
  双重平仓等于反向开仓。没开托管的那张平仓单由 `place()` 发出,发出时一并记进券商层的改单缓存,
  改单走和托管单同一个 `modifyHosted`(同 orderId 整张重发)。
* **先落闩。** 触发那一刻 `fired_state` 记成 `sweep:<原因>`,之后不再判第二次;追价单成交后换回原因本身
  (止盈 / 止损 / 利润回撤),界面上显示"追价平仓中",并按轮报"追价第 N 秒:挂 X,立刻成交价 Y,最多让到 Z"。
  平仓单被撤 / 被拒 / 失效也换回原因并**提醒持仓可能还在**——不重发,重发就是反向开仓的风险。
* **部分成交不缩量。** 3 张的单成交 1 张、持仓剩 2,按持仓算出的数量也跟着变 2,可券商那边的总量含已成交的
  那 1 张——把总量改成 2 就只剩 1 张在挂。改单时总量 = 剩余该平的 + 已成交的,且不超过原总量
  (用户在别处手动平了一部分才会更小)。
* **标的退回去也不停。** 用户要的是"到了就走",插针回落正是他预料的那一下。
* **重启接着追。** 托管单由 `adoptHosted` 认领,`fired_state` 里的 `sweep:` 落在库里,认领回来下一轮就接着追;
  没开托管的平仓单按 orderRef(= 记录 id)认领(`adoptCloseChase`),认不到就停在最后的价上,和托管单
  "软件关掉停在最后一次"同一语义。让价的轮数不落库,重启后从头数(先在自然价上等两轮再让)。
* 正股不追:限价就是目标价本身;市价单本来就立刻成交,也不追。

顺带修掉:单腿期权的限价以前一律按 0.05 对齐、托管止盈按两位小数取,可 SPX 期权 3 元以上的跳动是
0.10——12.37、9.88 这种价会被 IBKR 以 110 退单。现在 3 元以下 0.05、3 元及以上 0.10(对一分钱档的
个股期权同样合法),都朝成交方向取整。

托管停损单的触发价(止损 STP、利润回撤 STP 的 aux,TRAIL 的初始停损)同样按这条跳动对齐,方向是
**朝离开市场的一侧**:多头的卖出停损向下、空头的买入停损向上(`hostedStopPrice`)。单腿开了托管,
止损类目标就只有券商侧那张停损单站岗,它被 110 退掉就等于没有止损,所以必须对齐。

方向起初写反过(朝"更早触发"取整,想着少亏一跳),合并前的审查用真实口径复现出问题:持仓刚转盈利时
利润回撤停损离现价不到一跳,向上取一跳就压在现价上或越过现价,IBKR 当场触发,把引擎认为该拿着的仓平掉;
夜盘 SPX 期权买卖价差大,更容易撞上。取整绝不能把停损往市场推——只要引擎口径的触发价在保护一侧,
朝外取整后一定也在。代价是最多晚触发一跳。TRAIL 的初始停损券商校不校跳动没核对过,对齐了一定合法,
所以一起对齐。正股仍是两位小数,组合不托管停损。

### 设置时就拦下来的几种

算不出来的目标价不建追踪——一条永远算不出止盈位的追踪,在界面上和"还没到价"长得一模一样,
用户会以为它在保护自己。

| 拦什么 | 为什么 |
|---|---|
| 卖出的蝶(贷方) | 盈利区在中心之外,一个标的目标价说不清方向 |
| 算出来的价位不比现价更有利 | 挂上去会立刻成交。和"多头止盈价要高于现价"是同一条规矩;蝶会顺带提示往中心靠 |
| 认不出结构 | 正股、单腿期权,以及每条腿都带行权价与看涨/看跌的组合才行 |

**目标价可以在翼外。** 以前这里还拦"目标价在两翼之外",理由是"到那儿蝶就归零了"——那只在**到期那一刻**
成立。离到期还有时间,翼外的蝶照样有时间价值,而且标的往翼靠一步它就涨一截。用户的例子:SPX 7700,
开 7720/7740/7760 的蝶,看 7715 的看涨墙会插针回落——软件要做的恰恰是帮他吃到 7700→7715 这一段
(σ_剩余 15–20 点、约收盘前一两个小时的量级:这只蝶在 7700 约 0.6–1.5,到 7715 约 3.2–4.4)。真正说不通的翼外目标价(离蝶比现在更远)由上表第二条
拦下,不需要另立一条翼外规则。

翼外的目标价有一点和翼内相反:它**只剩时间价值**,同一个 7715,越接近收盘值得越少(翼内的目标价是越来越多)。
所以同样必须每秒重算——挂着的价跟着往下调,标的真冲到 7715 那一刻,挂的就是那一刻该值的价。

**贷方组合的口径。** 组合行的现价按"每组净值的绝对值"记、方向在数量的正负上(`comboRow`),而腿比例带的是
持仓自己的符号,贷方组合按比例加权出来是负数。以前没翻过来:止盈价是负的,永远到不了;托管时被夹成
最小跳动 0.05,挂出一张废单。现在贷方组合的预计价位按同一个绝对值口径给出(平仓要付多少)。

### 夜盘的现价:用期货推算

SPX 只在常规时段计算,夜盘报的是**昨收、一动不动**,SPXW 期权却照常在跳。拿昨收去反解 σ、
推断蝶的看涨看跌、挑行权价全是错的——2026-09-10 美东 02:10 实测:指数 7636.36 不动,真实现价约
7655,差 19 点,足够把「中心 7650 高于现价 → 看涨蝶」翻成看跌蝶。

所以配了期货代理的指数(`index_symbols.SPX.futures`,内置 SPX → ES),常规时段之外
`indexPrice` 返回**期货现价 − 基差**:

* **期货取到期日严格晚于今天的最近季月**(`frontQuarterly`):基差按月份算,离到期越近越小越稳
  (ESU6 离到期 8 天基差 7 点,ESZ6 是 73 点)。到期日当天就换下一张。
* **基差取上一个常规时段最后同一分钟**的两根 K 线相减(`contemporaneousBasis`),不是两个收盘价
  相减——ES 收盘在 17:00,比指数晚一小时,那一小时的行情会被当成基差(实测差 1.7 点)。半日市取 12:59。
* 基差一个夜盘只算一次,**落盘**在数据库旁边的 `index_basis.json`:历史数据恰恰是最先被挡的那一样,
  重启时不该再去取。
* 推不出来就退回官方指数,但 `spotInfo` 标成 `index_stale`,盯盘与预览**当作没有现价**——宁可只守
  不挂,也不拿十个小时前的数去反解。`system.status.index_spot` 里能看到每个指数的现价是怎么来的。
* 速记解析(「50蝴蝶」没写标的)以前直接退公开数据源——那也是指数本身,夜盘一样是昨收。现在先问
  券商,提示里写明现价怎么推的。

### 只有市场价能拿去发单

`clock` 档是写死的 EM 算的模型默认值。拿它挂**第一张**单,那个价用户没同意过;拿它每秒推一张已经
挂着的单,等于按一个假数抬止盈位。所以:

| 这一轮 | 做什么 |
|---|---|
| 有市场价(`none`/`net`/`leg`) | 按它挂 / 改,并记住这个价 |
| 没有,但以前有过 | 停在最后一次的市场价,不撤不改 |
| 从来没有过 | **只守不挂**:不挂新单,也不撤已经挂着的(重启后认领回来的那张) |

新建或修改追踪时,开了自动平仓 / 托管的,试算出来的必须是市场价,否则当场拒绝。

### 调度:一秒一轮,在引擎里,不看界面脸色

跟踪止盈和标的目标价的托管单都是"一秒一变"的东西,节拍慢一拍就是止盈位落后一拍。以前一秒一轮是
**界面**在调 `tracker.poll` / `tracker.reconcile`:窗口最小化、渲染层卡一下、界面没打开这一页,节拍就
跟着停;两条 RPC 还排在交易道里,和大模型解析、下单抢同一条队。现在:

* **节拍器在引擎里。** 连上券商就起一个 1 秒的单线循环(`startTrackerLoop`):一轮跑完才排下一轮
  (`setTimeout` 链,不是 `setInterval`),慢了不叠轮;下一轮的等待扣掉这一轮用掉的时间。
* **一轮只读一次持仓。** 读到的那一份同时给盯盘(`pollTrackers`)和托管对账(`syncHosted`),两边看的
  是同一个快照;读不到就报错跳过这一轮,**绝不当成空仓**(见上文真机那条)。
* **一把锁串起所有改追踪的动作。** 节拍、新建 / 修改 / 删除追踪、手动平仓、熔断停机走同一条 promise 链
  (`withTrackerLock`,RPC 层所有引擎实例共用),不会出现"对账挂着单、另一边把追踪删了"的交错。
* **界面只读结果。** `tracker.poll` / `tracker.reconcile` 改到本地即答道,节拍器在跑时直接返回最近一轮的
  结果和心跳,不再触发计算;触发或被拦时引擎主动推 `tracker` 事件,界面上的「节拍」小灯看心跳。
* **心跳看得见。** `system.status` 的 `tracker_loop`:轮数、慢轮数(> 1.5 秒)、最近 / 最慢一轮用时、距上一轮
  多久、最近一次错误,以及事件循环被占住的时长(`perf_hooks.monitorEventLoopDelay`)——节拍慢了,先看
  是这一轮本身慢,还是别的同步代码把整个进程占住了。

实测(2026-09-10,纸面账户,两条追踪,其中一条托管 BAG):稳态每轮约 60 ms。逐项压上大模型解析、速记、
一年回测、RS / 拐点 / 极值扫描、盘口、宏观带、板块行情、K 线 PA,每一项期间节拍间隔都不超过 1 秒、
事件循环最长被占 33–35 ms;整轮 18 页巡检(首次冷算扫描)里最坏的一次被占 389 ms,那一轮也没超过慢轮线。
启动后近 560 轮,慢轮只有连券商那一轮(2.1 秒,首次订阅持仓与行情)。

## 利润回撤:固定阈值与分档

`profit_drawdown_pct` 是单一百分比:利润比峰值缩水这么多就平。`profit_drawdown_tiers` 是
**分档**——按浮盈相对成本的倍数换阈值:

```
[{"above": 0, "pct": 40}, {"above": 1, "pct": 30}, {"above": 3, "pct": 20}]
```

取所有 `above ≤ 当前倍数` 里最高的一档;再配 `profit_drawdown_late = {"after": "15:00",
"factor": 0.5}` 可以让尾盘阈值减半。界面上勾「分档利润回撤(蝶式 40/30/20)」就是这一套,
RPC 里传 `profit_drawdown_preset: "fly"` 等价。

档位的**唯一事实源是 `flyexit.drawdown_tiers()`**(0DTE 蝶式止盈策略那一节),实盘这边只是
换了个基准:回放按"浮盈 / D"选档,实盘按"浮盈 / 成本"选档,而
`profit_peak / |cost_basis| = (现价 − D) / D`——两边同乘 数量×乘数 就约掉了,所以档位可以
逐字搬过去。黄金对拍锁住了这个等式:同一张组合,两套算出的触发价必须一模一样。

为什么蝶式要分档而不是一个固定百分比:蝶式的盈利有**硬天花板**(最大值 = 翼宽),越靠近
天花板剩余上涨空间越小、下跌风险越大;而同一个百分比在浮盈 0.5 点和 5.75 点时,一个在
组合价差的噪声里、一个是真钱。

## 算错了会赔钱的三个地方

盈亏与触发判断全部是纯函数(`tracker.ts`),脱机单测 28 项,盯的就是这三件:

**方向。** 多头止盈在上、止损在下,空头正好相反。写反了不报错,只会在开仓那一刻立刻
平掉——所以**设置时就拦**,而不是等触发了才发现。

**乘数只乘一次。** IBKR 的 `avgCost` 对期权是**含乘数**的整张成本(5.50 的期权 avgCost
是 550)。成本一侧不能再乘,市值一侧要乘。两边口径不一致会让盈亏差一百倍。

**跟踪止损的峰值要持久化。** 它跟的是"最有利价"不是最新价,只朝有利方向走。峰值不落库
的话,重启一次就退回当前价重新起算——已经锁住的那段利润白锁了。固定止损和跟踪止损同时
存在时取**离现价更近**的那个:保护按更严的算。

## 第四个地方:界面填的数是怎么进来的

上面三件都在纯函数里,测得很细。但还有一段一直没人盯:**界面的载荷 → RPC 入参 → 追踪设置**。`tracker.add`
是在授权软件自动发单,而界面发过来的数值全是字符串(`Tracker.tsx` 的 `start()` 用 `str(tp)` 取表单值),
空串表示"不设"。这一段解析错了,纯函数层的测试一条都不会红:

- 拒掉字符串 → 真应用里一条追踪都建不了(和 2026-09-10 `tracker.target_preview` 漏白名单是同一类:mock 测不出,真机才暴露);
- 把 `''` 当成 `0` → 一个设在 0 的止损;
- 悄悄丢掉一个键 → 追踪建成了,那道保护却没设上,用户以为设上了。

`tests/tracker-rpc.spec.ts` 钉的就是这一段:32 条,输入照界面的原样(字符串、`''`、`undefined` 的键过一遍 JSON 就没了),
经 `s.handle` 走完整条 RPC 路径,假券商只记下收到的单。它是特征测试——钉的是**现在的行为**,包括两处不那么好看的现状:

- `tracker.add` 的回执里 `enabled` 曾经是数字 `1`,`tracker.list` 里同一条是 `true`(回执回的是刚拼的那一行,没过读库的转换;
  `alerts.create` 是同一个毛病)。**2026-09-20 统一成布尔**,单独一笔,`golden:update` 的 diff 恰好一行。
- `tracker.update` 传 `auto_close` 曾经是**整份替换**:没带的键就没了,读的时候靠 `makeAutoClose` 补默认值——只传
  `{close_fraction_pct}` 的话,`order_type` 会从 LMT 悄悄回到 MKT、托管会被关掉。界面只用 `update` 切启停、不传 `auto_close`,
  所以一直是潜伏的。**2026-09-20 改成合并**(只给要改的键,没带的保持原样):在授权自动发单的路径上,部分更新不该悄悄换掉
  下单方式。里面的键不收 `null`——每一项都有默认值,没有"清掉"这个说法,给 `null` 是当场拒。

这份测试自己也验过:把解析分别改坏成上面三种样子(外加逐个丢掉追价上限、尾盘收紧、平仓比例、跟踪止损),6 个变异
全部被抓住。**给这个域的入参加 schema、迁进 `contract/` 的时候,这份测试不许改一个断言**;而且那个 schema 要用
`.strict()`——不认识的键当场拒,不能像别的域那样静默丢掉。

2026-09-20 `tracker.list` / `add` / `update` / `delete` / `target_preview` 就是这么迁的(契约与 schema 的设计见
`engine-rpc.md` 的「契约」一节):这份测试一个断言没改;`Targets` / `AutoClose` / `SpotTarget` 的定义搬进了
`contract/tracker.ts`,`tracker.ts` 里只剩转出,触发判定的函数体没动——改动前后的编译产物去掉注释逐字节一致。

## 盈亏以券商报的为准

IBKR 优先用 `ib.portfolio()`、富途用 `position_list_query` 的 `pl_val`——那是和你在券商
客户端里、以及月结单上看到的同一个口径。拿不到才自己算;**连价格都拿不到时如实回 None**,
界面显示「—」,而不是拿成本价冒充现价算出一个"盈亏为零"的假象。

## 它不是券商服务器上的条件单

盯盘在本机进行:**软件关掉就不再盯**。IBKR 的原生条件单挂在券商服务器上,掉线仍然有效;
这个不是。界面上用醒目的话写着这一条,因为把它当成前者是会出事的。
