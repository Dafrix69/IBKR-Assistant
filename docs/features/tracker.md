# 持仓追踪

盯住账户里的一个持仓,价格到位时由引擎自动发出平仓单。这条路径在用户不在场时发单,所以闸门、数量、方向的规则全部写死在代码里。
界面是「持仓追踪」页,RPC 是 `tracker.*`。

盯盘在本机进行:软件关掉、电脑关机就不再盯。要这段时间也有保护,只能打开「托管到券商」,把单子挂在券商服务器上。

## 目标

| 字段 | 含义 |
|---|---|
| `take_profit` / `stop_loss` | 持仓价到这里就平 |
| `trail_pct` | 跟踪止损:从最有利价回撤这么多个百分点就平 |
| `profit_drawdown_pct` / `profit_drawdown_tiers` / `profit_drawdown_late` / `profit_drawdown_arm` / `profit_drawdown_floor` | 利润回撤,见「利润回撤」 |
| `spot_target` | 标的目标价:标的走到这里就平,持仓的止盈价由引擎每一轮计算,见「标的目标价」。和 `take_profit` 只能选一个 |

自动平仓的设置(`auto_close`):

| 字段 | 默认 | 含义 |
|---|---|---|
| `enabled` | 关 | 打开就是授权软件替这份持仓发单 |
| `order_type` | `MKT` | `MKT` 或 `LMT`(`tracker.add` 把 `LMT` 以外的一律当市价);组合与盘外时段的市价一律改成限价 |
| `slippage_pct` | 0.3 | 限价单朝成交方向让价的百分比 |
| `close_fraction_pct` | 100 | 触发后平掉百分之多少,至少 1 张 |
| `host_at_broker` | 关 | 托管到券商,见「托管到券商」 |
| `chase_max_pct` | 10 | 追价平仓最多让到立刻成交价的百分之几 |

**设置时就拦下的错误。** 多头止盈要在现价之上、止损在之下,空头相反;写反的话开仓那一刻就会平掉,所以建追踪与修改追踪时共用一套
`checkTargets` 当场拒绝。同一份持仓不能建两条追踪。托管只有 IBKR 账户能开,并且要求打开自动平仓(见「托管到券商」)。

**容易算错的三处**(纯函数在 `tracker.ts`):

- 方向:见上。
- 乘数只乘一次:IBKR 的 `avgCost` 对期权是含乘数的整张成本(5.50 的期权 `avgCost` 是 550),成本一侧不再乘,市值一侧要乘。
- 跟踪止损的峰值(最有利价)持久化,只朝有利方向移动,重启后接着用。固定止损与跟踪止损同时存在时取离现价更近的那个。

## 闸门

平仓单不过开仓那套限额(单笔名义金额、期权张数、重复单、置信度):那些限制"新增多少风险",拿来挡平仓会让持仓超过限额的人出不来。
平仓只过下面这些闸门(`tracker.closeBlockers`):

| 闸门 | 说明 |
|---|---|
| 这条追踪打开了自动平仓,且全局 `auto_execute` 打开 | 用户授权软件发单 |
| 实盘账户要打开 `allow_live_trading` | 最外层的实盘保护,自动平仓同样受它约束 |
| 手动熔断期间一律不发 | 自动熔断不挡平仓,见「熔断与已有的保护」 |
| 当前时段能交易 | 盘前、盘后、盘外都能交易,只有休市拦下;托管单挂着等成交,不受这道闸门约束 |
| 没有触发过、持仓数量不为 0 | 一条追踪只发一次 |

组合与单腿过同一套闸门:开仓的组合单只过 `allow_live_trading`,平仓再多要一道授权,就成了能开不能平。

另外三条硬规则:

- **数量取持仓的绝对值,一股不多。** 多平一股就成了反向开仓。
- **先标记已触发再发单。** `fired_at` 在发单之前写入:发单途中出错时单子可能已经到了券商,下一轮再发一次就是反向开仓。宁可少发一单让人手动补。
- **到价了却发不出去,当场提醒一次**(`fired_state` 记为 `blocked`),不刷屏。

## 平仓单

- 组合一律限价(BAG 的市价单让每条腿各吃一次价差);盘前、盘后、盘外一律限价,并打上 `outsideRth`。其余按 `order_type`。
- 限价 = 参考价朝成交方向让 `slippage_pct`,再按跳动朝成交方向取整。期权与组合的参考价是立刻成交价(下文「追价平仓」),
  拿不到报价时用现价;算不出限价就拒绝发单并提醒,不拿一张不会成交的单冒充已平仓。
- 期权与组合的限价平仓单发出之后每一轮追价,直到成交;市价单、正股限价单不追。
- 平仓单对股票走 `SMART`,只留合约四要素。

**跳动。** 单腿期权价 3 元以下按 0.05、3 元及以上按 0.10(对一分钱档的个股期权同样合法),取整看算出来的那个价落在哪一档;
组合一律按 0.05;正股按两位小数。托管停损单的触发价(`hostedStopPrice`)朝远离市场的一侧取整:多头的卖出停损向下、空头的买入停损向上,
取整不能把停损推向现价,否则券商当场触发。代价是最多晚触发一跳。

## 时段

期权与组合按合约自己的交易时段判定:`BrokerRouter.contractHours`(reqContractDetails,按天缓存)配合 `hoursStatus`,
拿不到才用正股日历。IBKR 的 SPXW 时段是美东 20:15–次日 09:25 隔夜与 09:30–16:00 常规,正股日历判不对:

| 美东时刻 | 合约真实时段 | 正股日历 |
|---|---|---|
| 01:10 | 盘外,能交易 | 休市 |
| 09:26 | 休市 | 盘前 |
| 16:30 | 休市 | 盘后 |

「盘外」与盘前、盘后同样处理:能交易、只收限价单、要打 `outsideRth`。IBKR 的时段表已经包含周末与节假日。

## 现价

- 持仓行的现价来自 TWS 的 portfolio 推送;盘外常常为空,这时股票退到行情接口再取一次。都没有就报「拿不到现价,本轮不判断」。
- 期权腿的现价只认买卖中间价,其次是最新成交价。买价为 0、卖价有效(0DTE 远翼临近收盘常见)时按 `(0 + 卖价) / 2` 计算;
  买价为 −1 或缺失才算没有报价。
- **昨收只给界面看。** 个股期权没有夜盘,收盘后只有昨收。昨收写在 `close_price`,持仓列表另算一份 `close_pnl` / `close_pct`,
  界面标明「按昨收估算(休市无报价)」;它绝不进 `market_price`,不参与任何触发判断、σ 反解、托管单定价。
- 已知缺口:盯盘对股票的备用现价走 `BrokerRouter.indexPrice`,其中 `readPriceFrom` 仍会退到昨收,`streamPrice` 也会切到延迟行情;
  股票的追价平仓用的也是这条路。

**夜盘的指数现价。** SPX 只在常规时段计算,夜盘报的是不动的昨收,SPXW 期权却在交易。配了期货代理的指数(`index_symbols.SPX.futures`,
内置 SPX → ES)在常规时段之外,`indexPrice` 返回**期货现价 − 基差**:

- 期货取到期日晚于今天的最近季月(`frontQuarterly`),到期当天换下一张。
- 基差取上一个常规时段最后同一分钟的两根 K 线相减(`contemporaneousBasis`);ES 收盘比指数晚一小时,用收盘价相减会把那一小时算进基差。半日市取 12:59。
- 基差一个夜盘只算一次,存在数据库旁边的 `index_basis.json`,重启不再重取。
- 推算不出来时退回官方指数并标成 `index_stale`,盯盘与试算按没有现价处理。`system.status.index_spot` 显示每个指数的现价来源。

## 组合(蝴蝶 / 价差 / 铁鹰)

同一账户、同一标的、同一到期日的期权腿合成一条 BAG 行(`combos.ts` 的 `comboRow`),触发按整组净价判定,规则与单腿相同。

- **每条腿方向全部反转**:持仓 +1 / −2 / +1,平仓单就是 SELL 1 / BUY 2 / SELL 1。BAG 本身一律以 BUY 提交(IBKR 对 BAG 的 SELL 会把每条腿再反一次),
  带符号净价由 `bagSignedLimit` 换算:平掉借方蝶是收权利金,提交的净价是负数。
- **腿比例只认 1 和 2**,认不出的比例报错。
- **分批平仓至少平 1 张**:按比例算出 0 张时平 1 张,所以 1 张的组合按 50% 平也是全部平掉。
- 铁蝶按铁鹰(`IRON_CONDOR`)处理:同一行权价上看跌排在看涨前面。
- **认不出结构的组合只能提醒。** 断翼蝶、比例价差、风险逆转没有对应的结构,平仓单过不了下单 schema;`tracker.closeContractIssue`
  在设置时说出原因,打开自动平仓或托管当场拒绝,已有的追踪到价时只提醒一次。FOP 同样处理。
  这类组合的净值会穿过 0,所以现价带符号记(借方取净值本身,贷方取相反数),跟踪止损在峰值落到 0 以下时不给停损价。
  标准结构的净值不穿 0,取绝对值。

## 标的目标价

`spot_target` 填标的的价,止盈价由引擎每一轮现算:"标的走到这里时,这份持仓值多少"。
一份持仓 = 若干条腿按带符号比例加权;给定标的价 S 和 σ,每条腿按 Bachelier 定价再加权求和(`flyexit.structureValue`)。

| 持仓 | 预计价位 | 要不要 σ |
|---|---|---|
| 正股 | 就是目标价 | 不要 |
| 单腿期权 | Bachelier 单腿价 | 要 |
| 蝶 / 价差 / 铁鹰 | Σ 比例 × 腿价 | 要 |

预估收益按和 `unrealized()` 同一套算法(成本含乘数,市值一侧乘乘数)。

### σ 的五档来源,依次退让

| 来源 | 什么时候用 | 说明 |
|---|---|---|
| `ibkr` | 每条腿都有 IBKR 推送的模型 IV,且认得出到期时刻 | 每条腿各用各的 IV,换算成点数 σ 后在目标价处重估,锚在当前报价上 |
| `smile` | 组合,每条腿都有报价且解得出 | 每条腿用自己的报价反解 σ,再各自在目标价处重估;在当前标的价处正好还原现价,翼内翼外都能解 |
| `net` | 单腿;或蝶在两翼之间、腿报价不全 | 用这份持仓自己的报价反解一个 σ,所有腿共用,没有偏斜 |
| `leg` | 上面都解不动 | 从最贴近平值的那条腿反解,给所有腿用;远离平值的腿受偏斜影响,结果有系统性偏差 |
| `clock` | 都拿不到 | EM × √剩余方差,剩余方差按校准出的日内分布(`flyexit.VARIANCE_WEIGHTS`,见 [蝴蝶测算](fly-plan.md));这是模型默认值 |

界面照来源标注,让人知道这个数和市场对不对得上。

- **`ibkr` 档**:IBKR 的模型 IV(`MODEL_OPTION_IV`,纸面会话收到的是延迟版 `DELAYED_MODEL_OPTION_IV`,两个都认、实时优先)是年化对数正态波动率,
  换算成点数 σ = 标的价 × IV × √剩余年数(`ivPricing.ts`),平值附近与点数制一致,离平值越远误差越大。
  预计价 = 现价 + (IV 定价在目标价 − IV 定价在现价),IBKR 的 IV 只管"变多少"。
  到期时刻:周度 SPXW / NDXP / RUTW 与个股期权按到期日 16:00 美东;月度 SPX / NDX / RUT(交易类等于代码)开盘结算,09:30 到期,没带交易类就不用这一档。
  缺任何一条腿的 IV 就整档不用(个股期权夜里、行情被别处占用时 IBKR 不推模型值)。
  盯盘(`engine.applySpotTarget`)与试算(`tracker.target_preview`)用同一个 `legInputsOf` 拼各腿的报价、IV、到期。
- **蝶价在翼外不反解。** 蝶价对 σ 先升后降,翼外同一个蝶价对应两个 σ,按两个 σ 算"到目标价值多少"能差近一倍,
  所以 `impliedSigmaFly` 在 |S − K| ≥ W 时返回 null。`smile` 解的是每条腿各自的价,单腿的根唯一。
- **缺一条腿的报价,`smile` 整档不用**,退到 `net` 或 `leg`。
- 跟踪止损、利润回撤、固定止盈止损、追价平仓都不用 IV,它们看市场价与各腿买卖价。

### 每一轮重算

同一个标的目标价,对应的期权价随时间变化。7725 / 7750 / 7775 的蝶,标的到 7740(EM 36 的 `clock` σ):

| 时刻 | 10:00 | 12:00 | 14:00 | 15:00 | 15:45 | 16:00 |
|---|---|---|---|---|---|---|
| 蝶价 | 6.89 | 8.52 | 10.40 | 12.12 | 14.27 | 15.00(内在价值) |

设一次定死,早盘的价会在标的还没到的时候被打掉。盯盘与托管对账都一秒一轮,这个价跟着一秒一变。
目标价在翼外时只剩时间价值,越接近收盘值得越少,同样要每秒重算。

**只有市场价能拿去挂单**(`MARKET_SIGMA_SOURCES`:`none` / `ibkr` / `smile` / `net` / `leg`):

| 这一轮 | 做什么 |
|---|---|
| 有市场价 | 按它挂单或改单,并记住这个价 |
| 没有,但以前有过 | 停在最后一次的市场价,不撤不改 |
| 从来没有过 | 只守不挂:不挂新单,也不撤已经挂着的(重启后认领回来的那张) |

`clock` 只用来在还没拿到过市场价时给个初始估计。新建或修改追踪时,开了自动平仓或托管的,试算出来的必须是市场价,否则当场拒绝。

**标的到了没有**(`SpotTarget.reached`):同一组 σ 下,持仓在现价处的价值不低于目标价处的价值。单腿、价差是越过了目标价;
蝶是进入目标价与它关于中心的镜像之间。到了就改成追价平仓(下文),标的退回去也不停。

### 设置时拦下的几种

算不出目标价的追踪不建:它在界面上和"还没到价"看起来一样,用户会以为它在保护自己。

| 拦什么 | 原因 |
|---|---|
| 卖出的蝶(贷方) | 盈利区在中心之外,一个标的目标价说不清方向 |
| 算出来的价位不比现价更有利 | 挂上去会立刻成交;蝶会提示往中心靠 |
| 认不出结构 | 只认正股、单腿期权,以及每条腿都带行权价与看涨看跌的组合 |

目标价可以在翼外:离到期还有时间时翼外的蝶照样有时间价值,标的往翼靠一步它就涨一截。离蝶比现在更远的目标价由上表第二条拦下。
贷方组合的预计价位按"平仓要付多少"的绝对值给出。

## 托管到券商

`host_at_broker` 打开后,止盈、止损、跟踪、利润回撤挂在 IBKR 服务器上:GTC,同一个 OCA 组(一张成交,券商撤掉其余),
orderRef 是 `trk:<追踪>:<单型>`。软件关掉也生效,停在最后一次的价。只有 IBKR 账户能开。
托管要连着「到价自动平仓」:挂托管单就是发单授权,自动平仓关着时闸门给 `BLOCK_DISABLED`,一张都挂不出去、已挂的撤掉。
所以 `tracker.add` / `tracker.update` 在设置时就拒绝「托管开着、自动平仓关着」,话和界面表单同一句;`update` 查的是合并之后的那一份,
只在给了 `auto_close` 时查,库里已经是这个状态的旧追踪照常能切启停、改目标。

- 跟踪止损挂的是 IBKR 原生的 TRAIL 单,由券商自己跟随。其余动态的价(标的目标价算出的止盈价、利润回撤停损)由引擎每秒 `modifyHosted`
  原地改单(同 orderId 整张重发);撤了重挂会留出一段没有保护的时间。
- 股票的托管单走 `closeContract`、打 `outsideRth`,盘前盘后在券商侧也能触发。
- **组合只托管一张止盈限价单**,按标的目标价计算,所以组合托管要先填标的目标价。STP / TRAIL 对 BAG 的支持在 IBKR 侧没核对过,不挂。
  组合的止损、跟踪止损、利润回撤由引擎盯,触发时改那张托管单去追价。挂单与改单两头都用 `bagSignedLimit` 签符号,合约都走 `closeBagContract`,
  和到价自动平仓拼出同一张单。
- 券商侧的利润回撤停损单(ptrail)只看 `profit_drawdown_pct`,按起算门槛才挂,不用分档与最少回吐;股票与单腿期权都会挂。
- **被拒的处理,在错误到达那一刻按刚做的动作定**:刚挂的被拒 → 券商那边没有这张单,摘掉缓存,退避 60 秒,原因交给界面;
  改价被拒 → 原单原价还在,缓存恢复成上一版;202 已撤单 → 摘掉。比下单返回还早到的错误先暂存,登记之后再对上。
  券商接受过的单(推过 Submitted 或认领回来的)之后来的错误一律按"改价被拒"处理。
- 挂单抛错退避一分钟;拼不出合约这类自身的错退避十分钟、不计入熔断。券商自己撤了托管单时退避一分钟并提醒一次。
- 对账途中券商回报改了追踪(成交标记已触发)就停手,不拿这一轮开头的旧快照接着挂。未成交单列表没取到的那一轮不挂、不改、不撤。
- **认领**:重启后 `adoptHosted` 按 orderRef 认领券商侧的托管单(同一个 ref 有重复的留单号最新的,其余撤掉),等待超过 10 秒就作罢,
  那一轮不挂不改不撤。又有账户连上时重新认领一遍(认领按 orderRef 去重),避免重连后再挂一套。

## 追价平仓

托管的止盈单挂在模型价(中间价口径)上,可平仓卖在买价;夜盘 SPX 蝶的买卖价差常有一块多,标的真到了目标价,单子也可能就那么挂着。
追价平仓把平仓单挂到**立刻成交的价**上,没成交就越等越让。

**立刻成交的价**(`naturalClosePrice`):每条腿反着做一遍,持有的买入腿按买价卖出、卖出腿按卖价买回,加总得到净价
(这一步不取整,挂单时再按跳动朝成交方向取整)。
要卖掉的腿买价为 0 时按 0 计(IBKR 自己显示组合买价也这么算);其余任何一条腿没有有效买卖价就不算,这一轮不动那张单;
算出来不是正数也不算。托管的正股追价时,立刻成交价取现价朝成交方向让 `slippage_pct`。报价来自持仓腿的常驻行情订阅(`optionQuotes`)。

**越等越让**(`chaseLimit`):

| 轮(= 秒) | 挂的价 |
|---|---|
| 第 0–2 轮 | 托管单:立刻成交价;没托管的平仓单:第一次发出时的限价(立刻成交价再让 `slippage_pct`) |
| 第 3 轮起 | 每轮再让一跳(`CHASE_STEP_TICKS`) |
| 让满上限后 | 停在「立刻成交价 − 上限」,跟着立刻成交价移动 |

上限是 `chase_max_pct`(默认 10%,至少两跳)。挂的价只朝成交方向移动:平多头只降不升,所以没托管的那张单头几轮停在第一次的限价上。取整看挂出去的那个价所在档的跳动,
所以让满时可能比上限多出不到一跳。试算时把"最多让到多少"与"现在立刻平掉约多少"一起列出。追了 30 轮还没成交提醒一次。

**什么时候追价:**

| 情形 | 做什么 |
|---|---|
| 托管的组合或单腿期权:标的到了目标价 | 把 OCA 组里的止盈单改到立刻成交的价,没成交每轮再追 |
| 托管的组合:止损、跟踪止损、利润回撤触发 | 同上(组合在券商侧只有止盈单) |
| 托管的其它情形:负责这个触发的券商侧单子不在(止盈 → tp,止损 → sl / trail,利润回撤 → ptrail;被拒退避中、分档利润回撤没有券商侧的单、还没挂上) | 同上,组里没有止盈单就挂一张。必须先对过一次账才作数:刚建的、重启后还没认领的,缓存里没有时券商侧可能仍有 |
| 没托管、到价自动平仓,期权或组合的限价单 | 发出的平仓单每轮追价,直到成交 |
| 手动「立即平仓」 | 见「立即平仓」 |

硬规则:

- **改的始终是同一张单。** 另发一张就是两张各平一次,等于反向开仓。没托管的那张平仓单发出时一并记进券商层的改单缓存,改单同样走 `modifyHosted`。
- **先标记。** 触发时 `fired_state` 记成 `sweep:<原因>`,之后不再判定第二次;成交后换回原因本身(止盈 / 止损 / 利润回撤 / 手动平仓)。
  界面显示"追价平仓中",并按轮报"追价第 N 秒:挂 X,立刻成交价 Y,最多让到 Z"。
  没托管的平仓单被撤、被拒、失效时换回原因并提醒持仓可能还在,不重发;托管的追价单被拒或被撤时摘掉缓存、退避 60 秒,
  `fired_state` 仍是 `sweep:`,托管对账随后在组里按追价的价重新挂出止盈单。
- **部分成交不缩量。** 改单时总量 = 剩余该平的 + 已成交的,且不超过原总量。
- **重启接着追。** 托管单由 `adoptHosted` 认领,没托管的平仓单按 orderRef(= 记录 id)由 `adoptCloseChase` 认领;认不到就停在最后的价上。
  让价的轮数不落库,重启后从头数。

## 利润回撤

- `profit_drawdown_pct`:利润比峰值缩水这么多个百分点就平。峰值价持久化,峰值利润由它换算。
- `profit_drawdown_tiers`:按浮盈相对成本的倍数换阈值,取所有 `above ≤ 当前倍数` 里最高的一档,例如
  `[{"above": 0, "pct": 40}, {"above": 1, "pct": 30}, {"above": 3, "pct": 20}]`。
- `profit_drawdown_late`:例如 `{"after": "15:00", "factor": 0.5}`,尾盘阈值减半。
- `profit_drawdown_arm`(起算门槛):峰值浮盈 / |成本| 没到过这个倍数之前不触发。界面「利润回撤起算门槛 %」新建时默认填 10,清空 = 不设;
  入参 `profit_drawdown_arm_pct` 存成它 / 100,0、负数、超过 1000% 拒绝。没过门槛时界面写"未激活"。
- `profit_drawdown_floor`(最少回吐):现价离峰值价不到这么多价格点(每份,和蝶价同一单位)不触发。触发价取两个条件里离峰值更远的那个:
  多头 `min(成本 + 峰值浮盈 × (1 − 档位), 峰值 − floor)`,空头对称。便宜的蝶会被它把触发价压到成本以下
  (D = 0.30、峰值 0.45 时,40% 的线是 0.39,离峰值 0.20 的线是 0.25),界面把回撤线如实画在成本之下;D < 0.67 的蝶要靠 `stop_loss` 保底。

判定在 `trackerDrawdown.ts`(纯函数)。实盘与交易分析的回放是同一套闸门。

**蝶式预设。** 界面勾「分档利润回撤(蝶式)」或入参 `profit_drawdown_preset: "fly"` 使用蝶式那套:档位 40 / 30 / 20、15:00 之后乘 0.5、
最少回吐 0.20、起算门槛。数值只从 `flyexit.ts` 取(`drawdownTiers()` / `drawdownLate()` / `drawdownArm()` / `drawdownFloor()`),
回放按"浮盈 / D"选档,实盘按"浮盈 / 成本"选档,而峰值浮盈 / |成本| = (现价 − D) / D,两边同乘数量与乘数后相同;
黄金基线对拍锁住这个等式。给了预设就不看 `profit_drawdown_arm_pct`;改成自列档位时预设的几项一起清掉。

### 蝶式按金额起算

组合持仓勾蝶式预设时,起算与收紧改按**每组浮盈的金额**:浮盈到过 $100 才开始追(让 40%),到过 $200 收紧到 30%,
到过成本 3 倍让 20%(只在它高于 $200 那条线时才有)。建追踪时按这只蝶每组的开仓成本(组合行的 `avg_cost`,美元含乘数)
把两条金额线换算成倍数(`flyexit.drawdownUsdPreset`),存进同样的 `profit_drawdown_arm` / `profit_drawdown_tiers`,判定逻辑不变。
例如 $225 的蝶:起算线 0.444 倍,30% 那档从 1 倍成本挪到 0.889 倍。两组的仓合计 $200 才起算。
回放仍按 D 的倍数起算(1.3 × D),两边在这两条线上不同;档位百分比、尾盘收紧、最少回吐相同。
正股、单腿期权勾这个开关,或成本算不出来时,用按比例的预设(起算门槛 0.3)。

- 追踪建好后目标由库里那份决定;要换成新的算法,删掉重建。老追踪的 targets 没有 arm / floor 键,读出来是 null,行为不变。
- 实盘没有回放里的区间规则(0.8W 出界止损、14:00 后 0.45W、阶段 C)。

## 盯盘节拍

- **节拍器在引擎里。** 连上券商就起一个 1 秒的单线循环(`startTrackerLoop`):一轮跑完才排下一轮,慢了不叠轮,下一轮的等待扣掉这一轮用掉的时间。
- **一轮只读一次持仓**,同一个快照交给盯盘(`pollTrackers`)与托管对账(`syncHosted`)。读不到就报错跳过这一轮。
- **一把锁串起所有改追踪的动作**:节拍、建 / 改 / 删追踪、立即平仓、熔断走同一条链(`withTrackerLock`,跨引擎实例共用)。
- **界面只读结果。** `tracker.poll` / `tracker.reconcile` 在本地道,直接返回最近一轮的结果与心跳;触发或被拦时引擎主动推 `tracker` 事件。
- **心跳**:`system.status` 的 `tracker_loop` 给出轮数、慢轮数(> 1.5 秒)、最近 / 最慢一轮用时、距上一轮多久、最近一次错误,
  以及事件循环被占住的时长(`monitorEventLoopDelay`),节拍慢了先分清是这一轮慢还是进程被别的同步代码占住;
  还有 `hold`(醒后这一轮不判断的原因,照常判断时是空串)与 `live_tracks`(此刻在盯的追踪条数,主进程用它决定用电池时提醒不提醒)。

### 停摆与睡醒(`engine/wakeGuard.ts`)

合盖睡着时进程被冻住,节拍器的计时器也不走,醒来只是接着排下一轮;只有墙钟看得出中间过了多久。每一轮开始时把墙钟、单调时钟、
此刻连着的连接名、在盯的追踪交给 `WakeGuard`,规则如下:

| 规则 | 口径 | 理由 |
|---|---|---|
| 停摆 | 相邻两轮开始的墙钟差 > 30 秒 | 正常 1 秒;一轮卡在券商那头二十几秒的见过,不算 |
| 睡着还是卡住 | 墙钟差减单调时钟差占一半以上算睡着,否则算卡住 | macOS 的单调时钟在睡眠里不走 |
| 睡醒先不判断 | 券商连接(连着的连接名不变、不为空)连续稳住 20 秒才恢复;连接一变重新计时;最长 2 分钟 | 醒来那一秒 TWS 给新订阅的可能是睡前的缓存盘口,紧接着断线重连;峰值落库,一轮旧价或新旧腿拼出的净价就能把峰值抬上去,之后拿真价一比就是一次假回撤 |
| 卡住的不等 | 只有睡着的才等 | 卡住的那段时间行情一直在走,等只会更晚 |
| 一整段 | 连着跑满 60 秒没再停才算醒稳;之间的停摆并成一段 | 睡着以后系统每十几分钟维护唤醒一次、每次 2–21 秒,每一次都是一次停摆 |
| 报一次 | 一段结束时写一行日志、一条审计 `monitor_gap`;有在盯的追踪、整段超过 1 分钟才弹通知 | 维护唤醒不刷屏;没追踪的停摆只留痕 |

- 在盯的追踪:启用着、还没触发的,加上平仓单正在追价的。托管的另数,通知里说"券商那边的单照常有效"。
- 等的那几轮持仓照读(持仓腿与正股的常驻行情流跟着续订、到时限照样重订),不判触发、不推峰值、不追价、不改托管单;
  每一行是 `state: holding` 加原因,不带价与评估结果(这几轮的价不可信,不摆出来)。执行对账照做,它不看报价。
- 日志三种:`[盯盘] 节拍停了 …`(每次停摆)、`[盯盘] 醒后等了 N 秒 … 恢复判断`、`[盯盘] 这一段停摆结束 …`。
- 节拍器被有意停掉(引擎重建、断开券商)再起来不算停摆;引擎重建时 `WakeGuard` 交给新实例(`RpcServer.inheritLedgers`),
  醒后正在等的、一段还没报完的接着算。
- 分不出来的:墙钟被人往前拨一大截(看起来就是睡着了,多等 20 秒、多一条通知);单调时钟在睡眠里照走的系统(不确定 Windows 是不是),
  睡着会被当成卡住,只报不等。用电池时的提前提醒在主进程,见 [TWS 连接](tws-connection.md)。

## 盈亏以券商报的为准

IBKR 用 portfolio 推送里的盈亏,富途用 `position_list_query` 的 `pl_val`,和券商客户端、月结单同一个口径。拿不到才自己算;
连价格都拿不到时返回 null,界面显示「—」,不拿成本价冒充现价。

## 读不到 ≠ 平仓了

「持仓已不存在 → 停掉追踪、撤掉托管单」不可逆,所以只在确实读得到这个账户时才下这个结论:

- 读持仓报错(TWS 断线、会话在重连):这一轮整个跳过,心跳 `last_error` 写明原因。
- 账户的会话没连上(不在 `coveredAccounts()` 里):这条追踪这一轮只报「读不到它的持仓,先不判断」,不停、不撤、不发。
- 连回来的第一轮照常判断。峰值只用看得见的那几轮推进;跳空穿过止损就在这一轮平。

**持仓表的维护。** 持仓用常驻订阅,只用首份快照建表,之后按增量自己维护(`applyPositionUpdate`):底层库的缓存在某个持仓归零时会删掉排在它后面的全部持仓。

**腿的行情流被别处撤掉。** 会话层的行情流按合约缓存、不记谁在用;下单定价、盘口页这些临时订阅用完一撤,撤掉的可能正是盯盘那条。
被撤掉的流读到的是空盘口加 `error`,盯盘每一轮读腿价之前先过 `ensureOptionStreams` / `fillPositionPrices`,见到 `error` 就摘掉重订,
首次订阅等首笔报价最多 1.5 秒;那一轮没等到,这条腿没有价,按「拿不到现价,本轮不判断」处理。
期权的缓存键带交易类(SPX 与 SPXW 同到期同行权价各是各的流);持仓的键(`makeKey`)不带交易类,同时持有这两张时会合成一行,
见 [journal/shared-ticker-stream.md](../journal/shared-ticker-stream.md)。

**连着却不来盘口的流。** 断线重连后底层库按原 reqId 把行情流重订一遍,但 TWS 不一定真的再给(真机上见过只来一笔模型 IV、
一笔盘口都没有);流自己没了动静也一样。这种流不报 `error`:断过线的读到空盘口,没断过线的读到冻住的最后一个价。

- 会话层给每条流记两个时刻:最近一次请求(订阅、重连后库重订)与最近一笔盘口 tick(买卖价与量、成交价与量,含延迟的)。
  模型 IV、昨收不算盘口。
- `ensureOptionStreams` / `fillPositionPrices` 每一轮先过 `HeldStreams.usable`:连接还在、却超过时限一笔盘口都没来,
  只撤自己那一条(不带 generic)重订,新的请求换一个新的 reqId。断着的时候不判,等库连回来自己重订。
- 时限按此刻的时段(`heldStreams.silenceLimitMs`):盘中 30 秒,盘外 / 盘前 / 盘后 2 分钟,休市不判。期权用合约自己的时段
  (`cachedContractHours`,缓存里有才用),否则正股表。盘中 0DTE 期权与持仓正股每秒都在跳,半分钟没动静是流断了、不是清淡;
  判错的代价是一次撤订加重订,TWS 对新请求当场回一份现价。
- 重订的那一轮等首笔报价最多 1.5 秒;没等到就是「拿不到现价,本轮不判断」,过了时限再重订。
- 一段没盘口只在头一次写一行日志(`[ibkr] 行情流 … 撤掉重订`),盘口回来再写一行(`重订 N 次后盘口回来了`)。
- 同一条流挂在两个键上(两个账户持有同一条腿):一边重订好了,另一边直接接上那一条,不撤。撤了的话两边每一轮互相撤掉对方刚订的,
  谁都读不到价;流被别处撤掉之后也是这样处理。

**电脑睡着时盯盘不跑。** 用电池时合上笔记本盖子,macOS 直接睡眠,应用挡不住(见 [TWS 连接](tws-connection.md)「软件管不了的」)。
睡着以后引擎只在系统几秒钟的维护唤醒里跑一下,那时拿不到盘口;醒来那一刻 TWS 给新订阅的可能还是睡前的旧盘口。
所以睡醒之后先等连接稳住再判断,醒稳了报一次睡了多久、哪些追踪没人盯,见上面「停摆与睡醒」与
[journal/stale-streams-after-sleep.md](../journal/stale-streams-after-sleep.md)。

**平掉的持仓让出行情线路。** 持仓腿的常驻订阅一条占一条行情线路(IBKR 大约 100 条)。账本在 `heldStreams.ts`;
`BrokerRouter.positions()` 每次读到持仓之后,把持仓里已经没有的腿与正股撤掉,规则偏向多占一条:

| 情形 | 处理 |
|---|---|
| 读持仓报错 | 走不到撤订阅那一步,一条不撤 |
| 连过的连接里有一条此刻断着 | 那个账户的仓这一轮看不见,整轮不撤 |
| 同一张合约还有别的持仓在用 | 只销账,不撤流 |
| 同一只股顶栏行情带或标的现价也订着 | 只销账,不撤流 |
| 盯盘自己那条已被别处撤掉(读到 `error`) | 不撤:同一个键上如果有流,是别人后来订的 |
| 其余 | 只撤不带 generic ticks 的那一条;量能流、期权链、蝴蝶测算的流是别的变体,不碰 |

误撤的代价是一次重订,所以只看一轮。连接层本身的规则见 [TWS 连接](tws-connection.md)。

## 熔断与已有的保护

| | 手动熔断(按钮 / 菜单 / Dock / 状态文件损坏) | 自动熔断(解析或下单连续失败) |
|---|---|---|
| 新指令、条件单 | 不发 | 不发 |
| 券商侧已挂的托管单 | 撤光(`cancelAllOpen`) | 原样保留,不再挂新的、不再改价;界面写明"自动熔断:原样保留" |
| 软件止损、追价平仓、手动「立即平仓」 | 不发 | 照发,那是在减仓 |

自动熔断只说明软件在出错,这时撤掉持仓的保护是最坏的处理。自动熔断会当场弹通知。状态文件里没有 `auto` 这一项时按手动处理。
按下熔断时先合闸再排队撤单:撤单请求 15 秒没回应就放手,回执写明"挂单可能还在"。

## 立即平仓

托管追踪的所有单在同一个 OCA 组里。手动「立即平仓」(`sweepExisting`)把组里的止盈单改到(没有就挂一张)立刻成交的价上,没成交每秒再追;
负责某个触发的托管单不在券商侧时,盯盘(`onTriggered`)走同样的做法。**绝不另发一张组外的平仓单**:组外的单和止损同时成交就是反向开仓。

- 托管的正股同样能追价(立刻成交价取现价朝成交方向让 `slippage_pct`)。
- 点下去当场对一轮账,挂不出去的原因直接回在这一下里;上一次被券商拒绝留下的退避作废。
- 没托管的追踪:期权或组合的平仓单正在追价时,把那张单改到立刻成交的价接着追(重启后由 `adoptCloseChase` 认回来,同样处理);
  上一张平仓单(本进程认得、还没有终态)没在追价(正股限价单、市价单)时拒绝,不发第二张。没托管的正股手动平仓发一张普通平仓单,不追价。
- 时段按合约自己的交易时段判定。
- 触发原因记成 `manual`(`tk.STATE_MANUAL`),两条路都一样:新发的平仓单(摘要「手动平仓:卖出 …」、`auto_close` 痕迹)、
  改成追价的托管单(`fired_state` 是 `sweep:manual`、`hosted_sweep` 痕迹)。追踪卡片显示「已手动平仓」/「手动平仓,追价中」,用中性色。
  保护规则的止损护栏不数它、同标的冷却照常算([保护规则](protections.md));绩效体检的执行损耗把它和到价触发的分开列([绩效体检](performance.md))。

## 入参(`tracker.add` / `tracker.update`)

界面发来的数值全是字符串(`lib/TrackForm.tsx`),`''` 表示不设,不会当成 0。

- schema 是 `.strict()` 的:不认识的键当场拒绝;两个授权开关只收布尔。
- `tracker.update` 三种改法可以一起给:
  - `enabled`:重新启用会清掉上一次触发的标记(`fired_at` / `fired_state` / `fired_record`),可以再触发一次;
  - `auto_close`:**合并**,只给要改的键,其余保持原样,里面的键不收 `null`;
  - 目标字段:给了任何一个,就按"全部目标一起给"处理,没给的被清掉。
- `tracker.add` / `tracker.update` 的回执与 `tracker.list` 同一形状,`enabled` 是布尔。
- `tests/tracker-rpc.spec.ts` 用界面原样的载荷(字符串、`''`、缺键)走完整条 RPC 路径;改入参之前先看它,迁移不许改它的断言。

## 界面

- 追踪列表读不到时留着上一份,顶上说明"追踪列表没读到,下面是上一次读到的"。
- 连续 3 轮读不到盯盘结果就清掉心跳,改为提示"读不到盯盘结果…下面的价格与状态停在最后一次读到的时候"。
- 醒后在等的那几轮,心跳那一行与每张追踪卡片写心跳里的 `hold`(「电脑刚醒,先不判断…」),用警示色。
- 顶栏在引擎不答话时,券商那一格显示「状态未知」。
- 界面醒目地写明:盯盘在本机进行,软件关掉就不再盯。
