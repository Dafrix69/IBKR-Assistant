# 持仓追踪:到价自动平仓

盯住账户里的一个持仓,设好止盈止损,价格到位时**自动发出平仓单**。

这是整个软件里第二条会真实发单的路径(第一条是指令解析),而且它是在**你不在场的时候**
发。所以闸门要说清楚。

## 闸门:为什么不走 validator 那一套

平仓单**不过**开仓那套限额(单笔名义金额上限、期权张数上限、重复防抖、置信度)。
那些闸门限制的是"新增多少风险";平仓是**减少**风险。拿开仓的限额去挡平仓,后果是
持仓超过限额的人永远出不来——那比放开限额危险得多。

保留下来的是三类:

| 闸门 | 为什么留 |
|---|---|
| `auto_execute` + 每条追踪自己的开关 | 授权问题:你有没有同意软件替你发单 |
| 实盘账户还要 `allow_live_trading` | 这是整个软件最外层那道保护,自动平仓不能例外 |
| 组合(BAG)在实盘还要 `allow_combo_live` | 平组合要反转每条腿再发 BAG 单,这条路**还没在真机上核对过**。"允许碰实盘"和"信任这条新路径"是两件事,分开授权;纸面账户不受这道闸约束 |
| 熔断期间一律不发 | §9.7 说的是"停新单",平仓单也是新单 |
| 当前时段能不能交易 | 客观事实,不是策略。**盘前、盘后都算能交易**:追踪全时段有效,只有休市才拦 |

**期权按合约自己的时段判,不用正股日历。** `Settings.market_status` 是照美股正股写的
(4:00 盘前 / 9:30 盘中 / 16:00 盘后 / 20:00 休市),拿它判 SPX 期权是错的——IBKR 报的 SPXW
是 `19:15–次日 08:25` 加 `08:30–15:00`(US/Central,即美东 **20:15–09:25 隔夜** 与
**09:30–16:00 常规**)。差异是双向的:

| 美东时刻 | 合约真实时段 | 正股日历 | 后果 |
|---|---|---|---|
| 01:10 | 盘外(能交易) | 休市 | 0DTE 蝶整个隔夜段不设防 |
| 09:26 | 休市 | 盘前 | 以为能平,实际发不出去 |
| 16:30 | 休市 | 盘后 | 同上 |

所以期权/组合的持仓走 `broker.contract_hours()`(reqContractDetails,按日缓存)+
`config.hours_status()`,拿不到时段才退回正股日历。IBKR 的时段表已经把周末与节假日算进去
(`20260905:CLOSED`),比自己维护一份假期列表可靠。第三种状态「盘外」和盘前/盘后同等对待:
能交易、只收限价单、要打 `outsideRth`。(2026-09-04 纸面账户实测确认)

**盘前/盘后/盘外照样平。** 交易所盘外只收限价单,所以在这些时段触发的市价平仓会**自动转成
限价单**(按 `slippage_pct` 朝成交方向让价)并打上 `outsideRth`;限价平仓照旧,只加盘外标志。
盘外拿不到现价算不出限价时拒绝并当场提醒,不拿一张盘外根本不会成交的市价单冒充"已平仓"。
托管到券商的止盈/止损单对股票同样打 `outsideRth`,盘前盘后也能在券商侧触发。
持仓行的现价来自 TWS 的 portfolio 推送,盘外经常是空的——拿不到时引擎会退到行情接口再要一次
(仅股票);连行情也没有(账户没有该标的的数据权限)就如实报「拿不到现价,本轮不判断」。

另外三条硬约束:

* **数量取持仓的绝对值,一股不多。** 多平一股就从平仓变成了反向开仓——那是完全没被
  授权过的事。
* **先落闩再发单。** `fired_at` 在 `place()` 之前写:发单走到一半抛异常时,单子可能已经
  到了券商,这时下一轮再发一次就是反向开仓。宁可少发一单让人手动补,不可重复发。
* **到价了但发不出去,必须当场说。** 用户可能正指望这个止损保命,静默失败是最坏的结果。
  提醒只发一次,不刷屏。

## 组合(蝴蝶/价差/铁鹰)怎么平

同一账户、同一标的、同一到期日的期权腿会折成一条 **BAG 虚拟行**(`combo_row`)——用户盯的是
"这只蝴蝶值多少",不是三条腿各值多少。触发按整组净价算,口径与单腿完全同一套。

平它的时候有三条硬规矩:

* **每条腿的方向全部反转。** 持仓是 +1/−2/+1,平仓单就是 SELL 1 / BUY 2 / SELL 1。
  腿的 `action` 才是真实方向——BAG 本身**一律以 BUY 提交**,因为 IBKR 对 BAG 的 SELL 会把
  每条腿再反转一次,那就把保护翼卖了、收权腿买了,建出完全相反的结构。带符号净价由
  `bag_signed_limit` 换算:平掉借方蝶是**收**权利金,提交给 IBKR 的净价必须是负数。
* **组合一律不发市价单。** BAG 的 MKT 会让每条腿各吃一次价差,0DTE 蝶三条腿加起来能吃掉
  大半个净价。`order_type` 选了 MKT 也会自动转限价;拿不到组合现价算不出限价就拒绝发单。
* **腿比例只认 1 和 2。** 认不出的比例宁可报错也不猜——猜错的那张单会在券商侧变成一个
  谁也没打算持有的结构。
* **分批规则至少留 1 张。** "平 1/3"对 1–2 张的组合会算出 0 张,等于把分批做成清仓。

**托管到券商对组合仍然不可用**:组合的 GTC+OCA / STP 在 IBKR 侧支持不明,更没核对过。
组合只能走引擎盯盘这条路(每 8 秒一轮)。

**端到端集成测试。** 纯函数层之外,`combo-close.spec.ts` 9 条把
`poll_trackers` 整条链路跑一遍(触发 → 构造单 → schema → 闸门 → 发单 → 落闩),两侧同构。
串起来才会暴露只有真机才碰得到的那类问题——`unrealizedPNL` 那个拼写错就是这么找到的:
纯函数全绿,账户一有持仓就整个炸。

> **真机核对到哪一步(2026-09-04,纸面账户 TWS 7497)。** `preview_combo_close.py`(随 Python 引擎退役,TS 侧尚无对应脚本;下面的记录保留作核对依据)

## 利润回撤:固定阈值与分档

`profit_drawdown_pct` 是单一百分比:利润比峰值缩水这么多就平。`profit_drawdown_tiers` 是
**分档**——按浮盈相对成本的倍数换阈值:

```
[{"above": 0, "pct": 40}, {"above": 1, "pct": 30}, {"above": 3, "pct": 20}]
```

取所有 `above ≤ 当前倍数` 里最高的一档;再配 `profit_drawdown_late = {"after": "15:00",
"factor": 0.5}` 可以让尾盘阈值减半。界面上勾「分档利润回撤(蝶式 40/30/20)」就是这一套,
RPC 里传 `profit_drawdown_preset: "fly"` 等价。

档位的**唯一事实源是 `flyexit.drawdown_tiers()`**(0DTE 蝶式止盈策略那一节),实盘这边只是
换了个基准:回放按"浮盈 / D"选档,实盘按"浮盈 / 成本"选档,而
`profit_peak / |cost_basis| = (现价 − D) / D`——两边同乘 数量×乘数 就约掉了,所以档位可以
逐字搬过去。黄金对拍锁住了这个等式:同一张组合,两套算出的触发价必须一模一样。

为什么蝶式要分档而不是一个固定百分比:蝶式的盈利有**硬天花板**(最大值 = 翼宽),越靠近
天花板剩余上涨空间越小、下跌风险越大;而同一个百分比在浮盈 0.5 点和 5.75 点时,一个在
组合价差的噪声里、一个是真钱。

## 算错了会赔钱的三个地方

盈亏与触发判断全部是纯函数(`tracker.ts`),脱机单测 28 项,盯的就是这三件:

**方向。** 多头止盈在上、止损在下,空头正好相反。写反了不报错,只会在开仓那一刻立刻
平掉——所以**设置时就拦**,而不是等触发了才发现。

**乘数只乘一次。** IBKR 的 `avgCost` 对期权是**含乘数**的整张成本(5.50 的期权 avgCost
是 550)。成本一侧不能再乘,市值一侧要乘。两边口径不一致会让盈亏差一百倍。

**跟踪止损的峰值要持久化。** 它跟的是"最有利价"不是最新价,只朝有利方向走。峰值不落库
的话,重启一次就退回当前价重新起算——已经锁住的那段利润白锁了。固定止损和跟踪止损同时
存在时取**离现价更近**的那个:保护按更严的算。

## 盈亏以券商报的为准

IBKR 优先用 `ib.portfolio()`、富途用 `position_list_query` 的 `pl_val`——那是和你在券商
客户端里、以及月结单上看到的同一个口径。拿不到才自己算;**连价格都拿不到时如实回 None**,
界面显示「—」,而不是拿成本价冒充现价算出一个"盈亏为零"的假象。

## 它不是券商服务器上的条件单

盯盘在本机进行:**软件关掉就不再盯**。IBKR 的原生条件单挂在券商服务器上,掉线仍然有效;
这个不是。界面上用醒目的话写着这一条,因为把它当成前者是会出事的。

> 真机验证到哪一步:失败路径实测过(未连接券商时给的是明确拒绝,不是空列表);
> **带真实持仓的成功路径没能实测**——联调时 OpenD 已经关了,而 TWS 没在跑。
> 第一次用请务必先在模拟账户上跑一遍,确认平仓方向和数量都对再开实盘。
