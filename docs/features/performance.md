# 绩效体检

交易分析一次看一笔;这一页看全部:把已了结的交易摊成一本美元账,算出实盘比赛优胜者和他们的教练反复强调的那几个数,再用写死的规则挑出行为上的毛病。
代码在 `engine-ts/src/performance.ts`(区间与检验在 `inference.ts`),RPC 是 `review.performance`(读道),界面是「研究 → 绩效体检」。全部在本机计算,不调模型、不外发。

## 这些数的来源

| 来源 | 在这里变成什么 |
|---|---|
| Van Tharp(交易员教练) | 期望值、R 倍数、SQN |
| Mark Minervini(美国投资锦标赛冠军) | 平均亏损要远小于平均盈利、小亏就走、赚钱时加仓亏钱时减仓 |
| Larry Williams(1987 年 World Cup 期货冠军) | 资金管理决定能不能活下来;凯利只当上限参照 |
| Andrea Unger(World Cup 期货组四届冠军) | 优势只在某些时段 |
| Kevin Davey(World Cup 期货组) | 样本够多才谈得上优势 |
| 国内期货实盘大赛 | 收益与回撤一起看 → 恢复因子、最大回撤 |
| 职业交易员 / 自营公司 | 日亏上限(见 [保护规则](protections.md)) |
| Mark Douglas、Brett Steenbarger(交易心理) | 报复性交易、过度交易 |
| Jesse Livermore / William O'Neil | 截断亏损、让利润奔跑 → 持有时长的处置效应 |

## 账本

同一批交易、同一套去重,与知识总结、下单页的历史相似交易共用 `services/tradeHistory.ts`;库里的券商成交读全表(见 [交易分析](tradereview.md))。
打开这一页时也会把券商当天的成交同步进库(15 秒内不重复)。

| 来源 | 一笔是什么 | 盈亏 | 风险(R 的分母) |
|---|---|---|---|
| 券商成交合成的蝴蝶 | 开仓那张 + 配上的平仓单;没平的过了到期日按到期日收盘结算 | (平仓价 − 开仓价)× 乘数 × 张数,扣两边成交回报里的佣金 | 最大可亏:买蝶 = 权利金;卖蝶 = 翼宽 − 收的权利金(不对称的不算) |
| 股票持仓段 | 从空仓到空仓一段 | 已实现盈亏 − 佣金 | 初始止损:开仓后 15 分钟内设的追踪止损(见下);没设、设晚了的没有 |
| Flex 期权仓位 | 一个仓位的完整生命周期 | Flex 的已实现盈亏(已扣佣金) | 最大可亏:蝴蝶、垂直价差、单腿的借方开仓 = 权利金;贷方、比例蝶、日历不算 |
| 按结构整理的期权出场事件 | 一次出场一笔 | 导出里的已实现盈亏(已扣佣金) | 没有;也没有开仓时刻 |

不进账本的在账本下面分三类数出来:持仓中、结果不明(到期结算价取不到,没连 TWS 时取不到日线)、成本不明(建仓早于已同步的成交)。
回报里没有佣金的笔数写进说明。

**实盘与模拟。** 范围选「实盘 + 模拟」(`scope: all`,默认)时两边的交易混在一本账里算;结果的 `mix` 写明各几笔,两边都有时页面顶上出一条提示。
模拟盘的成交与滑点是撮合出来的,要看真实水平切到「实盘」。

## R 的分母与覆盖

R = 盈亏 / 初始风险。分母有两种,每一笔的 `risk_basis` 写明是哪一种:

| `risk_basis` | 用在 | 是什么 |
|---|---|---|
| `max_loss` | 蝴蝶、Flex 的借方结构 | 开仓时的最大可亏。它是个恒等式,不用猜;比"打算亏多少"大,所以这类交易的 R 偏小 |
| `stop` | 股票 | \|进场均价 − 初始止损\| × 峰值股数。加过仓的按峰值算,分母偏大、R 偏小 |

两种分母不是一回事,混在一个 SQN 里时结论里会写明各几笔;「品种」表把每一类的 R 期望、R 盈亏比、R 凯利、SQN 分开给。

**股票的初始止损。** 止损不在成交里,但建追踪时填了。追踪只能建在已有的持仓上,所以止损一定晚于成交;只认开仓后 `INITIAL_STOP_MINUTES`(15 分钟)
之内建的、止损在保护一侧(做多低于进场均价、做空高于)的最早那条追踪的 `stop_loss`。再晚设的不当分母:涨上去之后才把止损挪到成本下面一点,
分母只剩几美元,R 会虚高到几十。之后改过、上移过的也不算。来源是 `audit_log` 里界面写的 `tracker_add`(`store.plannedStops`,只增的痕迹);
配法(`performance.plannedStopFor`):同标的,痕迹里有账户别名的还要同账户。没有止损的股票不拿 ATR 的倍数之类的数去顶:那是猜的风险,不是当时愿意亏的数。
15 分钟是人定的时限(只够"成交 → 打开持仓追踪 → 填好止损"),没有数据可以估它;`r_coverage` 里 `late_stop` 的笔数就是它切掉的那些,嫌紧嫌松看这个数。

**覆盖。** R 的统计与 SQN 只代表有 R 的那一部分,而这部分不是随机抽的(设了止损的交易和没设的不是一类交易)。`r_coverage` 数出来:
范围内几笔、几笔有 R、两种分母各几笔,以及没有 R 的按原因分——`no_stop` 股票开仓后 15 分钟内没设止损、`late_stop` 止损设晚了、
`undefined_risk` 风险不止权利金、`no_open` 导入的出场事件没配上开仓、`no_cost` 开仓价或数量不明。每一笔的 `r_missing` 是同一套原因,账本的 R 那一栏鼠标停上去能看到。

## 指标

- **持平**:|盈亏| < 1 美元。它算一笔、进净盈亏与权益曲线,不打断连胜连亏,但**不进**胜率、盈亏比、保本胜率、期望值、凯利与 R 的统计。
- **胜率**、**盈亏比**(平均盈利 / |平均亏损|)、**保本胜率**(1 / (1 + 盈亏比))、**期望值**(分了输赢的那些笔的净额 / 笔数)是同一个分母。
  只有这样「期望值 = 胜率 × 平均盈利 − 败率 × |平均亏损|」与「胜率高于保本线 ⇔ 期望值为正 ⇔ 凯利为正」才是恒等式。
- **按美元还是按 R。** 整体的期望值、盈亏比、`kelly` 按美元算:品种混着时,几千上万名义金额的股票单会盖过几百权利金的蝶,界面的标签写着「按美元」,
  并提示看「品种」表(每类各算各的盈亏比与凯利)。`r_stats` 把胜率、盈亏比、凯利按 R 再算一遍:R 把仓位大小除掉了,
  而且凯利的本意是"单笔拿账户的百分之几去冒险",只有按 R 才对得上。有 R 时凯利那条结论说的是按 R 的。
- **SQN** = √min(N, 100) × 平均 R / R 的标准差,只数有 R、分了输赢的交易,不到 10 笔不算。档位照 Van Tharp 的表:
  1.6 以下 差、1.6–1.9 低于平均、2.0–2.4 平均、2.5–2.9 好、3.0–5.0 优秀、5.1–6.9 极好、7.0 起 圣杯。
  它照原式把每一笔当成独立的:同一天做好几笔相关的交易时偏高,正负分没分清看旁边 R 期望的区间。
- **平仓权益曲线**按了结时刻累计,峰值从 0 起步,与回撤护栏同一个算法;横轴是第几笔。
- **凯利比例** f = W − (1 − W) / 盈亏比,输赢不到 8 笔不算;只当上限参照,界面写明冠军实际的单笔风险在 0.5%–2%。
  公式把每笔亏损都当成平均亏损那么大:f 是"平均亏一笔亏掉账户的百分之几",不是权利金或 1R 占账户的比例。
- **时段**按美东开仓时刻:开盘半小时(09:30–10:00)/ 上午(至 12:00)/ 午后(至 15:00)/ 尾盘一小时(至 16:00)/ 盘外。
  档怎么分只有一处(`tradeSimilar.slotOf`),与下单页[历史相似交易](similar-trades.md)是同一张表;`performance.sessionOf` 只给每一档配一个稳定的键。
  另按品种、星期、标的拆开看。

## 区间与噪声

几十笔交易算出来的胜率与期望值本身就在晃,所以每个要紧的数旁边给 95% 置信区间,比两组的规则要先过一道"差别是不是噪声"。
算法都在 `inference.ts`,是教科书上的闭式或精确算法;95% 是统计上的惯例,不是调出来的数。

**同一天了结的几笔不当成几次独立的试验。** 一天做三只蝶、三只都看同一个收盘价,那是一次半试验,不是三次;当成三次,区间会窄得不该那么窄
(模拟 14 天、每天三笔、同日相关 0.3:本来没有优势的账有一成二会被说成"期望值为正 / 为负";按天成簇之后回到 5% 上下)。
所以区间按**美东了结日**成簇:簇内可以相关,只有天与天之间当独立,自由度是天数 − 1。每天只做一笔时,它们就是平常的 t 区间、Welch 区间、Wilson 区间。

| 量 | 方法 | 用在 |
|---|---|---|
| 胜率 | Wilson 区间(样本小、贴着 0 或 100% 时也不出界),样本数先按设计效应打折 | `stats.win_rate_ci` |
| 期望值、R 期望 | 平均数的 t 区间,方差取"按天成簇"与"每笔独立"两种算法里大的 | `stats.expectancy_ci`、`r_stats.expectancy_ci`、各分组的 `expectancy_ci` |
| 两组每笔盈亏之差 | 同上的两组版(每天一笔时就是 Welch 区间,两组方差不必相等) | `revenge`、`recent`、`overtrading`、`session`、止损护栏与冷却的建议 |
| 两组持有时长 | 每组每天取一个中位数,再做 Mann–Whitney 秩和(时长一头很长,不比平均数) | `disposition` |
| 两个比例之差 | Newcombe 区间(两边的 Wilson 区间拼出来) | `size_after_loss` |
| 中位数 | 次序统计量的精确区间,不假设分布;不到 6 笔定不出 95% | 执行损耗各合约类型的 `median_ci` |

- 区间跨着 0 就是"正负还没分清":期望值那条结论说的就是这一句,界面上这个数不上色,凯利也不给人当真。
- 交易全在同一天了结时,天与天之间的波动无从估起,区间是 null,结论照实说"一天的行情定不出区间"。
- 两组在同一天都有交易时:同涨同跌会让差别更确定,这里不靠它缩窄区间;此消彼长会让差别更不确定,这一头照实计入。
- 盈亏的分布偏、尾巴厚,t 区间在样本少时偏窄——它是"至少有这么不确定",不是保证。跨天持有、几天的行情连着走的相关也没有算进去。
- `session` 是从几个时段里挑最好与最差来比,等于把每一对都比了一遍:置信水平按对数收紧(Bonferroni),不然挑出来的那一对总是"显著"。
- 这道关和笔数、倍数、百分点那些门槛是「且」的关系:两头都过才开口。

## 行为规则

阈值写死,样本不够就不说,两组之间的差别没出噪声也不说(见上一节);先说期望值,再说风险,最后说行为。

| id | 什么时候说 | 语气 |
|---|---|---|
| `sample` | 不到 30 笔 | 提示 |
| `expectancy` | 输赢 ≥ 5 笔:期望值的区间整个在 0 以上 / 以下;跨着 0 时说「正负还没分清」 | 好 / 坏 / 提示 |
| `payoff` | 盈亏比 < 1 且胜率低于保本胜率 + 5 个百分点 | 留意 |
| `sqn` | 有 R 的交易 ≥ 10 笔;写明盖住了几笔、两种分母各几笔 | ≥ 2.5 好,1.6 以下留意,之间提示 |
| `kelly` | 输赢 ≥ 8 笔(有 R 用按 R 的):期望值的区间在 0 以下说"没有下注优势",跨着 0 说"还不能当真",在 0 以上才给数 | 留意 / 提示 |
| `recent` | 至少 20 笔:最近 10 笔为负而全部为正(该缩仓),或最近更好;且最近 10 笔与之前那些的差别出了噪声 | 留意 / 好 |
| `tail_loss` | 亏损 ≥ 5 笔且最大一笔超过平均亏损 3 倍;或亏损 ≥ 10 笔且最大 3 笔占总亏损一半以上 | 坏 |
| `drawdown` | ≥ 10 笔:恢复因子 ≥ 2 为好,否则留意 | 好 / 留意 |
| `worst_day` | ≥ 5 个交易日,最差一天 ≥ 亏钱日平均的 3 倍 | 留意,指向日亏上限 |
| `overtrading` | 单日笔数 ≥ max(4, 中位数 × 2) 的日子 ≥ 3 天,那些天每笔为负,且比其余日子差到噪声之外 | 留意 |
| `disposition` | 输赢各 ≥ 5 笔有持有时长:亏的中位数 > 赚的 × 1.5(坏),反过来(好);且秩和检验认两组不一样 | 坏 / 好 |
| `revenge` | 亏完 30 分钟内开的仓 ≥ 5 笔、其余 ≥ 5 笔,前者每笔为负,且比其余差到噪声之外 | 坏,指向止损护栏与冷却 |
| `size_after_loss` | 亏损了结后的头一笔 ≥ 5 次、盈利了结后的头一笔 ≥ 5 次;前者 ≥ 30% 占用放大到**同品种**中位数 1.5 倍以上,比后者高 10 个百分点以上,且两个比例之差的区间不跨 0 | 坏 |
| `session` | 两个时段各 ≥ 8 笔,最好的赚、最差的亏,且两者的差别出了噪声(按比较的对数收紧) | 提示 |

- `tail_loss` 的集中度要 10 笔亏损起步:5 笔一样大的亏损,最大 3 笔就占 60%,笔数少时"占一半"是必然的。
- `size_after_loss` 的"上一笔"是**这一笔开仓时已经平掉的最后一笔**(按了结时刻认,和 `revenge` 一样),不是开仓次序上的前一笔:
  前一笔可能还开着,那时并不知道它会亏。没有开仓时刻的了结(导入的出场事件)也算上一笔——那一笔亏了,人是知道的。
  同一时刻了结的有好几笔时(几只蝶一起到期结算),看它们合起来是赚是亏。一次了结只认它后面开的**头一笔**:
  亏一笔之后接连开五只蝶,是一次亏损之后的事,不是五次。
- `revenge` 与同标的冷却的那一组里,一笔开平在同一刻的亏损不把自己的了结当成"之前的那笔亏损"。
- `size_after_loss` 按同品种的中位数比,并要求比赢后明显高:股票的名义金额和蝶的权利金混在一起比,仓位本来就忽大忽小,会被误报成亏后加码。
- 结论只描述已经发生的事与一条可以对照的规矩,不给买卖建议、不给具体仓位。

## 执行损耗

自动平仓按触发那一刻的持仓现价(中间价口径)对实际成交均价计算。两条平仓痕迹(`auto_close` 到价平仓、`hosted_sweep` 托管单改成追价平仓)记下 `mark`
(触发那一刻的持仓现价),`hosted_sweep` 还记下托管止盈单的记录 id;`execQuality.ts` 把它和那张单的成交均价(组合只认 BAG 行)对上:

- **让出** = 平多头卖低了(mark − 成交)、平空头买高了(成交 − mark),× 成交份数 × 乘数。成交比触发价好时是负数,照实记。
  它只是**滑点**:佣金不在里面,另记一栏(`commission_usd`,取那张平仓单成交回报里的佣金)。
- 美元的合计与每笔平均可以跨合约相加。**百分比不行**:股票的是占股价的百分比(零点几),组合与期权的是占权利金的百分比(几个点),不是一个量。
  所以中位数按合约类型分(股票 = STK,蝴蝶 = BAG,期权 = OPT / FOP);整体的 `median_pct` / `avg_pct` 只在样本全是同一种合约时才有,混着时是 null。
- 每类的中位数带 95% 区间(`median_ci`,次序统计量的精确区间)。不到 6 笔定不出这个区间,界面标「样本少」——"几笔才够"由区间能不能定出来决定,不另设门槛。
- 回测的「每边成交成本」是佣金 + 滑点:填对应那一类的中位数,再加佣金占成交额的比例;标着「样本少」的不该拿去用。
- 模拟账户的笔数单独数出来(`paper`):模拟盘的成交是撮合出来的,不代表真实滑点。
- 算不出的记为 `missing`:痕迹里没有 mark(包括手动「立即平仓」把已有的单改成追价的那种)、单子没成交、找不到那张单。
- 持仓追踪的「立即平仓」走的是同两条痕迹,触发原因记成 `manual`,表里「路径」一栏写成「手动 · 立即平仓」或「手动 · 托管追价」,和到价触发的分开看。
- 手动下的单不在里面:限价单成交只会比限价好,市价单下单时没留参照价。这里只量"软件替你平"的那一段。

## 保护规则建议

`performance.protectionAdvice` 按这本账给保护规则的参数,界面「按建议填入」确认后发一次 `settings.patch`,只带那一条规则的那一段。引擎自己不改设置。

| 规则 | 什么时候建议 | 建议值 |
|---|---|---|
| `daily_loss` | 亏钱日 ≥ 5 天,且至少有一天越过建议线 | 亏钱日平均的 2 倍,向上取整到 10 美元 |
| `stoploss_guard` | 最长连亏 ≥ 4 笔,或「报复性交易」那条成立 | 120 分钟内 3 次 → 暂停 60 分钟 |
| `cooldown` | 同一只标的亏完 30 分钟内又开的 ≥ 5 笔,平均为负,且比其余差到噪声之外 | 30 分钟 |

- `daily_loss` 与 `cooldown` 在规则关着、或开着但比建议松时给;`stoploss_guard` 只在关着时给。已经比建议严的不劝人放松。
- `daily_loss` 的说明不说"到线就停,剩下的亏损就不会发生",只说把这条线放回这本账上走一遍的结果(`performance.dailyLossReplay`,建议里的 `replay`):
  判法和真规则(`protections.ts`)一样——每笔开仓的那一刻,数美东当天到这一刻为止已实现的净额,净亏到线,这一笔算被拦下。
  被拦下的笔后来是赚是亏都从账上拿掉(拦掉的盈利也算),它们不再计入当天的已实现盈亏;到线之前已经开着的仓照常走完,它们的亏损这条线管不着。
  回放给:几天碰到过线、拦下几笔(赚几笔、亏几笔)、这些笔合计多少;开仓时刻不明的另数。拦下的合计是正数时照实说"反而少赚"。
  回放按整本账算,真规则只数经引擎发出的单的已实现盈亏(见 [保护规则](protections.md)):在 TWS 里直接下的单多时,真规则到线比回放晚,说明里写着这一句。
  粒度也比真规则粗:账本把一笔交易的盈亏记在它平完的那一刻,真规则按每一批成交的回报累计——分批止损的交易,真规则到线更早。
- 线(亏钱日平均的 2 倍)是拿同一段历史定的,回放也在这段历史上:这是样本内的数,说明里写着"往后未必还合适"。2 倍这个倍数是经验值,没有拿数据估过。
- 回撤护栏不给建议:它和日亏上限切的是同一类坏日子,两条一起按数据填会互相冲突,由人自己挑。
- 止损护栏的建议写明它数哪些平仓:持仓追踪到价触发的止损类平仓;追踪上点的「立即平仓」、在 TWS 里直接下的单、指令框里手敲的平仓都不算。
  它的触发条件(连亏 ≥ 4 笔)不看那几笔隔多久,和规则的两小时窗口对不上,所以说明里另给一个旁证(`performance.lossBursts`):
  这本账上两小时内接连了结 3 笔亏损、够它停一次的情形出现过几回(窗口与暂停同真规则:还在暂停里又来一笔只是往后延,不算新的一回);
  0 回时照实写"按亏损了结来数,这组参数一次也凑不够"。只是旁证:账本里没有平仓原因,
  数的是亏损了结,真规则数的是持仓追踪触发的止损与利润回撤平仓,两边不是同一样东西。
  120 分钟 / 3 次 / 60 分钟这组建议值是经验值,没有拿数据估过。

## 分享卡片

页头「分享卡片」把当前范围画成一张 1080×1350 的 PNG(4:5),拷进剪贴板或另存:

- 默认不带金额:胜率、盈亏比、每笔期望(有 R 用 R,没有用利润因子;R 期望的区间跨着 0 时不上色)、SQN、连胜连亏、恢复因子;净盈亏与最大回撤要打开「显示金额」才画。
  权益曲线只画形状、不标坐标轴(刻度会把金额带出去)。
- 账本里混着模拟盘时副标题写「实盘 + 模拟盘」;不到 20 笔时页脚写「样本 N 笔,偏少」。
- 涨跌配色跟随设置。不含账户、标的明细、持仓。
- 图在渲染层画(`lib/shareCardDraw.ts`);写剪贴板、存盘在主进程(`image-export` 通道只收 `data:image/png`、限 12 MB,保存路径由主进程的对话框决定)。
  渲染层没有剪贴板权限。

## 仓位计算器

固定风险比例:先定这一笔最多亏账户的百分之几,再倒推做几份。算法在界面的 `lib/sizing.ts`,权益与比例记在本机 localStorage。
每份最大亏损的起始值取账本里蝴蝶每笔总风险的中位数。另给一行"照这个比例连亏历史最长连亏那么多笔,累计回撤多少"(复利),单笔风险超过 2% 时卡片转成留意。只算不下单。
