# 交易分析:蝴蝶与股票的复盘

页面顶上的「全部 / 蝴蝶 / 股票」筛选列表。两种交易走同一对 RPC、同一条 K 线通道,结论各有各的口径:
先讲蝴蝶,股票见文末[「股票」](#股票一段持仓算一笔)一节。

侧栏「研究 → 交易分析」。**分析的对象是 IBKR 里真实成交过的蝴蝶**,不是本地记录:引擎从 TWS 拉取
逐笔成交(`reqExecutions`),按订单(permId)把 1 条 BAG 行 + 3 条腿行合成一张蝴蝶(`ibtrades.ts`,黄金对拍 `ibtrades.json`),再拉取标的在**开仓前后到平仓 / 到期**的 K 线,画出三条行权价、
到期盈利区、开仓与结局标记,并按规则给出结论。交易记录详情里的蝴蝶也有「分析这笔交易」按钮直接跳过来。

**TWS 的接口只给当天的成交**,所以每次拉到的都存进本地库 `broker_fills`(只增不改,按 execId 去重),历史
一天天累积——想留住某天的成交,那天得连着引擎开过一次交易分析或点过「同步成交」。
**攒之前的历史用导入补**:`node dist/src/cli.js import-fills fills.csv --account <别名> [--dry-run]`
(`fillsCsv.ts`,`tests/fills-csv.spec.ts`)读 IBKR 账户成交导出,写进同一张 `broker_fills`,按 exec_id 去重、已有的行不动
(TWS 同步来的那份佣金是 0,导出里是真的,也不覆盖——只增不改)。导出里没有账户号,`--account` 按配置里的别名指明。
**只收股票**:那份导出的期权行没有行权价 / 到期日 / 看涨看跌,拼不出蝴蝶;残缺的行一旦进库,以后带合约描述的导出(Flex Query)
会因为 exec_id 相同被静默忽略。期权等 Flex。

**按结构整理的期权交易另走一张表**:`cli import-option-trades trades.csv --account <别名> [--dry-run]`
(`optionTradesCsv.ts`,`tests/option-trades.spec.ts`)把「一行 = 一个结构的一次动作」的导出写进 `imported_option_trades`,
不进 `broker_fills`,交易分析页也不用它(拼不出合约、画不了图)。它只给想法总结当出场成败的事实,见 [ideas.md](ideas.md)。

**Flex 期权仓位**:`cli import-option-positions option_positions.csv --account <别名> [--dry-run]`(`optionPositionsCsv.ts`,
`tests/option-positions.spec.ts`)。导出方从 Flex 逐腿成交(执行级 + 到期记账)按行权价配好的仓位表,一行一个仓位的生命周期:
开仓结构、中心、翼宽、到期、开仓净价,了结方式(整体平仓 / 持有到期 / **拆腿后到期** / 逐腿平仓),盈亏(按腿先进先出分回、已扣佣金)。
写进 `option_positions`(`importedTrades.ts`,和上面那张同在 `store.imports`)。**同一段时间以它为准**:它覆盖的 (账户, 美东日)
上,按结构整理的期权事件与券商成交合成的蝴蝶都不再算进结局(`services/tradeHistory.ts`)。
**交易分析页还不用它**:页面拿 `broker_fills` 合成蝴蝶画图,而那套配对认不出拆腿——先平身、翼到期的会被当成拿到期、按帐篷值算盈亏。
要把 Flex 逐腿成交也灌进 `broker_fills`,得先让 `tradereview` 认得拆腿,是另一件事。没连 TWS 时列表就是
库里累积的那些;富途没有同形的成交查询,这个页面在富途通道下只看得到之前从 IBKR 同步来的。打开「附带本地
未成交的记录」才会把本地校验过但没成交的蝴蝶也列出来(按限价估算,卡片上标明)。

净权利金优先取 BAG 行的成交价(券商撮合的净价);逐腿成交没有 BAG 行时按 Σ(买腿 价×比例) − Σ(卖腿 价×比例)
算。同一条腿分几笔成交按数量加权,时间取最早。只认 1:2:1、同到期、同方向的三腿,别的组合不猜。

开仓 ↔ 平仓的配对(`tradereview.pairButterflies`)想法的知识总结也在用(附带交易结果时,见 [ideas.md](ideas.md)),改它两边一起变。

引擎侧是纯函数(`tradereview.ts`,黄金对拍 `tradereview.json`),RPC 两个方法:
`review.candidates {include_local}` 列出可复盘的蝴蝶(同时把券商成交同步进库),`review.analyze {id, timeframe}` 复盘,
`id` 以 `ib:` 开头的是券商成交合成的记录。周期默认 `auto`:离现在越近越细
(1.5 天内 1 分钟、4.5 天内 5 分钟、9.5 天内 15 分钟、28 天内 1 小时,再远走日线),也可以手选。日内 K 线与
K线 PA 共用同一条缓存,日线走历史数据接口;和 PA 一样需要连接引擎,只有延迟行情权限也能出图。

几条口径,算错了会误导人,所以写死:

* **标的价格用 K 线收盘价**,开仓 / 平仓时刻对齐到"该时刻或之前最后一根 K 线"。成交时间接受 ISO 带时区、
  IBKR 原样的 `20260903 09:52:10`(按美东)两种。
* **平仓的认定**:其它记录里同一张蝴蝶(同标的、同到期、同方向、同三个行权价)的反向成交单;找不到且已过到期日
  16:00 美东就按**到期结算**(结算价取到期日最后一根 K 线的收盘);否则算持仓中,给"若此刻到期"的盈亏。
* **理论价值 = 到期内在价值**(蝴蝶的帐篷)。"曾有的机会"说的是"若在那一刻到期",**不是当时能卖到的价**——
  文字里明确写着。它也**不是下界**:离到期还有时间时,标的越靠近中心,蝶的市价比内在价值低得越多;而"最好的理论时刻"
  按定义就是标的离中心最近的那一刻。2026-09-26 之前这里写的是"是下界",真机上一张 7700/7720/7740 看跌蝶
  (3.15 买、+90 平)被写成「12:23 若当时到期 +411」,那一分钟组合中间价只有 4.65(+150),用户据此以为少赚了三百多。
* **有组合分钟线时改用中间价说**(`tradereview.marketOpportunity`,handler 在止盈回放之后调):IBKR 组合 MIDPOINT
  分钟线,窗口是开仓那一分钟起、到平仓那一分钟**之前**(那根 K 线收在平仓之后)或到期日 16:00 之前,取最高的收盘中间价
  写进 `stats.best_market`,"曾有的机会"那一条以它开头、内在价值那个数退到句尾并说明卖不到;平仓不比它差时改成 good,
  内在价值那条没出但盘面上真有过更好的浮盈时补一条。中间价仍比能成交的买价乐观,文字说"按它平仓",不说"能卖到"。
  只认多头蝶(卖出的蝶组合价的符号没核对过);拿不到组合分钟线(IBKR 只给最近一个到期日)就保持内在价值那句。
* **没成交的单**按限价算盈亏区间、按提交时间定开仓时刻,结果里 `notes` 与卡片都标"估算"。

结论有八条,每一条的数字都能在 `stats` 里对上:结构与盈亏区间、开仓位置(离中心几个翼宽)、开仓前 20 根与
开仓后 6 根 K 线的走势是否顺着蝴蝶要的方向(空头蝴蝶反过来)、持有期间的区间与最接近中心的时刻、盈利区内
收盘的 K 线占比、曾有的机会、结局(平仓 / 到期 / 持仓中)、方向对错。

## 股票:一段持仓算一笔

引擎侧 `stockreview.ts`(纯函数,`tests/stockreview.spec.ts`)。`review.candidates` 里 `kind: "stock"` 的行、
id 以 `stk:` 开头;`review.analyze` 见到这种 id 就走股票复盘,返回的 `kind` 也是 `"stock"`,没有 `exit_plan`
(止盈策略回放是蝴蝶的事,页面上 EM 输入框跟着置灰)。

* **一笔交易 = 一段持仓**:同一账户同一只股票,仓位从 0 到非 0 再回到 0。中途加仓、分批卖出都在这一笔里;
  成本按移动平均(加仓摊均价,减仓不动均价),已实现盈亏 = Σ(卖价 − 均价)× 数量,做空反号。一笔成交把仓位打穿
  (多 100 卖 150)就拆开:100 平掉旧的一笔,50 另起一笔反向的(id 带 `:r`)。同一订单(permId)的几笔成交并成
  一次“出手”,价格按数量加权——图上一个三角,而不是一串。
* **期初仓位靠当前持仓反推**(`services/stockTrips.ts`,想法总结附带交易结果时也用这一份):TWS 只给当天的成交,库里的成交是一天天攒的,最早那笔卖出多半卖的是更早买的货;
  照字面读就成了“做空再买回”。所以 期初仓位 = 当前持仓(`router.positions()`,15 秒缓存)− 库内成交净额,
  不为 0 的那一段标 `carried`:没有建仓价,**成本与盈亏不编**,只复盘出场(出场前走势、卖出之后)。
  没连券商、或券商读持仓报错时拿不到当前持仓(读不到 ≠ 空仓),每一笔标 `opening_assumed`,列表里写“期初持仓未核对”。
  这时**卖出不读成卖空**:期初按“刚好够卖”的多头算(从 0 累计到过的最低仓位,负多少补多少),先卖的那部分就是
  “卖的是更早买的货”——`carried`,成本与盈亏不编。最早的版本在这里当期初空仓,2026-09-19 真机上没连 TWS 打开就是
  一排「卖空 … 持仓中」,还给先卖后买的 RKLB 编出一笔 +342.92 的做空盈亏;而真是卖空的人,连上券商后按真实持仓
  重算会改回来。`notes` 里写明这条推断,以及“之前要是有空头仓位,方向可能认反”。
* **进场 / 出场位置**:均价落在持有期区间(K 线最高最低,成交价在 K 线之外时把成交价也算进去)的什么位置。
  进场 1 = 买在最低(做空:卖在最高);≥ 0.7 算进得好,≤ 0.3 提示之后有过更好的价格。
* **最大浮盈 / 最大浮亏**按持有期内 K 线的最高 / 最低对**最终均价**算,金额乘这一笔的最大持仓;加过仓的是估算
  (加仓前那段实际仓位更小),`notes` 里标明。**兑现率** = (出场均价 − 进场均价)/ 最大浮盈,`capture_pct` 是
  文字和界面共用的整数。浮亏超过浮盈两倍要点名。
* **开仓后走势**对第一次出手的成交价比,不对最终均价比:最终均价是加仓之后才有的,拿它衡量“一进场走得怎么样”会冤枉人。
* **卖出之后**看最后一次出场后的 20 根 K 线:对“要是没走”有利的那头(多头看最高)是“没吃到的”,另一头是“躲开的”,
  哪头大就是哪个结论。
* 持仓中的按最后一根 K 线收盘算浮动盈亏,已减仓的部分算已实现;佣金单列、不从盈亏里扣。

结论最多八条:结构(或“只有出场 / 成本未知”)、开仓前走势(顺势追 / 逆势接)、进场位置、开仓后走势、持有期、
出场位置(或“出场前走势”)、卖出之后、结局(平仓 / 持仓中)。每一条的数字都在 `stats` / `outcome` 里。

图:蜡烛 + 成交量 + 买入 / 卖出均价线 + 每次出手一个三角(买朝上、卖朝下,落在成交价上)。

**窗口按交易日算,不按根数**(2026-09-21 改):装下整段持仓,**前后各多给一个交易日**;总跨度不足
**5 个交易日**就继续往前补(前面没数据了才往后)。同时**不比原来的 40 / 20 根窄**——日线那条路上
40 根就是 40 个交易日,按交易日算反而会缩,所以两者取更宽的那个。超过 240 根抽稀时每次出手所在的
那根一定留着。

> 为什么改:原来和蝴蝶共用「前 40 根 / 后 20 根」。对 0DTE 蝶是对的——它本来就活在日内;对股票不对:
> **15 分钟下 60 根只有 15 小时**,而股票是跨天持有的,只给你看成交那一天等于没有上下文。
> 而且 K 线**早就取到了**(15 分钟那条一次取 10 个交易日,见 `marketdata.ts` 的 `TIMEFRAMES`),
> 是窗口把它扔掉了,不是数据不够——所以这一改不多取一根 K 线。蝴蝶那条路照旧不动。

**「交易日」是按美东日期前缀分的**,靠的是 `barTimestamp()` 把 IBKR 的交易所时区换算成美东再落字符串。
美股全时段 04:00–20:00 不跨午夜,所以一个日期前缀就是一个交易日。**这是一条承重前提**:换成跨午夜的
品种(期货、外汇)之后,一个交易时段会被劈成两个日期,窗口会缩到一半。现在到不了——`groupStockTrips`
入口就 `secType !== "STK"` 全部丢掉,`reviewStock` 对非股票记录直接抛「不是股票交易」,两道都有用例钉着
(`tests/stockreview.spec.ts` 的「只认股票」与「记录不是股票:报 ReviewError」)。谁要把期货接进复盘,
先回来改 `sessionOf()`。
