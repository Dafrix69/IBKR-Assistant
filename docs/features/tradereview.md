# 交易分析

蝴蝶与股票的逐笔复盘,页面顶上按「全部 / 蝴蝶 / 股票」筛选。两种交易走同一对 RPC、同一条 K 线通道,结论各有各的规则。
界面是「研究 → 交易分析」;交易记录详情里的「分析这笔交易」直接跳过来。

- `review.candidates {include_local}`:列出可复盘的交易,同时把券商当天的成交同步进库。
- `review.analyze {id, timeframe}`:复盘一笔。`id` 以 `ib:` 开头是券商成交合成的蝴蝶,以 `stk:` 开头是股票持仓段。
- 周期默认 `auto`:离现在越近越细(1.5 天内 1 分钟、4.5 天内 5 分钟、9.5 天内 15 分钟、28 天内 1 小时,更远用日线),也可以手选。
  日内 K 线与行情页共用缓存,日线走历史数据接口;需要连着券商,只有延迟行情权限也能出图。

## 成交从哪来

- **TWS 只给当天的成交**(`reqExecutions`),所以拉到的都存进本地库 `broker_fills`(只增,按 execId 去重),历史一天天累积。
  写入的时机:打开交易分析页或点「同步成交」、打开绩效体检页(15 秒内不重复)、执行对账在给出「去向不明」之前问一次当天成交、命令行导入。
  读的时候读全表(`store.listFills()`,不设上限,按成交时间从早到晚):蝴蝶的开平配对、股票从空仓推到空仓都要完整的历史。
  页面上的「库内成交 N 笔」数的也是全表(`store.countFills()`)。
- **之前的历史用导入补**:
  - `node dist/src/cli.js import-fills fills.csv --account <别名> [--dry-run]`(`fillsCsv.ts`):IBKR 账户成交导出,写进 `broker_fills`,按 exec_id 去重、
    已有的行不动。只收股票:那份导出的期权行没有行权价、到期日、看涨看跌,残缺的行进库之后,以后带合约描述的导出会因为 exec_id 相同被忽略。
  - `cli import-option-trades trades.csv --account <别名> [--dry-run]`(`optionTradesCsv.ts`):「一行 = 一个结构的一次动作」的导出,写进
    `imported_option_trades`,不进 `broker_fills`;只给想法总结当出场结果用,交易分析页不用。
  - `cli import-option-positions option_positions.csv --account <别名> [--dry-run]`(`optionPositionsCsv.ts`):从 Flex 逐腿成交配好的仓位表,
    一行一个仓位的生命周期(开仓结构、中心、翼宽、到期、开仓净价、了结方式、按腿先进先出分回的已扣佣金盈亏),写进 `option_positions`(`importedTrades.ts`)。
    它覆盖的 (账户, 美东日) 上,按结构整理的期权事件与券商成交合成的蝴蝶都不再算进结局(`services/tradeHistory.ts`)。
    交易分析页不用它:页面从 `broker_fills` 合成蝴蝶画图,而那套配对认不出拆腿。
- 导出里没有账户号,`--account` 按配置里的别名指明。
- 富途没有同样形状的成交查询,富途通道下只看得到之前从 IBKR 同步来的。打开「附带本地未成交的记录」会把本地校验过但没成交的蝴蝶也列出来,
  按限价估算,卡片上标明「估算」。

## 蝴蝶

**合成**(`ibtrades.ts`,黄金基线 `ibtrades.json`):按订单(permId)把 1 条 BAG 行加 3 条腿行合成一张蝴蝶。净权利金优先取 BAG 行的成交价;
没有 BAG 行时按 Σ(买腿价 × 比例) − Σ(卖腿价 × 比例)。同一条腿分几笔成交按数量加权,时间取最早。只认 1:2:1、同到期、同方向的三腿。

**规则**(`tradereview.ts`,黄金基线 `tradereview.json`):

- 标的价格用 K 线收盘价,开仓与平仓时刻取"该时刻或之前最后一根 K 线"。成交时间认四种写法:IBKR 实时推送的 `20260910-10:00:01`(UTC)、
  带时区名的 reqExecutions 字符串、不带时区的 `20260903 09:52:10`(美东)、美东墙钟 `YYYY-MM-DD[ HH:MM[:SS]]` 与带时区的 ISO。
- **平仓的认定**:其它记录里同一张蝴蝶(同标的、同到期、同方向、同三个行权价)的反向成交;找不到且已过到期日 16:00 美东,就按到期结算
  (结算价取到期日最后一根 K 线的收盘);否则算持仓中,给"若此刻到期"的盈亏。开平仓配对(`pairButterflies`)想法总结也在用,改它两边一起变。
- **理论价值 = 到期内在价值**(蝴蝶的帐篷)。"曾有的机会"说的是"若在那一刻到期",它可能高于当时能卖到的价:离到期还有时间时,标的越靠近中心,蝶的市价比内在价值低得越多。
- **有组合分钟线时改用中间价说**(`marketOpportunity`):IBKR 组合的 MIDPOINT 分钟线,窗口从开仓那一分钟起,到平仓那一分钟之前或到期日 16:00 之前,
  取最高的收盘中间价写进 `stats.best_market`;"曾有的机会"以它开头,内在价值退到句尾并说明卖不到。平仓不比它差时改成好的结论;
  内在价值那条没出现但盘面上真有过更好的浮盈时补一条。中间价仍比能成交的买价乐观,文字说"按它平仓"。只认多头蝶;拿不到组合分钟线
  (IBKR 只给最近一个到期日)时保留内在价值那句。
- 没成交的单按限价算盈亏区间、按提交时间定开仓时刻,结果与卡片都标"估算"。

**结论有八条**,每条的数字都在 `stats` 里:结构与盈亏区间、开仓位置(离中心几个翼宽)、开仓前 20 根与开仓后 6 根 K 线的走势是否顺着蝴蝶要的方向、
持有期间的区间与最接近中心的时刻、盈利区内收盘的 K 线占比、曾有的机会、结局(平仓 / 到期 / 持仓中)、方向对错。

## 止盈策略回放

蝴蝶复盘同时回放《SPX 0DTE 蝶式止盈策略》v2.1(`flyexit.ts`,黄金基线 `flyexit.json`,含一笔真实交易的回放)。蝶价走势用 IBKR 组合的历史分钟中间价
(`BrokerRouter.comboBars`,已到期的腿带 `includeExpired` 才能确认);拿不到的分钟用 Bachelier 模型价(σ_剩余)补,图上画虚线。

- **止盈 = 浮盈回撤追踪**:蝶价 ≥ 1.3 × D 之后开始记浮盈(蝶价 − D)的高水位,从高水位回吐掉当前档位的比例就全清。档位按浮盈分级收紧
  (蝶式的盈利有上限 = 翼宽,越靠近上限剩余上涨空间越小):浮盈 < 1 × D 让 40%、1–3 × D 让 30%、≥ 3 × D 让 20%,15:00 之后一律乘 0.5。
  回吐不足 `trail_floor`(默认 0.20 点,约一个组合价差)不触发。
- 回撤按浮盈算:D = 2.25、高点 8 时,回撤 30% 按浮盈在 6.28 出场,按蝶价要跌到 5.60。
- 位置信号优先于价格信号:标的出 0.45W 时按区间规则处理,阶段 C 整段交给区间规则。
- 阶段 B(14:00 至 σ_剩余 = W / 1.6):|S − K| > 0.45W 全清,14:00 留仓压到 1/3。阶段 C:|S − K| < 0.45W 持到结算、0.45–0.55W 清一半、更远清残值。
  任意时刻蝶价 ≤ 0.5 × D,或出 0.8W 且剩余方差 > 30%,止损。
- σ_剩余 = EM × √R,R 按半小时方差权重(拿历史数据校准的那一份,见 [蝴蝶测算](fly-plan.md));EM 默认 36,界面可改(应当每天从平值跨式取)。
- 分批规则至少留 1 张:不足 3 张时"清 1/3"按 max(1, n // 3)。开仓就在 0.8W 之外的远端虚值蝶,位置止损从标的第一次进入 0.8W 之后才生效,
  标的进入 K ± 10 时分批落袋。
- 固定倍数档位(1.35 × D / 1.70 × D)默认关闭,传 `tp1` / `tp2` 可以打开,与追踪并存:用 D 的倍数封顶会在 D 小的时候锁死出场。
- 触发判断只有中间价(策略要求按买价),回放结果略偏乐观,说明里写着;`trail_floor` 就是为此留的余量。
- 40 / 30 / 20 是按蝶式的上限效应与 0DTE 的衰减速度定的起点,没有经过拟合。
- 持仓追踪的蝶式预设用同一份档位、尾盘收紧、最少回吐,起算线按每组浮盈金额计算,见 [持仓追踪](tracker.md)「蝶式按金额起算」。

输出:蝶价图上的止损线、回撤激活线与随高水位上移的回撤触发价阶梯线;SPX 图上的 ±0.45W / ±0.55W / ±0.8W 临界线;逐分钟回放的出手事件
(时间、阶段、张数、价格、盈亏、触发的规则);「按策略 / 实际 / 持到结算 / 最高蝶价 / 浮盈高水位」五种结局对比。

## 股票

引擎侧 `stockreview.ts`(纯函数)。`review.candidates` 里 `kind: "stock"` 的行 id 以 `stk:` 开头;`review.analyze` 见到这种 id 走股票复盘,
返回的 `kind` 是 `"stock"`,没有止盈策略回放(页面上 EM 输入框置灰)。

- **一笔交易 = 一段持仓**:同一账户同一只股票,仓位从 0 到非 0 再回到 0。中途加仓、分批卖出都在这一笔里;成本按移动平均(加仓摊均价,减仓不动均价),
  已实现盈亏 = Σ(卖价 − 均价)× 数量,做空反号。一笔成交把仓位打穿(多 100 卖 150)就拆开:100 平掉旧的一笔,50 另起一笔反向的(id 带 `:r`)。
  同一订单(permId)的几笔成交并成一次出手,价格按数量加权。
- **期初仓位靠当前持仓反推**(`services/stockTrips.ts`,想法总结也用这一份):库里的成交是一天天积累的,最早那笔卖出多半卖的是更早买的货。
  期初仓位 = 当前持仓(`router.positions()`,15 秒缓存)− 库内成交净额,不为 0 的那一段标 `carried`:没有建仓价,成本与盈亏不编,只复盘出场。
- 没连券商或读持仓报错时拿不到当前持仓,每一笔标 `opening_assumed`,列表写「期初持仓未核对」。这时卖出不当作卖空:期初按"刚好够卖"的多头算
  (从 0 累计到过的最低仓位,负多少补多少),先卖的部分标 `carried`。说明里写明这条推断,以及"之前要是有空头仓位,方向可能认反";连上券商后按真实持仓重算。
- **进场与出场位置**:均价落在持有期区间(K 线最高最低,成交价在 K 线之外时把成交价也算进去)的什么位置。进场 1 = 买在最低(做空:卖在最高);
  ≥ 0.7 算进得好,≤ 0.3 提示之后有过更好的价格。
- **最大浮盈 / 最大浮亏**按持有期内 K 线的最高最低对最终均价算,金额乘这一笔的最大持仓;加过仓的是估算。**兑现率** = (出场均价 − 进场均价)/ 最大浮盈
  (`capture_pct` 是整数)。浮亏超过浮盈两倍要点名。
- 开仓后走势对第一次出手的成交价比较。卖出之后看最后一次出场后的 20 根 K 线:对"要是没走"有利的那头是"没吃到的",另一头是"躲开的",哪头大给哪个结论。
- 持仓中的按最后一根收盘算浮动盈亏,已减仓的部分算已实现;佣金单列,不从盈亏里扣。

结论最多八条:结构(或"只有出场 / 成本未知")、开仓前走势(顺势追 / 逆势接)、进场位置、开仓后走势、持有期、出场位置(或"出场前走势")、卖出之后、结局。
图是蜡烛、成交量、买入 / 卖出均价线,每次出手一个三角(买朝上、卖朝下,落在成交价上)。

**窗口按交易日算**:装下整段持仓,前后各多给一个交易日;总跨度不足 5 个交易日就继续往前补(前面没数据了才往后);同时不窄于 40 / 20 根(日线那条路上
40 根就是 40 个交易日)。超过 240 根抽稀时,每次出手所在的那根一定保留。

交易日按美东日期前缀区分,依赖 `barTimestamp()` 把 IBKR 的交易所时区换算成美东。美股全时段 04:00–20:00 不跨午夜,一个日期前缀就是一个交易日;
跨午夜的品种(期货、外汇)会被劈成两天。所以 `groupStockTrips` 入口丢掉 `secType !== "STK"` 的成交,`reviewStock` 对非股票记录直接报错;
要把期货接进复盘,先改 `sessionOf()`。
