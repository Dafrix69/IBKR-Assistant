# 从界面配置账户

「接入 → 账户」可以增加、修改、删除账户(别名、账号、纸面或实盘、挂到哪条连接、是不是默认)。这条路不经过引擎的 RPC:引擎的 `settings.patch`
照旧拒绝 `accounts` / `connections` 两段,写配置由主进程自己做(`desktop/accounts-setup.js`,通道在 `desktop/support-ipc.js`)。
要防的是界面里跑进别人的脚本,悄悄把实盘账号标成纸面(实盘闸门对它失效),或者把别名指到另一个账号上。

| 底线 | 怎么守 |
|---|---|
| 不能悄悄改 | 写之前一定弹原生确认框,框里每个字都是主进程对着将要写进去的内容写的:账号完整显示、纸面还是实盘、连接与端口、是不是默认;改已有的还写出原来是什么 |
| 实盘账号不能标成纸面 | 走 IBKR 的账户,账号不是 `D` 开头就不能标成纸面,存不进去;填的时候界面就提示 |
| 界面多带的东西进不了配置 | 只取表单那五项;连接、限额、闸门从这条路改不了 |
| 连接不能从界面改 | 账户只能挂到配置里已有的连接上 |
| 写坏了有路 | 原子写,改动前那一份留成 `.bak`;写完重启引擎,由它把整份配置再验一遍,验不过走"配置文件有问题"的对话框 |
| 默认账户只有一个 | 设了新的默认,其余的自动取消;删掉默认账户时第一个账户成为默认 |

主进程的顺序是先校验、再弹框、点了保存才写盘。

**引擎这一侧的同一条底线**(`config.ts` 的 `livePaperMismatches`):加载配置时,走 IBKR 的账户标的是纸面、账号却不是 `D` 开头,按实盘处理并留一条
`config_warnings`,手改配置填错的也被兜住。富途的账号是纯数字,从样子上分不出来,不套这条规则。

**账号在界面里出现多久**:只在提交的那一刻。列表显示引擎给的打码账号(`account_masked`);修改已有的账户时表单不回填账号,要重新填一遍。
日志里只记别名。

**首次启动**:示例配置里三个账户的账号是全零的占位。主进程认得出来(`placeholderAliases`),「交易指令」页的就绪清单多一步「填上你的券商账号」,
「账户」页顶上也有一条提醒。Windows 上的安装版新建配置时,交易库的位置改到应用自己的数据目录(`<userData>\data\trades.db`),
示例里的路径是 macOS 的样子;已有的配置不动。

**要去掉这条路**:删掉 `support-ipc.js` 的 `accounts-change` 与 `accounts-info` 通道、`preload.js` 里的 `accountsInfo` / `changeAccount`、
「接入」页的「账户」子页、「交易指令」页就绪清单里的占位账号那一步。

测试:`tests/desktop-accounts-setup.spec.ts`(存不进去的各种情况,含 `__proto__` 这样的连接名;确认框上的话;默认账户唯一;
写出来的配置引擎读得进去;先校验、再弹框、点了保存才写盘的次序)。
