# 从界面配置账户

2026-09-28 加的。「接入 → 账户」。

## 这改了一条老规矩,所以先说为什么

在这之前账户只能手改 `settings.json`。引擎的 `settings.patch` 明确拒绝 `accounts` / `connections` 两段(§9.6),
设置页底下写着"仅可手动编辑"。那条规矩防的是:界面里跑进一段别人的脚本,悄悄把实盘账号标成纸面(实盘闸门对它失效),
或者把别名指到另一个账号上。

防的东西没有变。但每个买了软件的人第一件事是用文本编辑器打开一份 JSON、把 `DU0000000` 换成自己的账号——
少一个逗号引擎就起不来。这不是卖得出去的样子。

所以加的这条路**不经过引擎的 RPC**(那边照旧拒绝),由主进程自己走,并且守住同一条底线:

| 底线 | 怎么守 |
|---|---|
| 不能悄悄改 | 写之前一定弹原生确认框。框里的每一个字都是主进程对着"将要写进去的内容"写的:账号完整显示、纸面还是实盘写明、连接与端口写明、是不是默认写明;改已有的还写出原来是什么 |
| 实盘账号不能标成纸面 | 走 IBKR 的账户,账号不是 `D` 开头就不许标成纸面——存不进去。填的时候界面就会说,不等点保存 |
| 界面多带的东西进不了配置 | 只取表单那五项;连接、限额、闸门从这条路改不了 |
| 连接仍然不能从界面改 | 账户只能挂到配置里已有的连接上 |
| 写坏了有路 | 原子写,改动前那一份留成 `.bak`。写完重启引擎,由它把整份配置再验一遍;验不过走"配置文件有问题"的对话框 |

如果你不要这条路:删掉 `support-ipc.js` 里的 `accounts-change` 通道与「接入」页的「账户」子页,别处不受影响。

## 引擎那一侧同样多了一道

`config.ts` 的 `livePaperMismatches`:加载配置时,走 IBKR 的账户标的是纸面、账号却不是 `D` 开头,
**按实盘处理**并留一条 `config_warnings`。失败朝安全的一侧——最坏的结果是一个真的纸面账户多过一道闸。
手改配置填错的也被这一道兜住。富途的账号是纯数字,从样子上分不出来,不套这条规则。

这改了一条老测试的输入(`fix-validator-limits.spec.ts` 里 `"true"` 那一条原来配的是 `U1234567`),行为变化是有意的。

## 账号在界面里出现多久

只在提交的那一刻。列表里显示的是打了码的(`account_masked`,引擎给的);修改一个已有的账户时表单不回填账号,
要重新填一遍。账号不进日志(日志里只记别名)。

## 首次启动

示例配置里三个账户的账号是全零的占位。主进程读配置认得出来(`placeholderAliases`),「交易指令」页的就绪清单
多一步「填上你的券商账号」,「账户」页顶上也有一条提醒。

Windows 上新装的时候,交易库的位置改到应用自己的数据目录(`<userData>\data\trades.db`)——示例里那个路径是 macOS 的样子,
照搬过去库会落在 `C:\Users\<人>\Library\…`。只在**新建配置的那一刻**改;已有的配置不动。

## 钉住它的测试

`tests/desktop-accounts-setup.spec.ts`:存不进去的各种情况(含 `__proto__` 这样的连接名——写测试时真的抓到了这个洞)、
确认框上的话、默认账户永远只有一个、写出来的配置引擎读得进去、主进程"先校验、再弹框、点了保存才写盘"的次序。
