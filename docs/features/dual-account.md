# 双账户发单

指令输入框下面有一排「发单账户」勾选(当前券商配置了两个以上账户时才出现)。勾一个,单子发到那个账户;**勾几个,每笔订单各发一份**:
引擎在解析之后、校验之前按勾选的账户把订单复制一遍(`engine.ts` 的 `fanOutOrders`),每一份独立走限额、实盘闸门、重复单检查,独立落库、独立下单,
结果卡片按账户分别显示。

- 指令里点名账户的订单(「用模拟账户买…」)不复制,照写的发;只有模型填 `account="DEFAULT"` 的订单才扇出。
- 单条输入的订单上限(`limits.max_orders_per_input`)在扇出之前截取,限的是"一句话最多几笔",与勾了几个账户无关;超出的以 `EXCEEDS_LIMIT` 拒绝。
- 重复单的指纹含账户别名,同一笔单发到两个账户不会互相当成重复。
- 勾选状态记在本机;没勾过时默认只勾默认账户。命令行同样支持:`parse` / `run` 加 `--accounts 模拟,主账户`。

## 纸面还是实盘

实盘闸门认的是配置里每个账户的 `is_paper`:

- **没写就按实盘处理**,只认布尔值或字符串 `"true"` / `"false"`,别的值加载配置时报错。没写的账户出现在 `Settings.config_warnings` 里,
  被闸门拦下时拒单说明会点出"配置里没写 is_paper"。
- **走 IBKR 的账户,标的是纸面、账号却不是 `D` 开头**(IBKR 的模拟账号都以 D 开头),按实盘处理并留一条 `config_warnings`(`config.ts` 的 `livePaperMismatches`)。
  富途的账号是纯数字,不套这一条。
- `allow_live_trading` 关着时勾上实盘账户也可以:实盘那份以 `LIVE_TRADING_DISABLED` 被拦下,纸面那份照常,正好用来先在模拟盘上跑同一条指令。
  勾选行下面直接写出这件事(「『主账户』是实盘账户,当前没有允许实盘下单……」加一个「去设置」),只提醒、不替用户改勾选;
  只配了一个实盘账户、勾选控件不出现时也照样提醒。
- 发单的确认框写明每个账户是纸面还是实盘,由主进程去问引擎,不听界面的;顶栏常驻「实盘已放开 / 仅纸面」。

## 两个 TWS 实例

两个 TWS 实例(例如 7496 个人账户、7497 公共账户)各自登录,配置里 `connections` 一条端口对一个实例,`accounts` 用别名把账号挂到对应的连接上。

- 诊断时(「接入 → TWS」的握手)核对别名账号是否在该实例可管的账户列表里,对不上的标红。
- 发单时(`BrokerRouter.forAccount`)按"上次走过的连接 → 配置里的连接 → 其余连接"的顺序,找管着这个账号的会话;账号在另一个实例上时自动改道并记一句
  「已自动改道」。所有已连的会话都不管这个账号时拒单;某个会话报不出账户列表时,信任配置里的那条连接。账户可以在「接入 → 账户」里配,
见 [从界面配置账户](accounts-setup.md)。

测试:`fanout.spec.ts`(扇出、各自校验与落库、点名账户不复制)、`fix-validator-limits.spec.ts`(`is_paper` 的判定)。
