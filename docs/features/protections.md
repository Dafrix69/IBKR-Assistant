# 保护规则:比熔断细一档的自动执行暂停

熔断(`killswitch.ts`)管的是**软件坏了**:连续下单失败、连续解析失败,到阈值就整体停,必须人工解除。
它分不出"今天不顺":接连三次止损、盈亏从峰值回撤几百刀、当天已经亏到了给自己定的线、刚平掉的标的立刻又要进——这些都不是故障,
是该歇一会儿。思路取自 freqtrade 的 Protections,规则口径按本项目的数据重写。

代码在 [`engine-ts/src/protections.ts`](../../engine-ts/src/protections.ts),配置在 `settings.json` 的 `protections` 段,**默认四条全关**。

## 四条规则

| 规则 | 判什么 | 参数 |
|---|---|---|
| `stoploss_guard` 止损护栏 | 窗口内止损平仓够次数 → 暂停 | `lookback_minutes` / `trigger_count` / `pause_minutes` |
| `max_drawdown` 回撤护栏 | 窗口内已实现盈亏从峰值回落够多 → 暂停 | `lookback_minutes` / `max_drawdown_usd` / `pause_minutes` |
| `cooldown` 同标的冷却 | 一只标的刚平过仓 → 这只不再下新单 | `minutes` |
| `daily_loss` 日内亏损上限 | 当天(美东)已实现盈亏净亏到线 → 当天不再下新单 | `max_loss_usd` |

止损护栏只数**止损类**离场:止损、跟踪止损、利润回撤(追价平仓的 `sweep:` 前缀按后缀认)。
**止盈不算**——赚着钱离场不是"今天不顺"。

回撤按窗口内累计已实现盈亏的**峰值到谷底**算,峰值从 0 起步(一路亏就是亏多少算回撤多少)。
盈亏只认券商佣金回报里的 `realizedPNL`,与[持仓追踪](tracker.md#盈亏以券商报的为准)同一个口径。

**日内亏损上限**是职业交易员与自营公司最常用的那条硬规矩(实盘比赛的优胜者几乎人人有一条自己的日亏线):
坏日子不许变成灾难日。它和回撤护栏的区别在切法——回撤护栏看**滚动窗口里从峰值回落多少**,日亏上限看
**美东当天零点起的净额**:上午赚 300、下午亏 800 的那天,净亏 500 才算到线;触发后停到**第二天美东零点**,
不是停一段分钟数。日界按美东日历(夏令时 / 冬令时由 `tz.ts` 换算),与交易日一致。

全局规则同时触发时,取**解除得最晚**的那条:都说该停,就听更保守的。

## 三条边界

**只挡新单,永远不挡平仓。** 持仓追踪发的平仓单走 `closePosition`、追价改价走 `syncHosted`,
两条路都不经过这个闸。保护期内挡住平仓等于让持仓裸奔,那比多亏一笔严重得多。

**不落终态。** 被挡下的单停在「仅校验未发送」,记录里追加一条 `保护规则拦下:…` 的告警,
保护期过了原样再发一次就行——不像熔断那样判死(`halted_by_breaker` 是终态)。
排队中的条件单同理:保护期内**继续排着**,不作废,到点还能触发(触发那一刻再查一次)。

**算不出来就放行。** 规则关着、库里读不到数据、查询抛异常,一律放行并留痕(`protections_failed`)。
保护规则误拦是妨碍交易,而它本身并不能挽回任何一笔已经发生的亏损。

## 状态从哪来:现算,不存

规则不写状态文件、不需要人工解除——每次问的时候从库里现算,到点自己就过去了:

- 平仓事件取 `audit_log` 里 engine 写的 `auto_close` 与 `hosted_sweep`(只增的,带 `symbol` 与 `state`)。
  追踪表的 `fired_state` 顶不了这个用:它一行一个持仓、就地更新,同一只标的平第二次就把第一次盖掉。
- 已实现盈亏取 `record_events` 里 `commission` 事件的 `realized_pnl`;开仓佣金回报里那个哨兵大数会被丢掉。
- 查库的起点是开着的规则里最早的那个(`protectionsSince`):日内亏损上限开着时至少从美东当天零点起。
- 四条都关着时**一次库都不查**(`protectionState` 直接返回空状态)。

## 界面

顶栏的模式格会显示「保护暂停」(橙点),悬停给出原因;交易指令页的发送条件里多一条「保护规则暂停中」。
`system.status` 带 `protections`:`paused` / `rule` / `reason` / `until_ms` / `cooldowns[]`——
带解除时刻是为了让界面直接说"还剩几分钟",不用再问一次。

四条规则的开关与参数在「设置 → 保护规则」里;打开某一条才展开它的参数行。
[绩效体检](performance.md)页在「最差一天远超平常」「亏完马上再进更差」时会指回这里。

**按体检建议填**(2026-09-26):[绩效体检](performance.md#保护规则建议2026-09-26)按账本给日亏上限、止损护栏、同标的冷却的参数,
确认后只 patch 那一条规则;引擎自己从不改这段配置。

日内亏损上限的美东日界(含冬令时)、按净额不按峰值、昨天的不算、查库起点覆盖当天零点,
以及接进引擎的——挡下的新单停在「仅校验未发送」且不落终态、没触发时照常发单、
**保护期内平仓照发**、三条全关时一次库都不查。
