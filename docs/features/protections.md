# 保护规则

熔断(`killswitch.ts`)管软件出错:连续下单失败、连续解析失败到阈值就整体停,人工解除。保护规则管"今天不顺":接连止损、盈亏从峰值回撤太多、
当天亏到了自己定的线、刚平掉的标的立刻又要进。触发时暂停一段时间的新单,到点自己解除。思路取自 freqtrade 的 Protections,规则按本项目的数据重写。

代码在 `engine-ts/src/protections.ts`,配置在 `settings.json` 的 `protections` 段,界面在「设置 → 保护规则」(打开某一条才展开它的参数)。**默认四条全关。**

## 四条规则

| 规则 | 判定什么 | 参数 |
|---|---|---|
| `stoploss_guard` 止损护栏 | 窗口内止损类平仓达到次数 → 暂停 | `lookback_minutes` / `trigger_count` / `pause_minutes` |
| `max_drawdown` 回撤护栏 | 窗口内已实现盈亏从峰值回落达到金额 → 暂停 | `lookback_minutes` / `max_drawdown_usd` / `pause_minutes` |
| `cooldown` 同标的冷却 | 一只标的刚平过仓 → 这只不再下新单 | `minutes` / `scope` |
| `daily_loss` 日内亏损上限 | 美东当天零点起的已实现盈亏净亏到线 → 当天不再下新单 | `max_loss_usd` / `basis` |

- 止损护栏只数止损类离场:止损、跟踪止损、利润回撤(追价平仓的 `sweep:` 前缀按后面的原因认)。止盈不算。
  持仓追踪里人点的「立即平仓」也不算:它的平仓痕迹记成 `manual`(不论是新发一张平仓单,还是把托管单改成追价)。
  同标的冷却对每一次平仓都算,止盈与手动平仓也算。
- 回撤按窗口内累计已实现盈亏的峰值到谷底计算,峰值从 0 起步(一路亏就是亏多少算回撤多少)。
- 日内亏损上限按美东当天零点起的净额(上午赚 300、下午亏 800,净亏 500 才算到线),触发后停到第二天美东零点;日界按美东日历,夏令时由 `tz.ts` 换算。
  它和回撤护栏的区别:回撤护栏看滚动窗口里从峰值回落多少。
- **冷却挡什么**(`cooldown.scope`):`symbol`(默认)= 这只标的的一切新单;`position` = 只挡和刚平掉的那份持仓**同一个结构**的单
  (同一到期、同样的腿;身份是持仓行的 `leg`,新单这一侧由 `engine/closing.ts` 的 `orderLegId` 拼成同一个样子)。
  只做一只标的的人(天天 SPX)用 `symbol` 等于平一次就全停;`position` 下换一个中心、换一个到期照常能开。
- **日内亏损拿什么算**(`daily_loss.basis`):`realized`(默认)= 引擎发出的单的已实现盈亏,见下文「状态从哪来」;
  `account` = 券商报的账户当日盈亏(IBKR 的 reqPnL:已实现 + 未实现,含在 TWS 里手动做的单)。
  - 每个账户各比各的,只停亏到线的那个账户(`system.status` 的 `protections.accounts[]`,顶栏与交易指令页照它写是哪个账户)。
  - 到过线的账户停到美东第二天零点,不因为浮亏收回去一点又放开(`engine/accountGuard.ts` 的 `withLatch`)。到线的那一刻在审计日志里记一条
    `daily_loss_trip`;引擎重建(改设置、重连都会重建)、软件重启之后从那里读回来。
  - 只认美元账户、一分钟内更新过的数(`accountFeeds.ts`)。一个账户都没报(没连券商、富途、订阅还没来、数太旧)时退回 `realized` 那一条——
    宁可用窄一点的口径,不让这条规则因为缺一个数就不生效。有的账户报了、有的没报时,**没报的那几个各自退回已实现盈亏**
    (那个数是引擎发的单合在一起的,不分账户,所以偏严),原因里写明是退回去算的。
- 全局规则同时触发时,取解除得最晚的那条。
- 金额为 0 的规则等于不生效(`daily.enabled && daily.max_loss_usd > 0`)。界面保存前检查(`lib/settingsForm.ts` 的 `formProblems`):开着的规则必须填正数;
  `toPatch` 不把空着的格子变成 0,没开的规则那几格空着就按已保存的值送回。

## 边界

- **只挡新单,不挡平仓。** 持仓追踪的平仓单(`closePosition`)与追价改价(`syncHosted`)都不经过这个闸门。
  手敲的指令被拦下之前先读一次持仓(一批只读一次):每条腿都朝减仓方向、数量不超过这个账户在这条腿上的持仓(`engine/closing.ts` 的 `reducesPositions`),
  才算平仓、照发;认不准(没有这条持仓、方向是加仓、卖得比持仓多、读不到持仓)一律当新单挡下。
  一条指令是开仓还是平仓要引擎对着持仓判定,所以交易指令页不把保护暂停当成发送条件:「发送」照常可点,
  输入框下面写明「保护规则暂停中:<原因>」,新开仓的单由引擎拦下。
- **排队中的条件单**:软件盯盘队列里的(AUTO_MID 定价的、富途的)在保护期内继续排着,不作废,触发那一刻再查一次;
  这一步同样做平仓识别(`accountGuard.isReduceOnly`):只在减已有持仓的那张照发——按账户当日盈亏算的暂停是被浮亏触发的,那时最该放行的正是排着的平仓单;
  挂在 IBKR 服务器上的原生条件单由券商触发,不再经过保护规则。
- **已知缺口**:校验层按开仓的最坏亏损给单腿期权定敞口,手敲的"卖出持有的看涨期权平仓"会被当成裸卖 Call 拒绝,卖出持有的蝴蝶也不认。
  这一关在保护规则之前;这类平仓请用持仓追踪的「立即平仓」。
- **不落终态。** 被挡下的单停在「仅校验未发送」,记录里追加一条 `保护规则拦下:…`,保护期过了原样再发一次即可。
- **算不出来就放行。** 查询或计算出错时放行并留痕(`protections_failed`):误拦是妨碍交易,而它挽回不了已经发生的亏损。规则关着、没有数据时直接放行。

## 状态从哪来:现算,不存

规则不写状态文件、不需要人工解除,每次问的时候从库里现算,到点自然过去:

- 平仓事件取 `audit_log` 里引擎写的 `auto_close`、`hosted_sweep`、`hosted_fill`(券商侧自己触发的托管单成交,股票最主要的止损路径是券商侧的 STP),
  每条带 `state`:`take_profit` / `stop_loss` / `profit_trail` / `manual`。
  追踪表的 `fired_state` 顶不了这个用:它一行一个持仓、就地更新,同一只标的平第二次就把第一次盖掉。
- 已实现盈亏取 `record_events` 里 `commission` 事件的 `realized_pnl`,开仓佣金回报里的哨兵大数丢掉。**同一 `exec_id` 只算先到的那一条**
  (跨全部记录去重):同一笔佣金回报可能写入好几次(引擎重建时去重集合清空、TWS 整批重推),先去重再按窗口筛选;没有 `exec_id` 的都算。
  只有引擎发出的单(库里有记录的)才有这些事件,直接在 TWS 里下的单不计入日内亏损上限与回撤护栏。
- 查库的起点是开着的规则里最早的那个(`protectionsSince`),日内亏损上限开着时至少从美东当天零点起;四条都关着时一次库都不查。
- 盈亏只认券商佣金回报里的 `realizedPNL`,与 [持仓追踪](tracker.md)「盈亏以券商报的为准」同一个来源。

## 界面

顶栏的模式格显示「保护暂停」(橙点),悬停给出原因;交易指令页的输入框下面写明「保护规则暂停中:<原因>」,「发送」照常可点。
`system.status` 带 `protections`:`paused` / `rule` / `reason` / `until_ms` / `cooldowns[]` / `accounts[]`(按账户暂停的那几条);顶栏的悬停提示显示 `reason`,
被拦下的单在警告里写明还剩多久。
[绩效体检](performance.md)在「最差一天远超平常」「亏完马上再进更差」时指回这里。

### 按体检建议填

[绩效体检](performance.md)「保护规则建议」按账本给日亏上限、止损护栏、同标的冷却的参数,用户确认后只 patch 那一条规则;引擎自己从不改这段配置。

## 测试

`protections.spec.ts`:窗口与阈值的边界、止盈不算、手动「立即平仓」不算止损但照样起冷却、到点自动解除、两条同时触发听更保守的、冷却按标的分、配置默认全关与写错即报、
日内亏损上限的美东日界(含冬令时)、按净额不按峰值、昨天的不算、查库起点覆盖当天零点;接进引擎之后:挡下的新单停在「仅校验未发送」且不落终态、
没触发时照常发单、保护期内平仓照发、四条全关时一次库都不查。`desktop-settings-form.spec.ts`:开着的规则必须填正数、空格子不变成 0,
并对着 `protections.ts` 的源码确认引擎把 0 当成不生效。`account-limits.spec.ts`:冷却按结构、日内亏损按账户当日盈亏(只停到线的账户、到过线不放开、
没报数时退回已实现)。目前只有离线测试,没有在真机上核对;**账户当日盈亏这一路(reqPnL 的字段在纸面与实盘账户上齐不齐、多久推一次)没有在真实 TWS 上看过**,
打开 `basis: account` 之前先在「设置」里看一眼它读到的数对不对得上 TWS 的账户窗口。
