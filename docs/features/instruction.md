# 交易指令:解析、校验、发单

一句中英混合的指令变成订单:先解析(本地速记或大模型),再由代码逐条校验,通过的直接发到券商,没有「仅解析」模式,实盘账户也一样。
模型只做翻译,限额、方向、账户、结构、时段、重复单全部由代码判定。
入口是「交易指令」页与 RPC `instruction.submit`;命令行 `node dist/src/cli.js parse | run` 走同一个引擎。
[Discord 跟单](follow.md) 也走这一条(来源记成 `discord`),但只认本地速记,大模型在那条路上不出场。

## 流程(`engine.ts` 的 `handleInstruction`)

1. 熔断合着:整条指令不解析,直接回提醒。
2. 从指令里抽出标的,向券商取现价快照。
3. 解析:先试本地速记;接不住的交给大模型。模型调用失败、回包不合法都照实报错。
4. 模型自己拒绝的片段照样落库,拒绝率是统计指标。
5. 单条输入的订单上限(`limits.max_orders_per_input`,默认 5)在扇出之前截取;再按勾选的账户扇出,见 [双账户发单](dual-account.md)。
6. 逐笔校验(下一节)。被拒的落库并说明是谁拒的(模型 / 校验 / 引擎 / 券商)。
7. 通过的订单:
   - 只解析(`instruction.submit` 带 `execute: false`,即「解析并校验」按钮,是试算不是闸门):停在「仅校验未发送」(`ValidatedOnly`),后台预先确认合约,点「发送」时组合腿不用再等券商往返;
   - 每笔发出前重查熔断,已合上的落终态 `halted_by_breaker`;
   - 交易纪律守护打开时,真要发出去的股票开仓单没有对应的交易意图就拒(`GUARD_NO_INTENT`,终态 `rejected_by_guard`),只解析的与减仓单不问,见 [交易纪律守护](guard.md)。
   - 保护规则拦下的停在 `ValidatedOnly`,平仓单照发,见 [保护规则](protections.md)。
8. 发单:先写一条 `submit_intent` 事件再调券商(见 [数据与配置的保险](durability.md))。
   - 条件单用 AUTO_MID 定价,或券商没有原生条件单(富途):进软件盯盘队列(`PendingTrigger`),软件关着就不会触发;
   - 其余条件单挂在 IBKR 服务器上,软件关着照样有效;
   - AUTO_MID 的组合按盘口中间价 ± `limits.max_spread_slippage`(默认 0.10)定限价,按组合跳动取整;买入限价不超过翼宽,贷方限价必须仍为负数,否则拒绝发单。
     `limits.auto_mid_spread_share`(0–1,默认 0 = 不用)填了之后改成让**盘口价差的一份**:限价 = 中间价 + 份额 ×(立刻成交的价 − 中间价),
     0.5 就是挂在中间价与对手价的正中(`autoMid.ts`)。等各腿买卖价时 25 毫秒看一次,齐了就走;腿上的行情订阅在这张单交给 TWS 之后才撤。固定让 0.10 对 0.30 的蝶是三分之一、对 12 块的价差不到百分之一;份额跟着盘口宽窄走。
     份额是用户填的,没有默认建议值;其余三道检查(腿方向与订单方向一致、借方不超过宽度、贷方仍为负)两种让法相同。

## 本地速记(`shorthand.ts`、`engine/localShorthand.ts`)

固定的 SPX 蝴蝶行话不经过大模型,约 2 毫秒出结果,产出和大模型同形,走同一套校验。例:`1.8 挂15蝴蝶 15CM`。

| 写法 | 含义 |
|---|---|
| 首尾孤立的数字、「权利金不超过 / 上限 / 不高于 N」 | 净权利金上限 → 限价单;没写 → AUTO_MID |
| 「挂」 | 当日限价 |
| 「N蝴蝶」(N ≤ 99) | 中心 = 现价的百位 + N |
| 「N cm」「翼宽 N」「±N 点」 | 翼宽 N 点 |
| 不写看涨 / 看跌 | 按中心与现价的高低推断 |
| 不写标的 / 张数 / 到期 | SPX / 1 张 / 当日到期;「明天」= 下一个工作日(只跳过周末,落在假日时由校验以「不是交易日」拒绝) |
| 「(这 / 本 / 下)周一…周五」「星期X」「礼拜X」「M月D日」,可带「到期」 | 写明的到期日。不带「下」= 本周那天;已经过了、落在周末、日期无效的在本地直接拒绝并说明,不猜成下周。节假日不查,合约不存在时由券商确认拦下。和「明天」或另一个日期同时写的整句交给大模型。三种语法(蝴蝶、价差、铁蝶)和跟单都认 |
| 尾部「理由:…」 | 摘下来写进 `reason`,前面照常解析 |

**贷方垂直价差**也在本地解析(同一个入口,`parseCreditSpread`)。例:`7770 7775 bear call 挂个-2-2.5`、`00 95 bull put 试下 -2 -2.5`。

| 写法 | 含义 |
|---|---|
| `bull put` / `bear call`(必须写全,跟不跟 spread 都行) | bull put 卖高买低的 put;bear call 卖低买高的 call。两个行权价谁写在前面无所谓 |
| 两个三到五位的数 | 写全的行权价 |
| 两个两位数 | 相对写法(现价的百位 + N),取离现价最近的一组;「00 95」是 7700/7695。最近的一组离现价 50 点或更远、两个数正好差 50 的不接 |
| 负数 | 收到的权利金。写的是区间(`-2 -2.5`、`-2到-2.5`)时按收得多的一头做限价;没写就按 AUTO_MID(下单时按盘口中间价),和蝴蝶一样 |
| 张数、标的、到期、盘外 | 和蝴蝶一样的默认值与写法 |

产出是卖出的 `VERTICAL`(`order.action = SELL`、`lmtPrice` 是正的权利金),和大模型产出的同形,走同一套校验。

**只写 `put spread` / `call spread`**(或「看跌价差」「看涨价差」)只在手动下单页本地解析(`tryParseShorthand` 的 `manual`),
口径是价格的符号:带负号 = 卖出贷方价差(同上);不带负号或没写价格 = **买入借方价差**,put 买高卖低、call 买低卖高,
`order.action = BUY`;两个三到五位的行权价之外恰好再有一个数时,它是付的权利金上限(必须小于宽度),没有就按 AUTO_MID。
例:`spy这周五的745 740 put spread` = 买 745P、卖 740P,周五到期,中间价挂。句中有「卖」的整句交给大模型。
[Discord 跟单](follow.md) 不开这一条:对方没写 bull / bear 的照旧不跟。

价差(上面两种都算)还认下面几条。蝴蝶不认价格口语;铁蝶只认它原有的「N 块」(见下面铁蝶的表),不认「N毛」「N块M」:

| 写法 | 含义 |
|---|---|
| 「N毛」「N毛M」「N块」「N块钱」「N块M」(N、M 是阿拉伯数字) | 价格口语,换成小数再按上面的规则读:`8毛` = 0.8、`8毛5` = 0.85、`1块2` = 1.2、`1块` = 1;`-8毛` = 收 0.8。零头必须紧跟毛 / 块;后面接「张」的是张数(`8毛5张` = 0.8、5 张,`8毛 2张` = 0.8、2 张)。换算在摘掉到期日之后、认负号之前做(`takeSlangPrice`)。「八毛」这种中文数字不认,剩下的「毛」让整句交给大模型 |
| 句中「对冲」「对冲下」「对冲一下」加紧跟的一串汉字(只在手动下单页) | 说明,原文写进 `reason`,从句子里摘掉再解析。这一串遇到数字、字母、空格、标点就停;串里有交易词(买、卖、张、股、挂、周、星期、礼拜、月、日、号、明天、毛、块、止损、止盈、平仓、蝴蝶、铁蝶、价差、看涨、看跌、到期、盘外类、理由、市价、限价、中文数字)或条件词(如果、或者、时候、涨到、跌到、突破、跌破、破了、站稳、守不住、翻倍、取消、撤单、加仓、接货、上移、下移、日历、正股、海鸥)就不摘,剩下的字让整句交给大模型。和尾部「理由:…」同时写时 reason 是「对冲说明;理由」。蝴蝶、正股的句子也一样摘 |
| 没写标的、行权价离默认的 SPX 现价超过 20% | 在本地拒绝(`UNSUPPORTED`),提示写明标的(如 `spy 745 740 …`),不猜成 SPY,也不交给大模型。写了标的而离现价太远的照旧交给大模型 |

例:`这周五spy的745 740 put spread对冲下选举 8毛` = 买 745P、卖 740P,周五到期,限价付 0.8,理由「对冲下选举」。

**铁蝶**(`parseIronFly`)也在本地解析,是蝴蝶测算「写进指令」默认写出的结构。例:`SPX 7750铁蝶 25cm 2张 -19.5`、`50铁蝶 25cm`。

| 写法 | 含义 |
|---|---|
| 「N铁蝶」「7750铁蝶」「7750 的」 | 中心,写法同蝴蝶(两位数 = 现价百位 + N) |
| 「N cm」「翼宽 N」「±N 点」 | 翼宽(必填) |
| 负数、「权利金 N」「N 块」 | 收到的净权利金,必须小于翼宽;区间按收得多的一头。孤立的正数也按收到的权利金理解并提醒一句(铁蝶在本系统里只能卖出)。没写按 AUTO_MID |
| 张数、标的、到期、盘外 | 和蝴蝶一样 |
| 看涨 / 看跌 / call / put、「买」 | 铁蝶没有方向、不能买:出现就整句交给大模型 |

产出四条腿:买 K−w put、卖 K put、卖 K call、买 K+w call,比例都是 1,`combo_strategy = IRON_CONDOR`(内侧同价)、`order.action = SELL`、`lmtPrice` 是正的权利金;
平仓、持仓行(`iron_butterfly`)、成交合成走的都是铁鹰这一个口径。[Discord 跟单](follow.md) 不认它(跟单只认买入蝴蝶与贷方价差,没改)。
只写 bull / bear、缩写(BPS、BCS)、带条件的,一律交给大模型。没写价格的手动下单按 AUTO_MID 接;[Discord 跟单](follow.md) 不跟没写价的,那道拒绝在跟单自己那里。

- 整条指令必须被语法完整覆盖,剩下任何成分就交给大模型。
- **闲字表**(`FILLERS`):「挂个」「试试」「尝试下」「试一下」「试试看」「一下」「彩票」「赌博小彩票」「好贵」「不要追价」这类口语先剥掉再解析。
  表里只收不带交易语义的词;动词(「走」「平」)、条件(「站稳」「止损」)、说不清的写法(`7605/10`)一概不在,整句交给大模型。价格口语「2块1」只在价差里认(见上表)。
  每加一个词都要升 `GRAMMAR_VERSION`。
- 解析器可以带一个 `ShorthandMeta` 出参,告诉调用方中心写的是不是「N蝴蝶」这种相对写法;手动下单不用它,[Discord 跟单](follow.md)用它在百位边上拒绝。
- 权利金必须小于翼宽;中心偏离现价超过 20% 视为漏写标的,交给大模型。
- 周末按默认当日到期的蝴蝶在本地直接拒绝,提示改写「明天」或写明到期日。
- 没连券商时现价取公开源(Cboe 延迟行情);引擎启动时预取 SPX 公开现价,之后每 4 分钟后台刷新。
- 本地解析抛出任何异常都交给大模型。语法版本记在 `GRAMMAR_VERSION`,改语法必须升版本。

## 大模型

- 发出去的只有指令原文、当前时间、行情快照与别名表。真实账号、余额、持仓、成交不出本机。
- 提示词 v1.8.0 起限额数字不进提示词,模型不判断限额、不输出 `EXCEEDS_LIMIT`:限额由校验层按统一规则复算,交给模型估算会误拒合规的单。
  配置里没写 `prompt_version` 时用 v1.0.0(限额仍在提示词里),示例配置写的是 `latest`。
  合约存不存在由软件向券商核实。
- 提示词在仓库根的 `prompts/`,按版本号只增不改(`system_v*.md`、`user_message_v*.md`、`fewshot_v*.json`),
  配置里 `prompt_version` 切换,`latest` 跟随软件带的最新一版。
- 供应商、结构化输出的降级、密钥存放见 [大模型接入](llm-providers.md)。
- 时延:大模型路径约 2 秒,主要由端点本身决定(到 DeepSeek 的 TLS 握手约 50 毫秒,连接复用省不了多少)。本地速记那条路上,
  从进引擎到订单交给 TWS 的分段见 [性能留痕](perf-log.md)「下单时延」。

## 校验(`validator.ts`)

| 顺序 | 检查 | 拒绝码 | 规则 |
|---|---|---|---|
| 1 | 置信度 | `LOW_CONFIDENCE` | 低于 `limits.min_confidence`(默认 0.9)拒绝 |
| 2 | 账户 | `UNKNOWN_ACCOUNT` | 别名必须在别名表里;实盘账户与纸面账户同样放行 |
| 3 | 合约 | `EXPIRED_CONTRACT` / `BAD_SPREAD` / `UNSUPPORTED` | 到期日不早于今天且是交易日;指数期权的交易类按到期日复核(下文);组合各腿交易类必须一致;期权乘数只认 100 |
| 4 | 价差结构 | `BAD_SPREAD` | 见下表 |
| 5 | 触发条件 | `AMBIGUOUS_TRIGGER` / `TRIGGER_MISMATCH` | 用现价快照复核方向;没有快照时按 `require_trigger_price_verification`(默认开)拒绝;现价离触发价不到 `trigger_min_gap_bps`(默认 5 个基点)拒绝 |
| 6 | 限额 | `EXCEEDS_LIMIT` / `UNSUPPORTED` / `UNPRICEABLE` | 名义金额不超过 `max_order_notional`(默认 5,000 USD);期权与组合不超过 `max_option_contracts`(默认 5 张)。可以按账户另设(下文「按账户的限额」) |
| 6b | 账户在手的累计上限 | `EXCEEDS_LIMIT` / `UNPRICEABLE` | 默认不设。见下文「账户在手的累计上限」 |
| 7 | 交易时段 | `MARKET_CLOSED` / `UNSUPPORTED` | 休市按 `closed_market_policy`(默认 `reject_market_orders`);盘外时段带 `outsideRth` 的市价单拒绝,不带的提醒"会等到常规时段才送交易所" |
| 8 | 重复单 | `DUPLICATE_ORDER` | 指纹(账户 + 方向 + 合约要素)相同、数量差在 20% 以内,出现在同一批或 `duplicate_window_minutes`(默认 10 分钟)内。前一张已经了结、这一次换了限价的放行(下文「重复单」) |
| 9 | 原因 | 只提醒 | 没写原因提醒补上 |
| 10 | 单笔风险预算 | 只提醒 | 见 [单笔风险预算](risk-budget.md) |

**价差结构**

| 结构 | 规则 |
|---|---|
| 垂直价差 | 两条腿一买一卖、同类型、同到期、1:1、行权价不同;腿的方向与借方 / 贷方一致;借方净权利金不超过行权价差 |
| 蝴蝶 | 只支持买入;三腿同类型、同到期、行权价互不相同、买低卖中买高、1:−2:1、两翼等距;净权利金不超过翼宽 |
| 铁鹰 / 铁蝶 | 只支持卖出;两条 Put 两条 Call、比例都是 1、内侧卖外侧买。四个不同行权价、Put 侧整体低于 Call 侧的是铁鹰;内侧两腿同价的是铁蝶,两翼必须等距,写明的权利金必须小于翼宽 |

**名义金额**

| 品种 | 算法 |
|---|---|
| 股票 | 数量 × 参考价。带限价的买单用限价;其余取限价、止损触发价、现价快照里最大的一个。都没有时股数不能超过 `max_mkt_shares`(默认 200) |
| 买入单腿期权 | 张数 × 100 × 限价;只认 LMT / STP LMT 的限价,其余(市价、STP、TRAIL)拒绝 |
| 卖出 Put | 张数 × 100 × 行权价(现金担保) |
| 卖出 Call | 不支持 |
| 借方组合 | 张数 × 100 × 净权利金 |
| 贷方组合 | 张数 × 100 × (宽度 − 收的权利金) |
| AUTO_MID 的组合 | 张数 × 100 × 结构宽度(借方、贷方都这样算) |

**按账户的限额。** `limits.by_account.<别名>` 可以给某个账户另设四项:`max_order_notional`、`max_option_contracts`、`max_open_risk_usd`、
`max_underlying_contracts`;没写的那一项用全局的(`Settings.limitsFor`)。纸面账户放宽、实盘收紧是它的本意,所以覆盖值可以比全局的松,也可以更紧。
界面上放宽任何一项(全局或某个账户的,包括新加一条比全局松的覆盖、删掉一条比全局紧的覆盖)不弹确认框,保存即生效。

**账户在手的累计上限。** 单笔上限管"这一单多大",这两条管"账户上一共压了多少"——一天开十只各 5 张的蝶,每一单都合规,账户上是 50 张。

| 键 | 含义 |
|---|---|
| `max_open_risk_usd` | 这个账户在手的期权与组合的最坏亏损合计(美元),加上这一单的名义金额,不超过它。0 = 不设 |
| `max_underlying_contracts` | 同一账户、同一标的、同一到期日上的张数(标准组合按组数),加上这一单,不超过它。0 = 不设 |

- 在手的最坏亏损由 `openRisk.ts` 从持仓现算,**不靠认结构**:同一账户、同一标的、同一到期日的期权腿放在一起,直接算到期那一刻的盈亏在哪个价位最差
  (到期盈亏对标的价分段线性,最差的点只可能在 0、某个行权价、或往上的无穷远处)。标准结构算出来和上面「名义金额」那张表是同一个数:
  买入的期权、借方组合、买入的蝶 = 付出的成本;贷方价差、铁鹰 = 宽的那一侧 × 乘数 × 张数 − 收到的权利金。两侧张数不等的"铁鹰"、分腿建起来净成本为正的贷方价差、
  和别的结构挤在同一天到期的,照认结构那张表会少算,这样算不会。净卖出的看涨往上没有对冲时没有上限:有限的那一段照算,再加 最高行权价 × 乘数 × 净卖出张数,并写明。
  没有估计、没有参数。只算同一到期日之内的对冲,日历价差的两条腿各算各的(偏大)。
- 只管期权与组合。正股最坏亏多少取决于止损,不在这两条里。
- **"在手"含今天发出去还没有终态的开仓单**(挂着没成交的、排队中的条件单;`riskQueries.workingOrders` + `accountGuard.withWorkingOrders`):
  它们成交之前持仓里看不见,不加的话连发两张各自合规的单,两张都过。部分成交的整张都算(成交的那一部分同时也在持仓里,偏大不偏小)。
- **在减已有持仓的单不拦**(`engine/closing.ts` 的 `reducesPositions`):账户已经到线的时候,平仓恰恰是该放行的那一种。
  同一条指令里的几张减仓单逐张扣着认:持有 2 组,「卖 2 组」「再卖 1 组」,后一张不是平仓,是反向开仓。
- 一条指令里的几张单累加着算:第二张看得见第一张。
- 设了上限而读不到持仓:**开仓的**单拒(`UNPRICEABLE`),核对不了的上限等于没有;减仓的单拿这个引擎最近一次读到的持仓认,照发。两条都没设时不读持仓。
- 富途通道读不出期权持仓(持仓行不分期权与正股):两条累计上限不查,订单的警告里写明「没有核对」。

**重复单。** 窗口内指纹相同、数量相近的第二张单拒绝;指纹不含价格。例外只有一种:前一张已经**撤掉**,
而这一次的限价和它差到一分钱以上——没成交、撤了、换个价再来,是有意的,放行。前一张成交了的照旧拦(那是加仓,真要加就改数量或等窗口过去);
被拒、出错的终态有过记错的先例(单其实还活着),不凭它放第二张;还没有终态的更不放,并且明说原因:它可能还挂在券商那边,两张都可能成交。
同一条输入里重复的两张照旧拦第二张。

**盘外时段。** 盘前、盘后,以及 SPX 期权自己的隔夜时段都能交易,但交易所只收限价单。`auto_outside_rth`(默认开)
给这些时段里的限价单自动加 `outsideRth`。期权的时段按合约自己的交易时段判定(按天缓存),取不到才用正股日历。

**指数期权的交易类。** SPX 的月度合约(交易类 `SPX`,开盘 AM 结算)最后交易日是第三个周五的前一个交易日;
其余交易日只有日到期类 `SPXW`(收盘 PM 结算)。复核只纠正这一天根本不存在的链,用户写了 `SPXW` 就保留:

| 下单时写的 | 月度到期的那一天(两条链都在) | 其它交易日 |
|---|---|---|
| 没写 | 按日期判定为 `SPX`,提醒 | `SPXW`,提醒 |
| `SPXW` | 保留 | 保留 |
| `SPX` | 保留 | 这天没有月度合约,改为 `SPXW`,提醒 |
| 认不出的类 | 按日期判定改正,提醒 | 同左 |

**合约确认。** 发单前向券商确认合约(`ibSession.ts`)。组合的各条腿一次全问出去再等回话;真发单的期权与组合解析出来就开始问,和合约时段同时走,
第一张真要发出去的单之前才等它回来,被校验拦下的不等(问错、问不到都无害:发单时正式再确认一遍,报真实的错)。股票期权不带交易类时,IBKR 可能同时回标准类与调整期权类
(如 `AAPL` 与 `2AAPL`,交割物不同):同一 conId 的重复行合并;多条时先认请求里写明的交易类,再认与标的同名的那条;
还分不出来就确认失败,不发单。

## 熔断

通过校验的订单直接发出,没有执行开关与实盘开关,也不弹确认框。能挡住发单的只有校验(限额等)、[保护规则](protections.md)和熔断。
旧配置里的 `auto_execute`、`allow_live_trading`、`consecutive_failure_breaker` 读进来就忽略。

**熔断(`killswitch.ts`)。** 状态写在交易库旁边的 `breaker.json`,主进程、命令行、引擎看同一个文件,重启后依然有效;
文件损坏按已熔断处理。只有手动熔断(按钮 `⌘⇧H`、菜单、Dock、命令行 `halt`):合上后不解析新指令、不发新单,撤掉全部未成交单、
清空软件盯盘的条件单队列,只能人工解除(`resume`),解除不需要确认。连续失败不会自动合上熔断。
文件里带 `auto: true` 的状态(自动熔断的遗留)按已解除读。熔断对持仓保护的影响见 [持仓追踪](tracker.md)「熔断与已有的保护」。
