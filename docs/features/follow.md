# Discord 跟单

一个 Discord bot 读一个频道,信任的发送者在里面发的蝴蝶速记不经确认直接走发单链路。
界面在「接入 → Discord 跟单」,配置在 `settings.json` 的 `follow` 段,bot token 在系统凭证库。**默认关、默认不连 Discord。**
消息还有第二个来源「本地收件」(见下),给对方的私密频道拉不进 bot 的情况;两个来源的消息走同一条判定与发单的路。

## 消息怎么进来

- **只用官方的 bot 通道**(bot token、Gateway v10)。不用任何人的用户 token:自动化个人账号(self-bot)违反 Discord 的条款、会封号,代码里没有这条路。
- bot 要在一个你能管理的服务器里。对方的频道拉不进 bot 时,让单子落到你自己的服务器:对方的频道是公告频道就点「关注」转过来;
  否则请对方同时在你的服务器里发一份。两种情况下软件这边没有区别:它只认「哪个频道、谁发的」。
- 关注过来的消息,发送者是那条关注的 webhook(ID 固定)。信任它等于信任所有能在源频道发公告的人。
- bot 需要三个 intent:`GUILDS`、`GUILD_MESSAGES`、`MESSAGE_CONTENT`。最后一个是特权 intent,要在 Developer Portal 里手动打开;
  没开时 Discord 以 4014 关闭连接,软件停下来并说明去哪里开。
- 连接只收不发:不向 Discord 发送任何消息。引擎不走代理:系统层面连不上 `gateway.discord.gg` 时这里也连不上。
- 配了频道 ID、凭证库里有 token 才连。没配频道时一个包都不发,也不去碰凭证库。

## 本地收件(`followInbox.ts`)

对方的频道是私密的、拉不进 bot、也不是公告频道时,bot 那条路走不通。本地收件不碰 Discord 的接口:一个本机脚本
(`desktop/tools/discord-window-follow.swift`)通过 macOS 的辅助功能读**你屏幕上** Discord 窗口里当前频道的消息列表,
新出现的消息一行一个 JSON 追加到交易库旁边的 `follow-inbox.jsonl`;引擎盯着这个文件,每行变成一条消息,之后和 bot 读来的消息一样过信任名单、
三个上限、只观察、发单。没有任何 token,Discord 那边什么都收不到,不是自动化账号。

- **从文件此刻的末尾读起**:引擎没在跑时追加的行不补——它们早就过了新鲜期,补进来只会刷一串「太旧」。文件变短(被清空、换了一个)就从头读。
  认不出的行记原因、跳过,后面的照读;状态写在面板「收件文件」那一行。
- **消息的时刻是脚本看见它的时刻**:屏幕上只有"几点几分",没有秒。脚本每 1.5 秒看一次,所以到引擎手里时通常只有一两秒,新鲜度那道检查照常。
- **发送者是显示名**:`author_id` 写成 `local:名字`,信任名单里也这样写(`config.ts` 的 `LOCAL_AUTHOR`)。频道里别人把昵称改成一样的,软件分不出来——
  风险揭示里写明了,只适合私密小群。消息 ID 是 `local:` 加脚本给每条消息算的 key,去重照旧按 ID。
- **判定里它是 `local` 频道**:`triage` 对 `channel_id = "local"` 的消息看 `local_inbox` 开关,对别的消息看 `channel_id`;本地收件开着不等于 bot 那条路放宽。
- 脚本只在窗口标题里是指定的频道时抄(`--channel 名字`),切到别的频道就停;只抄列表末尾新增、时间标签是今天且在几分钟之内的消息,
  往上翻出来的旧消息、跨天后改了标签的消息都不抄。Discord 的渲染进程默认不建辅助功能树,要用 `open -a Discord --args --force-renderer-accessibility` 启动。
- 打开本地收件(`local_inbox` 从关到开)在跟单开着时算放宽,要 `gate.follow` 的确认;确认框上写明消息来源与显示名的风险。

## 一条消息怎么判(`follow.ts`)

| 顺序 | 检查 | 不过的下场 |
|---|---|---|
| 1 | 是不是配置的那个频道 | 不看 |
| 2 | 发送者在不在信任名单里 | 不跟、不落日志,只进「频道里最近看到的消息」(内存里留 30 条) |
| 3 | 像不像蝴蝶速记(有「蝴蝶」或翼宽记号) | 闲聊:不跟、不落日志 |
| 4 | 消息发出多久了(按消息 ID 里的时刻,不按本机收到的时刻) | `stale`:超过 `max_age_seconds` 不跟 |
| 5 | 本地速记能不能完整接住,而且拿到了标的现价 | `unparsed` |
| 6 | 中心写的是「N蝴蝶」时,算出来的中心离现价不到 50 点 | `unparsed` |
| 7 | 是不是恰好一张买入蝴蝶 | `unparsed` |
| 8 | 单笔最坏亏损 ≤ `max_risk_usd` | `capped` |
| 9 | 跟单开关开着 | `observed`(只观察) |
| 10 | 没熔断、「允许自动执行」开着、连着券商 | `blocked` |
| 11 | 今天(美东)跟的单数 < `max_orders_per_day` | `capped` |
| 12 | 交给引擎 `handleInstruction`(来源记成 `discord`) | `sent` / `held` / `rejected` |

- **只认本地速记,不交给大模型。** 别人写的一句话没有人在旁边确认,让模型"理解一下"再直接发单,错一次就是真钱。
  带了速记不认的成分(止损、条件、平仓、两张单拼在一起)的消息只提醒、不发。语法见 [交易指令](instruction.md)「本地速记」。
- **必须拿到现价。** 速记靠现价核对"中心离现价超过 20% = 多半写错了";手动下单时这一步有人看着,跟单没有,所以拿不到现价就不跟,
  哪怕消息里写明了中心与看涨看跌。
- **「N蝴蝶」在百位边上不跟。** 「N蝴蝶」的中心是现价的百位加 N(`shorthand.ts`):现价 7690 时「00蝴蝶」算成 7600,可写的人多半指 7700。
  手动下单有人看摘要;跟单没有,所以算出来的中心离现价 50 点或更远(`RELATIVE_CENTER_MAX_POINTS`,正好 50 = 两个百位一样近)就记成 `unparsed`,
  说明里写着算成了什么、另一个百位是多少。写明完整中心(「7700蝴蝶」)的不受影响。这一步在判定之前,只观察时也一样说"没接住"。
  阈值是 `follow.ts` 的一个常量,不是配置项。
- **单笔最坏亏损** = 张数 × 100 × 净权利金上限;没写权利金的(AUTO_MID)按翼宽算,和校验层给 AUTO_MID 组合定敞口同一个口径。
  发到几个账户时各发一份、各算各的。
- **跟单的上限是多加的一道**:第 11 步里限额、重复单、交易时段、保护规则、熔断照常生效,取更严的那个。
- **只跟开仓。** 对方的平仓、改价、止盈止损软件不知道;跟进来的持仓由用户自己管,或者自己设 [持仓追踪](tracker.md)。
- **编辑与删除不处理。** 只认新消息(`MESSAGE_CREATE`):对方改了字不会改单,删了消息不会撤单。
- **同一条消息只处理一次。** 进程内按消息 ID 去重,跨重启靠日志表的唯一约束。
- **消息排队处理。** 两条挨着来的单子不并发进引擎,第二条看得见第一条(每日单数、重复单)。

## 大模型在这条路上不出场

跟单先自己用本地速记解析一遍,接住了才交给引擎;引擎自己还会再解析一遍。引擎只保留它从这句话里抽出来的标的的现价,
别的会重取,所以两遍之间现价可能差一点(中心的百位、看涨看跌跟着现价走),以引擎那一遍为准;单笔上限只看张数、权利金与翼宽,不随现价变。

引擎那一遍万一没接住(两遍之间现价取不到了),按手动指令的规矩会落到大模型。`refuseModelWhileFollowing` 给引擎的解析器加了一道闸:
跟单那一趟里调大模型当场拒,不发单、不计解析失败、不碰熔断。闸认的是调用链(`AsyncLocalStorage`),不是共享开关:
手动指令可以同时在跑,不受影响。这样做是因为 `engine.ts` 的 `handleInstruction` 已经顶着体积预算,没有往它身上加"只许本地解析"的参数。

## 授权:一次确认,不是每单确认

每一单都没有人点确认,所以授权在打开的那一刻做:`settings.patch` 让跟单**比现在放得更开**时,主进程要 `gate.follow` 的确认凭据
(见 [确认凭据](confirm-grants.md))。

| 改动 | 要不要确认 |
|---|---|
| 从关到开 | 要 |
| 开着时换频道、多信任一个人、换一个人 | 要 |
| 开着时账户变了(多一个、换一个、清空 = 改发默认账户) | 要 |
| 开着时调大任何一个上限 | 要 |
| 关掉;只观察时改任何配置;开着时少信任一个人、少发一个账户、调小上限 | 不要 |

- 凭据绑的是补丁落下去之后的整份:频道、信任名单、账户、三个上限。确认的是一份、存的是另一份,不放行。
- 确认框上的字全由主进程对着这一份写(`confirm-grants.js` 的 `followConfirmText`),账户是纸面还是实盘问引擎;含实盘账户时标题里写明。
- 没同意现行条款时不能打开(见 [条款同意](consent.md))。
- 关是当场生效的,不等「保存」。
- 没有另设的隐藏开关:跟单发得出去的前提就是这一个开关,加上手动发单本来就要过的 `auto_execute`、`allow_live_trading` 与熔断。

## 配置

```json
"follow": {
  "enabled": false, "channel_id": "", "author_ids": [], "accounts": [],
  "max_age_seconds": 30, "max_orders_per_day": 3, "max_risk_usd": 300
}
```

| 键 | 含义 | 范围 |
|---|---|---|
| `enabled` | 关 = 只观察:照样连、照样解析、照样记日志,一张单都不发 | |
| `channel_id` | 读哪个频道;空 = 不连 Discord | 带引号的 15–21 位数字 |
| `author_ids` | 信任的发送者(用户 ID,或关注的 webhook ID;本地收件的写 `local:显示名`) | 同上,或 `local:` 加 1–80 字 |
| `accounts` | 发到哪些账户别名;空 = 默认账户 | |
| `max_age_seconds` | 消息多旧就不跟 | 1–600 |
| `max_orders_per_day` | 一天(美东)最多跟几单 | 1–100 |
| `max_risk_usd` | 一单最坏亏多少美元 | ≥ 1 |
| `local_inbox` | 本地收件:读交易库旁边的 `follow-inbox.jsonl`;可以不填频道只靠它 | 默认关 |

- ID 必须写成字符串:它超过了 JSON 数字能精确表示的范围,写成数字当场报。
- 三个默认值(30 秒、3 单、300 美元)是保守的起点,没有数据依据,由用户按自己的情况改。
- 「开着却没填频道 / 没填信任的人」「账户别名已经不存在」不算配置错:没频道就不连,没人可信就一条都不跟,别名在发单那一刻核对(记成 `blocked`)。
  配置读不进来的后果是引擎起不来、持仓没人盯,不为一段跟单配置冒这个险。界面保存前会查这几样。
- bot token 存在系统凭证库(service `dafri-discord-bot`),经 `follow.set_token` 写入,不进配置、不进日志;见 [系统凭证库](credentials.md)。

## 连接(`discordGateway.ts`)

- 断线后手里有会话就续连(RESUME),Discord 会补发断开期间漏掉的事件;补来的消息可能已经是几分钟前的,由第 4 步按消息时刻挡下。
  没有会话就重新认证,漏掉的不补。
- 心跳没有应答按僵尸连接处理:断开、续连。重连按 1–2 秒起步、翻倍、封顶一分钟退避。
- 重试没用的错停下来不再连:token 不对(4004)、没开 Message Content Intent(4014)等。状态变成 `failed`,发一条系统通知;
  改好之后在界面点「重新连接」或重存 token。
- 连上后记下 bot 所在服务器的频道表:配置的频道不在里面时界面提示"bot 听不到那里的消息"。
- 引擎只在真正的入口(`rpc/server.ts` 的 `main`)里起这条连接;测试里直接起的 server 不连 Discord。

## 日志与通知

- 信任的发送者发来的、像单子的每一条消息落一行 `follow_log`(只增不改):原文(截到 200 字)、发送者、下场、原因、订单摘要、落了哪几条交易记录。
  「今天跟了几单」从这张表数,引擎重建、软件重启都不归零。
- 每一条都发一条系统通知,没跟的也发:没跟上比跟上了更需要人知道。
- 审计日志里记 `follow_signal`(消息 ID、发送者、下场),存 token 记 `follow_token_set`(不含 token)。

## 已知的边界

- **价格放在下一条消息里**:对方先发「20蝴蝶 20CM」、再单独发一条「3.6」。第一条没写权利金,按盘口中间价定价,最坏亏损按翼宽算(翼宽 20 → $2,000)。
  默认的单笔上限 $300 会把它记成 `capped`;**上限调到不低于翼宽 × 100 时,这种半条消息会被当成完整的单子发出去。** 软件不把相邻的两条消息拼起来。
- **评论里带「蝴蝶」二字**(「蝴蝶先走一下」「蝴蝶止损了哦」):第 3 步按"有蝴蝶二字"判像不像单子,所以这类话也会走到解析、记成 `unparsed` 并发一条通知。
- **发单那一两秒里配置正好重载**(同时在别的页面保存了设置):这张单由旧引擎发出,新引擎认不出它的回报,成交不会回写到这条交易记录。
  单子本身在券商那边是正常的,持仓以券商为准。
- 本机时钟比真实时间快过 `max_age_seconds`,所有消息都会被当成太旧;慢则不影响。
- 关注公告频道的那条路有延迟:对方点了「发布」之后消息才会转过来。
- 富途通道不支持组合单,蝴蝶会被引擎拒绝。

## 当前状态

只有离线测试,**没有在真实的 Discord 连接与真实券商上核对过**。离线测试覆盖:判定规则、配置校验、日志表、Gateway 协议(假 socket)、
从消息到发单的整趟(真引擎 + 假券商)、收件文件的读法、主进程的确认凭据(真的 `main.js` + 真的引擎子进程)。
本地收件的脚本在真机的 Discord 窗口上试过读取;整条路(脚本 → 文件 → 引擎 → 发单)没有在真实券商上核对过。
第一次真机使用请先只观察,再在纸面账户上打开。
