# Discord 跟单

一个 Discord bot 读一个频道,信任的发送者在里面发的速记——写明价格的买入蝴蝶、写明方向与价格的贷方价差——不经确认直接走发单链路。
界面在「接入 → Discord 跟单」,配置在 `settings.json` 的 `follow` 段,bot token 在系统凭证库。**默认关、默认不连 Discord。**
消息还有第二个来源「本地收件」(见下),给对方的私密频道拉不进 bot 的情况;两个来源的消息走同一条判定与发单的路。
每条信号处理完之后记一次盘口(对方写的价对着此刻的中间价,见「延迟的代价」);跟进去的蝴蝶成交之后可以自动建一条持仓追踪
(默认关,见「成交之后:自动建追踪」)。

## 消息怎么进来

- **只用官方的 bot 通道**(bot token、Gateway v10)。不用任何人的用户 token:自动化个人账号(self-bot)违反 Discord 的条款、会封号,代码里没有这条路。
- bot 要在一个你能管理的服务器里。对方的频道拉不进 bot 时,让单子落到你自己的服务器:对方的频道是公告频道就点「关注」转过来;
  否则请对方同时在你的服务器里发一份。两种情况下软件这边没有区别:它只认「哪个频道、谁发的」。
- 关注过来的消息,发送者是那条关注的 webhook(ID 固定)。信任它等于信任所有能在源频道发公告的人。
- bot 需要三个 intent:`GUILDS`、`GUILD_MESSAGES`、`MESSAGE_CONTENT`。最后一个是特权 intent,要在 Developer Portal 里手动打开;
  没开时 Discord 以 4014 关闭连接,软件停下来并说明去哪里开。
- 连接只收不发:不向 Discord 发送任何消息。引擎不走代理:系统层面连不上 `gateway.discord.gg` 时这里也连不上。
- 配了频道 ID、凭证库里有 token 才连。没配频道时一个包都不发,也不去碰凭证库。

## 本地收件(`followInbox.ts`、`followReader.ts`)

对方的频道是私密的、拉不进 bot、也不是公告频道时,bot 那条路走不通。本地收件不碰 Discord 的接口:一个本机程序
(`desktop/tools/discord-window-follow.swift`)通过 macOS 的辅助功能读**你屏幕上** Discord 窗口里当前频道的消息列表,
新出现的消息一行一个 JSON 追加到交易库旁边的 `follow-inbox.jsonl`;引擎盯着这个文件,每行变成一条消息,之后和 bot 读来的消息一样过信任名单、
三个上限、只观察、发单。没有任何 token,Discord 那边什么都收不到,不是自动化账号。

- **从文件此刻的末尾读起**:引擎没在跑时追加的行不补——它们早就过了新鲜期,补进来只会刷一串「太旧」。文件变短(被清空、换了一个)就从头读。
  认不出的行记原因、跳过,后面的照读;状态写在面板「收件文件」那一行。
- **消息的时刻是程序看见它的时刻**:屏幕上只有"几点几分",没有秒。它每 1.5 秒看一次,所以到引擎手里时通常只有一两秒,新鲜度那道检查照常。
- **发送者是显示名**:`author_id` 写成 `local:名字`,信任名单里也这样写(`config.ts` 的 `LOCAL_AUTHOR`)。频道里别人把昵称改成一样的,软件分不出来——
  风险揭示里写明了,只适合私密小群。消息 ID 是 `local:` 加脚本给每条消息算的 key,去重照旧按 ID。
- **判定里它是 `local` 频道**:`triage` 对 `channel_id = "local"` 的消息看 `local_inbox` 开关,对别的消息看 `channel_id`;本地收件开着不等于 bot 那条路放宽。
- 程序只在窗口标题里是指定的频道时抄(`--channel 名字`),切到别的频道就停;只抄列表末尾新增、时间标签是今天且在几分钟之内的消息,
  往上翻出来的旧消息、跨天后改了标签的消息都不抄。离开那个频道再回来,期间的消息不补:它们到引擎手里时会被当成刚发的。
  Discord 的渲染进程默认不建辅助功能树,要用 `open -a Discord --args --force-renderer-accessibility` 启动。
- 打开本地收件(`local_inbox` 从关到开)、开着时填上或换一个频道名(`local_channel`),在跟单开着时算放宽,要 `gate.follow` 的确认;
  确认框上写明消息来源、读哪个频道与显示名的风险。清空频道名不算:那只是软件不再自己读。

### 读窗口的程序由谁来跑(`followReader.ts`)

- **填了频道名,引擎自己跑。** 本地收件开着、`local_channel` 不空时,引擎把编译好的那一份拉起来(带 `--supervised`),换了频道名就换一个,
  关掉本地收件、引擎退出时一起停。靠人记得去终端里开脚本,忘了就是一整晚不跟,而且没有任何提示。
- **程序随 Mac 安装包带着**(`resources/tools/discord-window-follow`,打包前由 `tools/build_inbox_reader.js` 编译,用户的电脑上不用装 Swift);
  主进程用环境变量 `DAFRI_INBOX_READER` 把位置告诉引擎。不是 macOS、这一份软件没带它、没填频道名,引擎就不跑,用户自己运行脚本。
  两种跑法往同一个文件里写,引擎读文件那一半不区分;两个同时在跑也不会重复发单,消息按 ID 去重。
- **它是引擎的子进程,不是独立的后台服务。** 它的标准输入是一根引擎不写的管道:引擎没了(正常退、崩了、被杀)管道就断,它读到头自己退。
  不装开机启动项,不留孤儿进程。
- **状态走标准输出,一行一个 JSON**:`reading`、`waiting`(没有窗口停在这个频道)、`no_list`(窗口在、消息列表读不到)、`no_discord`、`untrusted`。
  引擎只认这五种,别的输出不认、不记:消息原文不经过引擎的日志。界面「读窗口」那一行显示它——这是"到底有没有在读"唯一看得见的地方,
  所以每一种"没在读"都写明人该做什么(`followForm.ts` 的 `readerText`)。
- **辅助功能权限算在软件头上**(macOS 按拉起它的那个应用认):要在「系统设置 → 隐私与安全性 → 辅助功能」里打开 IBKR-Assistant。
  没有权限时程序报 `untrusted`、以退出码 77 退出,引擎每 5 秒再拉起来看一眼,授权之后不用重启软件;系统的授权提示只让头一次拉起的那个弹。
- 别的退出按 1 秒起步、翻倍、封顶一分钟重启,读上过就从头算;原因写在「读窗口」那一行。
- **Discord 仍要用户自己带参数启动。** 软件不替人重启别的应用;窗口在这个频道却读不到消息列表时报 `no_list`,界面上写明那条命令。
- 手动运行的脚本软件看不见:没填频道名时「读窗口」那一行只说要自己运行脚本,它有没有在读看「收件文件」那一行的收到条数。

## 一条消息怎么判(`follow.ts`)

| 顺序 | 检查 | 不过的下场 |
|---|---|---|
| 1 | 是不是配置的那个频道 | 不看 |
| 2 | 发送者在不在信任名单里 | 不跟、不落日志,只进「频道里最近看到的消息」(内存里留 30 条) |
| 3 | 摘掉提及之后,有没有单子的骨架:蝴蝶的翼宽记号、价差的类型词(bull put / bear call)、或价差的样子(两个行权价 + 负的权利金) | 闲聊:不跟、不落日志 |
| 4 | 消息发出多久了(按消息 ID 里的时刻,不按本机收到的时刻) | `stale`:超过 `max_age_seconds` 不跟 |
| 5 | 本地速记能不能完整接住,而且拿到了标的现价 | `unparsed`(像价差却没写方向的,说明里写明差的是方向) |
| 6 | 中心写的是「N蝴蝶」时,算出来的中心离现价不到 50 点 | `unparsed` |
| 7 | 是不是恰好一张写明了价格的买入蝴蝶,或一张写明了收多少的贷方垂直价差 | `unparsed` |
| 8 | 单笔最坏亏损 ≤ `max_risk_usd` | `capped` |
| 9 | 跟单开关开着 | `observed`(只观察) |
| 10 | 没熔断、「允许自动执行」开着、连着券商 | `blocked` |
| 11 | 今天(美东)跟的单数 < `max_orders_per_day` | `capped` |
| 12 | 交给引擎 `handleInstruction`(来源记成 `discord`) | `sent` / `held` / `rejected` |

- **只认本地速记,不交给大模型。** 别人写的一句话没有人在旁边确认,让模型"理解一下"再直接发单,错一次就是真钱。
  带了速记不认的成分(止损、条件、平仓、两张单拼在一起)的消息只提醒、不发。语法见 [交易指令](instruction.md)「本地速记」。
- **先摘掉提及再判断**(`orderText`):`@everyone` / `@here` / `<@用户>` / `<@&身份组>` / `<#频道>`。对方几乎每条单子都带 `@everyone`,
  不摘的话 every 会被当成标的代码,一条都解析不出来。日志里记的仍是原文。
- **有单子的骨架才算单子**(`looksLikeOrder`)。光提到「蝴蝶」两个字的是评论(「蝴蝶先走一下」「蝴蝶止损了哦」),不落日志、不通知;
  没有翼宽的蝴蝶本来也解析不出来。价差没写方向的(「75 70 -2 试一下」)算有骨架:它是对方真发的单,不跟,但要落一条 `unparsed` 让人知道。
- **没写价格的不跟。** 对方常把价格放在下一条消息里(「20蝴蝶 20CM」,再一条「3.6」)。软件不把相邻的两条拼起来,也不替人按盘口中间价定价——
  手动下单时那一步有人看着,这里没有。记成 `unparsed`,上限调得再高也一样。
- **贷方价差必须写明方向。** 只认 `bull put`(卖高买低的 put)与 `bear call`(卖低买高的 call)。这类单子收的权利金接近宽度的一半,
  行权价贴着现价,靠现价猜它在上面还是下面不可靠。写的是区间(「-2 -2.5」)时按收得多的一头挂单:可能成交不了,不会比对方写的差。
  借方价差、单腿期权不跟。
- **必须拿到现价。** 速记靠现价核对"中心离现价超过 20% = 多半写错了";手动下单时这一步有人看着,跟单没有,所以拿不到现价就不跟,
  哪怕消息里写明了中心与看涨看跌。
- **「N蝴蝶」在百位边上不跟。** 「N蝴蝶」的中心是现价的百位加 N(`shorthand.ts`):现价 7690 时「00蝴蝶」算成 7600,可写的人多半指 7700。
  手动下单有人看摘要;跟单没有,所以算出来的中心离现价 50 点或更远(`RELATIVE_CENTER_MAX_POINTS`,正好 50 = 两个百位一样近)就记成 `unparsed`,
  说明里写着算成了什么、另一个百位是多少。写明完整中心(「7700蝴蝶」)的不受影响。这一步在判定之前,只观察时也一样说"没接住"。
  阈值是 `follow.ts` 的一个常量,不是配置项。
- **单笔最坏亏损**:蝴蝶 = 张数 × 100 × 净权利金上限;贷方价差 = 张数 × 100 ×(宽度 − 收到的权利金),和校验层给贷方组合定敞口同一个口径。
  发到几个账户时各发一份、各算各的。
- **跟单的上限是多加的一道**:第 12 步里限额、重复单、交易时段、保护规则、熔断照常生效,取更严的那个。
- **只跟开仓。** 对方的平仓、改价、止盈止损软件不知道,也不去猜。跟进来的持仓怎么收尾有两种:用户自己管(自己平,或者自己设
  [持仓追踪](tracker.md));或者打开「成交后自动建追踪」,让软件用**用户自己的**蝶式预设替买入的蝴蝶收尾(见下一节)。
  后一种不是跟着对方平——对方走的时候软件照样不知道。贷方价差只有前一种。
- **编辑与删除不处理。** 只认新消息(`MESSAGE_CREATE`):对方改了字不会改单,删了消息不会撤单。
- **同一条消息只处理一次。** 进程内按消息 ID 去重,跨重启靠日志表的唯一约束。
- **消息排队处理。** 两条挨着来的单子不并发进引擎,第二条看得见第一条(每日单数、重复单)。

## 成交之后:自动建追踪(`track_fly`)

只跟开仓、平仓全靠人事后去设,实际用起来就是每一单都裸着。`track_fly` 打开之后,跟进去的**买入蝴蝶**成交了,软件自己给它建一条
持仓追踪:蝶式预设(分档利润回撤)+ 到价自动平仓,`track_exit_at` 填了钟点还带到点平仓。默认关。

- **建的就是界面上那一条。** 服务不认识追踪的规则:它调的是装配时接进来的 `tracker.add` 的 handler(`rpc/server.ts` 一行),
  入参(`follow.ts` 的 `flyTrackParams`)和「持仓追踪」页给一只组合勾「分档利润回撤(蝶式)」「到价自动平仓」、别的不动时发的逐键相同
  (数值是字符串、`''` = 不设、限价平仓、不托管、止损类按中间价判),只多到点平仓的钟点与一句备注「Discord 跟单自动建立」。
  档位、按金额起算、追价、闸门都是 [持仓追踪](tracker.md) 那一头的;那边改了,这里跟着变。
- **到点平仓的钟点用不上时,追踪照建、不带它。** `tracker.add` 会拒绝一个落在合约到期之后的到点时刻(今天的钟点已经过了,下一次是明天,
  而当日到期的蝶那时已经不在了)。因为一个用不上的钟点让整条追踪建不成,那份持仓就什么保护都没有了,所以这一种拒绝之后去掉钟点再建一次,通知里写明没有带。
- **只管买入的蝴蝶。** 贷方价差照跟、不建:蝶式预设的起算线与档位是按"付出的成本"定的,套在收权利金的结构上没有意义。
  这类信号的说明里写明「不自动建追踪,平仓由你自己管」。
- **先要有成交的证据,再看持仓。** 发出去的蝴蝶登记成"在等"(记录 id、消息 id、账户、标的、腿身份),存在库的偏好表里,引擎重启不丢。
  有在等的时候每 3 秒核对一轮(`follow.ts` 的 `pendingVerdict`);先看这张单的交易记录,有了成交回报才去读持仓——
  一张限价单可能挂上几个小时,这段时间里不读持仓、不写库、不惊动界面:

| 这一轮看到 | 做什么 |
|---|---|
| 这张单没有成交回报、还挂着 | 等。账户里本来就有一只一模一样的蝶也不建——那一只是用户自己的,没有授权过 |
| 这张单走完了、一张没成交(撤了、被拒、失效) | 不再等,不提醒 |
| 有成交回报(部分成交也算),持仓里有这只蝶,上面没有追踪 | 建 |
| 有成交回报,持仓里还没有这只蝶 | 等;单子走完之后连续 5 轮都没有,提醒「持仓里找不到这只蝶」(已经平掉了,或者它的腿和同一到期日的别的持仓并在了一起) |
| 读不到这个账户的持仓(断线、会话没连上) | 等,读不到不等于没有 |
| 这只蝶上已有一条在盯的追踪 | 不另建(同一份持仓只能有一条),提醒「沿用已有的追踪」。那一条触发时平的是当时的全部持仓,所以加进来的数量也在里面;它的起算线与档位是建的时候按当时的成本换算的,不会因为加仓重算 |
| 这只蝶上留着一条停用或触发过的旧追踪 | 建不了,软件也不替人删(那条旧追踪可能还在追它自己的平仓单)。提醒「这一单现在没有追踪在盯」,要人删掉旧的再建 |
| 过了该等的那一天 | 不再等并提醒。当天到期的蝶等到当天(美东);到期日在后面的(夜盘里下的次日到期的蝶)多等一天 |

- **部分成交就建,单子走完之前接着看。** 两张成交了一张、剩下的还挂着:已经有持仓了,当场建。之后这一条不算"在等",
  但留着看这张单后来的成交(只看交易记录与追踪表,不读持仓):追踪还在盯,后成交的由它一起管;追踪已经触发过(或停了、被删了)
  而这张单又成交了,提醒「后成交的部分没有追踪」。单子走完或隔了日就不再看。
- **追踪管的是整份持仓。** 账户里本来就有同一只蝶(没设追踪)时,跟进来的那几张成交之后建的追踪连原来的一起管;
  通知里写明这只蝶现在一共几张。
- **腿身份对得上。** 持仓那一头的组合行按「到期|+1x行权价C,-2x…」认(`combos.comboRow`),订单这一头用 `engine/closing.ts` 的 `orderLegId`,
  两边同一种写法;1 张与多张的蝴蝶都是 +1 / −2 / +1。
- **`tracker.add` 拒了就说原因、不再试**(持仓刚被平掉、同一份持仓已有追踪……都是它自己那句话);建的那一下断了线,下一轮再试,
  连续 10 轮不成才放弃并提醒。
- **到点平仓落在"下一次到这个钟点"。** 和手动建的追踪同一条规矩:建追踪时今天的这个钟点已经过了,它就落在第二天,通知里写明是哪一天。
- **收回授权当场作数。** 关掉自动跟单、或者关掉这一项,还在等的一律不建(提醒一次)。已经建好的追踪是普通的追踪,在「持仓追踪」里改、停、删。
- 建好、沿用、建不了都发系统通知并留审计痕迹;界面上显示有几只在等。

## 延迟的代价:处理完之后记一次盘口

跟单比对方晚:消息在路上、解析、发单各要一点时间。信任的发送者发来的、解析出**恰好一张写明价格的单**的每一条信号——不管下场是
已跟单、只观察、超上限、闸门关着、没有发出还是被拒——处理完之后取一次这张单各腿的盘口,和对方写的价一起记下:
对方的价、组合中间价、立刻能成交的价(买的腿按卖价、卖的腿按买价)、消息发出多少秒之后取的、是不是纸面会话的行情。
没接住的、太旧的没有可比的价,不记。

- **只记不判。** 没有"贵多少算多"的线、没有汇总结论、界面不按差多少上色。晚几秒值多少钱要攒够条数由人自己看;
  这个数也不回流到发不发单、挂什么价。
- **绝不拖慢、也不连累那一张单。** 取盘口排在引擎返回之后,不占消息的队(下一条消息照常处理),出任何错都只落一行日志;
  没连 IBKR、TWS 不答话、有一条腿没有买价或卖价,一律不记、不重试、不提醒。
- **行情走蝴蝶测算那批自己的流**(`optionMarks.ts`,和测算、IV 记录共用一份),不用引擎给没写价的组合定价的 `legQuotes`:
  后者现订现撤,订的腿正好是持仓的腿时拿到的是盯盘那条常驻流,用完一撤,盯盘下一轮就得重订、多等一秒半
  (见 [持仓追踪](tracker.md)「腿的行情流被别处撤掉」)。跟单刚成交的那只蝶正是这种情形。代价是只在 IBKR 上记。
- **方向统一成"对方那个方向的正数"。** 买入蝴蝶三个价都是"付多少",贷方价差都是"收多少"(`follow.ts` 的 `followQuote`);
  中间价的方向和这张单对不上(盘口是坏的)不记。界面那一行把差额说成对自己是好是坏:蝴蝶「比对方贵 / 便宜」,贷方价差「比对方少收 / 多收」。
- **隔了多久**按消息的时刻算:bot 读来的是 Discord 盖的发出时刻;本地收件的消息没有这个时刻,按读窗口的程序看见它的那一刻算,界面写成「读到消息 N 秒后」。
- **纸面会话的行情可能是延迟的**(没有实时行情权限时 IBKR 给延迟盘口),这一条记在每一笔上,界面写明。
- 发出去的单取的是引擎落库的那一份合约;没落库的(只观察、超上限……)用这里自己解析的那一份。
- 存在 `follow_quotes` 表(消息 ID 唯一,只增不改),读日志时按消息 ID 接上。日志表不许改、而报价在日志落下之后才取,所以另起一张表;
  新表用 `CREATE TABLE IF NOT EXISTS` 建,不动库的结构版本号。

## 大模型在这条路上不出场

跟单先自己用本地速记解析一遍,接住了才交给引擎;引擎自己还会再解析一遍。引擎只保留它从这句话里抽出来的标的的现价,
别的会重取,所以两遍之间现价可能差一点(中心的百位、看涨看跌跟着现价走),以引擎那一遍为准;单笔上限只看张数、权利金与翼宽,不随现价变。

引擎那一遍万一没接住(两遍之间现价取不到了),按手动指令的规矩会落到大模型。`refuseModelWhileFollowing` 给引擎的解析器加了一道闸:
跟单那一趟里调大模型当场拒,不发单、不计解析失败、不碰熔断。闸认的是调用链(`AsyncLocalStorage`),不是共享开关:
手动指令可以同时在跑,不受影响。这样做是因为 `engine.ts` 的 `handleInstruction` 已经顶着体积预算,没有往它身上加"只许本地解析"的参数。

## 授权:一次确认,不是每单确认

每一单都没有人点确认,所以授权在打开的那一刻做:`settings.patch` 让跟单**比现在放得更开**时,主进程要 `gate.follow` 的确认凭据
(见 [确认凭据](confirm-grants.md))。

| 改动 | 要不要确认 |
|---|---|
| 从关到开 | 要 |
| 开着时换频道、多信任一个人、换一个人 | 要 |
| 开着时打开本地收件、填上或换一个本地收件的频道名 | 要 |
| 开着时账户变了(多一个、换一个、清空 = 改发默认账户) | 要 |
| 开着时调大任何一个上限 | 要 |
| 开着时打开「成交后自动建追踪」;它开着时填上或换一个到点平仓的钟点 | 要 |
| 关掉;只观察时改任何配置;开着时少信任一个人、少发一个账户、调小上限、关掉本地收件、清空它的频道名、关掉「成交后自动建追踪」、清空到点平仓的钟点 | 不要 |

- 凭据绑的是补丁落下去之后的整份:频道、信任名单、账户、三个上限、本地收件与它的频道名、成交后建不建追踪与到点平仓的钟点。
  确认的是一份、存的是另一份,不放行。
- 确认框上的字全由主进程对着这一份写(`confirm-grants.js` 的 `followConfirmText`),账户是纸面还是实盘问引擎;含实盘账户时标题里写明。
- **自动建追踪没有另设的授权。** 它会自动发平仓单,所以算在打开跟单的这一次确认里:开着时确认框写明"成交后软件自己建追踪、
  按蝶式预设到价直接发平仓单、到点平仓是几点、只管蝴蝶、对方的平仓仍然不知道";关着时也写一行"跟进来的持仓软件不会替你平"。
  跟单已经开着时再打开它、或者给它换一个钟点,是让软件多做一件会发单的事,要的还是这同一个确认框。
  关掉它、清空钟点是在减少自动化,不要确认:停掉自动化绝不比打开它难。
- 没同意现行条款时不能打开(见 [条款同意](consent.md))。
- 关是当场生效的,不等「保存」。
- 没有另设的隐藏开关:跟单发得出去的前提就是这一个开关,加上手动发单本来就要过的 `auto_execute`、`allow_live_trading` 与熔断。

## 配置

```json
"follow": {
  "enabled": false, "channel_id": "", "author_ids": [], "accounts": [],
  "max_age_seconds": 30, "max_orders_per_day": 3, "max_risk_usd": 300,
  "local_inbox": false, "local_channel": "",
  "track_fly": false, "track_exit_at": ""
}
```

| 键 | 含义 | 范围 |
|---|---|---|
| `enabled` | 关 = 只观察:照样连、照样解析、照样记日志,一张单都不发 | |
| `channel_id` | 读哪个频道;空 = 不连 Discord | 带引号的 15–21 位数字 |
| `author_ids` | 信任的发送者(用户 ID,或关注的 webhook ID;本地收件的写 `local:显示名`) | 同上,或 `local:` 加 1–80 字 |
| `accounts` | 发到哪些账户别名;空 = 默认账户 | |
| `max_age_seconds` | 消息多旧就不跟 | 1–600 |
| `max_orders_per_day` | 一天(美东)最多跟几单 | 1–100 |
| `max_risk_usd` | 一单最坏亏多少美元 | ≥ 1 |
| `local_inbox` | 本地收件:读交易库旁边的 `follow-inbox.jsonl`;可以不填频道只靠它 | 默认关 |
| `local_channel` | 本地收件读哪个频道:Discord 窗口标题里的名字。填了,软件自己跑读窗口的程序;空 = 自己运行脚本 | 0–100 字,不含换行 |
| `track_fly` | 跟进去的买入蝴蝶成交之后自动建持仓追踪(蝶式预设 + 到价自动平仓) | 默认关 |
| `track_exit_at` | 自动建的那条追踪的到点平仓钟点(美东);空 = 不设。只在 `track_fly` 开着时有用 | `HH:MM`(时可以只写一位),或空 |

- ID 必须写成字符串:它超过了 JSON 数字能精确表示的范围,写成数字当场报。
- 三个默认值(30 秒、3 单、300 美元)是保守的起点,没有数据依据,由用户按自己的情况改。
- `track_exit_at` 认的写法和持仓追踪的「到点平仓」是同一种(`trackerExits.clockMinutes`)。配置在地基层、引不到分析层,所以 `config.ts`
  里照着写了一份(`FOLLOW_CLOCK`),测试拿同一批写法对着两边与界面那一份;写得不对在读配置时就拒,不留到成交之后建追踪那一刻。
  软件没有给它预填钟点:几点走是用户自己的规则。
- 「开着却没填频道 / 没填信任的人」「账户别名已经不存在」不算配置错:没频道就不连,没人可信就一条都不跟,别名在发单那一刻核对(记成 `blocked`)。
  配置读不进来的后果是引擎起不来、持仓没人盯,不为一段跟单配置冒这个险。界面保存前会查这几样。
- bot token 存在系统凭证库(service `dafri-discord-bot`),经 `follow.set_token` 写入,不进配置、不进日志;见 [系统凭证库](credentials.md)。

## 连接(`discordGateway.ts`)

- 断线后手里有会话就续连(RESUME),Discord 会补发断开期间漏掉的事件;补来的消息可能已经是几分钟前的,由第 4 步按消息时刻挡下。
  没有会话就重新认证,漏掉的不补。
- 心跳没有应答按僵尸连接处理:断开、续连。重连按 1–2 秒起步、翻倍、封顶一分钟退避。
- 重试没用的错停下来不再连:token 不对(4004)、没开 Message Content Intent(4014)等。状态变成 `failed`,发一条系统通知;
  改好之后在界面点「重新连接」或重存 token。
- 连上后记下 bot 所在服务器的频道表:配置的频道不在里面时界面提示"bot 听不到那里的消息"。
- 引擎只在真正的入口(`rpc/server.ts` 的 `main`)里起这条连接;测试里直接起的 server 不连 Discord。

## 日志与通知

- 信任的发送者发来的、像单子的每一条消息落一行 `follow_log`(只增不改):原文(截到 200 字)、发送者、下场、原因、订单摘要、落了哪几条交易记录。
  「今天跟了几单」从这张表数,引擎重建、软件重启都不归零。
- 处理完之后取到的那一次盘口落在 `follow_quotes`(只增不改,一条消息一行),读日志时接成那条信号的 `quote`;没取到就没有这个键。
- 每一条都发一条系统通知,没跟的也发:没跟上比跟上了更需要人知道。记盘口不发通知。
- 自动建追踪的每一个结局各发一条通知:已建(这只蝶现在几张、带着哪些出场规则:起算线、档位、到点平仓、是不是自动平仓)、
  沿用已有的追踪、没有建(原因)、后成交的部分没有追踪、不再自动建(授权收回)。单子没成交而不建的不提醒。
- 审计日志里记 `follow_signal`(消息 ID、发送者、下场)、`follow_track`(建了哪条追踪、它的目标与平仓设置)、
  `follow_track_dropped`(不建了,原因)、`follow_track_failed`(`tracker.add` 没建成,原因);存 token 记 `follow_token_set`(不含 token)。
  追踪本身那条 `tracker_add` 的痕由 handler 照常留,发起方记的是 `ui`——它不知道是谁调的,`follow_track` 那一条说明了来路。

## 已知的边界

- **发单那一两秒里配置正好重载**(同时在别的页面保存了设置):这张单由旧引擎发出,新引擎认不出它的回报,成交不会回写到这条交易记录。
  单子本身在券商那边是正常的,持仓以券商为准。自动建追踪靠的正是这条记录上的成交回报:这种情形下它等不到,隔日提醒「不再等」,
  期间这只蝶没有追踪。
- **同一只蝶当天第二次跟进去**:第一次那条追踪触发、平掉之后留在表里(停用、已触发),第二次成交时建不了新的,只会提醒。
  要人到「持仓追踪」删掉旧的那条。
- **自动建的追踪和手动建的一样只在本机盯**:软件关着、电脑睡着时不触发;到价时「允许自动执行」关着、实盘闸门关着、手动熔断中,
  它只提醒、不发单。
- **记盘口和蝴蝶测算共用一批行情流**(最多 24 条,闲置一分钟撤):两边同时用时互相排队,测算面板那一下可能慢几秒;
  流多到要腾位置时,最久没读的先撤。
- 本机时钟比真实时间快过 `max_age_seconds`,所有消息都会被当成太旧;慢则不影响。
- 关注公告频道的那条路有延迟:对方点了「发布」之后消息才会转过来。
- 富途通道不支持组合单,蝴蝶会被引擎拒绝。

## 当前状态

只有离线测试,**没有在真实的 Discord 连接与真实券商上核对过**。离线测试覆盖:判定规则、配置校验、日志表、Gateway 协议(假 socket)、
从消息到发单的整趟(真引擎 + 假券商)、收件文件的读法、读窗口程序的看管(假子进程、假时钟)、主进程的确认凭据(真的 `main.js` + 真的引擎子进程)。
记盘口与自动建追踪同样只有离线测试:盘口的换算、取盘口不占消息的队、不碰持仓腿的常驻行情流(真的会话层 + 假的 TWS 库)、
成交回报到了才建、部分成交、撤单、重启接着等、交给 `tracker.add` 的入参,以及真的 `RpcServer` 上从消息到库里多出一条追踪的整趟
(和用界面的载荷建出来的那条目标与平仓设置一致)。真机上没看过的:IBKR 对这三条腿给盘口要多久(决定"隔了多久"里有多少是等行情)、
成交回报与持仓更新之间实际差多少、自动建的追踪在实盘上第一次触发。
本地收件的脚本在真机的 Discord 窗口上试过读取;整条路(脚本 → 文件 → 引擎 → 发单)没有在真实券商上核对过。
编译好的读窗口程序在真机上从终端跑过 `--supervised`:四种状态(在读、不在这个频道、Discord 没开、没有权限)与管道一断就退都对;
由装好的应用拉起它、以及授权提示与权限算在 IBKR-Assistant 头上这一段,没有在真机上核对过。
解析与判定对着一个真实频道三周的消息离线跑过(114 条里 22 条有单子的骨架,17 条会跟);贷方价差没有在真实券商上发过单。
第一次真机使用请先只观察,再在纸面账户上打开。
